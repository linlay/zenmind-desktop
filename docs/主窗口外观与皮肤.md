# 主窗口外观与皮肤

## 定位与范围

主窗口外观层统一拥有 Desktop renderer 的明暗模式、皮肤解析和文档样式投影。AppShell 负责布局、导航和业务状态，通过外观层消费当前明暗快照与设置命令，不再独立管理主题状态或写入浏览器主题缓存。

皮肤描述视觉差异，不能改变窗口操作、布局约束、页面身份或能力授权。明暗偏好与皮肤是独立维度，同一皮肤可以有浅色和深色版本。默认皮肤沿用基础 CSS；后续皮肤通过受控的视觉变量覆盖基础值，不复制默认配色，也不接受任意 CSS 或可执行脚本。

当前已建立统一管理、主窗口控件的语义变量、背景层及皮肤注册表，并在正式外观设置中接入持久选择、用户图片导入和 ZIP 皮肤包安装。Desktop 拥有皮肤安装及主窗口绘制；Agent WebClient 通过独立的受限外观快照消费语义颜色和背景模式。

## 所有权与状态流

- Main 的 Desktop profile 是明暗偏好、内置皮肤选择与自定义背景引用的权威来源。既有 settings IPC 负责明暗与平台窗口外观，专用外观 IPC 负责皮肤和受控图片导入。
- renderer 外观控制器持有当前主窗口的展示快照、系统主题订阅以及串行的设置写入。设置页与 Desktop Action 必须调用同一个控制器。
- 品牌命名空间下的浏览器存储只用于首屏缓存。成功读取 profile 后，规范偏好覆盖缓存；读取失败保留当前外观，不得把缓存当作规范值写回 Main。
- 系统明暗变化只重新解析跟随系统的显示值，不能把用户的“跟随系统”偏好持久化为某个具体明暗模式。

```text
启动缓存 + 当前系统明暗
  -> React 挂载前设置文档明暗
  -> 主窗口外观层挂载并读取 Main profile
  -> 规范明暗偏好 + 选中皮肤 + 可用的自定义背景
  -> 同步文档变量与 React 快照
```

用户切换时先预览目标明暗，通过既有 IPC 串行保存。Main 先提交 profile，再更新原生窗口明暗，写盘失败不能让窗口外框停留在被拒绝的颜色。保存成功后更新缓存；最新一次保存失败时回到最近一次成功确认的偏好并向调用方报告失败。旧读取、旧挂载和较早保存的迟到结果不能覆盖更新的选择。恢复配置触发的刷新必须等待已有保存完成，再读取 profile。

皮肤选择只接受内置或已安装注册表中的 ID。内置皮肤立即预览；外部皮肤等待 Main 确认并返回受控定义后应用。所有选择串行保存。明暗与皮肤拥有独立的读取和写入版本，避免其中一项的迟到结果覆盖另一项；皮肤切换不调用明暗保存 IPC。成功保存后才更新对应的启动缓存，失败回到最近一次确认的选择。图片导入、更换、恢复与皮肤保存共用皮肤操作队列，不能让较早导入的完成事件把较新的皮肤切回去。未知 ID 不改变当前外观。

皮肤与自定义背景是正交选择。切换内置皮肤保留已选图片；应用皮肤包默认使用包内背景，用户可选择保留自定义图片。恢复皮肤背景只移除图片覆盖，不改变按钮配色或明暗偏好。正式设置读取失败时显示重试入口，在获得规范设置前不开放修改；文件缺失不阻止用户更换或恢复背景。

## 自定义图片与持久化边界

Main 设置模块拥有用户导入的背景副本。系统文件选择器只向 Main 返回路径，renderer 不传入任意路径，也不获得本地路径。新增外观 IPC 只允许当前真实主窗口的顶层 frame 调用；选择器返回后再次校验所有者。macOS 使用系统文件选择器解析 Finder alias，Windows 显式避免将导入项加入近期文档。

只接受大小与像素数量受限的 PNG/JPEG 栅格图片。Main 先按签名和头部尺寸检查，再使用 Electron 的内存图片解码器解码、缩放和重新编码；不依赖平台缩略图提供者，不导入 SVG、CSS、远程 URL 或脚本。重新编码去除原始元数据，保留透明通道并限制输出大小。导入不修改原图，复制完成后移动或删除原图不影响 Desktop。

图片放在 Desktop 自身的数据分区，profile 仅保存不透明的受控资产引用与展示元数据，浏览器缓存仅保存皮肤 ID。新图片先落盘，再以同目录临时文件原子替换 profile；保存失败保留旧 profile 和旧图片，成功后才清理被替换的图片。文件写入、profile 变更和读取在 Main 外观队列中串行，其他设置仍通过 profile 的局部合并保留外观字段。图片字节只通过有界 data URL 投影到当前 renderer 内存，不存入 localStorage，不扩大 renderer 的本地文件或协议读取能力。

配置恢复沿用已有规范配置刷新事件。升级不会主动清空背景数据；如果恢复的 profile 引用不再存在的图片，则保留引用以提示用户、回退当前皮肤背景，并提供重新选择或恢复皮肤背景。缓存、缺失图片或渲染失败不能触发规范配置的隐式改写。

## ZIP 皮肤包

皮肤包是静态视觉数据，由版本化 JSON 与包内 PNG/JPEG 构成。Main 设置模块负责包校验、图片重新编码、安装和删除；renderer 只获得受控定义、缩略图和当前皮肤资源，不获得 ZIP 原始内容或磁盘路径。允许根目录或单层包装目录中的清单，忽略 Finder 元数据，不安装未声明的文件。外部皮肤的字段与 token 值必须经过白名单解析，不能提供脚本、任意 CSS、远程 URL 或可执行资源。

导入先在内存完成有界 ZIP 解码、清单及资源校验，再写入独立临时目录，以同根目录改名发布完整安装。路径、条目数量、压缩与展开尺寸、CRC、重复名称和符号链接均受校验；不调用平台解压命令，也不沿用 ZIP 内的磁盘路径或权限。选择器返回和异步处理结束后重新校验当前主窗口所有权。相同逻辑适用于 macOS 和 Windows，系统选择器及数据根沿用显式平台分支。

安装目录使用内部不透明 ID，清单 ID 与版本用于重复检测。同 ID 同版本拒绝重复安装，不同版本独立保存，导入不替换旧包也不自动应用。目录发布是安装提交点，profile 仅保存当前选择。列表返回有限的缩略图，只有当前皮肤返回完整背景，避免把所有已安装图片同时送入 renderer。

应用时串行保存皮肤选择及是否移除自定义背景，失败保留旧选择和旧图片。删除包先改名暂存，再提交当前皮肤的默认回退，失败恢复安装目录；已提交删除后的文件清理可重试。启动读取根据 profile 判断暂存删除是否已提交，恢复仍被选中的包或清理已删除包。用户关闭应用不会把半个安装当成可用皮肤。安装包或背景缺失时使用默认外观或皮肤底色，并保留恢复入口，不隐式改写用户选择。

资源文件随用户数据保留，不因升级清空。包格式、限制与精确字段以 `src/shared/desktop-skin-package.ts` 为准，运行期定义以 `src/shared/desktop-skin-definition.ts` 为准，制作示例见 `qa/skin-packages/`。

## Agent 皮肤动作

皮肤由独立的 `desktop.skin` 动作域管理，明暗偏好继续属于 `desktop.theme`。公开动作提供当前状态、摘要列表、指定本机 ZIP 导入、选择与删除；精确输入和结果以 shared action 定义及 `desktop-skin-actions.ts` 为准。导入不自动应用、不覆盖同 ID 同版本，选择与导入分别提交；删除当前安装皮肤回退默认皮肤。

Main 设置模块持有唯一外观 runtime 和串行队列。主窗口 IPC 与动作执行器通过组合根注入同一实例，读取、原生选择器和写入都在该队列内执行；Action 通过窄端口复用领域操作，不导入设置模块内部 store、不模拟 renderer sender。IPC 继续验证主窗口主 frame，公开动作只允许已授权 Desktop 或 Agent Platform 来源，使用既有动作确认策略，不向普通 Website/WebApp 开放主机文件访问。

动作导入路径指向 Desktop 所在主机，macOS 使用绝对 POSIX 路径，Windows 使用完整盘符路径，拒绝相对路径、URI、UNC 与设备路径；不做容器路径映射、下载或 shell 展开。包解析与原子安装沿用现有约束。公共响应仅投影目标摘要或选择状态，不返回磁盘路径、图片字节、完整视觉定义或额外列表。保存选择与实际回退分别表示，缺失包不隐式改写 profile。

成功变更通过既有规范配置刷新事件通知主窗口，导入或删除未选中皮肤也刷新列表。通知失败不撤销已提交变更，下次读取恢复规范状态；失败及取消不广播变更。外观控制器沿用现有快照协议更新 WebClient，不重建或刷新业务页面。

## 文档与浮层边界

皮肤变量作用于主窗口的文档根节点，使挂在 body 的菜单、Popover、Tooltip 和弹窗与主界面使用相同变量。外观层释放时恢复其覆盖的内联变量并移除自身皮肤标记，不能污染后续窗口页面或删除其他模块拥有的样式。

外观 Provider 仅包围 AppShell。桌宠、日志、动作工作台和实时诊断页面沿用其原有明暗启动行为，不接入主窗口皮肤生命周期。明暗初始化与运行期使用同一解析规则；缓存为跟随系统时，首屏直接解析当前系统明暗。

划词解释窗口中的 Service WebView 只消费外观快照：位于主窗口 Provider 内时订阅主窗口快照，辅助窗口没有 Provider 时使用自身启动明暗与默认实色外观。辅助窗口不创建主窗口皮肤控制器，也不调用仅主窗口可用的外观设置 IPC；主窗口设置入口仍强制要求 Provider。

默认皮肤没有变量覆盖，因此基础 CSS 继续是默认视觉值的唯一来源。主窗口原生按钮、导航、标签栏和浮层消费语义变量；布局尺寸、拖拽区域、控件点击区域和业务状态判定留在其原有模块；1.1 允许受控语义图标、栏目艺术字和未读/待处理样式覆盖。窗口关闭按钮的系统危险色、图片编辑工具的专业配色不作为普通按钮主色替换。

外观 Provider 在文档变量应用后读取解析后的 CSS 值，生成 Ant Design 的 ConfigProvider 主题；组件库不维护第二套默认配色。只在解析后的明暗或皮肤定义改变时重算组件主题，图片变更和保存状态不重建组件配色。深色算法生成其他派生色时，必须保留皮肤已解析的主色，避免原生按钮与组件库按钮出现偏色。Provider 从首帧起保持稳定，切换主题不能通过替换 React 树或添加主题 key 重建业务页面、草稿或 WebView。

挂到 body 的 Ant Design 浮层通过 React context 继承同一个主题。命令式弹窗使用 Modal.useModal 并在 Provider 内渲染其 contextHolder；静态 Modal.confirm/error 自建根节点，不能用于需要继承主窗口皮肤的交互。设置页保留必要的局部状态样式，但必须引用相同的控件变量，不重新定义一套局部配色。

## 背景合成

每个主窗口只有一层装饰背景，定位在 AppShell 内部、侧栏和工作区下方。背景覆盖窗口内部区域，不随内容滚动，不参与布局、指针命中、键盘焦点或拖拽判定。原生页面和侧栏用皮肤的半透明表面保证可读性；弹窗仍使用独立的浮层表面。

用户导入的照片与内置纹理采用不同的表面透明度：照片在工作区保留清晰的景物轮廓，侧栏增加底色保障导航可读，卡片与控件保留自己的阅读表面。背景来源标记只影响主窗口合成，随外观层释放恢复，不参与持久配置，也不改写 WebView 内 guest 文档的背景。

内置背景是随 renderer 打包的静态资源，不依赖运行中的服务或外部 URL。皮肤分别声明浅色与深色背景，按 cover 规则裁切。自定义图片在 renderer 解码失败时回退皮肤内置背景；内置背景也失败时只保留皮肤底色，不显示损坏图片图标、不阻断业务，也不反复重试。下一次图片变更可以恢复；缩略图失败状态以图片身份隔离，不能污染恢复后的图片。快速切换只替换装饰图片，不替换 Shell、路由或 guest 节点。

切回默认皮肤必须移除先前皮肤的变量覆盖；没有自定义背景时还须移除图片并恢复已有平台合成。背景的文档标记与皮肤变量一样由外观层管理，释放时恢复原值。仅切换图片失败状态不撤销皮肤配色。

## WebView 与平台边界

普通 Website 与 Browser（含 WorkPanel 网页）的宿主画布以白色兜底，不随 Desktop 明暗切换，避免外部网页未声明背景的区域出现深底黑字。工具栏继续跟随 Desktop 主题；网页自身的背景与深色偏好响应仍由网页控制，不注入 guest 样式。本地 WebApp 的透明背景复用策略保持独立。

WebView 是独立文档。主窗口内的 WebApp 默认复用唯一的 Desktop 背景层：存在皮肤图片时，主工作区与当前 WebApp WorkPanel 的宿主容器保持透明；WorkPanel 全屏仍保留同一背景层。guest 未设置背景的区域直接透出壁纸，guest 自己声明的背景色、图片或半透明表面按正常网页合成覆盖壁纸，Desktop 不探测、修改或清除这些样式，也不要求新增 Manifest 开关。

背景复用不分发图片或皮肤变量，不注入 guest CSS，不导航或重建 guest；页面可按自身需求提供文字与卡片的阅读表面。主区与 WorkPanel 转移、主题与图片切换保持原 guest 和业务状态。没有皮肤图片时沿用宿主既有底色；独立 WebApp 窗口不在主窗口背景层内，继续使用自己的窗口底色。Service WebView、Website 和 Browser 的既有表面保持不变；WebClient 的外观协作使用下述独立协议，不复用普通 WebApp 的隐式背景策略。

### Agent WebClient 外观协作

Service WebView preload 通过上下文隔离暴露固定的只读外观能力。只有来自当前 Agent WebClient guest、与可信服务地址同源的请求能够获得快照；其他服务页面即使存在该 preload，也不会收到皮肤数据。配色快照只包含最终明暗、受控视觉变量及宿主透出/实色模式，不包含图片、路径、凭据、选择器或业务身份。1.1 的独立视觉资源通道只提供校验后的功能图标与栏目艺术字 PNG，不分发壁纸。ZIP 与实时快照共用值校验，CSS 表达式在 Desktop 侧解析为有界颜色后再发送。

外观采用独立的请求与定向快照通道，不进入 Platform Frame Port、业务路由或 surface revision。首次消费桥后，当前 guest 的 URL 主题只承担启动提示；后续换肤和系统明暗变化只发送外观快照，不生成路由命令。未消费桥的旧 WebClient 仍沿用原有主题机制。订阅后主动读取处理初始化竞争；同版本重复快照可用于读取确认，较早版本与同版本冲突不能覆盖当前值。读取有界超时返回不可用，页面使用实色回退；后续合法快照可以恢复。

每个 preload 文档生成独立的不透明 nonce，宿主 envelope 绑定该 nonce；整页导航、guest replacement 或销毁会撤销旧协作状态，旧文档投递不能污染新文档。普通业务路由的原位切换不撤销外观能力。renderer 外观 relay 重建时可探测已有消费者并重新获取文档绑定，沿用单调 revision 与启动 URL 主题；未消费能力的旧页面不会因探测而切换协议。隐藏或恢复更新外观但不改变 Chat、Run、transport 与 guest 身份。

主窗口的 Main Chat，以及主工作区中的智能体、技能中心、连接器中心、注册配置、自动化和归档管理页，在启用图片背景且完成外观消费时透出同一 Desktop 壁纸，宿主仅清除自己的覆盖层。管理页及其详情沿用 Service surface 身份，背景资格不赋予 Chat 路由或运行权限；原位切换到未接入的页面时通过外观快照恢复实色，不重建 guest。macOS 在 vibrancy 上方合成，Windows 保留不透明原生底层和 renderer 系统栏。Copilot、WorkPanel、Kanban Chat 与记忆页面接收语义配色，背景模式保持实色。WebClient 负责阅读衬底、Composer 与浮层，Standalone 的外观偏好及资源由 WebClient 自己管理；宿主快照不写入其持久偏好。

原生市场、分享管理与 Kanban 看板在没有图片背景时沿用各自的实色内容表面；启用图片时只透出 Desktop 已绘制的背景，由主工作区的一层阅读衬底保证文字可读。Kanban 的页面、工具栏和列透出背景，任务卡片与弹窗保留独立阅读表面，详情中的 Kanban Chat 继续使用实色模式。它们不经过 WebClient 外观桥，也不复制或单独加载壁纸。Help 的匿名 WebView 同样只清除 Desktop 拥有的宿主背景；帮助站点必须自行处理其独立文档的透明画布与阅读衬底，其他外部站点的背景不受 Desktop 修改。

精确接口与生成镜像见 `src/shared/contracts/agent-webclient-bridge.ts` 与 `contracts/agent-webclient/`；隔离原生桥与合成验收见 `qa/webclient-appearance-smoke.mjs`。真实 WebClient 业务流与 Windows 原生窗口仍需按发布环境联调，不能由测试 guest 或平台 CSS 模拟推定完成。

macOS 的原生 traffic lights、透明窗口和 vibrancy 仍由 Shell 管理；使用图片皮肤时，renderer 在 vibrancy 上方绘制自己的背景底色与图片。Windows 在不透明窗口底色上绘制背景，顶部 renderer 系统栏消费皮肤表面色，继续保留原有高度、拖拽区与窗口控制按钮。两条平台路径显式区分；切回默认皮肤恢复原有合成，既有 IPC 仍只同步原生明暗。

## 外观 1.1：语义图标、栏目艺术字与状态标记

本次是未发布阶段的直接升级，皮肤包 schemaVersion、配色快照版本与外观桥版本统一使用字符串 `"1.1"`；不迁移或兼容旧包，旧包应删除后重新导入。该版本独立于 Desktop 应用版本、settings IPC、Frame Port 与 WorkPanel 业务协议。

每个明暗 variant 可声明受控 visuals：按功能命名的图片槽，以及未读/待处理颜色、未读形状、数字徽章形状与栏目字体风格。精确字段和允许槽名由 shared canonical contract 与皮肤包 parser 定义。固定栏目艺术字按语言提供；缺少对应语言或资源时保留真实文字。用户提供的项目图片与站点 favicon 不被通用皮肤覆盖。自定义字体文件、外部 SVG、任意 CSS 和脚本不进入皮肤包。

Main 沿用已有包校验与原子安装，只安装声明的 PNG 视觉资源，经尺寸校验和重新编码后改为受控文件名。每张视觉图片最多 256 KiB、边长最多 1024，整包视觉图片最多 4 MiB。renderer 获得当前包的受控视觉定义；图片缺失时逐槽回退默认图标，样式和其他资源继续工作。macOS 原生 traffic lights 保持原状，Windows 窗口控制和危险关闭态不进入普通皮肤图标槽。

Desktop 与 WebClient 共用同一套语义槽。配色通道传送小体积主题值，独立视觉桥传送资源目录并通过 `getAsset(resourceSet, slot)` 按需读取 PNG；两条通道同属 1.1。renderer relay 只接受当前可信 WebClient guest，preload 绑定独立文档 nonce；资源集随视觉定义变化更换，旧资源请求失效。资源标识不含磁盘路径、ZIP 路径或远程 URL。PNG 在 WebClient 内存中按资源集缓存，颜色更新不重复传整套图片，宿主资源不写入 Standalone 存储。

主窗口 AppearanceProvider 只管理样式投影，现有导航与 Composer 保持布局、快捷键、焦点、点击区和运行态所有权。未读与数字徽章只更换外观，不改变计数、汇总、截断、已读同步或 pending 判定。主题切换不重建业务页面或 WebView。

验证入口：`test/skin-visuals.test.mjs`、`test/desktop-skin-package.test.mjs`、`qa/skin-visuals-smoke.mjs`。参考皮肤制作：`node qa/skin-packages/build-bow-example.mjs`；传入 `--base <旧包.zip>` 可以保留原壁纸和配色并生成 1.1 包，原文件不修改。真实跨项目发布仍通过 WebClient Program bundle 构建与 Desktop 资源同步完成。

皮肤消费端不得按皮肤名称或 ID 分支，也不内置某个主题的专属造型。图标与艺术字来自包内语义图片，定制未读轮廓来自受限的百分比顶点数据；客户端只校验与渲染通用配置。新增主题造型只修改皮肤制作工具和资源，不要求两端增加主题枚举。

Desktop 壁纸层只显示原图，不叠加全局染色遮罩，也不接收或投影背景染色 token。New Chat 与有内容的 Main Chat 的阅读遮罩统一由 WebClient 自行管理；Standalone 同样只保留页面级阅读表面，避免重复叠加。

皮肤可按明暗分别提供新建对话与已有对话的页面遮罩颜色，通过既有受控颜色 token 白名单校验与外观快照传递；未声明的页面使用 WebClient 现有默认遮罩。该配置只在图片背景生效时使用，无图片或宿主能力失效仍回退实色，且不影响输入框、推荐卡片与其他阅读表面。不新增 Desktop 背景层或透明度叠加。旧消费端不认识新增 token，因此使用这些配置的包须配套更新 Desktop 与 WebClient。

截图入口属于客户端原生弹出菜单，不支持皮肤图标覆盖。解析皮肤包和视觉快照时直接忽略旧 `chat.screenshot` 配置，不校验其值、不加载对应资源，也不因该字段拒绝旧包；其他槽的校验规则保持不变。
