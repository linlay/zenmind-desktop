# 产物管理

## 定位与所有权

产物管理是 Desktop 原生能力页，位于云端分组中分享管理之前。它展示 Desktop 在线期间收到的产物推送索引，支持搜索、分页、元信息查看、文件下载、WorkPanel 查看和返回来源对话。原始产物、上传行为及其生命周期仍由 Platform 和服务拥有，Desktop 不复制二进制文件，也不把索引作为产物内容的事实源。

## 采集与存储

Main 的产物模块通过全局 Realtime Broker 的窄回调，采集 Primary lane 已校验 Run 身份、时间与序号的 artifact.publish 事件，并逐项记录产物。同时保留资源上传完成通知的 internal consumer，两种来源共用索引去重。产物发布即可入库，不依赖网关路由或上传成功。它不新建 WebSocket、不 attach Run、不消费 renderer 转发的事件，也不依赖产物页面是否挂载。

入口校验事件类别、产物和对话身份、必填元信息及毫秒时间契约。有效记录以对话身份和产物身份组成唯一键写入 Desktop 数据分区的 SQLite；同一身份只接受更新的推送，重复或乱序旧消息不改变已确认记录。读取采用有界分页与参数化查询；数据库仅存业务元信息，不存凭据、通用 URL 或任意本地路径。路径沿用品牌 Desktop 数据根，并显式处理 Windows 与 macOS 路径语义。

索引属于长期 Desktop 数据，升级和普通重启保留。数据库首次访问时才创建，不改变首次安装检测。当前没有上游历史补齐合同，因此不扫描服务目录、不臆造 URL、不主动请求 Run 回放补齐历史；离线期间未收到的事件不会自动补齐。

## UI 与安全边界

Main 仅给主窗口顶层 frame 提供只读列表 IPC，renderer 不直接打开 SQLite。写入后发送节流的无内容变更通知，页面再请求当前搜索和分页结果。每次页面查询使用最新请求序号，避免旧搜索结果覆盖新结果。

来源对话名称与 Agent 身份通过现有受限历史接口补齐，补齐失败不影响索引展示。有有效 Agent 身份时沿用既有聊天导航；索引不授予文件访问权限。查看与下载通过独立、仅限主窗口顶层 frame 的动作入口，根据 Chat 与 Artifact 身份重新读取 Platform 对话响应中的权威产物快照（不回放整段历史消息），严格解析产物相对引用；不从名称猜测路径、不接受任意 URL。查看沿用来源对话的 WorkPanel WebClient Document Surface，下载沿用受鉴权的资源读取与系统保存对话框。解析失败或资源不可用时显式失败，不扫描本地目录。

写入失败被隔离到产物模块，不能中断其他 Broker consumer。退出时解除订阅、通知计时器和 IPC；SQLite 操作完成即关闭连接。

## 实现事实源

- `src/main/modules/artifacts/`：事件校验、数据库、订阅和 IPC。
- `src/shared/artifacts.ts`：只读 DTO。
- `src/renderer/pages/artifact-management/`：产物列表和来源对话导航。
- `test/artifact-store.test.mjs`、`qa/manual-regression.md`：持久化、安全与手工回归。
