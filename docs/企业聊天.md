# 企业聊天

## 当前状态

Desktop 在企业 SSO 完整登录后提供右下角悬浮聊天入口。当前版本只消费
`zenmind-im-server` 的 v1 协议并支持一对一文字聊天；群聊、文件、
编辑和撤回虽然服务端协议已具备，但不在本次 Desktop UI 中开放。

聊天浮层目标尺寸为 `500 × 580`，在窄窗口和矮窗口中按可用视口缩小。未完成
SSO、企业聊天被关闭或 access token 缺失时，不显示悬浮按钮。

## 核心流程

```text
企业 SSO 完整登录
  -> main 读取 canonical sso-access-token
  -> POST /api/v1/session/exchange
  -> IM session token 只保留在 main 内存
  -> GET /api/v1/sync/bootstrap + GET /api/v1/users
  -> POST /api/v1/ws-tickets
  -> WS /ws?v=1&ticket=...
  -> sync.resume
  -> sync.ready
  -> renderer 显示员工、私聊历史和未读状态
```

打开员工会话时，Desktop 先在已有 direct conversation 中按成员查找；不存在时调用
`POST /api/v1/conversations` 创建唯一私聊，再读取最近 50 条历史。发送消息使用
稳定 `clientMessageId`，并只在 `sync.ready` 后通过 `message.send` 提交。

主进程负责 token 换票、HTTP、WebSocket、重连、短期 token 刷新、协议归一化和
消息幂等投影。preload 只暴露聊天 DTO 与命令，renderer 不读取 SSO 文件，也拿不到
企业 JWT、IM session token 或一次性 WebSocket ticket。

## 设置与配置

- `config/desktop/profile.json -> general.enterpriseChatEnabled`：是否开启企业聊天，
  缺失时默认 `false`。
- `desktop-init.json -> imServer.baseUrl`：部署时配置 IM server 地址；bootstrap 后写入
  `config/desktop/im-server.json`。开发环境未配置时回退 `http://127.0.0.1:11956`。
- loopback 允许 HTTP/WS；远端地址必须使用 HTTPS/WSS。
- Settings → 常规中的“企业聊天”开关立即启停 runtime。关闭时清理内存中的会话、
  员工和消息投影。

示例：

```json
{
  "imServer": {
    "baseUrl": "https://im.example.com"
  }
}
```

当前 `zenmind-im-server` 员工目录返回显式 `online` 布尔字段：
同一用户任一 WebSocket 完成 `sync.resume` 即为在线，最后一个设备断开才离线。
`status=active` 仍只是账户状态，不作为在线信号。Desktop 显示在线/离线并据此排序；
兼容未提供 presence 的旧服务端，此时显示灰色“在线状态未知”，不会自行猜测。

presence 协议：

- `GET /api/v1/users` 的每个员工返回 `online: boolean`；
- WebSocket 完成 `sync.resume` 后广播有权限可见的 `presence.changed`；
- 同一用户任一设备连接且完成同步即为在线，最后一个设备断开才转为离线；
- presence 是瞬时投影，不写可靠事件表、不推进聊天 `eventId`；
- Desktop 在收到 `sync.ready` 后重新请求员工目录，并用后续 `presence.changed`
  更新投影；不从 `status`、`updatedAt` 或消息时间推测。

## 生命周期

企业聊天是非核心 runtime，不进入 built-in service manager，也不影响核心服务启动卡：

- shell 与 IPC 就绪后可以读取状态；
- `non-core-ready` 阶段按 profile 开关启动；
- SSO 完成、注销和 Settings 开关变化会触发刷新或停止；
- WebSocket 断开后指数退避重连，最大间隔 30 秒；
- 应用退出时关闭 WebSocket、定时器和所有待处理请求。

`zenmind-im-server` 由独立仓库和部署流程负责。Desktop 不安装、启动、停止、修复或
改写该服务端配置。

## 约束与注意事项

- 只信任主进程从 canonical SSO 状态恢复的 access token。
- token、ticket、消息正文和用户 ID 不写 Desktop 日志。
- 远端聊天服务必须使用 TLS；不得通过 renderer fetch 绕过主进程。
- 当前 UI 过滤 group conversation，避免提前暴露尚未设计完整的群聊交互。
- 服务端可靠事件 cursor 只做增量优化；bootstrap 与会话历史仍是恢复事实来源。
