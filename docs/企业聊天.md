# 企业聊天

## 当前状态

Desktop 在企业 SSO 完整登录后提供可拖动的悬浮聊天入口。当前版本消费
`zenmind-im-server` 的 v1 协议，支持一对一聊天、私有群聊、文字、
文件、图片、三级截图、脱敏诊断包、当前设备个人资料和经接收方确认后执行的 Desktop Action。

聊天浮层采用紧凑的 `400 × 500` 目标尺寸，在窄窗口和矮窗口中按可用视口缩小。聊天入口从
基准 `54 × 54` 缩小 30% 至 `37.8 × 37.8`，内部聊天图标保持原始尺寸。未完成 SSO、
企业聊天被关闭或 access token 缺失时，不显示悬浮按钮。入口拖动位置保存在 renderer
的本地 UI 偏好中；窗口尺寸变化后必须重新限制在可见范围内，不能影响主窗口拖动。

消息页和联系人页在标题栏下方保留独立搜索框。消息搜索只筛选当前会话摘要，匹配联系人
姓名、邮箱、群名称和最近一条消息；联系人搜索匹配个人/机器人姓名与邮箱，以及已加入群聊
的群名称和成员资料，不请求或索引完整历史。联系人页把个人、群聊和机器人分区展示：个人
使用蓝色人形标识，群聊使用绿色群组标识，`kind=service_bot` 使用紫色机器人标识，不能再把
机器人按普通员工头像渲染。

会话行的“删除会话”是 renderer 本机隐藏操作，不调用 IM Server 删除接口，也不删除历史、
附件或成员关系。隐藏偏好按 `serverUrl + currentUser.id` 隔离，只保存 conversation ID 和
隐藏时的 `lastSeq`；收到更新序号更大的消息时自动恢复，从联系人主动打开私聊时也会恢复。

## 核心流程

```text
企业 SSO 完整登录
  -> main 读取 canonical sso-access-token
  -> POST /api/v1/session/exchange
  -> IM session token 只保留在 main 内存
  -> GET /api/v1/sync/bootstrap + GET /api/v1/users
  -> POST /api/v1/ws-tickets
  -> WS /ws?v=1&ticket=...
  -> sync.resume
  -> sync.ready
  -> renderer 显示会话、员工、群聊历史、附件和未读状态
```

打开员工会话时，Desktop 先在已有 direct conversation 中按成员查找；不存在时调用
`POST /api/v1/conversations` 创建唯一私聊。群聊使用相同接口创建 `type=group` 会话。
打开任一会话后读取最近 50 条历史。发送消息使用稳定 `clientMessageId`，并只在
`sync.ready` 后通过 `message.send` 提交。

文件和图片可通过附件菜单、会话输入框粘贴或截图菜单添加。回形针按钮只打开附件菜单，
菜单提供“上传任意附件”和“打包日志与配置”：前者继续使用原生多文件选择器；后者先展示
隐私确认，再由主进程只收集 `config/desktop` 与 `logs/desktop`，在内存中生成 ZIP 并通过
现有 IM 文件接口发送。诊断包不读取 `config/services`、`config/plugins`、`secrets`、SSO
状态文件或聊天正文；已知的 token、Cookie、Authorization、密码、API Key、私钥字段、JWT、
URL 凭据、本机 home 路径和 Desktop 数据根必须脱敏。单文件、总来源大小和文件数量均有上限，
日志超限时只保留尾部，配置超限时只保留开头；ZIP 中写入 manifest 说明范围、限制和遗漏项。

相机按钮只打开小菜单，不直接开始截图；菜单提供“自由截图”“当前桌面端”“整个电脑桌面”
三个档次。自由截图
复用区域选择浮层；当前桌面端直接捕获当前 ZenMind 主窗口；整个电脑桌面捕获鼠标所在的
当前显示器全屏。捕获当前桌面端时，主进程只在抓取像素期间临时隐藏企业聊天浮层及悬浮
按钮，截图完成后立即恢复，避免聊天 dialog 遮挡主窗口内容且不延长到附件上传阶段。粘贴内容在 renderer
读取为受大小与数量限制的附件 DTO，再通过 preload 交给主进程；token 和上传请求仍不进入
renderer。所有附件最终由主进程使用 IM session token 调用 `POST /api/v1/files`，取得 opaque
`fileId` 后再随 `message.send.fileIds` 绑定。renderer 不接触 token，也不直接拼接鉴权
下载 URL。图片预览由主进程鉴权读取并以受限的 data URL 返回；普通文件下载由主进程写入
Electron `app.getPath("downloads")`。自由截图与整个电脑桌面复用 Desktop 已有的 macOS /
Windows 显式平台屏幕捕获流程；当前桌面端使用 Electron 窗口捕获，不依赖系统屏幕录制
权限。三种截图结果均作为 `image/png` 上传。消息中的可内联图片支持点击预览，预览层通过
React portal 挂载到主页面并覆盖整个 Desktop 内容区域，不受聊天浮层尺寸和裁剪边界限制；
点击遮罩、关闭按钮或按 Esc 均可退出预览。

Desktop 不提供 Desktop Action 发送按钮、表单、preload/IPC 命令或 runtime 发送方法。
连接在收到 `sync.ready` 后通过 `device.capabilities.publish` 发布当前版本的远程动作白名单。
服务端客服机器人只能在 direct conversation 中发送结构化 `desktop_action_request` 消息，
请求必须选择对端已登记的 Desktop 设备及其已声明动作，并包含稳定 `requestId`、`args` 和
`expiresAt`。IM Server 绑定已验证的客服机器人、代操作人、会话成员、目标设备和能力白名单，
不再识别任何文本前缀信封。

接收端主进程再次验证目标设备、私聊、发送者、远程专用白名单、有效期和本地持久化幂等账本。
通过校验的请求在聊天浮层内自动展示确认弹框，弹框使用 Desktop 内置定义生成业务摘要，远端
`operatorNote` 仅作为补充说明，不能覆盖确认摘要或注入 `permissionMode`。只有用户在浮层内
确认后，renderer 才调用执行 IPC，主进程以 `permissionMode=full_access` 调用现有 Desktop
Action Bridge；拒绝、过期、不支持、执行失败和成功都会以 `desktop_action_result` 结构化消息
回复原请求。结果由 IM Server 校验必须来自目标员工的同一设备，并校验 `replyToId`、`requestId`、
动作名和目标设备一致。群聊、自己发送的消息和不在白名单中的请求都没有执行入口。

主进程向 renderer 投影 `pending / executing / handled / not_executable` 四种本地 action 状态，
只有当前设备、当前私聊中仍有效的 `pending` 请求可以弹出或人工确认。同步重置、切换会话、请求
被处理或失去可执行条件时，renderer 必须立即关闭旧确认框；“取消”先退出本地弹框，再提交拒绝
决定，不能因断线、过期或主进程状态变化锁住界面。

幂等账本使用稳定 `requestId`，并按规范化 IM 地址、当前用户和设备组成的 SHA-256 scope 隔离。
确认执行前必须先原子写入 `executing` 占位；占位失败时变更动作不得执行。动作结束后先把终态和
必要回执载荷写入账本，再使用稳定的 `desktop-action-result:<requestId>` clientMessageId 发送结果。
回执失败只进入待投递状态，`sync.ready` 后重试回执而不重跑本地动作；服务端 duplicate 响应视为
投递成功。Desktop 若在执行中退出，下一次启动把该记录收敛为“结果未知、未重试”的失败终态。
历史载入同时使用 `replyToId + requestId + action + targetDeviceId` 对齐请求和已有结果，因此即使
本地账本缺失，已收到终态回执的请求也不会再次展示。旧版仅含 `messageIds` 的账本继续按已处理
记录读取。账本不保存 action 参数、token、用户资料或完整 Desktop Action 响应。

远程动作分为导航、外观、网站/WebApp、安装更新和支持五组。Website 与 WebApp 的 canonical
动作已经不兼容地扁平化为 `desktop.website.*` 和 `desktop.webapp.*`，不提供
`desktop.web.website.*` / `desktop.web.webapp.*` alias。支持类动作可在用户确认后生成脱敏
诊断包、受限服务/WebApp 日志、安全系统信息或截图，并将产物作为结果消息附件发送。客服不
获得本地路径或任意日志读取动作。
技能、智能体和 WebApp 的修改分别使用 `desktop.skill.update`、`desktop.agent.update`
和 `desktop.webapp.updatePreferences`；技能修改只允许写入 agent-platform 已存在的可编辑文本文件，
单次上限 1 MiB，可携带 `baseSha256` 做并发保护。

主进程负责 token 换票、HTTP、WebSocket、重连、短期 token 刷新、协议归一化和
消息幂等投影。preload 只暴露聊天 DTO 与命令，renderer 不读取 SSO 文件，也拿不到
企业 JWT、IM session token 或一次性 WebSocket ticket。

## 设置与配置

- `config/desktop/enterprise-im.json` 是企业 IM 的唯一配置源，同时保存 `enabled` 与
  `baseUrl`；缺失或无效时回退为关闭和 `http://127.0.0.1:11956`。
- `desktop-init.json -> enterpriseIm` 必须显式声明布尔型 `enabled` 与 `baseUrl`；bootstrap
  后完整写入 `config/desktop/enterprise-im.json`，再次导入时覆盖这两个字段。
- 旧 `imServer`、`config/desktop/im-server.json` 和
  `profile.general.enterpriseChatEnabled` 不读取、不迁移，也不主动删除。
- loopback 允许 HTTP/WS；远端地址必须使用 HTTPS/WSS。
- Settings → 常规中的“企业聊天”开关立即启停 runtime。关闭时清理内存中的会话、
  员工和消息投影。
- 聊天浮层底部固定为“消息 / 联系人 / 设置”三个入口。“设置”中的座右铭与自定义头像是
  Desktop 本地资料，按规范化 `serverUrl + currentUser.id` 的 SHA-256 scope 隔离，不修改企业
  SSO 或 IM Server 用户资料。元数据写入 `config/desktop/enterprise-chat-profile.json`，头像写入
  `data/desktop/enterprise-chat-profile/<scope>/avatar.<ext>`；renderer 只接收受大小限制的 data URL，
  不接触本地路径。头像只允许实际内容为 PNG、JPEG 或 WebP 且不超过 2 MiB；座右铭最多 160 字。

示例：

```json
{
  "enterpriseIm": {
    "enabled": true,
    "baseUrl": "https://im.example.com"
  }
}
```

当前 `zenmind-im-server` 员工目录返回显式 `online` 布尔字段：
同一用户任一 WebSocket 完成 `sync.resume` 即为在线，最后一个设备断开才离线。
`status=active` 仍只是账户状态，不作为在线信号。Desktop 显示在线/离线并据此排序；
兼容未提供 presence 的旧服务端，此时显示灰色“在线状态未知”，不会自行猜测。
员工目录是 presence 的当前投影；会话成员 DTO 每次载入或刷新后都必须与该目录合并，
避免联系人列表显示在线而会话标题退化为“在线状态未知”。

presence 协议：

- `GET /api/v1/users` 的每个员工返回 `online: boolean`；
- WebSocket 完成 `sync.resume` 后广播有权限可见的 `presence.changed`；
- 同一用户任一设备连接且完成同步即为在线，最后一个设备断开才转为离线；
- presence 是瞬时投影，不写可靠事件表、不推进聊天 `eventId`；
- Desktop 在收到 `sync.ready` 后重新请求员工目录，并用后续 `presence.changed`
  更新投影；不从 `status`、`updatedAt` 或消息时间推测。

## 生命周期

企业聊天是非核心 runtime，不进入 built-in service manager，也不影响核心服务启动卡：

- shell 与 IPC 就绪后可以读取状态；
- `non-core-ready` 阶段按 `enterprise-im.json -> enabled` 启动；
- SSO 完成、注销和 Settings 开关变化会触发刷新或停止；
- WebSocket 断开后指数退避重连，最大间隔 30 秒；
- `sync.ready` 后补投当前用户与设备 scope 中尚未确认送达的 Desktop Action 回执；
- 应用退出时关闭 WebSocket、定时器和所有待处理请求。

`zenmind-im-server` 由独立仓库和部署流程负责。Desktop 不安装、启动、停止、修复或
改写该服务端配置。

## 约束与注意事项

- 只信任主进程从 canonical SSO 状态恢复的 access token。
- token、ticket、消息正文和用户 ID 不写 Desktop 日志。
- 远端聊天服务必须使用 TLS；不得通过 renderer fetch 绕过主进程。
- 群成员管理沿用服务端 owner/admin/member 权限；当前 Desktop 先开放创建群聊和群消息，
  后续成员增删与角色调整继续走服务端既有 API。
- IM Server 与客服机器人只能投递 Desktop Action 信封，永远不能访问 Desktop Action Bridge
  或绕过 Desktop 浮层的本机确认。
- 文件字节只走 HTTPS，不进入 WebSocket。图片预览设置本机大小上限，超限时退化为文件卡片。
- 本机会话隐藏不属于 IM 协议，不得据此修改服务端会话、消息或已读事实。
- 服务端可靠事件 cursor 只做增量优化；bootstrap 与会话历史仍是恢复事实来源。
- SQLite、对象存储和局域网快传决策见[企业聊天架构评估](企业聊天架构评估.md)。
