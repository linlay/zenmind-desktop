# 前端嵌入与导航

## 文档定位

本文描述 Desktop 如何承载 Web surface，以及各类页面的导航所有权、存储隔离和能力边界。具体路由、IPC、消息名、菜单项、像素和组件状态以源码及测试为准。

## Surface 模型

Desktop 不把所有前端合并成一个静态站点，而是按来源和信任级别承载不同 surface：

| Surface | 内容来源 | 宿主职责 |
| --- | --- | --- |
| Service / Plugin | 服务健康状态提供的 `webUrl` | 生命周期关联、受限 preload、单页或独立入口 |
| Agent WebClient | host-managed 或服务前端 | Chat、管理页、Copilot、可信 realtime/WorkPanel bridge |
| History Dialog | Desktop renderer 原生列表 | 通过受限 Assistant bridge 读取和操作 Chat，不创建 guest surface |
| Website | 用户或市场登记的远端 URL | SSO session、导航限制和多标签状态 |
| WebApp | Desktop 本机 loopback gateway | Manifest 生命周期、同源 bridge、workspace 或独立窗口 |
| Help | 品牌配置的公开站点 | 匿名、独立 partition、同源导航 |
| Public Share | 外部浏览器访问 Tunnel `/share/{id}` | Desktop 只负责打开返回的公开 URL，不托管或渲染页面 |
| Browser / Work Panel | 用户或 Agent 打开的网页 | 标签生命周期、受限 CDP 与上下文菜单 |

`surfaceId` 是 Desktop 内部稳定、短小的运行实例身份，URL 不是身份。Main Chat、Kanban Chat 与 Browser 使用可读的根级 ID，Copilot Dock 使用可读的固定 child ID；Website、WebApp 以及 Chat 次级视图使用带领域前缀的稳定哈希 ID。持久化 entry key 和 Desktop route 不随运行时 ID 改名。

Surface 同时声明语义角色、`root / child / utility` 层级、可选父级和交互等级。Overview、Debug、BTW、Source、Planning、Artifact、Reference、File 等 owner Chat 次级视图随父级关闭而回收，但隐藏父级不等同于关闭。Detached Project 和无已登记页面上下文的 Copilot Dock 可以暂时没有父级；固定实例 Copilot Dock 是父级回收规则的例外，其父级只表达当前页面上下文，不转移 guest、刷新或 CDP 所有权，父页面关闭、导航、刷新和重新登记均不得重建已经 mounted 的 Dock guest。

Kanban route 是 Copilot Dock 保持挂载规则的硬性例外。进入 Kanban 时 AppShell 必须隐藏所有入口、拒绝程序化 open/toggle 并卸载 Dock guest；Main 的 Surface Registry 同时拒绝 Kanban context 的 Dock 登记。旧 Kanban Dock session 被忽略，其他页面的 context session 保留，离开 Kanban 后仍可按原页面恢复。Kanban Chat 自身继续作为独立根级 surface。

固定根级 ID 是 `main-chat`、`kanban-chat` 和 `browser`，固定 child ID 是 `copilot-dock`。动态实例使用领域前缀加稳定双 FNV/base36 哈希；Chat 次级模块为 Overview、Debug、BTW、Source、Project、Diff、Artifact、Reference、File、Planning、Agent、Copilot、Skill 与 Web。哈希输入来自模块稳定键，不得使用展示 URL 代替稳定键。History dialog 是原生 renderer 模态层，不登记 surface。

浏览器中的每个 URL 只拥有 `tabId`；Run、Office 等长任务使用自己的运行或操作身份；Pet 和普通原生窗口使用 consumer/window 身份。只有具有独立 guest 生命周期且需要被 Desktop 定位、诊断或控制的对象才登记 surface。Main 通过 renderer 登记的 guest WebContents、surface 类型、稳定内部键和父级关系判断页面是否真实存在，并拒绝不符合宿主策略的角色、ID 或权限组合。

## 宿主与生命周期

```text
配置或运行状态
  -> renderer 选择 surface host
  -> WebView / BrowserWindow 挂载 guest
  -> preload 登记 surface 与 tabs
  -> main 校验 guest 身份并提供受限能力
  -> 卸载时注销 surface、回收 guest 与临时存储
```

隐藏和关闭是不同状态：为了保留 Chat、Website、WebApp 或 Work Panel 的页面状态，非活动 surface 可以继续挂载；真正关闭时必须注销 registry、销毁 guest，并按所属策略清理临时 partition。关闭最后一个标签后不能留下指向已销毁 guest 的活动状态。

Surface 诊断按 `debug / warn / error` 分级。attach、detach、navigation、`dom-ready` 和成功路由同步属于 debug，生产 renderer 不发送；开发环境按 `surfaceId + webContentsId + stage + URL` 在短窗口内去重聚合。可恢复的 IPC 重试与回退记为 warn，确定性非法登记、最终 IPC 失败和真实加载错误才记为 error。Main 以 50ms 或 64KB 为阈值异步批量写入既有 `main.log` / `error.log`，只有 error 进入 `error.log`，退出前最多等待 500ms 排空。

WebApp 的 workspace 与独立窗口只是两种渲染容器。切换容器可以复用同一 runtime 和 gateway，不能因此扩大页面权限或改变 Manifest 能力。

主工作区与 WorkPanel 之间共享每个 WebApp 唯一的 canonical WebView。AppShell 以 `webappId` 保存运行期 presentation owner，并通过稳定宿主的布局覆盖展示到主区或某个 Chat 的 active WorkPanel item；转移只更新 owner 与外层引用，不能 reparent DOM、创建第二个 guest 或修改持久 `openMode`。WorkPanel 隐藏或切换 Chat 时 guest 保持 mounted 但 inactive；关闭 WorkPanel WebApp tab 时销毁 guest、保留 runtime。独立窗口仍使用既有 WebContentsView，不参与这条迁移；已在独立窗口打开时，WorkPanel 入口只能聚焦该窗口。

## 导航所有权

Desktop Router 决定当前工作区和 active surface。默认情况下，Desktop 可以导航 guest，普通 Service、Plugin、Website、WebApp 和 Browser 不能用自身导航反向改写 Desktop Router。

反向同步只开放给三类明确场景：

- 当前 active 的 Agent Chat 将新建会话收敛为稳定 Chat URL。
- 当前 active 的 Main Chat guest 从一个 Agent 明确切换到另一个 Agent 的裸路由，Desktop 将其收敛为目标 Agent 的 ownerless 新 Chat URL。
- Agent 管理页请求 Desktop 打开一个已经验证有效的 Chat。

非活动 Chat、临时 Kanban Chat、项目浮层、Copilot 和 Work Panel 不拥有外层路由。它们可以维护自己的页面历史，但不能发布为当前 Desktop 页面或抢占其他 surface 的导航状态。

Chats 与 Projects 的历史入口由 AppShell 打开单例原生 dialog：Chats 初始显示全部记录，Projects 只用当前 `agentKey` 初始化可切换的 Owner 筛选。Cmd+K 的 Actions 分组在 New Chat 后提供 Open chat history，且仅在搜索面板打开时响应 macOS `Cmd+H` / Windows `Ctrl+H`，关闭搜索面板并打开同一个未筛选 dialog；面板关闭时不覆盖操作系统原有快捷键。History dialog 使用无独立标题栏的 Cmd+K 式搜索头部；Owner 与日期条件收进参考 Kanban Projects Select 的内置 Filter popover，结果计数显示在 Filter trigger 内。dialog 通过专用 `assistant.listHistoryChats` IPC 读取 Main 规范化的最小 Chat DTO；搜索、Owner 和日期筛选均保留在 renderer 本地。打开和关闭不改变 Desktop Router、不创建 WebView，也不获得 query、attach 或 BTW live lease。用户选择具有有效 Agent 身份的记录后，AppShell 才关闭 dialog，并用既有 Main Chat 导航和焦点恢复流程打开 canonical `agentKey + chatId`。

Projects 列表是 Agent Platform catalog 的 CODER/KBASE 投影，直接沿用 Platform 返回顺序。展开侧栏的 Projects 标题栏提供“全部展开 / 全部收起”，只批量改变 Project 容器的展开状态；执行全部展开时，每个 Project 都重置为首批 5 条 Chat，之后用户仍可在单个 Project 内使用查看更多或历史入口。只有展开侧栏支持在 Project 标题上用鼠标或键盘直接拖拽，标题前不保留占宽手柄；收起侧栏的 Popover 只展示同一结果。Project 拖拽时原节点留在原位变淡，另用不参与列表布局的半透明 Project 名称浮层跟随指针，目标节点前后显示插入线，其他列表节点不移动；浮层与 Chats 一样挂载到页面根层，避免受 Sidebar 包含块影响产生坐标偏移。开始拖拽时临时收起全部 Projects，结束或取消后恢复拖拽前的完整展开集合。拖拽移动整个 Project 标题节点及其所属 Chats 和运行状态，不允许 Chat、Project 内 Chat 或导航分组之间换序；普通点击标题、更多操作和新建 Chat 继续使用各自交互。保存期间禁止再次拖拽，失败时回滚并强制刷新，成功时以 Main 返回的规范化 Project 顺序为准。

Projects 保存只使用 HTTP public `/api/agents/order`：Main 将 CODER/KBASE 顺序替换进全部有效 Agent 序列的 Project 槽位后提交，不读取 admin catalog。Platform 负责把有效顺序合并回共享的完整 admin 序列，因此 invalid Agent 槽位不会暴露给 Desktop，也不会被 Desktop 改写；该接口不增加 WebSocket route。

动态路由参数只允许一次编码和一次解码。业务身份比较忽略宿主展示参数及查询参数顺序，避免主题、语言等变化重放 Chat 业务导航；未知或业务相关参数不能被静默丢弃。

Main Chat guest 只有在可信同源、精确的裸 `/agent/:agentKey` 路由且目标 Agent 不同于 Desktop 当前 Agent 时，才能表达“切换 Agent 并新建对话”。Desktop 自行生成单调递增的 13 位 `newChat` nonce，以 replace 把外层路由更新为目标 `/agent/:agentKey?newChat=...`，并继续使用同一个 WebView；旧 Chat 身份、其他会话参数和 guest 提供的会话身份都不继承。选择带 canonical `chatId` 的目标历史 Chat 仍走已有 Chat 导航，不生成 `newChat`。快速连续切换时最终 Desktop 路由与 guest 登记共同决定有效来源，迟到的旧 Agent 同步不能恢复旧 owner。

新 Chat 的 URL 通常由关联 query stream 的首个合法 `chat.start` 收敛。附件暂存可能在 query 前预建 Chat；此时 outbound query 已携带 canonical `chatId`，Main 只接受服务端 `request.query` 对同一 `requestId + chatId + owner` 的完整回显作为等价 Chat 身份证据。Main 在确认真实 active Main Chat、surface generation、`agentKey` 与 `newChat` nonce 后，请求 renderer 原位把 `newChat` 替换为 canonical `chatId`；renderer 只有在外层路由提交、同一 guest 实际进入 canonical URL 且以该 `ownerChatId` 重新登记成功后才确认完成。普通 guest navigation 不得为仍处于 `newChat` 的 Desktop 路由猜测 canonical Chat；用户已经切换页面或 generation 失效时必须 fail closed，不能抢回导航。

Main Chat 的 Surface Registry 同时保留用于普通诊断的 pathname 与仅供授权使用的完整 Desktop route identity。canonical owner 登记必须和完整 Desktop canonical route、guest 实际 canonical URL 一致；已有 owner 不能被迟到的普通 ownerless 快照清空，只有 Desktop 与 guest 同时进入同一个精确 `agentKey + newChat nonce` 时才能开始新的 ownerless generation。

Main Chat 路由切换遵循 `switching → ready` 状态机，并把身份收敛为三段：Desktop route 是唯一 `desiredChat`，guest 实际 URL 是只读 `observedChat`，Registry active owner 是唯一可供 Query 与 WorkPanel 消费的 `committedChat`。目标变化、surface active 变化或 guest replacement 都递增 route revision 并立即撤销 committed；只有 desired、observed、owner、WebContents 与当前 revision 全部一致才重新提交。`route_not_aligned` 是正常过渡，不属于错误；真实主框架导航必须强制触发重新观测，即使 URL state 字符串未变化。为防 Chromium 丢失 SPA 导航事件，宿主只在当前 revision 内按 50/150/300/500ms 执行有界重新观测，1 秒仍不收敛只记录诊断；IPC 调用异常仍独立在 100ms、300ms 后各重试一次，禁止无限注册风暴。

WebView 事件监听只随 guest 实例或 generation 变化绑定。Desktop 路由、active、owner 和回调更新通过最新引用供监听器读取，普通 Chat 切换和无关页面切换不得解绑/重绑监听。guest 尚未 `dom-ready` 时宿主只保存最新目标 URL；快速 A→B→C 通过单调 transition id 丢弃迟到结果，最终只应用 C，禁止对尚未附着的 WebView 调用导航。Main Chat 的目标业务路由变化必须同时通过受限 route bridge 交给 WebClient Router，并保留同源直接导航及 `loadURL` 兜底；只有业务路由与全部宿主参数都等价时才能跳过 bridge，变化的 `chatId`、`newChat` 或 Agent 不能被误判为仅宿主参数同步而静默丢弃。

Main 在转发每一条 `/api/query` 前都必须交叉校验 payload owner、真实 IPC sender、guest 实际 Agent 路由、Surface Registry 当前 URL 和完整 Desktop route identity。即使 Platform WS v2 与 Frame Port v2 的逻辑 Session 一直存活，canonical 导航已完成但 owner 登记尚未到达仍只是 transitional snapshot：Main 最多等待既有 1500ms 登记窗口，并在匹配登记到达后重新解析真实 sender 和最新 generation。等待期间不得激活 live session、签发 token、连接 Broker、detach 当前 Run 或向 Platform 发送 query；超时、guest 销毁、generation 替换、页面/Agent/Chat 变化均在本地返回 `protocol_error`。canonical Query 的 outbound `chatId` 从 committed owner 派生；guest 字段为空可以补齐，非空但不一致继续拒绝。

已有 Chat 内的“新对话重问”必须在 query 前使用受限 Service WebView bridge 准备新的 route source。Desktop 只接受当前 active Main Chat、精确 `agentKey + sourceChatId` 和合法 13 位 nonce；首次导航 push 到 `newChat`，等外层 route、同一 guest URL 与无 owner Surface 登记一致后才 ACK。WebClient 在 ACK 前不得清空或发送；登记失败或超时由 Desktop 回滚来源 route。后续仍由既有 canonical 同步 replace 为 `chatId`，不得放宽 Main 的 owner 冲突校验。

## Partition 与认证边界

- Agent WebClient 使用专用持久 partition。Platform 数据请求与 Run 实时请求均可进入 `__AGENT_WEBCLIENT_PLATFORM_FRAME_PORT__`；上传、下载、语音等显式 HTTP-only 请求仍由 Desktop host 在 main 注入和刷新凭据。guest 不接收 access token。Frame Port 全程传输结构化帧，不模拟 WebSocket，也不在 guest 侧计算心跳或重连。Agent Platform `/ws`、query/attach 流和 Run control HTTP 入口在 host 层固定拒绝。
- Website 使用官网 SSO partition 获取 Cookie 会话；页面不能读取 Desktop token 文件。
- Help 使用独立匿名 partition，不复用 SSO Cookie，也不接入 Token Bridge。
- WebApp 页面只访问自己的 loopback gateway，并通过同源 `/__desktop` bridge 调用 Manifest 允许的能力；它不加载 Service WebView preload。
- 普通 Service 和 Plugin 使用各自宿主策略，不因为 URL 与 Website 相似而获得官网会话。
- 普通 WorkPanel Web item 与 Website 使用同一个 Desktop 应用浏览器 SSO partition，共享 Chromium 管理的应用 Cookie、缓存和上游登录重定向状态；关闭 item 或 workspace 只销毁 guest，不清理这份持久浏览器 session，退出登录时由 SSO 控制器统一清理。由真实来源 guest 发起的受限 `blob:` popup 创建新的外层 item，并继续使用同一应用浏览器 partition。该共享只改变浏览器 session，不合并 Website 与 WorkPanel 的 surface、bridge、Chat 归属或自动化授权。

token、Cookie、文件系统路径和 Electron 对象只停留在 main。preload 只暴露结构化请求，renderer 和 guest 只接收完成当前工作流所需的结果。

公开分享页不属于 Desktop surface，也不继承 Desktop SSO、partition 或 guest bridge。Desktop 只打开 Tunnel 返回的 `/share/{id}` URL；外部浏览器直接从 Tunnel 获取完整 HTML 主文档。

## Bridge 与能力策略

不同 surface 使用不同 bridge，不能合并成通用远端页面 API：

- Service WebView bridge 处理宿主展示参数、受限路由、认证申请和明确的 Desktop 集成能力。
- History dialog 只使用 `assistant.listHistoryChats` 以及既有的 `assistant.exportChat`、`assistant.archiveChat`、`assistant.deleteChat` 专用 IPC。Main 持有 Platform endpoint 与 token，请求固定 Platform Chat 接口并返回最小 DTO；renderer 不获得 token、Platform URL 或通用 Platform request 能力。归档和删除由 AppShell 统一回收对应 Work Panel、刷新 Sidebar，并在命中当前 Chat 时执行回退导航。
- Agent WebClient 的 Platform Frame Port 与 WorkPanel 使用固定全局 bridge。Main 根据真实 IPC sender、guest WebContents、origin、route、partition、surface 类型和 owner Chat 派生 capability；guest 自报的 surface、Chat 或 capability 不参与授权。WorkPanel 通过自己的 `getCapabilities()` 查询保留独立授权边界。
- Agent WebClient guest 的 surface 类型只从宿主持有的结构化 `surfaceRole` 映射；页面 route、查询参数、文件路径和展示 URL 不参与身份分类。File、Artifact、Reference、Source、Planning 等非 live 子 Surface 使用 management 数据能力，只能发送普通 Platform request/response，不能因此获得 Run lease。
- 固定 bridge 全局可见不表示 guest 已完成 Surface Registry 登记。可信 WebView 首次打开 Frame Port 而 target 尚未登记，或持久逻辑 Session 上的新 query 遇到 Main Chat transitional identity 时，Main 最多等待 1500ms，并在登记完成后重新执行完整授权；不可信 session、错误 service/origin、已销毁 guest、generation 替换或等待超时仍立即或最终 fail closed。等待期间不得访问 Agent Platform。
- Frame Port 原样承载 Platform `request/response/stream/push/error`，只改写外层关联 id。通过真实 sender、origin、partition 和 Surface Registry 校验的普通平台请求可在 mounted surface 上转发；query/attach/BTW 额外要求具有对应 live capability 且 surface active。新 query 的 canonical Chat identity 来自关联 `chat.start`；附件暂存已预建 Chat 时，也可来自匹配 outbound `requestId + chatId + owner` 的服务端 `request.query` 回显。canonical Run identity 只来自随后匹配的 `run.start`；`chat.created` 和 `run.start` 都不用于猜测 query 的 Chat 归属。Platform stream 一帧对应 guest message 一帧。
- Frame Port 的逻辑 Session ID 在物理 WebSocket 重连前后保持稳定，但 Session 不拥有 Root Observer、Overview lease 或 upstream stream。`reconnecting` 只暂停新请求；已接受 Run 仍登记在 Broker RunChannel 中，有 Root Observer 的 Channel 在所属 lane 恢复后用 `runId + lastSeq` attach，dormant Channel 等合法 observer 再次打开时才恢复。Chat 切换、Surface inactive、owner/context 变化或 registration generation 替换由可信 Registry 生命周期原子替换或撤销旧 Main Chat bundle，有 active Run 时解除它的 upstream observation，不关闭 LogicalSession 或 Primary WS；关闭或重建 Frame Port 本身也不得释放仍 active 的 bundle。后续 `/api/chat` 仍通过同一条 Broker WS 加载新 Chat。WebContents 销毁时可回收对应 LogicalSession；协议不兼容、身份失效与应用退出才轮换或关闭物理 WS。
- Main Chat、Copilot Dock 与 Kanban Chat 是常规 Root Observer；宿主 active 状态通过可信 Surface Registry 生命周期进入 Main。active Main Chat 登记同步创建唯一 Overview lease，Main Chat query/attach 只使用该 bundle。BTW 是唯一可交互的 WorkPanel 子 Surface：激活且归属于 Main Chat 时可发送 `/api/btw` 和恢复 BTW RunChannel，但它复用 Main Chat Root Observer，不能发送 `/api/query`。独立“详细解释”窗口使用固定 `selection-explain` 辅助 Root Observer，只允许 BTW lane 的 attach、续问和中断；它不替换 Main Chat/Copilot/Kanban active observer、不成为 Desktop Action target，也不接收全局 Push。Overview 用普通 attach 帧订阅既存 lease 与 RunChannel 本地 replay/fan-out；在 Main Run 尚未登记时保持事件驱动 pending，不创建 Platform attach。Debug 仍是按需 clone。两者 detach 都只释放本地 subscriber。Source、Planning、Artifact、Reference、File 等子 Surface 只做 replay 或文件读取。
- 同一 mounted guest 的 URL、owner Chat 或 registry 元数据刷新不等于 surface active 状态变化，不能重复发送 active lifecycle。只有真实的 active/inactive 转换或 guest replacement 才触发 WebClient replay/attach 恢复。WebClient 仅当 URL canonical `chatId` 与已投影页面状态的 `chatId` 一致时才可在 active 恢复中强制重读；Chat 切换过渡期两者不一致时必须等待新路由的正常 `/api/chat`，不得以旧 state 再发一次请求。
- WebApp bridge 由本机 gateway 提供，按页面 origin、运行中实例和 Manifest 能力再次校验。
- Website 与 Help 默认没有 Desktop 原生能力；需要系统浏览器打开的跨域链接由宿主处理。
- Surface live active、页面可见性与公开 CDP current 是三种独立状态。Embedded CDP 只操作 registry 中仍存活、active 且与 Desktop 当前页面快照一致的非 child guest；候选缺失或不唯一时 fail closed，不能按登记顺序、URL 或历史 target 回退。Copilot Dock 即使为了 Realtime 保持 live active，也不进入公开 target 列表。
- `Page.reload` 由 Desktop 对已经授权的精确 guest WebContents 执行普通或忽略缓存刷新，不临时 attach/detach debugger；相邻 Website、WebApp、Service 或 Copilot guest 不得因此重建。
- Chat Work Panel 是 Chat 私有的内部 CDP surface，不进入 Website、WebApp 或 Browser 的公开 surface 列表。

任何能力都不能仅凭调用方传入的 `surfaceId`、URL 或 target id 授权。Main 必须将请求与当前 renderer、guest WebContents、登记 generation、所属 surface 和活动页面快照交叉验证。

公开 Surface 查询只返回 canonical 短 ID。升级兼容期可以在 Desktop Web Action/CDP 输入端解析旧 ID，但不能为旧 ID 建立第二份登记，也不能把别名带入 Agent WebClient 的安全授权协议。

Web tab 变更动作的 renderer provider 必须从提交后的 browser state 构造公开 post-state，而不是复用包含 guest 身份的 Embedded CDP 注册结构。公开结果保留当前 surface 的完整 tabs、每个 tab 的加载与前进后退能力以及明确的 activeTab，便于调用方在 navigate、reload、goBack、open、close 或 switch 后继续操作；Main 再逐字段校验和投影，确保 HTTP、Desktop WebSocket 与 Platform 反向 WebSocket 得到相同形状。Electron `guestId`、`webContentsId`、重复的 openedTab/activeTabId 和其他 surface 不得越过公共边界。

## WorkPanel

稳定 Chat 可以拥有一个运行期 workspace。item 是 `webclient`、`web`、`native` 或宿主本地文件的判别联合；Native registry 只注册 `resource-image`，其他 native surface 稳定拒绝。`resource-image` 是无 guest 的 React/Canvas surface，关闭 item/workspace、renderer 销毁或应用退出时释放句柄、watcher 与远端临时缓存。

AppShell 的唯一 reducer/command service 派生 item 稳定身份并拥有全部 workspace 状态；Broker Overview lease 不进入 `WorkPanelState`。任何 item 创建或显示 workspace 前，AppShell 必须先确保 owner Chat 的 Overview 位于第一项；Overview 固定为 pinned、non-closable，产物、网页或其他 item 不能替换、重排或单独关闭它，只有关闭整个 workspace 才一并回收。从侧栏请求其他 Chat 的 WorkPanel 时先记录绑定目标 route 与 commit revision 的 pending-open 并导航，只有目标 canonical `committedChat` 到达后才创建 workspace/Overview WebView；route、generation 或 WebContents 改变时取消旧 pending，5 秒未提交则清理并显示错误。workspace 的 `ownerChatId` 只作为 Chat 分区键，不参与判断当前 Chat。Desktop 另持有不持久化、不进入 bridge contract 的 owner Chat 可见集合：`openItem`、`activateItem` 自动显示对应 workspace；右上角按钮只 hide/show，隐藏时 tabs、active item、guest 和宽度保留且所有 guest 的 active 都是 `workspace visible && active item`；`closeWorkspace` 表示销毁 UI subscriber 并清理可见状态。隐藏或关闭不释放 Broker lease。切换 Chat 按各自状态恢复，不得串用 workspace。其他 pinned 或 non-closable item 同样不能由普通 close 删除。

已通过 canonical Chat 与 Run 身份校验的后台 Run 可以继续操作自己 Chat 的 WorkPanel。若该 Chat 尚无 workspace，Desktop 使用宿主注入的可信 owner 身份先创建 Overview，再创建目标 item；非当前 Chat 的 workspace 与 WebView 保持挂载并可预加载，但不能改变外层路由、激活其他 Chat 或显示到当前 Chat。Run 终态只撤销后续动作 grant，不自动销毁已经创建的 workspace。

WorkPanel 拥有键盘焦点时，Main 必须拦截 macOS `Cmd+W` 或 Windows `Ctrl+W`，并把命令交还给当前 WorkPanel：优先关闭 active closable item；active item 不可关闭时，继续关闭 workspace 中最后一个 closable item；不存在 closable item 时关闭整个 workspace（包含固定 Overview）。点击或用键盘聚焦 WorkPanel（包括 tab）即把它设为当前关闭快捷键目标；进入 `<webview>` 或因关闭 tab 发生的 DOM 焦点变化不释放该所有权，只有点击 WorkPanel 之外、隐藏或回收 workspace 时才释放。macOS 应用菜单的 `Command+W` 不得直接绑定原生 close role；它先把关闭请求交给 renderer 判定，只有 renderer 确认快捷键目标不属于 WorkPanel 后才能回调 Main 执行窗口默认关闭/隐藏。不能依据 URL 推断 guest 身份。

Main Chat 的 WorkPanel 入口由 Desktop 持有，只在 `/agent/:agentKey` 路由显示；稳定 `chatId` 产生前按钮禁用。首次点击仍以规范化 `/overview/:chatId` 创建 Overview item，但创建动作受 Main Chat 可信 surface 登记门控；正常页面加载可以继续显示，实时数据不得依赖用户重试。WorkPanel WebClient descriptor 按 module 使用独立 context。Artifact/Reference 的打开由 Agent WebClient v5 优先调用 `openResource`：Desktop 只对签名匹配的 PNG、JPEG、WebP 创建 `resource-image`，其他类型返回 `unsupported_native_type` 后由 WebClient 打开 `/resource-viewer/:agentKey?chatId=...&file=...`；授权、缺失、身份冲突与越界错误不得回退 Viewer。Standalone 或旧 v4 WebClient 保留当前 Viewer。File 的 `context.path` 保留 Platform 可解析的原始请求路径；Project 与 File Diff 的 path 仍必须是 workspace 相对路径并拒绝 `..`。Web item 只接受无用户名密码的 HTTP(S) URL。

WorkPanel tab strip 的末尾固定跟随一个参与横向滚动的 `+` 入口。宿主菜单按 Terminal、Web、Files、Side Chat、Project、WebApp 排列：Terminal 仅为禁用占位；Project 只对可信 catalog 中的 KBASE 或具有有效 workspace 的 CODER 显示/启用；Side Chat 使用 `/btw/:chatId`，用户每次新建时由宿主生成 `instanceId`，已知 `btwId` 时仍按 canonical BTW 去重。Web、Project、WebApp 与本地文件按资源身份去重，Side Chat 实例不去重。新增状态与 workspace 都只存在于本次 Desktop 运行期。

`webapp-ref` 与 `local-file` 是仅供 Desktop 宿主创建的 descriptor。前者只包含 `webappId` 和显示名；后者只包含 opaque `handleId`、文件名和预览类别，不能通过 Agent bridge、HTTP Action Bridge 或公共 `desktop.workpanel.openTab` 创建。用户文件选择与内部 Platform-only `desktop.workpanel.openLocalFile` 都必须由 Main 的 handle registry 生成句柄；后者只接受相对于来源 Agent 权威 workspace 的路径，并以绑定 owner Chat、renderer sender 和 generation 的一次性 claim 进入 renderer。专用临时 partition 注册 `zenmind-local-file://`，允许同目录相对资源和必要的 `data:`/`blob:` 内容，但拒绝 HTTP(S)、WebSocket、FTP、外部导航、popup 与全部权限请求；每次本地资源请求仍经过规范化路径与 realpath 边界校验。该 session 不含 SSO、Desktop token、WebApp bridge 或 Node 能力。可批注 HTML 的内容区固定显示与 Web item 同风格的刷新、文件名和编辑/完成工具栏；文件名只作展示，不暴露真实路径。关闭 item/workspace 或 renderer 销毁时释放句柄和 session；未知格式只提供 Finder/Explorer 定位及系统默认应用打开。

File 仍遵循“先打开宿主面板，再请求 Platform”。Artifact/Reference 在 Standalone 中继续由 WebClient Preview Panel 请求 `/api/resource`；Desktop 原生图片则由 Main 优先读取本地 `chats/<chatId>/artifacts|references/...`，本地不存在时用 Main 持有的 Platform 身份取得远端字节并写入受控临时缓存。远端句柄保留 Platform 响应的源 `size:mtimeMs` revision，不能使用临时缓存 mtime。renderer 只获得 handle、文件信息与 revision，不获得绝对路径、Token 或内部 descriptor。

原生图片预览态把文件名、格式/大小和源尺寸收纳到信息悬浮层，固定单行显示信息入口、实际显示比例、缩放、“打开方式”与“编辑”；外部应用打开属于资源查看能力，即使图片超过编辑上限也继续可用。Main 通过绑定 opaque handle 的 IPC 返回图片字节，renderer 只为当前运行期预览和编辑历史创建本地 `blob:` URL；CSP 的 `img-src blob:` 不扩展导航、网络访问或跨 renderer 传递能力，URL 不持久化并在历史淘汰或 surface 卸载时撤销。字节缺失或浏览器无法解码时 surface 静默保留为空白预览，禁用依赖像素的编辑入口，不显示错误条且不影响其他 WorkPanel item。编辑态使用同一 React/Canvas surface，顶部固定为单行，只保留“返回预览”、撤销/重做、缩放与保存等会话操作；宽度不足时撤销、重做和保存可收敛为带悬浮说明的图标，但普通样式的“返回预览”始终同时显示返回箭头与四字文案，整行不得换行或依赖横向滚动。“返回预览”结束本次编辑会话并重新读取原资源，必须丢弃尚未保存的像素历史、选区、批注、工具参数、冲突状态和错误提示；预览态不得保留或显示任何编辑态提示。保存只有在存在可提交的像素修改且当前允许提交时才使用强调色。Photo 工具由左侧单列图标栏承载，每个图标向右显示工具名；旋转、水平/垂直翻转和选区自由变换收纳在“变换”的 hover/focus 二级菜单，图片尺寸与画布尺寸保持为两个独立工具。自由变换从当前选区提取像素，显示可拖动、四角可缩放的边框并支持角度输入，应用后才进入像素历史。批注修改、对象擦除、背景移除/替换、扩图和增强全部作为连续的紫色工具按钮平铺在“调整”之后，不再提供聚合式 AI 工具入口、工具列表对话框或独立的智能修改执行按钮；只有需要文字或目标尺寸的单项工具显示自己的轻量参数浮层。“批注修改”一级工具同时承担圈选和填写要求，执行动作只出现在批注检查器底部。普通选区只服务自由变换等像素操作和对象擦除；智能区域修改只消费带文字要求的批注，不再让用户在“用选区圈选”和“用批注圈选”之间重复选择。批注检查器使用摘要列表，只展开当前一条修改要求，并与选区说明、画布尺寸、调整、自由变换和单项 AI 参数浮层一样支持在画布区域内拖动；内容过多时只在浮层内部滚动，不参与 viewport 尺寸计算，也不得触发图片适配比例变化。智能修改成功后才清除已消费的批注；其他会使批注失效的像素操作必须先确认清除。缩放和平移不进入最多 50 步的像素历史。每个 workspace 同时只有一个 active 编辑器；切换到另一张图片编辑时，离开的图片同样按返回预览处理并丢弃未保存草稿。编辑上限为单边 8192、总像素 4000 万，超限资源只允许预览和外部打开。

“擦除对象”与普通选区共用选区引擎，但必须表现为完整的任务模式：没有选区时点击该工具应自动进入选区并显示“圈选目标 + 擦除选中对象”的就地操作；已有选区时再次点击工具可以直接执行。普通选区按钮与擦除对象按钮不能同时显示 active，智能处理失败时必须返回擦除选区模式并保留当前选区以便重试。

保存每次重新选择：Artifact 默认创建新 Artifact、也可带 expected revision 覆盖原资源；Reference 只能创建 Artifact。透明结果不能覆盖 JPEG。提交由 Platform `resource.image.commit` 负责，Desktop 不直接写 Agent Platform 资源目录；新资源使用新 stable identity 打开新 tab，覆盖则更新原 tab。外部应用只打开验证后的原文件；远端缓存必须先下载副本。原文件的 `size:mtimeMs` 变化在无草稿时自动刷新，有草稿时形成 source conflict，只允许丢弃草稿重载或另存新 Artifact。

WorkPanel 外层 tab 的右键菜单由 Desktop 按可信 descriptor profile 生成：普通 Web tab 提供刷新与复制实际 URL，Artifact/Reference tab 分别保留来源语义，但都提供文件名复制、预览刷新、下载、在系统文件管理器中显示以及用系统默认应用打开当前 Resource Viewer 文件；其他 WebClient tab 不暴露内部服务 URL。Desktop 按 Resource Viewer 当前同源的文件扩展名分类判断内嵌预览能力：HTML、PDF、图片、文本、音频和视频等可预览格式保持完整内容展示；Office 与未知格式由 WebClient 直接在 `.content-viewer-panel` 中央纵向渲染文件管理器定位和默认应用打开动作，Desktop 外层不叠加重复操作层。按钮经 Service WebView bridge 提交 `requestId + action + chatId + profile + relativePath`，不提交本地绝对路径；Main Chat Surface 以当前 owner Chat 校验身份，WorkPanel Surface 还要求请求与当前 item 的可信 descriptor 完全一致。下载动作仍通过版本化 host action 通知 Resource Viewer，由 WebClient/Platform 既有执行器负责。文件管理器显示与默认应用打开都不触发下载：Desktop 只接受 Resource Viewer 中与 owner Chat 一致的 `artifacts/...` 或 `references/...` 相对路径，Main 将其解析到 Agent Platform 运行根的 `chats/<chatId>/` 下，并在拒绝绝对路径、`..`、错误目录前缀和 realpath 越界后交给 Electron shell；前者在 macOS/Windows 分别交给 Finder/文件资源管理器定位现有文件，后者按系统应用关联打开。所有 profile 共用全屏、关闭当前和关闭其他 tab；固定或 non-closable item 必须保留。全屏状态由 AppShell 独占拥有：进入时 WorkPanel 覆盖整个 Desktop UI 并请求主窗口原生全屏，其他导航、面板和普通浮层不可见且不可聚焦，但现有 tab 与 guest 不得重建；退出时只撤销由 WorkPanel 自己触发的原生全屏，进入前已存在的系统全屏必须保留。系统原生全屏被外部退出、所属 workspace 隐藏或回收时，AppShell 必须同步退出 WorkPanel 独占布局。

可信本地 HTML/图片与具备 capability 的 Artifact/Reference tab 可以进入评审模式。普通 Web item 中 URL 本身不携带用户名密码的 HTTP(S) 顶层 HTML 使用后退、前进、刷新、地址和编辑工具栏，并按应用浏览器 partition 携带现有 Cookie；本地 HTML 使用刷新、文件名和编辑工具栏；Artifact/Reference 外层使用刷新、资源名和编辑工具栏，编辑能力在 guest 声明 capability 前保持禁用。地址始终可直接输入，“编辑”只负责进入页面元素批注，激活后显示“完成”；页面内容不能自行开启模式。图片评审只创建编号矩形，并同时保留原图像素矩形与归一化矩形，覆盖层在滚动、缩放和全屏变化时按归一化坐标重绘。HTML 评审拦截选择期间的链接、提交和点击，保存 Full XPath、辅助 selector、经过脱敏的元素摘要与文档坐标；导航、刷新、资源版本变化或目标删除后无法重定位的批注必须显式失效。普通 Web/本地 HTML 由隔离 preload 命中顶层 DOM；Artifact/Reference HTML 由不带 `allow-same-origin` 的 sandbox `srcDoc` 内窄桥完成同等命中，父页面只接收当前 iframe source 与运行期 token 匹配的消息。V1 不跨被评审文档内部的嵌套 iframe 或 Shadow DOM，也不支持伪元素、文字范围和自由画笔；未声明 capability 的 HTML 安全降级为只读，不能通过放宽 iframe origin 来换取定位能力。

评审面板在窄 WorkPanel 使用底部抽屉，在宽布局和全屏使用右侧栏；tab 只显示不可交互的批注数量。图片最多导出一张带编号矩形的有界临时 PNG；HTML 只交接有界定位摘要，不交接 DOM。交给智能体只把固定格式文本、原资源语义引用、结构化区域数据及可选 staged PNG 追加到 owner Chat 的 canonical Main Chat Composer，不覆盖已有草稿、不自动发送，也不在用户发送前上传。workspace 文件要求原位修改并刷新现有 tab；Artifact/Reference 的草稿明确要求保留原资源、生成新版本并打开新 tab；普通 Web 批注携带安全的页面 URL 与元素定位，但不假定 Desktop 能访问该站点源码，无法定位实现时必须明确说明而不能猜测修改。

WorkPanel Web item 的普通主框架导航保留在当前外层 tab；popup、`target="_blank"`、`window.open()` 与右键“在新工作面板标签打开”统一由 Main 根据真实 `chat-work-panel` guest 标记为 WorkPanel 目标，再由 renderer 以来源 guest 所属 owner Chat 创建新的外层 Web item。普通 Web item 与公开 `openWeb` 输入仍只接受 URL 本身不携带用户名密码的 HTTP(S) URL，页面认证只来自共享应用浏览器 partition 中由 Chromium 管理的 Cookie。页面运行期产生的 `blob:` 只作为来源绑定的内部 popup 能力，Main 校验 creator origin、真实 opener guest 与 surface，renderer 再由该 guest 反查 owner Chat 和来源 item；目标 item 使用同一应用浏览器 partition，但仍保留来源 Chat 归属。`blob:` 不得交给系统外部打开、下载分流、公共 Desktop Action 或 Agent Bridge，也不能跨 Website、Chat 或 WorkPanel item 猜测来源。该链路不得导航到 Desktop Browser 根路由，也不得在隐藏的 `ExternalWebviewPage` 内部 tab 栏创建不可见标签。网页加载期间，外层 tab 图标显示 loading，内容区顶部显示细进度条；完成、失败或 item 卸载后必须清除。

## 上下文菜单与页面交互

Main 为已登记 WebView 应用基于 surface 类型的固定菜单策略。Browser、Website、WebApp 与 Work Panel 可以在安全范围内导航或交给系统浏览器；Service、Help 和 Plugin 不能把原 guest 导航到任意外部来源。

可信 Agent WebClient 可以返回结构化语义目标，但不能提供任意菜单命令、脚本或认证数据。Main 在显示和执行阶段都重新校验 guest、origin、partition 与 target；超时或失效时退回安全的 Electron 菜单。

可信内嵌对话的非编辑文本选区由 Desktop renderer 覆盖显示“添加到对话”“详细解释”“在顺便问中提问”。preload 只上报矩形与首尾探测点；Main 要求首尾解析为同一个消息或代码 target，并在按钮点击时重新校验不透明 selection ID、guest、URL 与 registration。选中文字始终由 WebClient 在执行时读取：添加到主 Composer 或 BTW 只暂存 `selection` reference，不自动发送。“在顺便问中提问”只通过既有 WorkPanel bridge 打开当前 Chat 的单例 BTW 子 Surface，不在 Agent guest 内再嵌一层 RightSidebar；来源与 BTW guest 间的正文使用同源内存态一次性交付，Desktop 只看到固定 target 和 Chat ID。详细解释由来源 WebClient 发起一次隐藏 BTW Run，Desktop 只接收 `chatId/runId` 并打开单例解释窗口。解释窗首次打开和后续复用时都以 CuteJ 主窗口 bounds 为锚点，对齐到整个 Desktop 界面内部的右下角；macOS 保留 20px 边距，Windows 保留 16px 边距，最后再用主窗口所在显示器的 work area 夹紧坐标。所有动作结果与窗口 handoff 都禁止携带正文、Prompt、Token 或临时 URL。

## 安全与平台约束

- WebView 禁用 Node 集成并启用上下文隔离；具体 sandbox 策略按宿主类型显式设置。
- 不可信跨 origin 导航、popup 和下载由 main 统一判断，不能由 guest 自行扩大允许列表。
- 调试 URL 必须脱敏 token、授权码和 secret，调试状态不能改变页面权限。
- 文件选择、屏幕捕获、麦克风和系统打开等原生能力在 macOS 与 Windows 分别处理权限和失败行为。
- renderer 热更新或 guest replacement 期间使用能力探测和 generation 校验，旧 guest 不能继续操作新 surface。
