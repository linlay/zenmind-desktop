# 前端嵌入与导航

## 当前状态

Desktop 不再提供统一静态资源服务。内置服务、插件和本地网站应用都直接暴露自己的 `webUrl`，渲染层通过 webview 或内置 browser surface 打开。

服务前端模式来自归一化后的 service definition。内置服务通常来自 manifest `frontend.mode`，插件 manifest 使用 `service.ui`，最终都会归一化成 `frontendMode`。

- `none`：无前端，仅控制中心管理。
- `embedded`：详情页可打开前端，不进入顶部/侧边主导航。
- `standalone`：运行中进入导航，可作为独立 surface 打开。

## 核心流程

```text
service state healthMeta.webUrl
  -> buildPluginEmbeddedUrl()
  -> PluginPage webview
  -> service-webview preload bridge
  -> route / auth / settings / clipboard / screenshot messages
```

导航来源：

- 内置 routes 和 agent-webclient routes。
- running standalone service。
- `config/webs/order.json` 中的外部网站与本地网站应用排序。
- webapp running state 中的 `webUrl`。
- 内置 browser route。

service webview bridge 支持：

- 非主聊天 surface 的 route sync：`desktop:service-webview:route`。
- clipboard、目录选择、打开路径、下载文件、截图、插件设置读写。
- agent-webclient access token 请求和响应：`desktop:agent-auth:*`。
- agent-webclient management surface 在归档恢复等场景请求打开会话时，由 Desktop 外层路由切换到常驻 chat surface，避免 management webview 内部先渲染聊天页导致路由失步和闪烁。
- Desktop 侧边栏归档当前会话时，只有后端单条归档结果成功后才刷新列表；随后切换到同智能体的下一条会话，没有下一条时进入该智能体空白页，避免失效 `chatId` 持续显示“正在加载会话”。
- Desktop 侧边栏重复触发历史或新建会话时，除了更新外层路由，还会把新的 URL 直接派发给已挂载的主聊天 WebView。历史面板的“再次打开”额外复用受限的 `openChatHistory` 展示动作；该动作不携带消息、run 或会话内容，不参与 `chatId`/新会话同步。

当用户在「关于软件」连续点击 5 次解锁当前 Desktop 会话的 Debug 设置时，渲染层会在激活的服务、插件和外部 WebView 左上角叠加实际导航 URL。该标记不接收鼠标事件、不注入 guest 页面，也不修改 webview bridge；其中 URL 的 token、授权码、secret 和 API key 参数会脱敏显示。

## 配置与接口

`buildPluginEmbeddedUrl()` 对特定服务做嵌入 URL 归一化：

- `identity-center`：打开 `/admin/`。
- `agent-platform`：打开 `/monitor`，可附加 `access_token`。
- `agent-webclient`：根据 `embedPath` 打开嵌入路由，并附加 `hostTheme`、`lang`；仅聊天与 Copilot 实时路由附加 `wsSource`。认证上下文通过 Token Bridge 响应传递，不再写入 URL。主聊天只接受 Desktop URL 导航和 Token Bridge；不接收聊天业务 bridge。webclient 创建 chat 后自行更新 `?chatId=`，Desktop 只被动镜像这个 URL，绝不根据 WebSocket frame 派生路由。

Chats 中的 bootstrap 初始化不引入原生页面：每个 Desktop 启动会话在 bootstrap 导航数据就绪后只自动导航一次，seed 存在时进入 `/agent/<bootstrapAgentKey>?chatId=<bootstrapChatId>`，索引缺失时进入现有 `?newChat=<timestamp>` 路由。该导航只加载 WebClient，不发送消息；用户离开后本次启动不再强制跳回。欢迎语中的 Markdown 使用同一 chatId 下的 `desktop-overview.png` 和 `desktop-sidebar-actions.png`，由 WebClient 现有资源 URL 转换和 Chat 主区域渲染；Desktop 不插入独立初始化 UI。初始化完成后的自动恢复也只使用 agent-webclient 的新会话路由。

Web surface runtime 提供：

- `desktop.web.listSurfaces`
- `desktop.web.getActiveSurface`
- `desktop.web.activateSurface`
- `desktop.web.navigate`
- `desktop.web.openTab`
- `desktop.web.closeTab`
- `desktop.web.switchTab`

## 约束与注意事项

- webview 初始 URL 不应拼裸相对路径；统一通过 `buildPluginEmbeddedUrl()` 处理。
- 需要认证的嵌入页不能直接读 Desktop secrets，必须走 bridge 申请 token。
- Agents、Archives、Automations、Memory 和 Registries 等管理页只使用 HTTP/SSE，不附加 `wsSource`；未来重新引入 `/ws` 时必须显式定义新的 surface 来源。
- `wsSource` 只在 `/ws` 建连时补充 `source` 与 `deviceId` 监控元数据；preload 不监听、解析或转发任何 WebSocket message。
- 本地网站应用只有 running 且存在 `webUrl` 时才进入可操作 surface。
- route sync 仅服务非主聊天嵌入页；主聊天以 URL 为唯一业务接口。唯一的展示动作例外是侧边栏重复打开历史面板所用的 `openChatHistory`，不得扩展为聊天加载、创建或 run 同步。
- WebView URL 调试叠层仅随当前主窗口会话的 Debug 解锁状态出现；重启后恢复隐藏。
