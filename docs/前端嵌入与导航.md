# 前端嵌入与导航

## 当前状态

Desktop 不为所有产品提供一个共享静态资源服务。内置服务和插件暴露自己的 `webUrl`；本地网站应用则由 Electron Main 为每个实例创建独立 loopback gateway，并将该 gateway 的 `webUrl` 暴露给渲染层。渲染层通过 webview 或内置 browser surface 打开。

服务前端模式来自归一化后的 service definition。内置服务通常来自 manifest `frontend.mode`，插件 manifest 使用 `service.ui`，最终都会归一化成 `frontendMode`。

- `none`：无前端，仅控制中心管理。
- `embedded`：详情页可打开前端，不进入顶部/侧边主导航。
- `standalone`：运行中进入导航，可作为独立 surface 打开。

## 核心流程

```text
service.healthMeta.webUrl
  -> buildServiceWebviewUrl()
  -> ServiceWebviewSurface
  -> service-webview preload bridge
  -> route / auth / settings / clipboard / screenshot messages
```

导航来源：

- 内置 routes 和 agent-webclient routes。
- running standalone service。
- `config/webs/order.json` 中的外部网站与本地网站应用排序。
- webapp running state 中的 `webUrl`。
- 内置 browser route。

Desktop 左侧导航按当前 route 派生为三种互斥模式：主工作区、能力导航和设置导航。进入
`/agents`、`/skills`、`/mcp-servers`、`/registries`、`/archives` 或 `/help` 时，主侧栏替换为
固定宽度的能力列表；`/agents/:agentKey` 与 `/skills/:skillKey` 继续高亮各自父项。能力列表只包含
智能体、技能中心、MCP 连接器、注册配置、已归档对话和帮助，不包含 Automations、Memory、Market
或 Settings。能力页和设置页的「返回应用」都返回最后一个主工作区 route，并从 Desktop 自维护的
侧栏历史中移除二级侧栏 route；直接深链进入时回退到 Kanban，Kanban 禁用时回退到 Chat。
二级侧栏固定为 200px、不允许折叠或拖拽调宽，退出后恢复主侧栏原有宽度和折叠状态。该模式只改变
Desktop 外壳导航，不改变 agent-webclient management surface、Help partition 或 WebView 路由同步。

Cmd/Ctrl+K 全局搜索的动作快捷键只在搜索弹层打开时生效：新建对话为 Cmd/Ctrl+N，智能体管理为 Cmd/Ctrl+A，技能中心为 Cmd/Ctrl+S，MCP 连接为 Cmd/Ctrl+M，设置不分配快捷键；控制中心不再作为独立搜索动作，因为设置已包含该入口。新会话动作在所有页面始终展示，非智能体页面使用 Desktop 已解析的默认 Chat 智能体。主窗口和嵌入 WebView 都由 main 进程先拦截这些组合键并向 renderer 发送规范化动作，避免 macOS 原生菜单抢占 Cmd+M。macOS 的对话数字槽位使用 Cmd+数字，智能体槽位使用 Option+数字；Windows 分别使用 Ctrl+数字和 Alt+数字，Linux 不提供对应映射。结果行的 macOS Command/Option 提示使用 SVG 符号，不显示英文修饰键名称。

动态路由 segment 在边界上遵循固定的单次转换规则：Router 或 pathname 提供的编码 segment
只调用一次 `decodeURIComponent` 得到业务值；由业务值生成 URL 时只调用一次
`encodeURIComponent`。`/agent/:agentKey`、`/agents/:agentKey` 和
`/copilot/:agentKey` 共用该规则。空值或非法百分号编码视为无效路由；不得递归解码，也不得根据
字符串是否含 `%` 猜测其编码状态。Catalog 匹配始终使用解码后的业务 `agentKey`，Desktop
路由、`embedPath` 和 WebView URL 始终保存单层编码的 segment。

service webview bridge 支持：

- 非主聊天 surface 的 route sync：`desktop:service-webview:route`。主聊天仅在业务路由不变而 `theme`、`hostTheme`、`lang` 或 `wsSource` 发生变化时，使用同一通道替换宿主展示参数。
- 已挂载但 inactive 的 agent-webclient surface 仍接收语言、主题等宿主展示参数并记录自身导航状态，但不得将 WebView 路由反向写入 Desktop Router；只有当前 active surface 拥有外层路由同步权。
- clipboard、目录选择、打开路径、下载文件、截图、插件设置读写。
- Website/WebApp 目录查询：嵌入的 agent-webclient 发送 `desktop:webs:list:request`，Desktop 调用既有 `electronAPI.webs.list()` 后返回 `desktop:webs:list:response`。
- agent-webclient access token 请求和响应：`desktop:agent-auth:*`。
- agent-webclient management surface 在归档恢复等场景请求打开会话时，由 Desktop 外层路由切换到常驻 chat surface，避免 management webview 内部先渲染聊天页导致路由失步和闪烁。
- 普通 Service/Plugin、Website/WebApp 和 Browser surface 默认只有 Desktop 到 WebView 的单向路由所有权，不得因 guest 导航改写 Desktop Router。反向同步仅开放给当前 active 的 agent-webclient chat surface，以及 management surface 到有效 chat 的显式转换；跨 origin、非法 segment、缺少 `agentKey` 或缺少 `chatId` 的 guest URL 一律忽略。
- Desktop 侧边栏归档或永久删除当前会话时，只有后端操作成功后才刷新列表；随后切换到同智能体剩余会话中的最新一条，没有下一条时进入该智能体空白页，避免失效 `chatId` 持续显示“正在加载会话”。
- Desktop 侧边栏重复触发历史或新建会话时，除了更新外层路由，还会把新的 URL 直接派发给已挂载的主聊天 WebView。对于主聊天，比较规则是同 origin、同 `/agent/<agentKey>` 且所有业务 query 参数相同；`theme`、`hostTheme`、`lang`、`wsSource` 及参数顺序仅属于宿主展示参数，语义相同不得重复 `pushState` 或派发 `popstate`。当这些宿主参数的值确实变化时，Desktop 通过 route bridge 让 WebClient 使用 replace navigation 更新展示状态，不重放聊天业务路由。`newChat`、`chatId`、`history`、`historyRequest` 和未知 query 参数均属于业务路由，仍会正常导航。历史面板的“再次打开”额外复用受限的 `openChatHistory` 展示动作；该动作不携带消息、run 或会话内容，不参与 `chatId`/新会话同步。
- 主聊天反向同步按业务身份去重：身份由解码后的 `agentKey` 与除 `theme`、`hostTheme`、`lang`、`wsSource` 外的 query 构成，参数顺序不影响相等性。Desktop 记录最后一次下发给 chat WebView 的业务身份；guest 回报相同身份时判定为宿主回声，不调用外层 `navigate()`。guest 与当前 Desktop 路由业务等价时同样不导航。只有 active chat 的真实业务变化使用 replace；因此 `newChat` 收敛为稳定 `chatId` 只发生一次，后续重复事件被等价判断拦截。

当用户在「关于软件」连续点击 5 次解锁当前 Desktop 会话的 Debug 设置时，渲染层会在激活的服务、插件和外部 WebView 左上角叠加实际导航 URL。Debug 页标题右侧的「关闭调试」会立即结束本次会话的 Debug 解锁、隐藏 Debug 分区和 URL 标记，并返回「关于软件」。该标记不接收鼠标事件、不注入 guest 页面，也不修改 webview bridge；其中 URL 的 token、授权码、secret 和 API key 参数会脱敏显示。

## 配置与接口

`buildServiceWebviewUrl()` 对特定服务做嵌入 URL 归一化：

- `identity-center`：打开 `/admin/`。
- `agent-platform`：打开 `/monitor`，可附加 `access_token`。
- `agent-webclient`：根据 `embedPath` 打开嵌入路由，并附加 `hostTheme`、`lang`；Desktop 管理路由 `/mcp-servers` 对应 WebClient 同名页面，并包含在 host-managed SPA fallback 白名单中。仅聊天与 Copilot 实时路由附加 `wsSource`。认证上下文通过 Token Bridge 响应传递，不再写入 URL。主聊天只接受 Desktop URL 导航和 Token Bridge；不接收聊天业务 bridge。webclient 创建 chat 后自行将 `?newChat=` replace 为 `?chatId=`；这是同一条 live query 的 URL 身份收敛，Desktop 只被动镜像和更新侧栏选中态，不得回写该语义相同路由或触发 WebView 重放。Desktop 绝不根据 WebSocket frame 派生路由。

`desktop:webs:list:response` 的 `items` 固定为
`{ id, entryKey, label, kind, url?, updatedAt }[]`。`kind` 只允许 `website` 或 `webapp`；
Website 可返回配置 URL，WebApp 不暴露 launcher 或本地目录。该 bridge 只提供 Composer
选择 Site 所需的可信目录指针，不读取网页内容，也不代表 Site 当前已打开。

Chats 中的 bootstrap 初始化不引入原生页面：每个 Desktop 启动会话在 bootstrap 导航数据就绪后只自动导航一次，seed 存在时进入 `/agent/<bootstrapAgentKey>?chatId=<bootstrapChatId>`，索引缺失时进入现有 `?newChat=<timestamp>` 路由。该导航只加载 WebClient，不发送消息；用户离开后本次启动不再强制跳回。欢迎语中的 Markdown 使用同一 chatId 下的 `desktop-overview.png` 和 `desktop-sidebar-actions.png`，由 WebClient 现有资源 URL 转换和 Chat 主区域渲染；Desktop 不插入独立初始化 UI。初始化完成后的自动恢复也只使用 agent-webclient 的新会话路由。

Help 同样不再维护原生内容。固定路由 `/help` 从 `config/desktop/help.json` 读取公开网站 URL，
并使用无 preload、无 Node 集成的 Electron WebView 全屏展示。Help 使用独立的
`persist:<storageNamespace>-help` partition，不复用官网 SSO partition，不读取
`sso-access-token.txt`，也不调用 Token Bridge。初始加载和后续主框架导航都只允许配置 URL
的同 origin 地址；跨 origin 导航与 popup 交给系统浏览器。配置缺失或加载失败时仅显示
Desktop 原生的错误与重试壳。Desktop 加载 Help 时固定覆盖查询参数 `desktop=1`，并把当前
界面语言与已解析主题分别写入 `lang=zh-CN|en-US` 和 `theme=light|dark`；语言、手动主题或
系统主题变化后重新加载 Help，使网站切换为桌面嵌入布局并与宿主显示状态保持一致。

Website WebView 统一使用 `persist:<storageNamespace>-sso` partition，以便和 Desktop Cookie SSO 共享上游会话及 `access_token` Cookie；本地 WebApp、Help、agent-webclient 和普通 Service/Plugin 继续使用各自 partition。Cookie SSO 启动恢复从临时失败转为成功时，renderer 只对当前已挂载、使用 SSO partition 的所有 Website 标签各执行一次 reload，使网页在双 session Cookie 刷盘后同步恢复；不能按登录 URL 猜测，也不能 reload Help、WebApp、agent-webclient 或普通服务。

Web surface runtime 提供：

- `desktop.web.listSurfaces`
- `desktop.web.getSurfaceState`
- `desktop.web.activateSurface`
- `desktop.web.navigate`
- `desktop.web.reload`
- `desktop.web.refreshSurface`
- `desktop.web.goBack`
- `desktop.web.openTab`
- `desktop.web.closeTab`
- `desktop.web.switchTab`

`desktop.web.listSurfaces` 只返回 Desktop 壳中各 surface 的摘要，每个 Browser、Website、WebApp
或 Service 一条，不展开内部标签。`desktop.web.getSurfaceState({ surfaceId })` 按精确 id 读取指定
surface，不会激活它；返回 surface 的 `open` / `active` 状态、全部存活 tabs、每个 tab 的 URL、
标题、favicon、加载与前进后退状态，以及 `activeTabId`。因此后台 surface 的完整标签状态同样
可读。旧的 `desktop.web.getActiveSurface` 不保留别名或兼容回退。

Browser、Website 与 WebApp 的 renderer host 会把该 surface 的完整 guest WebContents 标签集合
注册给 main；Service 保持单标签语义。CDP 是否允许访问某个 surface 不采用 URL 猜测，也不由
调用参数选择，而是以 Desktop 当前页面快照标记的激活 surface 为唯一边界。

WebApp 的 `webUrl` 永远指向 gateway，而不是原始后端端口。`static` 模式由 gateway 托管 HTML 并只代理 `apiPrefix`，`proxy` 模式代理整站；两种模式都支持 streaming/SSE/WebSocket，并拦截 `/__desktop/*`。因此 WebView、surface registry、`.m` Mobile Tunnel 和 `.wa` 公网发布不需要知道 launcher 类型。

WebApp 可通过 manifest/设置偏好 `openMode` 选择侧边栏点击后的宿主容器：

- `workspace`：默认行为，在主内容区打开并进入 `/webs/webapp:<id>`。
- `dialog`：兼容字段名，实际宿主为独立的 Electron 非模态浮动窗口。点击后保留当前主页面
  和路由，原生标题栏支持拖动、缩放、最小化和最大化，主窗口仍可继续操作。
- 每个 WebApp 最多创建一个浮动窗口；重复点击会恢复并聚焦已有窗口，不重复创建 gateway
  或后端进程。不同 WebApp 可以同时拥有各自的浮动窗口。
- 每个 WebApp 的侧边栏操作菜单按当前宿主显示“在新窗口打开”或“在内置窗口打开”。切换时
  复用当前 runtime/gateway、关闭原宿主，并把 `openMode` 持久化为 `dialog` 或 `workspace`。
- 侧边栏收起后，Sites 弹层中的 WebApp 操作菜单保留可点击的“关闭 webview”，关闭成功后
  Sites 弹层和操作菜单一并消失；收起态隐藏“卸载 WebApp”，“在新窗口打开”位于 Popover
  点击遮罩之上并保持可操作。展开侧边栏后恢复既有卸载操作。
- 浮动窗口不注入 Desktop 工具栏，WebApp 内容完整占用原生窗口内容区。切回内置窗口后进入
  `/webs/webapp:<id>`，runtime 不重启。
- 浮动窗口只加载 Desktop gateway `webUrl`，启用 `contextIsolation`、sandbox 并关闭
  Node 集成。跨 gateway origin 的导航被阻止，安全的 HTTP(S)/mailto 链接交给系统浏览器。
- 关闭浮动窗口会停止对应 WebApp runtime；Desktop 主动停止、重启或卸载时会先回收窗口。
  旧 manifest 缺省为 `workspace`。

本地 WebApp 不加载 service webview preload。schema v5 页面使用同源 ES Module
`import { desktop } from "/__desktop/bridge.js"`；gateway 固定以 JavaScript MIME、`no-store` 和
`nosniff` 返回 SDK，并要求 action 请求 Origin 与当前 loopback `webUrl` 完全匹配。SDK 不注入
`window`，page token 只保存在 gateway 内部，不能进入 HTML、URL、日志或页面存储。schema v4
页面仍可通过同源 action 路径调用 legacy chat/complete/目录选择。

文件/目录/保存路径选择只执行原生选择交互，不能扩展为 Desktop 代替 WebApp 读写文件。声明
`native.microphone` 的 schema v5 页面可以在 workspace guest 或所属浮动窗口请求 audio-only media；
Main 按实际 guest origin 和运行中 WebApp 再次校验 capability。macOS 显式调用系统麦克风授权，Windows
显式保留由 `getUserMedia()` 触发系统授权的路径；camera/video 和 audio+video 请求都不借麦克风授权放行。
音频流始终留在 WebApp 页面，由标准 `MediaStreamTrack.stop()` 关闭，Desktop 不录制或上传。

所有可操作 Web surface 都通过 preload 的 `embeddedCdp.registerSurface` 登记到主进程 registry。
登记以 `surfaceId` 为键，携带 Website/WebApp/Browser/Service 类型、完整标签列表、活动标签 id、
每个 guest WebContents id、URL、标题、加载与前进后退状态；标签切换或导航后更新，surface 卸载后
通过 `unregisterSurface` 移除。主进程读取时必须逐个按 id 验证 guest 仍存活且类型为 `webview`，
不得用配置 URL 或 hostname 推测 surface 是否已打开。后台已挂载 surface 保留登记和完整标签状态，
但只有当前 active surface 能成为 embedded CDP 命令目标。

Browser、Website 与 WebApp 只有一个标签状态转换：标签关闭按钮、`desktop.web.closeTab`、
`Target.closeTarget` 和 guest `close` 事件都调用它。关闭活动标签时先选左侧最近存活标签，没有左侧
才选右侧；关闭非活动标签不改变当前选择；关闭最后一项时先注销 surface，再卸载宿主并进入 `/webs`
空状态。每次事务同步更新 React state、同步 ref、WebView 集合和 main registry，CDP 关闭成功响应必须
等待登记的新状态完成。主进程过滤已销毁 guest 后如仍有 tabs，也按相同的左优先规则选中存活标签，
不得留下 `activeTabId=null`。

工具栏刷新按钮只刷新活动标签。`desktop.web.refreshSurface` 是集成动作，不在普通工具栏上触发；它
原位 reload 快照中的全部存活标签，不卸载 AppShell 或 Website surface。单 target 的 CDP 刷新继续
使用 `Page.reload`。两种刷新、guest replacement 与标签切换都不得改变右侧 Copilot Dock 状态。

renderer 在开发热更新期间可能短暂连接到尚未重启的旧 preload；此时必须通过能力探测跳过 surface
登记，不能因为新方法缺失进入全局异常页。完整重启 Desktop 后使用新 preload 恢复登记；新 payload
不降级发送到只支持单标签的旧接口。

无选中内容时，根路由 `/` 保留纯色居中兜底页。关闭最后一个 Site/Browser 后进入 `/webs`，显示“暂无打开的网站应用”空状态，不再展示“正在加载核心组件”，避免把已关闭的 WebView 误解为仍在加载。两种空状态都不参与核心服务启动状态判断；核心服务的读取、安装、初始化、启动和失败进度由独立的 `StartupLoadingScreen` 覆盖层展示。

Copilot Dock 在物理上是当前 Desktop 应用会话内的单一 WebView，在逻辑上按稳定 `surfaceId` 分别记录
Website、WebApp、Browser 和 Desktop 页面状态。每个 surface 的记录表示 Dock 已打开，并保存该
surface 最后一次相对 WebClient agent/chat URL；没有记录表示该 surface 未打开 Copilot。切换 surface
时复用同一个已挂载的 WebView：目标有记录则显示 Dock 并导航到保存的 URL，目标没有记录则隐藏 Dock，
不能沿用来源 surface 的 Copilot。返回原 surface 时恢复其最后 agent/chat；当前页面上下文始终只由
新的 active surface 提供，因此 Copilot 只操作当前可见页面。进入 agent-webclient 主页面或当前配置
明确禁用 Copilot 的页面时 Dock 暂时隐藏，返回该 surface 后仍按它自己的记录恢复。

renderer 使用带版本号的 `sessionStorage` 快照保存 `surfaceId -> { embedPath, agentKey, chatId? }` 映射；
只允许 `/copilot` 相对路由及 `chatId` 查询参数，禁止保存 token、消息正文和完整认证 URL。打开 Dock、
用户切换 agent、选择历史 chat 或 WebClient URL 收敛时更新当前 surface 记录；renderer 刷新后恢复
当前 surface 的原 agent/chat，恢复只导航既有路径，不创建会话、不重复发送消息，也不依赖 run id。
Agent WebClient 负责在新会话取得稳定 `chatId`、选择历史 chat 或清空会话时更新 guest URL；Desktop
只监听 `did-navigate` / `did-navigate-in-page` 并保存归一化后的 `/copilot/:agentKey?chatId=<id>`，不从
query 流推断会话，也不增加 chatId IPC。guest 完整 URL 中的 `lang`、`theme`、`hostTheme` 和 `wsSource`
由 WebClient/宿主继续维护，但不进入会话快照，恢复时由宿主重新注入。
Website/WebApp 的 `copilotAgentKey` 只在该 Site 尚无打开记录时冷启动选择初始 agent。恢复、冷启动、
surface 切换和 Desktop 显式 open worker 请求产生的 URL 回报不能写回 Website 偏好，只有用户在 Dock
内实际切换 agent 才能更新当时 active Website 的 `copilotAgentKey`。用户主动关闭 Dock 时只删除当前
surface 记录；target reload、surface refresh、guest replacement 和 Website 内部标签切换不删除记录。
关闭并重启 Desktop 后 sessionStorage 随 renderer session 消失，所有 Dock 默认关闭。

## 约束与注意事项

- webview 初始 URL 不应拼裸相对路径；统一通过 `buildServiceWebviewUrl()` 处理。
- 动态 path segment 必须通过共享 route codec 和 Agent-family route builder 解析、构造；不得在已编码的 Router 参数上再次调用 `encodeURIComponent`，也不得递归调用 `decodeURIComponent`。
- 需要认证的嵌入页不能直接读 Desktop secrets，必须走 bridge 申请 token。
- Help 网站必须允许匿名访问；若未来需要登录，应另行设计显式认证协议，不能让 Help partition
  隐式复用 SSO Cookie 或读取本地 JWT。
- Site 目录 bridge 只允许列举已有 Website/WebApp 的公开指针字段，不得扩展为返回认证、启动参数或文件系统路径。
- Agents、Archives、Automations、Memory、Registries 和 MCP Connectors 等管理页只使用 HTTP/SSE，不附加 `wsSource`；未来重新引入 `/ws` 时必须显式定义新的 surface 来源。
- `wsSource` 只在 `/ws` 建连时补充 `source` 与 `deviceId` 监控元数据；preload 不监听、解析或转发任何 WebSocket message。
- 本地网站应用只有 running 且存在 `webUrl` 时才进入可操作 surface。
- WebApp Bridge 的原生权限只属于当前本地 gateway page scope；`openMode`、WebView partition、Tunnel 发布和后端 token 都不能扩大 capability。
- `openMode` 仅决定 Desktop 渲染容器，不能作为运行时、权限、发布或智能体能力边界。
- route sync 默认服务非主聊天嵌入页；普通 surface 不拥有 guest 到 Desktop Router 的反向同步权。主聊天仅允许同步变化后的宿主展示参数，业务路由仍以 URL 为唯一接口；只有 active chat 的真实业务身份变化和 management 到有效 chat 的转换可以写外层 Router。另一个展示动作例外是侧边栏重复打开历史面板所用的 `openChatHistory`，两者都不得扩展为聊天加载、创建或 run 同步。
- WebView URL 调试叠层仅随当前主窗口会话的 Debug 解锁状态出现；重启后恢复隐藏。
- embedded CDP 的“已打开 Site”只表示 Site WebView 已挂载且登记的 guest 仍存活，不等同于
  Site 已配置、WebApp runtime 正在运行或内置 Browser/服务 WebView 在后台存在。
