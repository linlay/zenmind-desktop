# 前端嵌入与导航

## 文档定位

本文描述 Desktop 如何承载 Web surface，以及各类页面的导航所有权、存储隔离和能力边界。具体路由、IPC、消息名、菜单项、像素和组件状态以源码及测试为准。

## Surface 模型

Desktop 不把所有前端合并成一个静态站点，而是按来源和信任级别承载不同 surface：

| Surface | 内容来源 | 宿主职责 |
| --- | --- | --- |
| Service / Plugin | 服务健康状态提供的 `webUrl` | 生命周期关联、受限 preload、单页或独立入口 |
| Agent WebClient | host-managed 或服务前端 | Chat、管理页、Copilot、可信 realtime/WorkPanel bridge |
| Website | 用户或市场登记的远端 URL | SSO session、导航限制和多标签状态 |
| WebApp | Desktop 本机 loopback gateway | Manifest 生命周期、同源 bridge、workspace 或独立窗口 |
| Help | 品牌配置的公开站点 | 匿名、独立 partition、同源导航 |
| Browser / Work Panel | 用户或 Agent 打开的网页 | 标签生命周期、受限 CDP 与上下文菜单 |

`surfaceId` 是 Desktop 内部稳定、短小的运行实例身份，URL 不是身份。Main Chat、Copilot Chat、Kanban Chat 与 Browser 使用可读的根级 ID；Website、WebApp 以及 Chat 次级视图使用带领域前缀的稳定哈希 ID。持久化 entry key 和 Desktop route 不随运行时 ID 改名。

Surface 同时声明语义角色、`root / child / utility` 层级、可选父级和交互等级。Overview、Debug、BTW、Source、Planning、Artifact、Reference、File 等次级视图属于 owner Chat；父级关闭会回收仍挂在该父级下的 guest，但隐藏父级不等同于关闭。Detached Project 和无已登记页面上下文的 Copilot Dock 可以暂时没有父级。

固定根级 ID 是 `main-chat`、`copilot-chat`、`kanban-chat` 和 `browser`。动态实例使用领域前缀加稳定双 FNV/base36 哈希；Chat 次级模块为 Overview、Debug、BTW、Source、Project、Diff、Artifact、Reference、File、Planning、Agent、Copilot 与 Web。哈希输入来自模块稳定键，不得使用展示 URL 代替稳定键。

浏览器中的每个 URL 只拥有 `tabId`；Run、Office 等长任务使用自己的运行或操作身份；Pet 和普通原生窗口使用 consumer/window 身份。只有具有独立 guest 生命周期且需要被 Desktop 定位、诊断或控制的对象才登记 surface。Main 通过 renderer 登记的 guest WebContents、surface 类型、稳定内部键和父级关系判断页面是否真实存在，并拒绝不符合宿主策略的角色、ID 或权限组合。

## 宿主与生命周期

```text
配置或运行状态
  -> renderer 选择 surface host
  -> WebView / BrowserWindow 挂载 guest
  -> preload 登记 surface 与 tabs
  -> main 校验 guest 身份并提供受限能力
  -> 卸载时注销 surface、回收 guest 与临时存储
```

隐藏和关闭是不同状态：为了保留 Chat、Website、WebApp 或 Work Panel 的页面状态，非活动 surface 可以继续挂载；真正关闭时必须注销 registry、销毁 guest，并按所属策略清理临时 partition。关闭最后一个标签后不能留下指向已销毁 guest 的活动状态。

WebApp 的 workspace 与独立窗口只是两种渲染容器。切换容器可以复用同一 runtime 和 gateway，不能因此扩大页面权限或改变 Manifest 能力。

## 导航所有权

Desktop Router 决定当前工作区和 active surface。默认情况下，Desktop 可以导航 guest，普通 Service、Plugin、Website、WebApp 和 Browser 不能用自身导航反向改写 Desktop Router。

反向同步只开放给两类明确场景：

- 当前 active 的 Agent Chat 将新建会话收敛为稳定 Chat URL。
- Agent 管理页请求 Desktop 打开一个已经验证有效的 Chat。

非活动 Chat、临时 Kanban Chat、项目浮层、Copilot 和 Work Panel 不拥有外层路由。它们可以维护自己的页面历史，但不能发布为当前 Desktop 页面或抢占其他 surface 的导航状态。

动态路由参数只允许一次编码和一次解码。业务身份比较忽略宿主展示参数及查询参数顺序，避免主题、语言等变化重放 Chat 业务导航；未知或业务相关参数不能被静默丢弃。

## Partition 与认证边界

- Agent WebClient 使用专用持久 partition。Platform 数据请求与 Run 实时请求均可进入 `__AGENT_WEBCLIENT_PLATFORM_WS__` Frame Port；上传、下载、语音等显式 HTTP-only 请求仍由 Desktop host 在 main 注入和刷新凭据。guest 不接收 access token。Agent Platform `/ws`、query/attach 流和 Run control HTTP 入口在 host 层固定拒绝。
- Website 使用官网 SSO partition 获取 Cookie 会话；页面不能读取 Desktop token 文件。
- Help 使用独立匿名 partition，不复用 SSO Cookie，也不接入 Token Bridge。
- WebApp 页面只访问自己的 loopback gateway，并通过同源 `/__desktop` bridge 调用 Manifest 允许的能力；它不加载 Service WebView preload。
- 普通 Service 和 Plugin 使用各自宿主策略，不因为 URL 与 Website 相似而获得官网会话。
- 每个 WorkPanel Web item 使用独立临时 partition；关闭 item 后只清理该 guest 与 partition，Desktop 重启不恢复。

token、Cookie、文件系统路径和 Electron 对象只停留在 main。preload 只暴露结构化请求，renderer 和 guest 只接收完成当前工作流所需的结果。

## Bridge 与能力策略

不同 surface 使用不同 bridge，不能合并成通用远端页面 API：

- Service WebView bridge 处理宿主展示参数、受限路由、认证申请和明确的 Desktop 集成能力。
- Agent WebClient 的 Platform Frame Port 与 WorkPanel 使用固定全局 bridge。Main 根据真实 IPC sender、guest WebContents、origin、route、partition、surface 类型和 owner Chat 派生 capability；guest 自报的 surface、Chat 或 capability 不参与授权。WorkPanel 通过自己的 `getCapabilities()` 查询保留独立授权边界。
- Agent WebClient guest 的 surface 类型只从宿主持有的结构化 `surfaceRole` 映射；页面 route、查询参数、文件路径和展示 URL 不参与身份分类。File、Artifact、Reference、Source、Planning 等非 live 子 Surface 使用 management 数据能力，只能发送普通 Platform request/response，不能因此获得 Run lease。
- 固定 bridge 全局可见不表示 guest 已完成 Surface Registry 登记。可信 WebView 首次打开 Frame Port 而 target 尚未登记时，Main 最多等待 1500ms，并在登记完成后重新执行完整授权；不可信 session、错误 service/origin、已销毁 guest 或等待超时仍立即或最终 fail closed。等待期间不得访问 Agent Platform。
- Frame Port 原样承载 Platform `request/response/stream/push/error`，只改写外层关联 id。通过真实 sender、origin、partition 和 Surface Registry 校验的普通平台请求可在 mounted surface 上转发；query/attach/BTW 额外要求具有对应 live capability 且 surface active。新 query 的 canonical identity 来自关联 stream bootstrap event；`chat.created` 不用于猜测 query 归属。Platform stream 一帧对应 guest message 一帧。
- Main Chat、Copilot Chat 与 Kanban Chat 至多一个 active；宿主 active 状态通过专用 surface lifecycle 消息传入保持 mounted 的 guest。BTW 是唯一可交互的 WorkPanel 子 Surface：激活且归属于 Main Chat 时可发送 `/api/btw` 和恢复该 BTW 的 attach，但不能发送 `/api/query`。Overview、Debug、Source、Planning、Artifact、Reference、File 等子 Surface 不拥有 live Run capability，只做 replay 或文件读取。
- 同一 mounted guest 的 URL、owner Chat 或 registry 元数据刷新不等于 surface active 状态变化，不能重复发送 active lifecycle。只有真实的 active/inactive 转换或 guest replacement 才触发 WebClient replay/attach 恢复。
- WebApp bridge 由本机 gateway 提供，按页面 origin、运行中实例和 Manifest 能力再次校验。
- Website 与 Help 默认没有 Desktop 原生能力；需要系统浏览器打开的跨域链接由宿主处理。
- Embedded CDP 只操作 registry 中仍存活的 guest。普通公开 surface 默认只允许当前 active surface 成为命令目标。
- Chat Work Panel 是 Chat 私有的内部 CDP surface，不进入 Website、WebApp 或 Browser 的公开 surface 列表。

任何能力都不能仅凭调用方传入的 `surfaceId`、URL 或 target id 授权。Main 必须将请求与当前 renderer、guest WebContents、登记 generation、所属 surface 和活动页面快照交叉验证。

公开 Surface 查询只返回 canonical 短 ID。升级兼容期可以在 Desktop Web Action/CDP 输入端解析旧 ID，但不能为旧 ID 建立第二份登记，也不能把别名带入 Agent WebClient 的安全授权协议。

## WorkPanel

稳定 Chat 可以拥有一个运行期 workspace。item 是 `webclient`、`web` 或 `native` 的判别联合；当前交付承载 WebClient 和一 item 一 guest 的 Web 页面，Native registry 保持空 allowlist，并稳定拒绝未注册 surface。

AppShell 的唯一 reducer/command service 派生 item 稳定身份并拥有全部 workspace 状态。任何 item 创建或显示 workspace 前，AppShell 必须先确保 owner Chat 的 Overview 位于第一项；Overview 固定为 pinned、non-closable，产物、网页或其他 item 不能替换、重排或单独关闭它，只有关闭整个 workspace 才一并回收。Desktop 另持有不持久化、不进入 bridge contract 的 owner Chat 可见集合：`openItem`、`activateItem` 自动显示对应 workspace；右上角按钮只 hide/show，隐藏时 tabs、active item、guest 和宽度保留且 guest 全部 inactive；`closeWorkspace` 表示销毁并清理可见状态。切换 Chat 按各自状态恢复，不得串用 workspace。其他 pinned 或 non-closable item 同样不能由普通 close 删除。

WorkPanel 拥有键盘焦点时，Main 必须拦截 macOS `Cmd+W` 或 Windows `Ctrl+W`，并把命令交还给当前 WorkPanel：优先关闭 active closable item；active item 不可关闭时，继续关闭 workspace 中最后一个 closable item；不存在 closable item 时关闭整个 workspace（包含固定 Overview）。点击或用键盘聚焦 WorkPanel（包括 tab）即把它设为当前关闭快捷键目标；进入 `<webview>` 或因关闭 tab 发生的 DOM 焦点变化不释放该所有权，只有点击 WorkPanel 之外、隐藏或回收 workspace 时才释放。macOS 应用菜单的 `Command+W` 不得直接绑定原生 close role；它先把关闭请求交给 renderer 判定，只有 renderer 确认快捷键目标不属于 WorkPanel 后才能回调 Main 执行窗口默认关闭/隐藏。不能依据 URL 推断 guest 身份。

Main Chat 的 WorkPanel 入口由 Desktop 持有，只在 `/agent/:agentKey` 路由显示；稳定 `chatId` 产生前按钮禁用，首次点击以规范化 `/overview/:chatId` 创建 Overview item。WorkPanel WebClient descriptor 按 module 使用独立 context：BTW、Source、Planning、Artifact、Reference、File 与 Project 不再共享一个全可选对象；`module/context` 负责宿主识别和去重，`route` 只负责 WebClient 导航。Overview、Debug、BTW 把 `chatId` 放在路径中，Source 与 Planning 把各自资源身份放在路径中；Artifact 与 Reference 保留各自 module/context，但统一导航到 `/resource-viewer/:agentKey?chatId=...&file=...`。File 的 `context.path` 保留 Platform 可解析的原始请求路径，允许相对路径、POSIX/macOS 绝对路径、Windows 盘符路径和 UNC 路径，只做空值、长度、控制字符与分隔符规范化；稳定键使用规范化后的请求路径，因此绝对与相对别名可以形成不同 tab。Project 与 File Diff 的 path 仍必须是 workspace 相对路径并拒绝 `..`。Desktop 不再生成 `/artifact-view/:agentKey`、`/reference-view/:agentKey` 或旧的 Overview/Debug/BTW Agent 路径，也不提供兼容重定向。Web item 只接受无用户名密码的 HTTP(S) URL。

File、Artifact 与 Reference 都遵循“先打开宿主面板，再请求 Platform”：Standalone WebClient 打开自身 Sidebar，Desktop Bridge 打开 WorkPanel；File Surface 复用 Preview Panel 请求 `/api/file`，Artifact/Reference Surface 复用同一 Preview Panel 请求 `/api/resource`。Desktop 不读取 WebClient 的 `currentWorker.workspaceDir` 来预判 File 所属关系，也不复制 ChatScope、canonical path、symlink 或越界规则；Platform 是这些权限的唯一权威，拒绝结果在已经打开的面板内明确显示。

WorkPanel 外层 tab 的右键菜单由 Desktop 按可信 descriptor profile 生成：普通 Web tab 提供刷新与复制实际 URL，Artifact/Reference tab 分别保留来源语义，但都提供文件名复制、预览刷新和下载当前 Resource Viewer 文件；其他 WebClient tab 不暴露内部服务 URL。下载动作只通过版本化 host action 通知当前 Resource Viewer，实际目标解析、鉴权、文件名和下载仍由 WebClient/Platform 既有执行器负责，Desktop 不从 route 推断资源路径。所有 profile 共用全屏、关闭当前和关闭其他 tab；固定或 non-closable item 必须保留。

WorkPanel Web item 的普通主框架导航保留在当前外层 tab；popup、`target="_blank"`、`window.open()` 与右键“在新工作面板标签打开”统一由 Main 根据真实 `chat-work-panel` guest 标记为 WorkPanel 目标，再由 renderer 以来源 guest 所属 owner Chat 创建新的外层 Web item。该链路不得导航到 Desktop Browser 根路由，也不得在隐藏的 `ExternalWebviewPage` 内部 tab 栏创建不可见标签。网页加载期间，外层 tab 图标显示 loading，内容区顶部显示细进度条；完成、失败或 item 卸载后必须清除。

## 上下文菜单与页面交互

Main 为已登记 WebView 应用基于 surface 类型的固定菜单策略。Browser、Website、WebApp 与 Work Panel 可以在安全范围内导航或交给系统浏览器；Service、Help 和 Plugin 不能把原 guest 导航到任意外部来源。

可信 Agent WebClient 可以返回结构化语义目标，但不能提供任意菜单命令、脚本或认证数据。Main 在显示和执行阶段都重新校验 guest、origin、partition 与 target；超时或失效时退回安全的 Electron 菜单。

## 安全与平台约束

- WebView 禁用 Node 集成并启用上下文隔离；具体 sandbox 策略按宿主类型显式设置。
- 不可信跨 origin 导航、popup 和下载由 main 统一判断，不能由 guest 自行扩大允许列表。
- 调试 URL 必须脱敏 token、授权码和 secret，调试状态不能改变页面权限。
- 文件选择、屏幕捕获、麦克风和系统打开等原生能力在 macOS 与 Windows 分别处理权限和失败行为。
- renderer 热更新或 guest replacement 期间使用能力探测和 generation 校验，旧 guest 不能继续操作新 surface。

## 实现事实源

- `src/renderer/service-webview/ServiceWebviewSurface.tsx`：Service 与 Agent WebClient 宿主。
- `src/renderer/app-shell/embedded-surfaces/`：Website、WebApp、Browser 等 surface host。
- `src/main/browser-surface-registry.ts`：surface、guest 和 tab 登记。
- `src/main/webs/surface-runtime.ts`：公开 Web surface 控制。
- `src/shared/auth-bridge.ts`、`src/shared/service-webview-bridge.ts`：URL 与 bridge 契约。
- `src/renderer/work-panel/`、`src/shared/work-panel.ts`：异构 WorkPanel 宿主与唯一状态机。
