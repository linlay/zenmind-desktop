# 前端嵌入与导航

## 当前状态

Desktop 不再提供统一静态资源服务。内置服务、插件和本地网站应用都直接暴露自己的 `webUrl`，渲染层通过 webview 或内置 browser surface 打开。

服务前端模式来自归一化后的 service definition。内置服务通常来自 manifest `frontend.mode`，插件 manifest 使用 `service.ui`，最终都会归一化成 `frontendMode`。

- `none`：无前端，仅控制中心管理。
- `embedded`：详情页可打开前端，不进入顶部/侧边主导航。
- `standalone`：运行中进入导航，可作为独立 surface 打开。

## 核心流程

```text
service state healthMeta.webUrl
  -> buildPluginEmbeddedUrl()
  -> PluginPage webview
  -> service-webview preload bridge
  -> route / auth / settings / clipboard / screenshot messages
```

导航来源：

- 内置 routes 和 agent-webclient routes。
- running standalone service。
- `config/webs/order.json` 中的外部网站与本地网站应用排序。
- webapp running state 中的 `webUrl`。
- 内置 browser route。

service webview bridge 支持：

- route sync：`desktop:service-webview:route`。
- action channel：`desktop:service-webview:action`。
- clipboard、目录选择、打开路径、下载文件、截图、插件设置读写。
- agent-webclient access token 请求和响应。

## 配置与接口

`buildPluginEmbeddedUrl()` 对特定服务做嵌入 URL 归一化：

- `identity-center`：打开 `/admin/`。
- `agent-platform`：打开 `/monitor`，可附加 `access_token`。
- `agent-webclient`：根据 `embedPath` 打开嵌入路由，并附加 `hostTheme`、`lang`、`desktopAuthContext`、`wsSource`。

Web surface runtime 提供：

- `desktop.web.listSurfaces`
- `desktop.web.getActiveSurface`
- `desktop.web.activateSurface`
- `desktop.web.navigate`
- `desktop.web.openTab`
- `desktop.web.closeTab`
- `desktop.web.switchTab`

## 约束与注意事项

- webview 初始 URL 不应拼裸相对路径；统一通过 `buildPluginEmbeddedUrl()` 处理。
- 需要认证的嵌入页不能直接读 Desktop secrets，必须走 bridge 申请 token。
- 本地网站应用只有 running 且存在 `webUrl` 时才进入可操作 surface。
- route sync 保留 legacy channel 兼容，但新代码应使用 `desktop:*` channel。
