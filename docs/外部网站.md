# 外部网站

## 文档定位

本文描述 Desktop Website 入口的持久化、宿主和安全边界。记录字段、排序文件、favicon 缓存和页面 UI 以源码及测试为准。

## Website 模型

Website 是用户或市场登记的远端 HTTP(S) 入口，不包含本地程序包，也不由 Desktop 管理后端生命周期。Desktop 保存稳定 identity、显示信息、目标 URL 和少量宿主偏好。

Website 与 WebApp、Service 和 Browser 是不同资源：相同 URL 或相似界面不能让它们共享安装状态、原生能力或数据目录。

## 主要流程

```text
添加或导入 URL
  -> 校验协议、identity 与重复项
  -> 持久化 Website 记录
  -> 进入 Sites 排序
  -> 按需挂载 Website surface
  -> 注销或删除时回收页面状态
```

删除 Website 只删除 Desktop 入口、缓存图标和相关宿主偏好，不影响远端站点账号或数据。

公共 Desktop Action 的 Website 添加和更新只返回提交后的 `item`，删除只返回 `websiteId`；写动作不返回完整 Website 列表或本地化成功提示。显式 `website.list` 仍是获取集合快照的唯一 action。领域校验或重复项失败转换为公共错误，details 只保留输入 issues、请求 Website ID 或重复 Website ID。

## 宿主与认证

Website 与普通 WorkPanel Web 使用同一份 Electron 默认 session，以 Chromium Cookie 会话访问站点，但页面不能读取 Desktop token 文件。页面仅可通过专用 `auth` bridge 发起经原生确认的同源会话交换，不获得 token 读取或通用 Token Bridge 权限。认证恢复成功后只刷新实际挂载且属于该默认 session 的 Website 与普通 WorkPanel 网络页；关闭 WorkPanel item 不清理共享 Cookie。

Desktop Router 决定 active Website。页面内部导航默认不改写外层路由；跨 origin、popup 和系统协议由 main 根据安全策略交给系统浏览器或拒绝。Website 页面用 `window.open(blobUrl)` 或 `target="_blank"` 打开的 HTTP(S)-origin `blob:` 是来源绑定的运行期 popup：Main 校验 creator origin 和真实 opener guest 后，将它送回同一 Website surface，并由新标签继承来源 partition；Blob URL 不进入系统外部打开，也不能作为 Website 配置或公共打开输入。

Website 可以保存自己的多标签页面状态和 Copilot 偏好，但这些偏好不扩大页面权限，也不证明页面当前已打开。

当前 Website 的 macOS `Cmd+W` / Windows `Ctrl+W` 每次关闭当前 tab，沿用标签关闭事务选择相邻存活 tab；焦点位于网页或主 renderer 时都支持连续关闭。快捷键只更新当前实例，后台 Website 与 WorkPanel 不受影响。最后一个 tab 关闭时回收整个 Website 实例并退出该页面，不在同一次命令继续关闭主窗口；持久 Website 入口保留。

Website 切到后台仍保留已挂载实例及 tab。合法 Copilot Run 绑定该实例后可发现和控制现存及后续新增 tab，不随前台路由变化。popup 必须按真实 sourceGuestId 精确投递到所属 Website，包括后台新 tab 再打开后续 tab；未知来源不得回退到前台 Website。新 tab 只更新所属 Website 内部选择，不发布为 Desktop 当前页面。关闭 tab 回收 guest，关闭整个实例后旧 Run 授权永久失效；重开同名 Website 是新实例。

## AWCP 外挂

对没有原生 AWCP 的网站，Desktop 按用户安装的网站桥包注入页面适配器。设置中的「网站桥」独立管理 ZIP 导入、更新、导出、启停、卸载和页面脚本查看，不改变 Website 入口或 WebApp 安装状态。管理 IPC 只允许主窗口主 frame 调用，网页和 Agent 不能安装脚本。

一个网站桥是一个 ZIP 包，包结构固定为清单、`pages/` 下的页面脚本和 `shared/` 下被页面引用的共享模块。**域名只在清单顶层声明一次**：清单把稳定的域名标识映射到精确 origin，一个包可以声明多个 origin（例如同一业务的多个站点或子域）；页面规则、动作参数、手册与返回结果一律使用域名标识加根相对路径，脚本中不出现域名。切换环境只改这一处映射，页面规则与脚本原样复用。跨域目标表示为“域名标识＋相对路径”，由宿主注入的解析函数按清单转换；宿主不允许相对路径落到声明之外的 origin。**一个 origin 是一套站点系统**：清单可为它声明名称与实现说明，手册目录据此提示调用者不同 origin 的人员选择、附件等实现彼此独立。

**一个页面一个脚本**，页面选择分两步。宿主 Main 先按顶层 origin 与 pathname 选出最具体的 URL 形状下的全部候选页面：忽略 query/hash，支持整段路径参数，静态路径优先；请求 API 地址不参与匹配，不支持子域通配。页面运行时再按候选页面声明的识别条件选定一页：条件只有 hash 参数、`document.title` 与可见元素自身文字三种，全部精确相等，元素自身或任一祖先隐藏、inert、aria-hidden 或完全透明时文字不参与识别；一条规则内条件全部满足、任一规则命中即算命中。恰好一个候选命中时加载该页；无命中或多页同时命中时，使用同一 URL 形状下唯一不带条件的页面，没有则不提供业务动作。条件不做包含或前后缀匹配、不接受选择器或字段指纹，避免用户填写的内容参与识别。hash 导航与每次读取手册都会重新识别；所选页面变化时，旧页面的在途请求被取消、脚本与模块实例被回收，再加载新页面。

页面按声明顺序加载 `shared/` 模块，再加载页面脚本；模块返回工具对象而非动作，后加载的模块和页面脚本可使用先前模块，同一次选页内共享这些实例与页面内状态，换页后重新创建。根目录模块与站点系统无关；`<域名标识>/` 下的模块属于该系统，只能被该 origin 的页面引用，宿主在导入时校验。版本只记录在清单，脚本与文件名不各自维护版本。

AWCP 协议由 Desktop 的页面运行时实现，包内脚本只声明业务动作：运行时把所选页面脚本的动作作为唯一的 AWCP 入口，生成手册目录，负责信封与参数 Schema 校验、重复 requestId 防护、超时、取消，以及页面切换时的回收。AWCP v1 手册目录没有页面字段，当前页面名称、识别依据、未识别或歧义状态写入站点说明。注入时选中的页面脚本或模块不合约、返回 Promise 或初始化异常时，整页不安装，不留下部分能力；之后换页加载失败或页面声明了不合约的动作时，回收该页的脚本、模块与监听器，只在站点说明中报告，在所选页面变化前不重复加载。没有无条件兜底页时，进入无匹配或歧义状态也视为离开失败页，清除旧失败记录；再次唯一命中时允许重新加载。页面脚本可以从当前可见界面派生动作，手册 revision 跟随所选页面与其声明内容变化。

首装只安装 env.zip 显式携带的网站桥 seed，Desktop 自身不内置任何站点的桥；卸载后不会在下次启动自动恢复。具体包结构及作者约定见 [网站桥包示例](../qa/website-bridge-package.md)，校验与执行事实源为 `src/shared/website-bridge.ts` 和 `src/main/modules/web-surfaces/website-bridges/`。

环境打包通过 `.include.json` 的 `web-bridges-center` 选择源码包，与 `skills-center` 一样放在环境根的同名目录，并生成 `desktop-init.json` 的 `websiteBridges.items`。该目录只被读取，不随初始化删除；Desktop 自己的安装副本与启用状态仍在 Desktop 数据目录。Desktop 与 Website 一样仅在首次初始化安装，安装前整体校验身份、origin 冲突、路径、大小和脚本语法；已有清单（含空清单）及后续初始化均保留用户状态。macOS 与 Windows 通过各自用户目录解析同一包结构。桥 seed 不创建 Website 入口，也不写服务配置。

Main 验证 ZIP 的路径、大小、重复文件、符号链接和脚本语法，只保存包、不执行包内业务代码。包资源与启用目录分别持久化，每个包以稳定且唯一的 manifest ID 定位固定安装目录，内容哈希仅用于完整性校验与提交判定。更新先完整暂存新包，将旧目录移至备份，再将新包移入 ID 目录，最后原子提交安装清单；失败恢复旧包及启用状态。进程中断后以清单中的哈希选择已提交的新包或恢复备份。macOS 与 Windows 均通过移走旧目录后向空缺路径重命名，避免依赖覆盖非空目录的行为。只读取固定 ID 目录，不提供旧哈希子目录的兼容加载或自动迁移。两个包只要声明了任一相同 origin 就不能同时启用。变更立即重新匹配已登记 guest；损坏的持久配置拒绝加载，不自动覆盖。唯一的例外是可识别的旧清单格式安装包：它不被执行或迁移，只在内容与安装清单提交的摘要一致时在列表中标记为需要更新并保留启用状态；摘要不符的旧包或残留备份不会被采用，更不会覆盖已提交的安装目录，用户导入同 ID 的新版包后恢复，其余包不受影响。

Website 与普通 WorkPanel 网页在可信登记后，由 Main 在顶层 guest 的 main world 安装适配器，刷新和同文档导航重新匹配；注销、关闭和离开规则范围会回收适配器与在途请求。首次授权 AWCP 请求也会执行幂等安装，避免登记与加载时序造成假缺失。已有原生 AWCP 不被覆盖。注入机制在 macOS/Windows 共用 Chromium 页面执行与 Cookie 语义，不依赖平台路径或本地 Node 能力。

Chrome 复用同一网站桥包和启用目录，由 Main 为获授权的精确页面编译脚本，受控 Playwright Worker 在首个 AWCP 请求时按需安装；不会遍历或注入用户其他标签。Chrome 页面继续使用该 Chrome profile 的原 Cookie 会话，与 Electron guest 的 Cookie 不互相复制。桥包变更同时撤销 Chrome 中的旧手册绑定并回收自定义注入，具体调用与取消边界见[浏览器自动化](浏览器自动化.md#chrome-awcp-与标准操作)。

写操作的约定由各桥遵守：只触发网站原生控件，由网站自己处理表单校验、鉴权、CSRF、网络提交与导航；填写与提交分开，提交前比对实际表单，内容变化要求重新核对。读取使用当前 guest 的同源 Cookie 会话，不读取 Cookie 值、不注入 Desktop token、不提供任意 URL 请求代理。submitted 只表示提交事件已派发，不能代替服务端成功；写入不自动刷新网页，不自动重试，超时或取消不代表服务端回滚。

自定义脚本只在所匹配网页的上下文运行，拥有该网页本身的权限，不获得 Node 或通用 Desktop IPC。脚本作者负责在清理回调或 AbortSignal 中回收自己的监听器与在途操作；运行时保证协议层的取消应答，但无法替任意自定义代码保证业务取消或重试语义。

Agent 继续通过 `desktop_cdp` 的 `AWCP.getManual` / `AWCP.invoke` 使用能力，遵守既有 Run、精确 Surface、revision 和已读章节门禁。安装适配器本身不产生页面控制授权，也不扩大跨 Chat、文件预览或原生 Desktop 能力。

## 安全约束

- 只接受明确允许的 HTTP(S) URL，拒绝本地文件和脚本协议。
- `blob:` 只允许来自已登记 Website guest 的同来源 popup，不持久化、不跨 partition 转发，也不根据 URL 猜测 opener。
- Website 不获得文件系统、进程、密钥或任意 Desktop Action 能力。
- surface 是否存在由真实 guest 登记决定，不根据配置 URL 猜测。
- favicon 和页面标题是不可信远端数据，需要限制类型、大小和展示方式。
- 不把认证查询参数、Cookie 或本机路径写入记录和日志。

## 网页身份与操作

Container 持有网页宿主与标签集合，每个可操作网页实例拥有独立 Surface 身份。普通 Chat 打开网址默认进入 WorkPanel，Website/WebApp Copilot 沿用所属容器；网页发现与操作共用来源授权，不因承载位置或前后台状态切换模型。本地文件预览与 WebApp bridge 权限不随之扩展。完整模型见[前端嵌入与导航](前端嵌入与导航.md#网页-container-与-surface)，动作与 CDP 边界见[桌面协议与动作桥](桌面协议与动作桥.md#网页-container-与-surface)。
