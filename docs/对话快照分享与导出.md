# 对话快照分享与导出

## 通用分享契约与实施阶段

通用分享以每次创建的 shareId 为内容、私有资源及撤销的独立单位。同一来源再次发布重新冻结内容；预览、资源读取、Desktop 交接和已接入在线服务只选择该 ID 的行为，不创建其他入口对象。来源业务拥有内容准备、业务版本及上下文；公共分享模块拥有发布、管理和精确接收方分派，身份和导航继续归 Identity、Shell。业务上下文不成为任意 Desktop Action，也不启动安装恢复或后台续接。

精确字段以 `src/shared/contracts/shares.ts`、`src/main/modules/shares/http-contract.ts` 及对应测试为准。Hub 提供永久生命周期、通用 HTTP、隔离预览和已有 WebApp 发布绑定；Desktop 提供公共发布、管理、匿名解析、精确注册、品牌入口和有界交接。市场、插件及 WebApp 通过各自所有者注册和校验，不在公共分派器中增加业务分支。迁移必须先使旧非永久记录失效，再删除相关字段；旧永久分享保留。旧 wire 固定值仅留在适配器，新模型没有到期或一次性状态。

显式的业务预览包只在可信外层的 opaque sandbox iframe 中执行，包内相对资源均经同一 shareId 的清单、撤销和 Hash 检查。外层精确的 frame-src 限制包内自导航，包资源拒绝顶层文档及非支持的 Fetch Metadata 目的地，脚本不能接触主页面、身份、Desktop preload 或任意网络。外层不处理包 postMessage；品牌接收入口由可信外层生成。普通对话 HTML 附件仍采用原清洗和禁脚本策略，本地 HTML 导出继续归 Worker，不能与显式可执行包混用。

## 职责边界

Agent Platform 负责从一致读取生成 `ConversationSnapshotV1`。`.tools/artifacts.json` 是分享资源的唯一清单；快照导出逐条筛选规范的 `artifacts/<runId>/<file>` manifest 记录，映射为名称、MIME、大小和 SHA-256 描述，不读取附件正文。清单损坏或单条记录无效只会让相关附件缺席，不阻断对话正文。实际文件的普通文件、大小和 Hash 校验由 `chatresource` 在专用 Artifact Read 时统一执行。Platform 不加载模板、不生成分享 HTML，也不理解分享生命周期。

Agent WebClient 维护唯一的只读渲染实现。分享渲染包独立构建，包含模板、manifest、JS、CSS 和字体，由显式发布命令整体替换 Tunnel 当前资源；普通 WebClient Program Bundle 不携带该渲染包。

Desktop 负责鉴权和编排。点击分享入口只在主对话列打开紧凑的选择弹窗，遮罩与轻提示也限制在主对话列，不创建链接；用户选择复制链接、生成二维码或浏览器打开时，常驻 Worker 才从 Platform 读取 Snapshot，再逐个通过 `POST /api/chat/artifacts/read` 按 `chatId + sourceRef` 冻结可用产物；单个附件不可用时省略，并把 Snapshot 附件数组重写为实际冻结结果。同一 Worker 将冻结 Snapshot 和附件描述包成通用信封，Main 以一个 multipart 请求上传已准备的 manifest 字节与相同的资源，新建链接固定永久有效。异步期间选择弹窗保留，当前操作按钮和轻提示显示进度；完整操作成功后选择弹窗关闭，二维码成功时另行打开独立的可关闭弹窗，不显示原始链接。二维码弹窗支持把 PNG 拷贝到剪贴板，或复用 Desktop 下载能力保存到下载文件夹。任一步操作失败时保留选择弹窗，重试复用本次已创建的链接；重新打开选择弹窗则是新的分享会话。若 Worker 实际省略附件，链接创建成功后显示简短警告，401/403 使用现有附件身份提示。独立的分享管理页按当前账号读取全部有效分享元数据，显示冻结标题、类型、创建和访问时间，并提供复制和直接撤销操作。列表不读取本机 Chat 历史；仅明确的 conversation 来源在用户点击时尝试原业务定位，来源不存在不影响分享管理。Desktop 不下载模板、不生成公开分享 HTML；本地 HTML 导出仍由同一 Worker 读取 Snapshot 和 Tunnel 当前模板后组装文件。

二维码 PNG 以对话名称命名，沿用 Desktop 下载路径的非法字符替换与同名避让。拷贝时优先使用浏览器图片剪贴板，失败后调用 Electron 系统剪贴板接口。

二维码中央使用当前 Desktop 品牌生成的应用图标，并以高纠错级别编码；图标绘入二维码 Canvas，拷贝和保存的 PNG 与界面展示一致。

Tunnel 是分享数据与生命周期的事实源。它在数据库保存 Snapshot JSON、分享关系和资源元数据，在 `CONVERSATION_SHARE_RESOURCE_DIR/shares/<shareId>/resources/<resourceId>` 保存实际字节。上传先流式写入同文件系统的 `.staging`，完整校验后原子移动，再提交数据库事务；数据库不保存文件正文或任意文件路径。匿名访问 `/share/{id}` 时使用当前唯一模板生成 HTML。

```text
公开分享：Platform manifest/正式产物 -> Snapshot -> Desktop Worker -> Tunnel staging/持久化目录 -> 当前模板 -> HTML
本地导出：Platform Snapshot -> Desktop Worker <- Tunnel 当前模板 -> 本地 HTML
```

renderer 只接收文件结果和分享元数据，不接收 Platform/Tunnel token、Snapshot 或 HTML 字节。

## 协议与语义

`/api/chat/export?format=snapshot` 返回 `ConversationSnapshotV1`。来源业务在现有 Worker 中准备通用分享信封，正文只序列化一次；manifest 完整预算包含信封、Snapshot 和两处附件描述，超额只从尾部同时移除描述和对应字节，不截断正文。读取旧 V1 时缺少可选大小或 Hash 的附件仍由 Worker 从实际字节补齐。

Main 公共 shares 模块使用 v2 管理接口，复用可信 origin 派生、Node fetch、UTF-8/响应大小和时间校验、超时及禁止重定向策略。发布、列表、撤销直接使用 Identity 已有状态、凭据就绪、恢复/刷新入口，不从 renderer 接受身份或目标 URL，也不建立认证缓存。401 明确拒绝只刷新重试一次；创建响应丢失返回失败，不后台重发。准备、请求及返回阶段校验当前身份，撤销监听在本次操作结束释放。公开 resolve 不发送 bearer 或 Cookie，也不要求 Tunnel 已开启。

旧发布 Desktop 继续通过 Hub 的 v1 适配器；Desktop 的旧 wire client 只作为兼容边界保留，其网络传输与 v2 共用实现，退休字段不再进入 shared 通用模型或 UI。旧 Assistant 列表/撤销方法转发同一公共 Facade。公共管理 IPC 和对话创建均限定当前 MainWindow 的主 frame，异步返回前再次确认；管理页和分享会话随 Identity 主体变更重新挂载，迟到结果不进入新页面。公开 renderer 不得上传任意信封或自报来源业务。

选择弹窗不读取或撤销历史记录；复制和撤销已有链接仍由分享管理页承担。新 Hub 迁移先撤销历史有限期和一次性记录，再删除相关数据库字段及 claims 表。旧永久分享保持原 ID、内容与资源；旧 HTTP 适配器仅返回 expiresAt=null、singleUse=false。公开读取不创建领取 Cookie，HEAD 不更新访问时间。

浏览器与 Desktop 的本地 HTML 导出从 `CONVERSATION_EXPORT_ASSET_ORIGIN/assets/conversation-export/conversation.template.html` 获取当前模板。模板失败不得回退远程地址或生成部分文件。

公开页的 HTML 附件直接加载预览地址。Tunnel 的附件错误页只允许同源 iframe 展示；普通分享错误页仍禁止嵌入，成功预览继续使用独立 sandbox 和严格 CSP。

## Worker 与安全

- Worker 必须是仅依赖 Node 内置模块的自包含产物；不得经领域模块入口间接引入 Electron 主进程运行时。URL 校验等纯策略由基础设施层共享，打包回归需在没有开发依赖的目录中实际启动 Worker。
- Worker FIFO 串行读取 Snapshot；公开分享任务不请求模板，本地 HTML 任务并行请求 Snapshot 和模板。
- Snapshot 请求只接受可信 Platform 回环地址，带短期 bearer token，禁止重定向；模板只接受配置的 Tunnel asset origin，禁止重定向。
- Desktop 模式下，带 app scope、device claim 和非空本地主体的宿主 token 只能通过严格的 `POST /api/chat/artifacts/read` 按 `sourceRef` 跨 owner 读取 manifest 已发布文件；`list/get`、`artifactId` read、Standalone 和通用 `/api/resource` 仍沿用原 owner 边界。
- Worker 按 Platform 响应头读取 Snapshot，附件使用 Tunnel 的独立预算，共用 15 秒期限；模板在 HTTP 读取处执行 256 KiB 保护。HTML 没有独立业务上限，组装与保存不重复检查大小，保留现有安全转义与分配失败提示。Worker 严格检查正文；可选附件在状态、Content-Type、声明长度、实际长度或 SHA-256 不一致时省略。
- 本地 HTML 拼接对 `<`、`>`、`&`、U+2028 和 U+2029 做 JSON Unicode 转义；Tunnel 服务端渲染执行同等安全转义。
- Main 以 transfer list 接收 `ArrayBuffer`，公开分享直接上传 Worker 已准备的信封字节与已校验附件，本地导出按字节写盘。
- token 不得进入 renderer、URL、日志或错误文本。

## 发布与迁移

分享渲染器随 Tunnel 二进制原子发布。普通 WebClient 发布不会改变分享页面；更新分享渲染器必须显式构建、同步、测试并重新构建 Tunnel。已被历史 HTML 引用的哈希资源继续保留；发布顺序为先部署兼容新旧 V1 的渲染器，再部署 Platform 和 Desktop。

旧 BLOB 库迁移时先停止 Tunnel 并备份数据库和资源目录。启动迁移逐条校验旧正文的大小和 SHA-256，经 staging 原子写入分享资源目录，再在事务中复制元数据、删除旧 BLOB 表并升级 SQLite schema 版本；迁移可安全重跑。运行时只读文件目录，不保留 BLOB 回退。

撤销先使数据库记录不可访问，再删除目录；启动及每小时清理仅回收已撤销资源和失败上传孤儿。文件或元数据删除失败保留可重试状态，永久分享不会按时间回收。升级前必须保留原库及资源目录备份，新 schema 不能直接交旧 Hub 运行。

## 验收

验证打开操作栏不创建链接，三项操作按需上传，失败重试复用已创建链接；创建请求上传的 Snapshot 附件声明与实际冻结附件完全一致，正文在附件失效时仍可分享，快照来源明确且为永久分享。账号级列表不携带查询参数，返回当前所有者的通用冻结元数据；对话和非对话记录、缺失本机来源均可管理。管理页直接撤销；旧非永久记录已失效、永久内容与资源保持且不设置领取 Cookie，公开页面直接请求附件预览。更新分享渲染包后分享统一使用当前模板展示。覆盖 `</script>`、`<`、`&`、U+2028/U+2029，并确认三端 test/build 通过。
