# 市场系统

## 文档定位

本文描述 Desktop 市场的目录、下载、安装和本地记录边界。Catalog 字段、接口路径、缓存文件和 UI 细节以源码、远端 contract 及测试为准。

## 系统边界

市场 Server 提供可浏览的 catalog 和下载元数据；Desktop 负责本机筛选、缓存、下载验证、安装编排和安装记录。Catalog 不是本机已安装状态，安装记录也不能反向成为远端商品事实源。

市场覆盖插件、Skill、Agent、桌宠、Sandbox Image、CLI Tool、MCP、Website/WebApp 和 Software Package 等资源。每种资源由专用安装器处理，不能用一个通用解压流程跳过领域校验。

## 主要流程

```text
加载 catalog
  -> 按品牌、平台与能力过滤
  -> 用户选择资源
  -> 使用 Desktop SSO access token 调用 auth/me 验证登录态
  -> 使用 Desktop SSO access token 调用 resolve
  -> 校验目标 Desktop 版本、依赖和平台
  -> 使用同一授权调用标准 download 端点
  -> 下载到临时缓存
  -> 校验类型、identity、版本、摘要和包结构
  -> 调用领域安装器
  -> 成功后提交本地安装记录
```

Catalog 用于展示，不是安装授权。安装时必须以 Server 的 `resolve` 响应为准，并从对应资源类型的标准 `download` 端点下载；资源元数据中的直链不能绕过授权。下载和安装是两个事务。下载成功不表示安装成功；安装失败时保留可诊断结果，但不能写入虚假的 installed 状态。

市场目录、详情与下载权限统一由市场 Server 根据当前市场 SSO 身份判断，Desktop 不解析人员名单、不传入自定义 userId，也不使用连接器的实例授权身份代替市场用户。未登录时目录和技能说明允许匿名请求，仅展示服务端返回的公开内容，不触发登录或换票；已登录时向已配置的市场 API 携带同一 SSO Bearer token，先验证身份并在 401 时单次刷新，再读取当前用户可见资源。所有资源类型共用此入口，包括技能、连接器、MCP、CLI 和网站应用。目录与详情禁止 HTTP 缓存，不保存跨账号私有目录；身份变化时丢弃在途旧响应并重建页面状态。认证失败不得复用上个账号结果或静默冒充完整的个人目录。收藏仅叠加在当前可见目录上，不授予可见性；安装仍通过 resolve/download 再次校验权限。匿名请求不携带 Cookie、Authorization 或设备身份；凭据仅发送给配置的市场 API，不能附加到任意 catalog 外链。

Skill 页的“创建技能”是对话预填入口，不是安装或写入动作。Desktop 只读取已配置的默认 Chat Agent，打开带 13 位 `newChat` 标记的新 Agent WebClient 路由，并附带受控的一次性 `composerDraft` 与 `composerSkill=skill-creator`；它不得在 renderer 中直接创建 Run。参数名声明能力类型，参数值声明具体选择，后续同类入口可使用独立的 `composerPlugin` 等字段。WebClient 将参数转换成可编辑草稿和选中 Skill 后立即从 URL 移除，用户真正发送后才进入 Agent 流程。创建流程必须触发已安装的 `skill-creator`，先展示目标目录和完整文件预览并校验，得到确认后才写入 `skills-center`。写入后由 Platform watcher 刷新后续 Run 的 Skill catalog；返回或刷新市场时应能在“我安装的”中发现该本地 Skill。该流程不上传、不发布市场条目。

## 数据分层

技能浏览页只使用市场接口的精选标记（商品级 `featured` 规范化为 `skillFeatured`，仅布尔值 true 生效；不回退到旧版本的 `skill.featured`，避免取消精选后被旧标记重新选入），每次最多展示三个精选项，并支持换一换；缺少精选数据时隐藏整栏（标题、换一换和占位区域），不使用下载量补选。技能与技能包共用卡片尺寸，头像使用市场图标元数据，普通技能详情按当前市场身份读取技能原文，技能包详情展示具体子技能。“使用技能提问”只通过既有 Composer 预填协议选择一个已安装的具体技能，不自动发送，也不把技能包标识作为可执行技能。

“我安装的”使用独立的 URL 视图，统一展示本地导入和云端安装的技能。图钉偏好经受限 Desktop IPC 交给 Platform 按已验证用户主体保存，与 WebClient 共用同一份技能顺序。Desktop 使用单项置顶/取消置顶操作，不整表覆盖其他客户端的修改。技能包操作展开为具体子技能，全部子技能均已置顶时才将包卡片显示为置顶，不保存包 ID 作为可执行技能键。Platform 仅重排原有可用集合，WebClient 每次打开技能菜单读取最新顺序，置顶不增加技能或执行权限。旧市场本地置顶迁移一次；同步失败必须提示，不能假装已同步。批量卸载先展示确认清单，再逐项调用现有卸载入口，失败项保留以便重试。页面不引入技能全局启用或停用状态。

连接器浏览页消费市场正式 `connector` 类型的公共 catalog，保留后端发布的名称、描述、能力元数据和平台制品，通过独立的 `connectors` section 返回目录与加载状态。旧 `mcp` 安装记录不能补成云端连接器卡片，CLI 能力也不能改变商品的 `connector` 类型。macOS 连接器按 darwin 平台家族允许安装：优先精确架构和 universal，否则选择以 darwin 开头的可安装制品，并保留原平台键用于 resolve/download。此放宽仅适用于连接器分发，不改变插件等安装器的架构校验，也不保证原生二进制跨架构可执行。没有当前系统制品的商品仍可浏览详情，但必须显示平台不可用。

连接器遵循《智能体连接器规范 1.0-draft · 2026-09-09》。Desktop 市场拥有目录、下载、原生交互和受限 IPC；Platform 独占包校验、版本安装、当前实例授权、启停、调用门禁和解绑清理。市场下载仍走 SSO 验证、resolve、摘要验证，再把原始 ZIP 交给 Platform。自定义远程 MCP 只生成固定清单 ZIP；本地包只从原生文件选择器导入。两种入口都不直接写服务配置，也不自动把安装视为授权成功。

卡片“连接并启用”依次准备、检查授权、按清单取得授权、确认状态并启用；取消或页面离开时精确取消本次会话，迟到响应不能继续启用。每个连接器的绑定和启用由当前 Platform 实例统一管理，不随 Desktop 登录账号切换：停用保留凭据，解绑阻止新调用并使旧授权事务失效，清理本地凭据但保留安装程序。没有独立校验方式的凭据 CLI 显示“已配置，待验证”。权限不足和网络故障不能统一显示为需要重新登录。

授权入口由 Platform 的当前会话提供；Desktop main 再次验证主窗口或可信 WebClient 来源、会话身份和地址策略，使用独立临时授权窗口，不暴露 Desktop 登录材料。凭据表单仅向 Platform 提交，不写入包、市场记录或日志。详情页“去试试”还须确认目标 Agent 已挂载且运行状态生效，再创建可编辑的新对话草稿，不自动发送业务请求。旧 MCP 专用协议只兼容存量记录，不能处理 Connector ZIP。

- Catalog 缓存可以过期和重建，不是用户数据。
- 下载缓存只保存可验证的临时包，并受容量和清理策略约束。
- 安装记录描述本机成功安装的资源身份与来源，不代替实际领域 store。
- 用户设置、插件数据、WebApp 数据和 Agent Platform 资源继续存放在各自领域目录。

## 安装边界

- 插件、WebApp 和 Website 进入 Desktop 自己的事务安装入口。
- Agent、Skill、Tool、Team 和 Registry 等平台资源遵循 Agent Platform 的运行目录 contract；Desktop 市场只允许把已校验的 MCP YAML 原子写入 `registries/mcp-servers`，不得修改其他 Registry 分类。
- Sandbox Image 交给容器领域导入，Desktop 不解析镜像内部业务。
- 桌宠资产通过桌宠包校验和安装逻辑处理。
- Software Package 安装到 Desktop 管理的程序目录，按 `id/version` 隔离版本，并在完整校验与解压成功后原子更新当前版本指针；失败时恢复原版本。
- MCP 市场制品一期只接受后端固定的 `market + 唯一 mcpServers` JSON，Server 只能声明 `type: streamable-http` 和 `url`。Desktop 转换为受控 Registry YAML 后，以文件方式原子写入 Agent Platform runtime 的 `registries/mcp-servers`。需要当前登录身份的 gateway MCP 写入 `authSource: identity-file`，由 Platform 按请求从 Desktop 启动时通过 `--identity-file` 提供的文件读取 token，不能把 token 或本机路径写入 YAML。运行中的 Agent Platform 由自己的文件 watcher 热重载，未运行时在下次启动加载；Desktop 不调用 Platform 管理 API。市场不得下发或执行 stdio 命令。
- Skill 市场制品只接受 ZIP。普通单 Skill 由 Desktop 负责商品身份、目标平台、下载摘要和分发安全，在技能中心之外准备完整 ZIP 后交给 Platform 管理接口发布；Desktop 不直接重命名或覆盖 `skills-center` 中的正式目录。`SKILL.md`、frontmatter、Skill Key、运行环境与提示词限制由 Agent Platform Catalog 校验。技能包由 Desktop 完成 Market 鉴权、resolve、下载与传输大小控制后，将原始 ZIP 交给 Agent Platform，Desktop 不解析包内 manifest、不落子技能，也不复制 Platform 的 Skill 业务规则。
- WebApp 市场一期只安装 `websiteKind: local-app` 的 ZIP 制品；外部网址继续由 Website 领域管理。Tooling 不为 Market 验包额外生成 Manifest。Desktop 使用现有 `auth/me -> resolve -> download` 链路校验商品身份、平台、摘要和 ZIP 安全，再复用 WebApp v2 标准安装事务读取 `webapp.json`、启动 Gateway 并提交本地记录。
- 普通 Skill 使用与当前 Desktop 匹配的 `targets` 项或 `universal` 单 ZIP 制品；旧数据中的 `skill.kind: single` 按普通 Skill 处理。只有 `skill.kind: package` 进入技能包链路：它不要求 catalog `assets`，Desktop 使用 Market 的 `/skills/<id>/package/download` 动态包，并通过受控的 Agent Platform 管理接口交付原始 ZIP。Platform 在隐藏 staging 中校验 `manifest.json` 和必选子技能，以同一事务安装或更新全部子技能；任一步或 Catalog 重载失败都恢复旧子技能与旧包状态。
- 技能包 ZIP 只作为请求期间的临时输入，成功或失败后都删除。持久化内容只有普通的 `skills-center/<skill-id>/` 子技能目录和 Platform 管理的 `skills-center/.package/<package-id>.json` 包状态；`.package` 不参与 Skill Catalog 扫描。Desktop 的市场记录只保存技能包商品的安装状态，不保存子技能列表。
- MCP 市场安装只写入 Registry 并触发工具同步，不在下载时选择 Agent。MCP Registry 只负责连接、鉴权和同步；Agent 是否使用某个 MCP，由 Agent 自己的 `toolConfig.mcp-servers` 正向声明。Desktop 不修改 Agent YAML，也不把逐个工具名写入 Registry。Platform 在后续新 Run 中加载 Agent 所选 Server 当前同步成功的工具，已有 Run 不因热同步自动扩权。
- Market MCP JSON 不得携带 `command`、`args`、`env`、静态 `authToken` 或认证请求头。MCP 工具与 Platform 本地工具重名时不得借绑定关系扩大本地工具权限。

更新和卸载同样调用领域能力，市场层不能直接删除程序目录、用户数据或运行进程。
普通 Skill 的目录提交由 Platform 的监听保护与可回滚事务负责，Desktop 在远端确认成功后更新市场安装记录。Desktop 保留变更前的恢复包，市场记录写入失败时通过同一 Platform 接口补偿恢复；补偿失败或请求结果不确定时明确报错并保留恢复包，不直接修改正式目录。该跨进程过程不是分布式原子事务，禁止将不确定结果标记为成功。MCP 的文件变更与安装记录继续遵循各自领域安装事务。技能包的子技能与 `.package` 状态由 Agent Platform 自己的事务提交，Desktop 不参与该文件事务。

Skill 版本比较遵循 Semantic Versioning 2.0.0。已安装版本低于云端版本时，云端条目重新进入可更新列表；更新仍走 `resolve -> download -> 校验 -> 领域安装器`，不能覆盖式修改当前稳定副本。

## 可靠性与安全

- 网络失败时可以展示最近一次有效 catalog，但不能用部分响应覆盖完整缓存。
- 下载必须限制大小、协议、重定向和文件类型，并在安装前验证摘要与包结构。
- 临时目录和缓存路径必须位于 Desktop 管理根，不能接受远端提供的任意绝对路径。
- 远端文案、图标和元数据不获得本地执行权限。
- MCP 文件安装不能覆盖缺少市场安装记录的同名 Registry 文件；更新失败时必须恢复原文件。
- token、下载授权和本机路径不进入 renderer 日志或持久 catalog。
- 市场授权只复用 Desktop SSO access token；401 时允许在 main process 刷新一次后重试，不向 renderer 暴露 token。远端 gateway MCP 需要同一身份时必须通过受控 `authSource` 获取，不能依赖 Platform 进程环境或持久化 token 副本。

市场 API 基地址由品牌环境和用户设置提供，必须使用 HTTPS；仅 `127.0.0.1`、`localhost` 和 `::1` 回环地址允许 HTTP 用于本地开发。安装动作必须先请求同一基地址下的 `/auth/me`，再依次调用对应类型的 `resolve` 与标准 `download` 端点；不能把外网展示站地址写死为 Desktop API，也不能绕过标准下载端点使用 catalog 中的制品直链。

## 实现事实源

- `src/main/modules/marketplace/`
- `src/shared/contracts/marketplace.ts`
- 各资源领域的安装、更新与卸载实现
- 市场 catalog、下载、缓存和安装测试

连接器清单的 `auth_browser` 决定登录默认展示方式：`embedded` 使用隔离的应用内窗口，`system` 或未声明使用系统浏览器。市场授权中的用户可显式选择应用内或浏览器打开，选择仅用于本次授权、多步骤继续沿用，不写回连接器包、不重新登录。切换只关闭展示窗口，不触发授权取消；“取消添加”和关闭应用内窗口仍按既有取消规则回收会话。主窗口选择内嵌时，Main 必须重新从 Platform 读取同一有效会话及可信地址，不能接受 renderer 自报 URL；guest 默认策略不能借此被绕过。

系统浏览器网页关闭不可作为可靠的授权取消信号。Desktop 授权等待使用独立计时器限制为 3 分钟，超时中止本次流程并取消已知授权会话，释放界面忙碌状态；迟到的授权响应不得继续启用或挂载。详情保留主动取消和重试。

市场技能安装记录只表示来源与历史，不作为当前安装存在性的证明。普通技能状态以实际 skills-center 扫描为准，并优先采用实际版本；技能包及其子技能归属由 Platform 包清单确认。成功读取为空与读取失败必须区分，读取时不删除历史记录。

## 普通技能发布兼容性

本地文件、命令导入与市场普通技能使用同一 Platform 条件事务入口。Desktop 在变更前向 Platform 请求完整快照及 revision，不再自行读取运行中的技能目录。Platform 在 Catalog 事务保护内生成快照，并在同一保护区完成预期 revision 检查、替换或删除及发布；响应携带提交后的 revision。Desktop 安装记录写入失败时，必须带该 revision 请求补偿恢复；其他管理请求已经修改或重新创建资源时返回冲突，保留较新的资源和恢复包。

此保护协调 Platform 管理接口之间的操作，不承诺为绕过服务直接修改磁盘的外部进程提供文件系统快照隔离。Platform 不可用或不支持条件事务时明确失败，不回退到旧 overwrite 或 Desktop 直接写目录。Desktop 与对应 Platform 修复须配套发布；技能内容继续由 Platform 校验，不为了兼容旧的未校验导入而合成或篡改 SKILL.md。
