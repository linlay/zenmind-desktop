# 市场系统

## 文档定位

本文描述 Desktop 市场的目录、下载、安装和本地记录边界。Catalog 字段、接口路径、缓存文件和 UI 细节以源码、远端 contract 及测试为准。

## 系统边界

市场 Server 提供可浏览的 catalog 和下载元数据；Desktop 负责本机筛选、缓存、下载验证、安装编排和安装记录。Catalog 不是本机已安装状态，安装记录也不能反向成为远端商品事实源。

市场覆盖插件、Skill、Agent、桌宠、Sandbox Image、CLI Tool、MCP、Website/WebApp 和 Software Package 等资源。每种资源由专用安装器处理，不能用一个通用解压流程跳过领域校验。

## 主要流程

```text
加载 catalog
  -> 按品牌、平台与能力过滤
  -> 用户选择资源
  -> 使用 Desktop SSO access token 调用 auth/me 验证登录态
  -> 使用 Desktop SSO access token 调用 resolve
  -> 校验目标 Desktop 版本、依赖和平台
  -> 使用同一授权调用标准 download 端点
  -> 下载到临时缓存
  -> 校验类型、identity、版本、摘要和包结构
  -> 调用领域安装器
  -> 成功后提交本地安装记录
```

Catalog 用于展示，不是安装授权。安装时必须以 Server 的 `resolve` 响应为准，并从对应资源类型的标准 `download` 端点下载；资源元数据中的直链不能绕过授权。下载和安装是两个事务。下载成功不表示安装成功；安装失败时保留可诊断结果，但不能写入虚假的 installed 状态。

公共 catalog 浏览不依赖 Desktop 登录态，也不得为了读取 catalog 触发 access token 刷新。公共请求不携带 Cookie、Authorization、设备 ID、主机名或用户名；平台与架构筛选在本机完成。Desktop 已确认用户登录时，另行调用受保护的个人收藏接口，并按 `type + id` 将收藏状态叠加到公共 catalog；收藏请求失败只能降级为不展示个人收藏，不能清空公共条目与本地安装状态。登录过期、换票失败或用户尚未登录时，Desktop 仍展示公共条目与本地安装状态；只有收藏、resolve、download、安装和其他用户态动作需要有效凭据并遵循 401 单次刷新重试。

Skill 页的“创建技能”是对话预填入口，不是安装或写入动作。Desktop 只读取已配置的默认 Chat Agent，打开带 13 位 `newChat` 标记的新 Agent WebClient 路由，并附带受控的一次性 `composerDraft` 与 `composerSkill=skill-creator`；它不得在 renderer 中直接创建 Run。参数名声明能力类型，参数值声明具体选择，后续同类入口可使用独立的 `composerPlugin` 等字段。WebClient 将参数转换成可编辑草稿和选中 Skill 后立即从 URL 移除，用户真正发送后才进入 Agent 流程。创建流程必须触发已安装的 `skill-creator`，先展示目标目录和完整文件预览并校验，得到确认后才写入 `skills-center`。写入后由 Platform watcher 刷新后续 Run 的 Skill catalog；返回或刷新市场时应能在“我安装的”中发现该本地 Skill。该流程不上传、不发布市场条目。

## 数据分层

- Catalog 缓存可以过期和重建，不是用户数据。
- 下载缓存只保存可验证的临时包，并受容量和清理策略约束。
- 安装记录描述本机成功安装的资源身份与来源，不代替实际领域 store。
- 用户设置、插件数据、WebApp 数据和 Agent Platform 资源继续存放在各自领域目录。

## 安装边界

- 插件、WebApp 和 Website 进入 Desktop 自己的事务安装入口。
- Agent、Skill、Tool、Team 和 Registry 等平台资源遵循 Agent Platform 的运行目录 contract；Desktop 市场只允许把已校验的 MCP YAML 原子写入 `registries/mcp-servers`，不得修改其他 Registry 分类。
- Sandbox Image 交给容器领域导入，Desktop 不解析镜像内部业务。
- 桌宠资产通过桌宠包校验和安装逻辑处理。
- Software Package 安装到 Desktop 管理的程序目录，按 `id/version` 隔离版本，并在完整校验与解压成功后原子更新当前版本指针；失败时恢复原版本。
- MCP 市场制品一期只接受后端固定的 `market + 唯一 mcpServers` JSON，Server 只能声明 `type: streamable-http` 和 `url`。Desktop 转换为受控 Registry YAML 后，以文件方式原子写入 Agent Platform runtime 的 `registries/mcp-servers`。需要当前登录身份的 gateway MCP 写入 `authSource: identity-file`，由 Platform 按请求从 Desktop 启动时通过 `--identity-file` 提供的文件读取 token，不能把 token 或本机路径写入 YAML。运行中的 Agent Platform 由自己的文件 watcher 热重载，未运行时在下次启动加载；Desktop 不调用 Platform 管理 API。市场不得下发或执行 stdio 命令。
- Skill 市场制品只接受 ZIP。普通单 Skill 仍由 Desktop 负责商品身份、目标平台、下载摘要和分发安全，再写入 `skills-center`；`SKILL.md`、frontmatter、Skill Key、运行环境与提示词限制由 Agent Platform Catalog 校验。技能包由 Desktop 完成 Market 鉴权、resolve、下载与传输大小控制后，将原始 ZIP 交给 Agent Platform，Desktop 不解析包内 manifest、不落子技能，也不复制 Platform 的 Skill 业务规则。
- WebApp 市场一期只安装 `websiteKind: local-app` 的 ZIP 制品；外部网址继续由 Website 领域管理。Tooling 不为 Market 验包额外生成 Manifest。Desktop 使用现有 `auth/me -> resolve -> download` 链路校验商品身份、平台、摘要和 ZIP 安全，再复用 WebApp v2 标准安装事务读取 `webapp.json`、启动 Gateway 并提交本地记录。
- 普通 Skill 使用与当前 Desktop 匹配的 `targets` 项或 `universal` 单 ZIP 制品；旧数据中的 `skill.kind: single` 按普通 Skill 处理。只有 `skill.kind: package` 进入技能包链路：它不要求 catalog `assets`，Desktop 使用 Market 的 `/skills/<id>/package/download` 动态包，并通过受控的 Agent Platform 管理接口交付原始 ZIP。Platform 在隐藏 staging 中校验 `manifest.json` 和必选子技能，以同一事务安装或更新全部子技能；任一步或 Catalog 重载失败都恢复旧子技能与旧包状态。
- 技能包 ZIP 只作为请求期间的临时输入，成功或失败后都删除。持久化内容只有普通的 `skills-center/<skill-id>/` 子技能目录和 Platform 管理的 `skills-center/.package/<package-id>.json` 包状态；`.package` 不参与 Skill Catalog 扫描。Desktop 的市场记录只保存技能包商品的安装状态，不保存子技能列表。
- MCP 市场安装只写入 Registry 并触发工具同步，不在下载时选择 Agent。MCP Registry 只负责连接、鉴权和同步；Agent 是否使用某个 MCP，由 Agent 自己的 `toolConfig.mcp-servers` 正向声明。Desktop 不修改 Agent YAML，也不把逐个工具名写入 Registry。Platform 在后续新 Run 中加载 Agent 所选 Server 当前同步成功的工具，已有 Run 不因热同步自动扩权。
- Market MCP JSON 不得携带 `command`、`args`、`env`、静态 `authToken` 或认证请求头。MCP 工具与 Platform 本地工具重名时不得借绑定关系扩大本地工具权限。

更新和卸载同样调用领域能力，市场层不能直接删除程序目录、用户数据或运行进程。
普通 Skill 和 MCP 的文件变更与安装记录必须在同一本地事务中提交；记录写入失败时恢复原文件，不能留下“操作报错但新版已落盘”的状态。技能包的子技能与 `.package` 状态由 Agent Platform 自己的事务提交，Desktop 不参与该文件事务。

Skill 版本比较遵循 Semantic Versioning 2.0.0。已安装版本低于云端版本时，云端条目重新进入可更新列表；更新仍走 `resolve -> download -> 校验 -> 领域安装器`，不能覆盖式修改当前稳定副本。

## 可靠性与安全

- 网络失败时可以展示最近一次有效 catalog，但不能用部分响应覆盖完整缓存。
- 下载必须限制大小、协议、重定向和文件类型，并在安装前验证摘要与包结构。
- 临时目录和缓存路径必须位于 Desktop 管理根，不能接受远端提供的任意绝对路径。
- 远端文案、图标和元数据不获得本地执行权限。
- MCP 文件安装不能覆盖缺少市场安装记录的同名 Registry 文件；更新失败时必须恢复原文件。
- token、下载授权和本机路径不进入 renderer 日志或持久 catalog。
- 市场授权只复用 Desktop SSO access token；401 时允许在 main process 刷新一次后重试，不向 renderer 暴露 token。远端 gateway MCP 需要同一身份时必须通过受控 `authSource` 获取，不能依赖 Platform 进程环境或持久化 token 副本。

市场 API 基地址由品牌环境和用户设置提供，必须使用 HTTPS；仅 `127.0.0.1`、`localhost` 和 `::1` 回环地址允许 HTTP 用于本地开发。安装动作必须先请求同一基地址下的 `/auth/me`，再依次调用对应类型的 `resolve` 与标准 `download` 端点；不能把外网展示站地址写死为 Desktop API，也不能绕过标准下载端点使用 catalog 中的制品直链。
