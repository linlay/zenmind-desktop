# 市场系统

## 当前状态

Desktop 市场系统负责 catalog 读取、离线合并、本地安装记录、下载缓存和资源安装。市场条目类型包括 plugin、skill、agent、sandbox-image、pet、cli、website-app。

市场本身不直接运行插件或服务；它把资源下载、校验和分发给对应安装器，例如插件安装走 `plugin-market.ts`，本地网站应用安装走 `website-app-market.ts`。

## 核心流程

```text
listMarketItems()
  -> load sections in parallel
  -> normalizeCatalog()
  -> merge cloud catalog + local installed items

installMarketItem(itemId)
  -> try plugin
  -> try sandbox image/template
  -> try pet
  -> try cli
  -> try website app
  -> fallback skill
  -> upsert marketplace-installed.json
```

市场分区：

- `plugins`
- `skills`
- `agents`
- `sandboxImages`
- `pets`
- `cli`
- `websiteApps`

## 配置与接口

状态与缓存：

- 设置：`config/desktop/market.json`。
- 安装记录：`state/marketplace/marketplace-installed.json`。
- 下载缓存：`cache/marketplace/downloads/`。
- 备份缓存：`cache/marketplace/backups/`。

动作接口：

- `desktop.market.getSettings`
- `desktop.market.listItems`
- `desktop.market.refresh`
- `desktop.market.getItemDetail`
- `desktop.market.installItem`
- `desktop.market.updateItem`
- `desktop.market.uninstallItem`
- `desktop.market.importSkill`
- `desktop.market.importSandboxImage`
- `desktop.market.exportSandboxImage`
- `desktop.market.deleteSandboxImage`

## 约束与注意事项

- `DEFAULT_MARKETPLACE_CATALOG_URL` 和 `DEFAULT_MARKET_API_BASE_URL` 当前默认为空，需要配置后才访问远端。
- 收藏操作需要市场 API base URL 和 Desktop access token。
- 安装器必须按条目类型校验 asset 和平台适配，不要跨类型复用安装路径。
- 本地导入资源也会写安装记录，source 使用 `local`。
