# 异常上报

## 定位与边界

Desktop Main 拥有异常上报的配置、脱敏、持久队列、身份附加、重试与 Electron Crashpad 生命周期。renderer、preload、React Error Boundary 和 Service WebView 只通过既有诊断契约提交结构化异常，不能持有 Ops 凭据、写队列或直接上传。

一期只上传 JS 异常和原生 minidump，不上传聊天正文、附件内容、Token、Cookie、完整本地路径、任意日志文件，也不执行原生符号化。Ops 使用独立地址，不经过 Tunnel。

## 主流程与状态所有权

`desktop-init.json` 的独立异常上报配置经校验后进入品牌隔离的 canonical 配置；打包应用只接受 HTTPS，开发模式只额外允许 loopback HTTP。上报默认启用，设置页明确说明数据范围并允许用户关闭。

Main 将所有 JS 来源规范为白名单 DTO，在入队前脱敏并限制正文与队列大小。后台使用 canonical 登录 JWT；没有登录身份时匿名发送。失败保留有界队列并延迟重试，服务明确接收后才删除。

Crashpad 在创建业务窗口前启动。运行中关闭时立即禁止后续上传、停止 JS 入队、清空 JS 队列和待传 dump；Electron 收集器本身不能在本次进程中停止。下次启动若仍关闭，则不启动 Crashpad并再次清理残留 dump。

## 不变量

- 异常报告不得改变原有异常传播或进程退出语义；Main 使用 `uncaughtExceptionMonitor` 观察未捕获异常。
- 本地队列和匿名安装 ID 按品牌隔离，不能跨品牌读取。
- 生产地址不允许明文 HTTP，且不从 Tunnel 配置推导 Ops 地址。
- 用户关闭优先于重试、登录状态和运行时上传状态。
- 原生 crash 的 Crashpad multipart 字段保持 Electron 约定，服务端负责兼容并生成幂等键。

实现事实源位于 `src/main/error-reporting/`、共享 Desktop API 契约、preload 诊断入口和对应测试。
