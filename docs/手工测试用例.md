# 手工测试用例

## 环境准备

```bash
npm install
npm run sync:assets
npm run dev
```

如需测试容器服务，先确认 Docker 或 Podman 可用。打包测试前先确认 `BRAND`、`ENV_ZIP`、`DEMO` 等环境变量符合目标场景。

## 启动与核心服务

1. 启动 `npm run dev`。
2. 进入控制中心，确认 `identity-center`、`agent-platform`、`agent-webclient` 可见。
3. 首启场景下确认 `identity-center` 先 running，随后 `agent-platform` 和 `agent-webclient` 启动。
4. 使用包含 `desktop-init.json`、bootstrap agent、seed JSONL、seed `chats.db`、`<bootstrapChatId>/desktop-overview.png` 和 `<bootstrapChatId>/desktop-sidebar-actions.png` 的干净 env.zip 首启，确认自动打开并选中“点击我完成初始化工作”，且从 Chats 侧栏点击该 bootstrap 会话可正常进入；仅回放 assistant 自我介绍且没有创建 run。欢迎语完全在 WebClient 原有 Chat 主区域显示，先展示标有黄色框的导航 / 内容 / 副驾或概览分区图，再展示新建 Chat、Project、Site 的侧边栏指引，图片通过既有资源接口加载。Bootstrap Chat 和 Help 均显示黄色引导框，设置菜单自动展开，并可看到完整新手引导卡与浮动气泡。
5. 从初始化 Chat 主动进入 Help 或其他页面，确认本次启动不再强制跳回；重启且 bootstrap 仍存在时确认重新自动选择同一 Chat。发送消息后确认正常创建 run、接收 SSE 和处理 awaiting，profile 的正式默认 Agent 未被改写。
6. agent-platform 的 nav 列表移除 bootstrap 后，确认黄色引导和引导卡立即消失；若当前仍在 bootstrap Chat 且 `defaultChatAgentKey` 可用，Desktop 自动进入准确的默认智能体新会话，无需等待或接收 `run.complete`。已有 `chats.db` 时确认用户数据不被覆盖，Desktop 自动打开 bootstrap 新会话并选中黄色降级入口。
7. 查看服务详情，确认 PID、日志路径、端口、web URL 展示正常。
8. 停止和重启 `agent-platform`，确认状态和日志更新。

## 前端嵌入与认证

1. 打开 `agent-webclient` 页面，确认 webview 正常加载。
2. 检查所有 agent-webclient URL 都不包含 `desktopAuthContext`；聊天和 Copilot 分别包含 `wsSource=desktop-chat` 和 `wsSource=desktop-copilot`。
3. 打开 Agents、Archives、Automations、Memory 和 Registries，确认 URL 不包含 `wsSource`，Network 中没有 `/ws` 连接。
4. 在 agent-webclient 中触发需要 token 的请求，确认没有手动输入 token。
5. 停止并重启 `agent-platform`，确认旧 token 被丢弃，聊天 HTTP/WS 通过 Token Bridge 恢复。
6. 打开 `identity-center` 管理页，确认进入 `/admin/`。
7. 打开 `agent-platform` monitor，确认 access token 注入后页面可访问。

## 设置：使用情况

1. 未登录但当前接口密钥有用量时，确认顶部仅显示一次“访客模式”和“使用数据按当前接口密钥统计”；统计、热力图与计费信息正常展示，且没有登录按钮。
2. 完成 SSO 登录后刷新，确认显示头像、姓名和邮箱（可用时），并仅显示一个“已登录”状态标识。
3. 登录进行中确认显示“正在登录…”，SSO 状态读取失败时显示“身份状态暂不可用”；两者均不影响当前接口密钥的用量展示。
4. 在深色主题与 720px 以下窗口宽度下，确认上下文文字可换行、刷新按钮不溢出，且头像、状态与刷新按钮可被键盘访问。

## Chats 侧栏

1. 展开 Desktop 侧栏，确认 Chats 标题默认不显示默认智能体控件；hover 标题行或通过键盘焦点进入标题行后，在折叠箭头后显示当前默认 Chat 智能体名称的紧凑选择器。点击后确认每个选项显示「智能体名称 · 角色」，关闭态只显示名称；Enter/Space、方向键和 Escape 均可操作。收起侧栏后打开 Chats Popover，确认同样可切换。切换中英文时 aria 标签和更多历史文案正确。
2. 准备多个 REACT 会话并使其更新时间不同；确认 Chats 显示 agent-platform 全局排序的前 8 条，而非某个默认 agent 的 `recentChats`。准备 TEAM 或缺少 `agentKey`/有效时间字段的摘要，确认均不进入列表。
3. 产生第 9 条及更多 REACT 会话，确认 Chats 仍仅显示服务端排序的 8 条，并在末尾显示「查看更多历史」。点击后确认打开当前默认 Chat 智能体的 WebClient 历史列表；该历史可以与全局前 8 条来自不同智能体。
4. 点击任一会话，确认按该会话自己的 `agentKey` 与 `chatId` 打开；对一个未出现在导航 agent 列表中的有效 agentKey，hover 卡片应以 agentKey 作为名称兜底。点击 Chats 的「新建对话」并发送首条消息后，确认 WebClient 在取得稳定 `chatId` 时将 URL 从 `?newChat=` 替换为 `?chatId=`，新会话按服务端排序进入 Chats 后立即选中；该收敛期间协议日志只能保留原 `/api/query` live stream，不能出现随后的 `/api/chat`、`/api/attach` 或 `duplicate_observe`。仅修改 `theme`、`hostTheme`、`lang`、`wsSource` 或其参数顺序时不得重放页面；更换 `chatId`、`newChat` 时间戳或 history 参数时仍须正常导航。刷新运行中的稳定 `?chatId=` 页面时，确认仍按恢复链路请求一次 `/api/chat`，并对 active run 进行一次有效 `/api/attach`。请求失败、取消或没有稳定 `chatId` 时不得错误选中其他会话。
5. 使列表中分别存在未读、运行中和 awaiting 会话；确认对应行状态和 Chats 分组未读/等待徽标正确。未读会话在 chatName 前显示与 Projects 相同的 8px 蓝色圆点，不混入或占用标题文字；运行中显示 loading，awaiting 显示对应 Await 状态与橙色 spinner。对已展示会话依次发送带 `startedAt` / `finishedAt` 的 `run.started` / `run.finished`、带 `createdAt` / `answeredAt` 的 `awaiting.asking` / `awaiting.answered`，以及带 `createdAt` / `readAt` 的 `chat.unread` / `chat.read` push，确认状态立即更新，随后在短暂防抖后按服务端全局结果收敛；再发送仅含 `chatId`、`lastRunId`、`lastRunContent` 与合法 `updatedAt` 的 `chat.updated`，确认预览立即更新且主进程日志没有 `[assistant-navigation] time_contract_violation`。对非 heartbeat push 刻意发送旧 `timestamp`，确认不会更新本地状态、记录诊断并刷新快照。状态更新不依赖该会话的 agent mode。亮/暗主题和 280–360px 侧栏宽度下均应与 Projects chat 行保持一致。
6. 打开 renderer DevTools Console，执行 `const { recentFrames } = await window.electronAPI.assistant.getNavigationLiveStatus(); console.table(recentFrames)`；确认返回 `source: "desktop-nav"`、连接阶段和脱敏 `ws://.../ws` endpoint，`recentFrames` 按时间从旧到新最多保留 20 条连接、请求、响应、push、错误或无效帧记录，且每条仅含时间、方向、事件类别和 WS type，不包含 payload、token 或 deviceId。Network 面板不显示该主进程 WS，只显示 Vite HMR 等 renderer 连接。
7. `defaultChatAgentKey` 尚未出现在 nav、bootstrap agent 可用且 bootstrap REACT 会话位于前 8 条时，确认标题显示 bootstrap 名称、引导可见且可打开该会话；默认 agent 出现后，标题和新建对话目标切换为正式默认智能体，但全局 REACT Chats 列表不按默认 agent 切换。若当时仍停在 bootstrap Chat，本次启动仅自动进入一次默认 agent 的新会话；停在 Help 或其他页面时不跳转。
8. 在 Chats 标题的 hover/focus 选择器或「助理设置」切换默认 Chat agent，确认关闭态名称、新建对话目标和更多历史目标同步更新，已返回的全局 REACT Chats 列表不被按默认 agent 过滤，当前打开的会话不跳转。保存失败时选择器恢复原值并显示错误提示。
9. 智能体加载期间或没有可用 Chat agent 时，hover/focus 后确认标题选择器保持禁用并显示不可用提示，新建对话按钮保持禁用；已有全局会话仍可按其 agentKey 打开。

## 收起态主导航视觉

1. 在亮、暗主题下展开 Desktop 侧栏，确认 Kanban 与 Automations 使用独立的 16×16 线框图标；Chats、Projects、Sites 的分组标题不显示图标。
2. 收起侧栏，确认五项改为独立的 28×28 实心 SVG，而非把 16×16 线框图标放大；点击区域仍为 56×56，选中背景使用弱灰、文字使用主文字色与 500 字重；选中图标仍使用导航主蓝色（Kanban 保留三条彩色竖轨）。
3. 确认收起态 Kanban 为三条彩色竖轨、Automations 为镂空指针的实心时钟、Chats 为带三点的实心对话气泡、Projects 为带横向留白的实心文件夹、Sites 为带单一纬线与两条细长经线镂空的简化实心地球；Sites 不出现分块式地球。
4. 确认 Chats、Projects、Sites 的收起态文案与展开态完全一致；底部工具区和收起按钮图标仍保持 16×16 紧凑尺寸，主导航的 Popover、焦点漫游和路由行为不变。
5. 打开普通 Chat 智能体的会话（含 bootstrap、未读、运行中和等待中会话）时，Chats 是唯一处于选中态的分组；打开 CODER/KBASE 项目、其会话、历史或新建对话时，Projects 是唯一处于选中态的分组。展开态标题保持透明，收起态显示弱灰选中背景、主文字色与 500 字重。切换收起/展开、亮/暗主题、刷新、深链和 pending 跳转后均不得同时选中 Chats 与 Projects；未知智能体在类型数据返回前不显示这两个分组的选中背景。
6. 打开由底部 Settings 菜单进入的 Agents、Archives、Registries、Market 或 Skills 页面，确认底部 Settings 触发器显示弱灰选中背景、主文字色与 500 字重；关闭或打开菜单均不恢复蓝色选中态。

## 侧栏空状态引导

1. Chats 空状态：清除所有对话 → 展开侧栏 → Chats 下仅显示居中灰字「将鼠标移到「对话」上，点击 + 开始新对话。」；hover Chats 标题 `+` 按钮出现，点击进入新建对话流程。切换到无可用 Chat 默认智能体的环境 → Chats 空状态改为「请先在助理设置中选择可用的 Chat 默认智能体。」且 `+` 按钮禁用。
2. Projects 空状态：清空所有项目 → 展开 Projects → 显示居中灰字「将鼠标移到「项目」上，点击 + 添加项目。」；hover 标题 `+` 可用，点击进入创建项目流程。
3. Sites 空状态：删除所有网站 → 展开 Sites → 显示居中灰字「将鼠标移到「站点」上，点击 + 添加或导入站点。」；hover 标题 `+` 按钮可用，点击 `+` 弹出新增/导入菜单。
4. 加载保护：Sites 在启动加载期间不闪现空状态；仅在网站数据加载完成后且列表为空时显示。
5. 亮/暗主题、280–360px 展开侧栏宽度下验证三组文案可读、换行不遮挡。
6. 收起侧栏后确认无新增按钮或异常弹层。

## WebView URL 调试叠层

1. 在设置侧栏连续点击「关于软件」5 次，确认 Debug 分区和当前激活 WebView 左上角的淡色 URL 标记同时出现。
2. 在服务 WebView 中进行普通导航和页内导航，确认 URL 标记更新为当前地址；带 token、授权码或 API key 的参数显示为 `REDACTED`。
3. 打开内置浏览器或外部网站，切换标签后确认只显示活动标签 URL，且地址位于浏览器工具栏下方的 WebView 内容区。
4. 点击、输入、滚动、拖拽 WebView 页面以及使用浏览器工具栏，确认 URL 标记不拦截任何交互。
5. 重启 Desktop，确认 Debug 分区和 URL 标记恢复隐藏。

## 插件

1. 打开 Settings，确认 Plugins 紧接在 Control Center 下方，随后才是 Kanban、Market 等入口。
2. 准备一个单顶层目录、`pluginApiVersion: 1`、目标平台匹配且 `requiredPaths` 完整的插件 `.zip`；导入后确认非 resource 插件进入待初始化。
3. 分别尝试导入 `.tar.gz`、API 版本不支持、平台不匹配、顶层目录不匹配、缺少 required path 的包，确认在复制到插件目录之前显示明确错误。
4. 修改插件配置后点击初始化，确认 `lifecycle.deploy` 可重复执行且不依赖用户机器上的编译器；启动后确认日志、PID 和 web URL 正常。
5. 保存插件 Settings，确认默认值、平台快捷键、范围/选项校验和 restart-required 提示正确。
6. 在 macOS 运行 Activity Monitor，确认顶部灵动岛显示当前 running chat；在 Windows 运行对应 ZIP，确认右上角桌面小组件显示相同信息，空闲隐藏和最大条目数设置生效。
7. 运行 Calendar，新增今天、明天、后天的日程和待办，确认桌面三日浮层、完成状态、提醒时间和默认桌宠提醒正确；每日记录不进入浮层。
8. 运行 Clipboard，确认全局快捷键、搜索、上下键/Enter、数字快捷选择、置顶、删除、清空未置顶和暂停采集正常。
9. 运行 Selection Menu 并授予 macOS 辅助功能权限，确认任意应用划词后能翻译、生成回复、改写、记录并复制结果；排除应用不显示菜单。
10. 卸载插件，确认服务 registry 消失，插件拥有的 WebApp/Agent/Automation 与浮层被清理，用户的无关资源不受影响。

## 外部网站

1. 添加 `https://example.com` 外部网站。
2. 确认生成 `data/webs/websites/<id>/website.json`。
3. 修改 label 和 agentKey，确认导航和 manifest 更新。
4. 调整排序，确认 `config/webs/order.json` 使用 `website:<id>`。
5. 删除网站，确认本地网站应用目录不受影响。
6. 侧栏视觉：亮/暗主题、280–360px 侧栏宽度下，确认网站行文字 14px、默认弱字色/400 字重（对齐 Chats），hover 变为主字色，激活时主字色/500 字重；WebApp 行保持改造前的既有样式。
7. Favicon 显示：未缓存网站显示域名首字母 monogram；打开网站后，WebView 初始主标签页发现的真实 favicon 下载为 `data/webs/websites/<id>/favicon.<ext>`，并替换侧栏图标。关闭网站后缓存保留。
8. 绿点与关闭：打开但非当前激活的网站右侧固定 24px 槽位显示 6px 绿色状态点；当前激活站点也显示绿点。hover 或行内聚焦（focus-within）时，绿点在同一槽位原位替换为关闭 `×` 按钮（tooltip 显示「关闭 webview」），不新增空白或改变文本可用宽度；点击 `×` 关闭 WebView 并回到 Sites 空白页；关闭中同一槽位显示 loading 态。键盘漫游与右键菜单关闭路径正常工作。
9. Favicon 缺失：对未提供 favicon、下载失败或图标不可用的站点确认降级为 monogram，不显示破损图片占位。
10. 持久化缓存：重启 Desktop 后确认已缓存的 favicon 直接显示；再次打开站点可刷新缓存。网站被删除或 URL 修改后确认对应 `favicon.<ext>` 清除。
11. WebApp 不受影响：本地 WebApp 行保持原有图标（`more_actions`）和启动/停止/运行状态表现，不出现绿点或关闭 ×。

## 本地网站应用

1. 准备纯前端（无 `backend`）和带 Node `backend.entry` 的两类目录或 archive。
2. 安装或复制到 `data/webs/webapps/<id>/`。
3. 启动 webapp，确认 `runtime.json` 写入 backend/frontend port。
4. 访问 `webUrl`，确认静态页面加载。
5. 请求 `frontend.apiPrefix`，确认代理到 Node 后端。
6. 停止 webapp，确认进程树清理、日志保留。
7. 安装使用 `desktop.assistant.translate` 的翻译 WebApp，分别选择英语、日语和中文，确认结果由 Desktop 当前助理模型返回，页面和 WebApp 包内均不包含模型密钥。
8. 启动纯前端 WebApp，确认状态为 `running`、`backendUrl` 为空、`backendPort`/`pid` 为空，页面可正常加载。
9. 在两种 WebApp 中通过 `/__desktop/actions/call` 调用 `desktop.assistant.complete`，确认本地同源页面可返回文本；携带公网 Origin 的请求返回 403。

5. 连接远端控制时确认 cloud issue 仅作为只读缓存，不调用旧 issue CRUD。

## 桌面协议

1. 通过 Desktop WebSocket 连接 `ws://127.0.0.1:7082/ws`，携带有效 app token。
2. 发送 `session.hello`，确认返回 Desktop runtime 信息。
3. 调用 `action.list`，确认 public actions 可见。
4. 调用 `service.list`、`service.status`，确认服务信息返回。
5. 调用 `desktop.web.website.add` 或 alias `web.website.add`，确认弹出精简 Desktop action 确认框，默认只显示动作、目标、权限和参数摘要。
6. 展开确认框详情，确认可见 `requestId` / `runId` / `chatId` / `agentKey` 等调试上下文，敏感参数已隐藏；点击执行后确认外部网站创建。
7. 准备 `website.json` 中 `createdAt` / `updatedAt` 为 ISO 字符串的网站，经 agent run 执行 `desktop.web.website.list` 与 `desktop.web.website.add`：确认流以成功终态结束，bridge 响应中的两个字段均为 epoch-ms number，且不返回 `422 time_contract_violation`；再次添加同一 URL 时返回“已存在”业务结果而不是 422。确认 manifest 仍保持 ISO 字符串存储。
8. 对低风险 page control 动作确认「允许本次页面操作」「仅执行这一步」「取消」三种选择仍可用，高风险动作仍会单独确认。

## 打包与卸载

1. macOS 执行 `BRAND=zenmind npm run dist:mac`，确认 DMG 输出。
2. Windows 主机执行 `BRAND=zenmind npm run dist:win`，非 Windows 主机执行 `npm run dist:win-docker`。
3. 设置 `ENV_ZIP` 打包，确认首启导入只复制缺失文件。
4. 设置 `DEMO=true` 打包，确认 demo webapp 模板首启安装。
5. macOS 运行应用包内 `uninstall.sh`，确认默认保留数据，选择清理时删除运行数据和程序数据。
