# 手工测试用例

## 环境准备

```bash
npm install
npm run sync:assets
npm run dev
```

如需测试容器服务，先确认 Docker 或 Podman 可用。打包测试前先确认 `BRAND`、`ENV_ZIP`、`DEMO` 等环境变量符合目标场景。

## 启动与核心服务

1. 启动 `npm run dev`。
2. 进入控制中心，确认 `identity-center`、`agent-platform`、`agent-webclient` 可见。
3. 首启场景下确认 `identity-center` 先 running，随后 `agent-platform` 和 `agent-webclient` 启动。
4. 使用包含 `desktop-init.json` 和 `agents/bootstrap/agent.yml` 的干净 env.zip 首启时，确认自动进入 `/agent/<bootstrapAgentKey>`，侧栏显示初始化智能体高亮、新手引导步骤和帮助入口；初始化智能体从导航列表消失后，引导同步结束。
5. 查看服务详情，确认 PID、日志路径、端口、web URL 展示正常。
6. 停止和重启 `agent-platform`，确认状态和日志更新。

## 前端嵌入与认证

1. 打开 `agent-webclient` 页面，确认 webview 正常加载。
2. 检查 embedded URL 包含 host theme、language、desktop auth context 或 ws source。
3. 在 agent-webclient 中触发需要 token 的请求，确认没有手动输入 token。
4. 打开 `identity-center` 管理页，确认进入 `/admin/`。
5. 打开 `agent-platform` monitor，确认 access token 注入后页面可访问。

## 插件

1. 准备一个单顶层目录的插件 `.zip`。
2. 在控制中心导入插件，确认非 resource 插件进入待初始化。
3. 修改插件 `.env` 后点击初始化，确认 `lifecycle.deploy` 执行成功。
4. 启动插件，确认日志和 web URL 正常。
5. 卸载插件，确认服务 registry 消失，插件资源被清理。

## 市场

1. 配置 market catalog 或使用测试注入 catalog。
2. 刷新市场，确认 plugins、skills、agents、sandboxImages、pets、cli、websiteApps 分区可见。
3. 安装一个插件条目，确认写入安装记录。
4. 安装一个 website-app 条目，确认出现在本地网站应用列表。
5. 卸载对应条目，确认本地资源和安装状态更新。

## 外部网站

1. 添加 `https://example.com` 外部网站。
2. 确认生成 `data/webs/websites/<id>/website.json`。
3. 修改 label 和 agentKey，确认导航和 manifest 更新。
4. 调整排序，确认 `config/webs/order.json` 使用 `website:<id>`。
5. 删除网站，确认本地网站应用目录不受影响。

## 本地网站应用

1. 准备包含 `webapp.json`、`frontend/index.html`、Node `backend.entry` 的目录或 archive。
2. 安装或复制到 `data/webs/webapps/<id>/`。
3. 启动 webapp，确认 `runtime.json` 写入 backend/frontend port。
4. 访问 `webUrl`，确认静态页面加载。
5. 请求 `frontend.apiPrefix`，确认代理到 Node 后端。
6. 停止 webapp，确认进程树清理、日志保留。

## 看板与助理

1. 打开一条有历史内容的会话，从侧边栏会话菜单执行归档。
2. 确认当前页面切换到同智能体下一条会话；没有下一条时进入该智能体空白页，不停留在已归档 `chatId` 的加载状态。
3. 进入“已归档对话”，确认内容完整；执行“还原并打开”后确认会话返回活动列表且消息可见。
4. 对同一会话再次执行归档，确认归档列表仍可正常显示，并可再次还原。

2. 指派 agent 并启动 run，确认 issue 写入 `chatId` / `runId`。
3. 等待 assistant event，确认 run state 更新为 completed / failed / cancelled。
4. 配置 automation 字段，确认 agent-platform automation 创建或更新。
5. 连接远端控制时确认 cloud issue 仅作为只读缓存，不调用旧 issue CRUD。

## 桌面协议

1. 通过 Desktop WebSocket 连接 `ws://127.0.0.1:7082/ws`，携带有效 app token。
2. 发送 `session.hello`，确认返回 Desktop runtime 信息。
3. 调用 `action.list`，确认 public actions 可见。
4. 调用 `service.list`、`service.status`，确认服务信息返回。
5. 调用 `desktop.web.website.add` 或 alias `web.website.add`，确认弹出精简 Desktop action 确认框，默认只显示动作、目标、权限和参数摘要。
6. 展开确认框详情，确认可见 `requestId` / `runId` / `chatId` / `agentKey` 等调试上下文，敏感参数已隐藏；点击执行后确认外部网站创建。
7. 对低风险 page control 动作确认「允许本次页面操作」「仅执行这一步」「取消」三种选择仍可用，高风险动作仍会单独确认。

## 打包与卸载

1. macOS 执行 `BRAND=zenmind npm run dist:mac`，确认 DMG 输出。
2. Windows 主机执行 `BRAND=zenmind npm run dist:win`，非 Windows 主机执行 `npm run dist:win-docker`。
3. 设置 `ENV_ZIP` 打包，确认首启导入只复制缺失文件。
4. 设置 `DEMO=true` 打包，确认 demo webapp 模板首启安装。
5. macOS 运行应用包内 `uninstall.sh`，确认默认保留数据，选择清理时删除运行数据和程序数据。
