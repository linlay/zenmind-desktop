# 手工测试用例

## WebView 动态原生右键菜单

1. 分别在主聊天、Copilot 全页与 Dock、Project、管理页、Help、普通 Service/Plugin、Browser、Website 和 WebApp 右键，确认使用主窗口所属的系统原生菜单；普通空白 Service 页面仅显示刷新，Browser 类空白页显示可用的后退、前进、刷新和 HTTP(S) 页面地址复制。
2. 在输入框验证撤销、重做、剪切、复制、粘贴、全选只在 Electron `editFlags` 允许时出现；macOS 使用 Command 系快捷键且 Redo 为 Shift+Command+Z，Windows 使用 Ctrl 系且 Redo 为 Ctrl+Y。
3. 在用户消息、助手消息和代码块上无需预选即可复制原始内容；先选择任意文本后再次右键，确认只复制选区，不再显示复制整个消息或代码。
4. 在 WebClient 链接上验证侧栏预览、Desktop Browser 新标签、系统浏览器和复制链接；在 Browser/Website/WebApp 链接上额外验证当前原标签打开。Help、Service 与插件链接不得把原 guest 导航离开应用。
5. 验证 Workspace 文件预览/复制路径、Chat 附件预览/下载、鉴权图片复制与下载。菜单和剪贴板不得出现 loopback 页面地址、Bearer、`/api/resource` 临时地址或 object URL；`javascript:`、`file:`、不可信 `data:` 与通用 `blob:` 不产生打开/保存动作。
6. 流式输出期间快速连续右键，并在菜单弹出后切换标签/Surface、reload、crash 或触发 guest replacement，再点击旧菜单；确认旧动作静默取消，不操作当前其他页面且不崩溃。
7. 在普通浏览器打开 agent-webclient，确认右键继续显示浏览器默认菜单，页面没有调用 `preventDefault()`。

## WebClient 选区快捷工具条（界面阶段）

1. 分别在主 Chat、Copilot 全页与 Dock、Kanban 等内嵌对话中选择用户消息、助手消息、Markdown 正文和代码文字，确认选区上方出现 Desktop 横向工具条，包含“添加到对话”“详细解释”“在顺便问中提问”；靠近顶部时翻转到选区下方，左右和底部始终保留至少 8px 可见边距。
2. 在输入框、contenteditable、管理页、Project、普通 Service/Plugin、Website/WebApp 和普通浏览器 WebClient 中选择文字，确认不出现工具条；抓取 guest-to-main 与 main-to-renderer payload，确认不包含选中文字、消息正文、代码、Token 或临时 URL。
3. 三个按钮均保留正常 hover/focus 样式；点击任一按钮只关闭工具条，不修改主 Composer/“顺便问”草稿，不打开侧栏，不发送 query/steer/BTW 或 Desktop Action。
4. 使用鼠标拖选、多行选区和 Shift+方向键键盘选区，确认工具条位置稳定。开始新选区、清空选区、滚动、调整窗口、按 Esc、切换路由/Surface、reload、crash 或替换 guest 时工具条立即关闭，迟到的旧语义响应不得重新显示。
5. 在 macOS、Windows 的亮暗主题及窄 Copilot Dock 下验证分段胶囊、边框、阴影、分隔线、文字截断和 hover 均清晰；随后重复 WebView 原生右键菜单用例，确认右键行为和系统菜单样式不变。

## 环境准备

```bash
npm install
npm run sync:assets
npm run dev
```

如需测试容器服务，先确认 Docker 或 Podman 可用。打包测试前先确认 `BRAND`、`ENV_ZIP` 等环境变量符合目标场景。

## 启动与核心服务

1. 启动 `npm run dev`。
2. 进入控制中心，确认 `identity-center`、`agent-platform`、`agent-webclient` 可见。
3. 首启场景下确认 `identity-center` 先 running，随后 `agent-platform` 和 `agent-webclient` 启动；服务准备期间显示全窗居中的 `StartupLoadingScreen` 卡片，包含三个核心组件的状态、已就绪数量和进度条。
4. 将核心服务启动时间延长至 45 秒以上，确认卡片显示「启动较慢」、「重新检查」和「进入控制中心」；使启动恢复失败或在恢复完成后停止任一核心服务，确认卡片显示失败信息，进入控制中心后可查看服务详情且启动卡不遮挡设置页面。分别在 macOS 与 Windows、亮暗主题和窄窗口下确认卡片可完整滚动、遮罩连续。
5. 在 Windows 让核心服务启动失败，确认点击右上角关闭按钮后主窗口隐藏、进程仍在运行且通知区域出现应用托盘图标；点击托盘图标可重新打开窗口，打开托盘菜单可进入设置，并通过「退出」完成应用退出。启动失败页不显示额外的「退出应用」按钮。
6. 在核心服务已就绪时停留于根路由 `/`，确认主内容区显示纯色「正在加载核心组件」兜底页；关闭最后一个 Site/Browser 并进入 `/webs` 时确认 WebView 已卸载，且主内容区显示「暂无打开的网站应用」，不再显示核心组件加载提示。随后打开 Chat、Site、设置、市场或看板，确认空状态不覆盖所选内容，标题栏拖拽区域保持正常。macOS 切换到其他应用使 Desktop 失焦后，直接在标题栏按下并拖动，确认第一次按下即可同时激活并移动窗口，无需再次点击；Windows 保持既有首次拖动行为。
7. 使用包含 `desktop-init.json`、bootstrap agent、seed JSONL、seed `chats.db`、`<bootstrapChatId>/desktop-overview.png` 和 `<bootstrapChatId>/desktop-sidebar-actions.png` 的干净 env.zip 首启，确认自动打开并选中“点击我完成初始化工作”，且从 Chats 侧栏点击该 bootstrap 会话可正常进入；仅回放 assistant 自我介绍且没有创建 run。欢迎语完全在 WebClient 原有 Chat 主区域显示，先展示标有黄色框的导航 / 内容 / 副驾或概览分区图，再展示新建 Chat、Project、Site 的侧边栏指引，图片通过既有资源接口加载。Bootstrap Chat 和 Help 均显示黄色引导框，设置菜单自动展开，并可看到完整新手引导卡与浮动气泡。
8. 在 macOS/Linux 检查导入后的任意 `.sh`（包括 `agents/bootstrap/bootstrap.sh`）权限为 `0755`，可直接以绝对路径启动；将某个已导入 `.sh` 人工改为 `0644` 后再次导入同一 env.zip，确认脚本内容仍不覆盖且权限恢复为 `0755`。Windows 对应的 `.ps1` 应使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <absolute-path>` 启动。
9. 从初始化 Chat 主动进入 Help 或其他页面，确认本次启动不再强制跳回；重启且 bootstrap 仍存在时确认重新自动选择同一 Chat。发送消息后确认正常创建 run、接收 SSE 和处理 awaiting，profile 的正式默认 Agent 未被改写。
10. agent-platform 的 nav 列表出现 `defaultChatAgentKey` 后，确认黄色引导和引导卡立即消失、普通 Chats 列表不再显示 bootstrap 会话；当前停在 bootstrap Chat 或再次通过旧链接打开该 Chat 时，Desktop 都自动进入准确的默认智能体新会话，无需等待或接收 `run.complete`。已有 `chats.db` 时确认用户数据不被覆盖；默认智能体尚未出现时，Desktop 仍可打开 bootstrap 新会话并选中黄色降级入口。
11. 查看服务详情，确认 PID、日志路径、端口、web URL 展示正常。
12. 停止和重启 `agent-platform`，确认状态和日志更新。

## 前端嵌入与认证

1. 打开 `agent-webclient` 页面，确认 webview 正常加载。
2. 检查所有 agent-webclient URL 都不包含 `desktopAuthContext`；聊天和 Copilot 分别包含 `wsSource=desktop-chat` 和 `wsSource=desktop-copilot`。
3. 打开 Agents、Archives、Automations、Memory 和 Registries，确认 URL 不包含 `wsSource`，Network 中没有 `/ws` 连接。
4. 在 agent-webclient 中触发需要 token 的请求，确认没有手动输入 token。
5. 停止并重启 `agent-platform`，确认旧 token 被丢弃，聊天 HTTP/WS 通过 Token Bridge 恢复。
6. 打开 `identity-center` 管理页，确认进入 `/admin/`。
7. 打开 `agent-platform` monitor，确认 access token 注入后页面可访问。
8. CuteJ 登录后确认 `browserSession` 请求 `/oauth2/auth` 返回 200/202，并立即生成 `state/desktop/sso-session.json`；文件为 schema v2 且不包含 `user`、Cookie 或 access token。
9. 确认 `/oauth2/auth` 的已验证响应头包含稳定用户 ID 后立即生成 `sso-user-info.json`；email/name 为空时 `sub` 仍使用用户 ID，name 回退为同一 ID。让 `/authorization` 返回 401，确认 session/user-info 仍存在、`sso-access-token.txt` 不存在，侧栏显示用户 ID 和“访问令牌未就绪”。
10. 让 `/oauth2/auth` 不返回用户 ID 且 Cookie userinfo 也失败，而 `/authorization` 成功，确认 session/token 文件存在、user-info 文件不存在；反向失败时确认已经写入的 user-info 不被删除。完全关闭并重启 Desktop，确认磁盘文件只作为恢复候选，不会在上游 Cookie 校验与强制换票完成前直接显示已登录。
11. ZenMind 系统浏览器 OIDC 登录后确认 ID token 验证、基础用户信息、access token 分别落盘；模拟 Bearer userinfo 或 Site Token Bridge 失败，确认已经写入的文件不回滚。注销后确认三个 canonical 文件均删除。
12. 分别在 macOS 与 Windows 验证状态目录来自 Electron runtime/home 路径而非硬编码；macOS/Linux 使用 `stat` 确认三个文件权限为 `0600`。
13. 已有有效登录态时再次发起登录，确认等待期间仍展示原用户；让新 session 校验失败，确认原 session/user-info/token 文件和已登录状态均保留。只有新 session 校验成功后，才允许清理原账号的下游 user-info/token。
14. 让 Cookie session 返回 202，并在 `X-Auth-Request-User` 返回 `107078`，同时 userinfo 返回 200 但 `email=""`、`/authorization` 成功：确认三个文件均存在，最终用户为 `sub=107078`、`name=107078`，登录不再显示“用户信息未就绪”。再移除用户 ID 响应头并让 userinfo 不含稳定 ID，确认只保留 session/token 两个文件。
15. 让 session、userinfo、token 三步均成功，确认统一 finalize 后 WebView 自动关闭并显示真实用户；让 userinfo 成功但 token 返回 401，确认结果面板保留 session/user-info，并显示“访问令牌未就绪”。
16. 未登录时点击普通“登录”或在部分成功结果页点击“重试”，确认免登录复用；已登录账号菜单只显示“退出登录”，不显示“重新打开”或“切换账号”。
17. 注销后确认三个 canonical 文件和专用 SSO partition Cookie 全部清理，而默认 session 中无关网站 Cookie 不受影响；再次登录时确认可以选择其他账号。分别在 macOS 和 Windows 验证。登录结果为部分成功时，确认关闭、重试两个操作均可键盘访问。
18. 展开主侧栏时，已登录账号确认底部触发器从左到右显示头像、用户名和最右侧齿轮；Market 选中时用户名改为当前路由的 i18n 名称，头像移到齿轮左侧。头像 URL 缺失或加载失败时始终显示用户名首字符，不显示路由名首字符；长文案正确截断。进入 Agents、Skills Center、MCP Connectors、Registries、Archived Chats 或 Help 后确认底部触发器随主侧栏一起被能力侧栏替换；点击「返回应用」后原账户触发器恢复。退出登录后确认改为“未登录 + 最右侧齿轮”，SSO 未配置或状态尚未加载时仍显示原“设置”入口；收起主侧栏后只显示 16px 齿轮。分别在 macOS、Windows、亮色和暗色主题下确认点击、Enter/Space 仍可打开内容不变的 Settings 菜单。
19. 先打开带稳定 `chatId` 的 Chat，再切换到 Site 或 Kanban 并从该页进入 Settings → 外观；切换中英文、手动主题和系统主题后，确认始终停留在 `/settings/appearance`，常驻但 inactive 的 Chat WebView 仍更新宿主展示参数且不反向覆盖 Desktop 路由。点击“返回应用”后应恢复进入 Settings 前的完整 pathname 与 query。分别在 macOS 和 Windows 验证。
20. 分别在 macOS 与 Windows 完成 Cookie SSO 登录，打开至少两个 Website 并确认网页已登录；完全退出 Desktop 后重新启动，确认主窗口出现前先请求 `/oauth2/auth` 和 `/authorization`，即使旧 JWT 仍有超过 15 分钟有效期也会换取新 JWT。Desktop 账户与两个 Website 必须同时恢复登录，不得出现一边已登录、另一边要求登录。
21. 检查新 JWT 写入的 `access_token` Cookie：专用 `persist:<storageNamespace>-sso` partition 和 Electron default session 中值相同，`expirationDate` 等于 JWT `exp`，且状态广播发生在两个 session 刷盘之后。用缺少合法 `exp` 的 JWT 重测，确认当前进程可用 session Cookie，但下次启动仍执行完整校验和换票。
22. 重启恢复时让 `/oauth2/auth` 或 `/authorization` 返回 401/403，确认 `sso-session.json`、`sso-user-info.json`、`sso-access-token.txt`、`secrets/sso-site-token.json` 和头像缓存被清理；专用 SSO partition 全部 Cookie 与 default session 中已知 SSO Cookie 被清理，Desktop 和 Website 同时退出。企业聊天断开，Kanban、Market 与 Tunnel Hub 不再使用旧 token。
23. 重启恢复时分别模拟断网、5 秒超时、429 和 5xx，确认 canonical 文件和上游 session Cookie 保留、两个 Electron session 中派生的旧 `access_token` Cookie 被移除；Desktop 显示“暂时无法验证登录状态”、`authenticated=false`，Website 不注入旧 JWT，企业聊天与 Tunnel Hub 不启动。普通智能体新建 Host Bash 仍应从保留的 canonical 文件获得 `AP_ACCESS_TOKEN`。重复查询状态不得从磁盘把 Desktop 变回已登录。恢复网络后通过 `sso.getStatus` 或等待 5 分钟定时器，确认只发生一次并发校验/换票，所有使用 SSO partition 的 Website 各 reload 一次，Kanban、Market、企业聊天和 Tunnel Hub 恢复；Help、WebApp、agent-webclient 和普通服务 WebView 不 reload。
24. 在磁盘保留账号 A 的 user/token 后，让启动校验返回账号 B 的稳定用户 ID 并成功换票，确认账号 A 的 user/token/头像在保存 B 前清理，最终文件、侧栏、Website 和凭据消费者全部只显示账号 B，不出现字段混用。
25. 标准 OIDC 且未配置 `browserSession + cookieAccessTokenExchange` 时重启，确认仍按既有文件恢复语义处理；Help 独立 partition 和 agent-webclient Token Bridge 行为保持不变。
26. 先启动 Platform 且保持未登录，确认普通智能体 Host Bash 中没有 `AP_ACCESS_TOKEN`；登录后新建 Bash 应取得文件中的 token，换号后取得新 token，注销后再次新建 Bash 应不再包含该变量。整个过程中 Platform 不重启，已有 Bash 不被中断。确认 Workspace Terminal、`file_grep/file_glob`、Container、Proxy、ACP、MCP、LSP 和 sidecar 均未自动获得该变量；分别在 macOS 与 Windows 验证带空格的 canonical 路径转发。

## 企业聊天

1. 在 `zenmind-im-server` 配置与企业 SSO access token 匹配的 OIDC issuer、audience 和 JWKS，并在 `desktop-init.json -> enterpriseIm` 显式写入布尔型 `enabled` 和服务 `baseUrl`；首次 bootstrap 后确认生成包含同值的 `config/desktop/enterprise-im.json`，服务健康检查正常。CuteJ Web 全新 runtime 应默认开启，其余正式环境与 example 默认关闭；旧 `imServer`、`im-server.json` 和 Profile 旧开关均不生效。
2. 完成 session、userinfo、access token 三步企业 SSO 登录，再到 Settings → 常规显式开启“企业聊天”，确认右下角出现 `37.8 × 37.8`（原 `54 × 54` 缩小 30%）聊天按钮，内部聊天图标仍清晰醒目；点击后打开约 `400 × 500` 的紧凑浮层，显示当前服务连接状态和除自己之外的企业员工。头像失败时显示姓名首字符；服务端返回显式 `online` 时显示在线/离线，未返回时显示灰色“在线状态未知”，不得把 `status=active` 误标为在线。联系人列表与进入私聊后的标题栏必须显示相同的 presence。联系人页必须把个人、已加入群聊和 `kind=service_bot` 机器人分区显示，并分别使用蓝色人形、绿色群组、紫色机器人图标/底色和类型标签。
3. 点击另一名员工，首次自动创建唯一 direct conversation，重复进入不创建第二个会话；发送一对一文字消息后双方实时收到，发送方消息靠右、接收方消息靠左，Enter 发送、组合键换行、空消息不可发送。
4. 关闭接收方 Desktop 后继续发送多条消息，再重新登录并连接；确认 `sync.resume` 后历史按 `seq` 恢复、消息不重复、未读徽标正确，打开会话后通过 `receipt.read` 清零。
5. 发送期间断开 `zenmind-im-server`，确认浮层显示重连状态且不丢失已确认消息；恢复服务后在最长 30 秒退避窗口内自动重连。远端 HTTP 地址应被拒绝，loopback HTTP 与远端 HTTPS 分别使用 WS/WSS。
6. 在 Settings → 常规开启“企业聊天”，确认 `enterprise-im.json -> enabled` 立即变为 `true`，在仍有完整 SSO token 时自动连接；关闭后该字段变为 `false`，按钮、浮层、内存会话和 WebSocket 立即清理，重启后保持关闭。普通 env.zip 导入必须用 `desktop-init.json -> enterpriseIm.enabled` 覆盖当前用户选择，同时用同节 `baseUrl` 热重载服务地址；`profile.json` 不得出现企业 IM 开关。
7. 注销企业 SSO，确认按钮立即消失且 WebSocket 断开；检查 renderer DevTools、URL、localStorage 和 Desktop 日志，确认不存在企业 JWT、IM session token、WebSocket ticket 或消息正文。
8. 分别在 macOS、Windows、亮色、暗色、窄窗口和矮窗口验证浮层不越界，键盘焦点、返回、刷新、关闭、员工选择和发送按钮可操作；打开右侧 Copilot 时，宽窗口下聊天浮层移到 Copilot 左侧。
9. 创建包含三名员工的私有群聊，确认会话列表、群名称、成员头像、历史、未读与群消息正常；普通成员不能越权管理成员。

2. 准备一个单顶层目录、`pluginApiVersion: 1`、目标平台匹配且 `requiredPaths` 完整的插件 `.zip`；导入后确认非 resource 插件进入待初始化。
3. 分别尝试导入 `.tar.gz`、API 版本不支持、平台不匹配、顶层目录不匹配、缺少 required path 的包，确认在复制到插件目录之前显示明确错误。
4. 修改插件配置后点击初始化，确认 `lifecycle.deploy` 可重复执行且不依赖用户机器上的编译器；启动后确认日志、PID 和 web URL 正常。
5. 保存插件 Settings，确认默认值、平台快捷键、范围/选项校验和 restart-required 提示正确。
6. 在 macOS 运行 Activity Monitor，确认顶部灵动岛显示当前 running chat；在 Windows 运行对应 ZIP，确认右上角桌面小组件显示相同信息，空闲隐藏和最大条目数设置生效。
7. 运行 Calendar，新增今天、明天、后天的日程和待办，确认桌面三日浮层、完成状态、提醒时间和默认桌宠提醒正确；每日记录不进入浮层。
8. 运行 Clipboard，确认全局快捷键、搜索、上下键/Enter、数字快捷选择、置顶、删除、清空未置顶和暂停采集正常。
9. 运行 Selection Menu 并授予 macOS 辅助功能权限，确认任意应用划词后能翻译、生成回复、改写、记录并复制结果；排除应用不显示菜单。
10. 卸载插件，确认服务 registry 消失，插件拥有的 WebApp/Agent/Automation 与浮层被清理，用户的无关资源不受影响。
11. 保持插件 WebApp 的内嵌界面和独立窗口同时打开后卸载插件；确认界面先关闭，再停止发布、gateway 和进程树。让 stop 或 PID 复验失败，确认插件资源目录和安装记录保留且卸载返回错误。

    guest URL 原位变为带 `chatId` 的同一路径并保留语言、主题参数；选择历史 chat 时 URL 切到对应 ID，

15. 对各自已打开 Copilot 的 Website 分别执行 renderer 刷新、`Page.reload`、

    chatId? }`，不含 token、正文或认证 URL。手动关闭 A 的 Dock 后切到 B，B 的记录保持；切回 A 不再
    显示。进入 agent-webclient 主页面或明确禁用 Copilot 的页面时 Dock 暂时隐藏，返回原 surface 后按

## 本地网站应用

### Manifest v2

1. 准备纯静态、electron-node、executable、Python runtime 和 Java runtime 包，确认列表只读取 Manifest v2，设置详情显示 id、key、version、target、routeConfig、userConfig、command type 与 `desktopBridge.version`，不显示 capability 数组。
2. 构造其他 schema、数组式或对象式 capability、`openMode`、`frontend.spa`、`frontend.apiPrefix`、capability instruction、未知宿主字段、缺少 id/key/version/target/health 和非法 command，确认 Tooling 与安装器都严格拒绝且不产生部分目录。
3. 构造当前 OS/架构匹配和不匹配的 target；在 `any` 包中加入原生文件，在平台包中加入错误格式或架构的 PE/Mach-O；确认在替换旧版之前拒绝。
4. 对 frontend/backend 路径测试绝对路径、`..`、空段、符号链接逃逸和 shell 文本，确认全部拒绝。
5. 构造任意嵌套 appConfig 与全部 userConfig 字段类型；从前端读取 `desktop.app.getConfig()/getUserConfig()`，从后端读取 `WEBAPP_MANIFEST_PATH/WEBAPP_USER_CONFIG_PATH`，确认定义、默认值和实际用户值边界正确。测试 secret-like key、危险对象键和大小上限。
6. 修改本地 label、openMode 和 userConfig，确认不写回 webapp.json；升级新增、删除或改类型字段后按当前定义合并，运行中的后端按统一策略重启。
7. 导入多顶层目录、嵌套 Manifest、目录名与 id 不一致、路径穿越、大小写冲突、符号链接、超大文件、超多条目、异常压缩比和含 `.env/node_modules/logs` 的 ZIP，确认返回明确 stage/code 且正式安装目录不变。

### Gateway 与静态应用

1. 启动纯静态 Manifest v2 应用，确认只有独立 `127.0.0.1` gateway、无子进程，state 为 `running` 且 `backendUrl` 为空、`backendPort`/`pid` 为 null。
2. 验证根路径资源、localStorage、Service Worker、静态文件 MIME、深路由直接打开和刷新；有 `navigationFallback` 时仅 HTML 导航回退，省略时返回 404，缺失 JS/CSS/图片始终返回 404。
3. 确认前端永远由 Desktop 静态托管，只有 `routeConfig.backendPrefixes` 及其子路径代理后端；优先级固定为保留路由、API、真实静态文件、HTML navigation fallback、404。
4. 用长响应、chunked streaming、SSE 和 WebSocket 分别验证代理；停止后确认 listener、socket 和端口全部释放。
5. 请求 `/__desktop/*`，确认永不落到后端；GET/HEAD `/__desktop/bridge.js` 确认 MIME 为 JavaScript、`Cache-Control: no-store`、`nosniff`，源码包含 chat 和 reserved `not_implemented`，不包含 `assistant.complete`。通过 `/__desktop/actions/call` 调用允许的动作，确认本地同源成功，而缺少 Origin、伪造公网 Origin、`.m` 和 `.wa` 均返回 403。
6. 同时启动两个应用，确认端口与 origin 独立，一个应用停止或异常不影响另一个。

### Desktop Bridge v1

1. 在 Manifest v2 页面执行 `import { desktop, DesktopBridgeError } from "/__desktop/bridge.js"`；确认无 `window.desktop` 全局对象。逐项验证 `capabilities.list()` 的 `status` 和 permission；公开能力的兼容字段 `declared=true`、reserved 为 false，`has()` 对 available 能力返回 true。
2. 不在 Manifest 声明 capability，通过 `userConfig.fields` 中 `type: "select"`、`source: "desktop.agents"` 的字段选择 Agent，并确认选择结果按字段 `name` 保存在包外用户配置中；验证默认 Helper Agent、显式 Agent 和统一 `{ text, agentKey, chatId, runId }` 返回。确认 Desktop 原样转发 message，不追加 instruction；显式 Agent 不可用和 message 超过 12,000 字符返回明确错误。
3. 尝试从页面或后端传入 agentKey、instruction、permission、chatId、runId 与 full_access，确认全部拒绝。带后端的 WebApp 自动获得一次性 token 且只能调用 chat；停止、异常退出和重启后旧 token 失效，原生页面 actions 不能用后端 token 调用。
4. 分别调用 browser、files、directory、savePath、clipboard write 与 notification：browser 只接受 HTTP(S)；对话框取消和单选/多选/过滤器正确，返回 path/name 但不读文件，savePath 不创建文件；剪贴板超过 1 MiB 拒绝且没有 read API；通知只接受 title/body，第 6 次短时调用限流，点击最多聚焦所属 WebApp。浮动窗口打开对话框时确认其为 owner，否则归属主窗口。
5. 在 macOS 与 Windows 分别验证麦克风 `prompt/granted/denied`，覆盖 workspace guest 和浮动窗口。`open()` 先请求权限再返回 audio-only `MediaStream`，调用每个 track 的 `stop()` 后停止；video 或 audio+video 请求拒绝。确认音频不经过 Desktop Action Bridge、日志或上传链路，停止 WebApp 后旧页面不能继续借 capability 请求。
6. 调用 screen capture、clipboard read、file reveal、五个 window、三个 camera 和 share 预留函数，确认 Promise 固定以 `DesktopBridgeError.code=not_implemented` reject，没有系统弹窗或 IPC/action fallback；`capabilities.list()` 标记 reserved，旧 Manifest 尝试在兼容数组中声明 reserved 能力仍会安装失败。

### 后端进程

1. 清空系统 Node 路径后启动 electron-node 包，确认使用 Electron runtime 的独立子进程，且安装阶段不执行 `npm install`。
2. 后端检查 `HOST`、`PORT`、`WEBAPP_ID`、`WEBAPP_ROOT`、`WEBAPP_MANIFEST_PATH`、`WEBAPP_DATA_DIR`、`WEBAPP_STATE_DIR`、`WEBAPP_LOG_DIR`，确认值正确且目录已创建；manifest env 不能覆盖保留变量。
3. 让后端启动失败、健康超时和运行中异常退出，确认 gateway 关闭、状态为 `error`、整个进程树被清理且错误进入 `error.log`。
4. 在 macOS arm64/x64 与 Windows arm64/x64 对相应 executable 验收；确认 target 严格匹配，Windows 拒绝非 `.exe` 入口，Desktop 检查 PE/Mach-O 格式。
5. 对 HTTP/TCP health、参数/环境、shutdownTimeoutMs、停止和子进程树清理分别验收；确认不经过 shell、cwd 固定安装根目录。

### Python 与 Java runtime

1. 准备 `command.type=runtime` 的 Python 和 Java/JAR 示例，在设置页将 runtime 绑定到本机绝对路径；确认绑定保存在 Desktop 本地设置且不写回 Manifest。
2. 清空绑定后验证 PATH fallback、最低版本探测和版本过低场景；不可用时让用户选择已有可执行文件，不自动下载。
3. 验证 Python 与 Java 按 `<webapp-id>:<runtime>` 分别绑定；卸载程序不修改其他 WebApp 的绑定。

### 安装事务、状态与回归

1. 用相同 id 更新运行中的应用，确认流程为同盘 staging → 停旧版 → backup rename → 激活新版 → 启动验收 → 删除 backup；最终仍只有 `webapps/<id>/`，没有 `versions/` 或 `current.json`。
2. 分别在 staging 校验、旧目录 rename、staging rename、新版健康验收阶段注入失败，确认旧版立即恢复并按更新前状态重启。
3. 在 `backed-up` 和 `activated` journal 阶段强制结束 Desktop；重启后确认正式目录缺失时恢复 backup，正式目录完整时清理遗留 staging/backup。
4. Windows 在停止进程树后模拟文件占用，确认 rename 有界重试且最终失败时可恢复；macOS 同时确认恢复后的 native 执行位。
5. 更新前后写入 `webapp-data/<id>`，确认升级与失败回退均保留；卸载后确认程序和持久数据删除，不保留历史版本。
6. 收起侧栏后打开 Sites 弹层和 WebApp 操作菜单，确认“关闭 webview”可点击且能关闭
   当前 surface，关闭后 Sites 弹层和操作菜单均消失；“卸载 WebApp”不出现；点击“在新窗口打开”
   后确认独立非模态窗口出现。
   展开侧栏后确认“关闭 webview”仍可用且卸载操作恢复。
7. 新安装 Python/Java runtime 缺失或版本过低时确认安装暂停并要求选择本机路径；已有应用升级前置或健康检查失败时确认旧版目录未被替换或被完整恢复。
8. 设置页确认 `blocked/error/stopped/running`、id/key/version/target、routeConfig、command、health、userConfig、Bridge 版本和 runtime 绑定展示正确，不再显示 Manifest capability 数组。
9. 安装调用 `assistant.chat` 的 WebApp，验证 Agent 来自动态 userConfig，默认 Helper 可回退，`appConfig + userConfig` 提示词由 WebApp 组合，Desktop 不追加 instruction 且调用方不可覆盖 Agent。
10. 让小君创建并通过 `desktop.webapp.install({ archivePath, expectedId? })` 安装纯前端 WebApp，确认侧栏刷新但应用保持 `stopped`，没有导航、`webUrl`、`.wa` 发布或启动副作用；传 `itemId` 或缺少 `archivePath` 均返回 `invalid_args`，市场来源只能使用 `desktop.market.installItem`。随后显式 `open`，确认状态和 `webUrl` 正确；Bootstrap 不持有构建或桌面动作权限。
11. 保持移动端订阅 `webapp.changed` 后安装应用，确认 `.m` 地址可用且 catalog 不含 launcher 路径、Java 路径、容器名、内部端口、安装路径、阻塞详情或 token；断开移动端不影响本地安装。
12. 对 stopped WebApp 直接调用 `desktop.webapp.publish`，确认返回 `webapp_not_running` 且没有启动/gateway 副作用；设置页一键发布显式执行 `start -> publish`，确认 Tunnel 未配置时提示清晰，配置后发布、二维码、停止分享和 `.m` 链路正常。调用 `unpublish` 后确认 runtime 仍运行且本地数据保留；重启 WebApp 后稳定路由同步到新 gateway 端口。
13. 模拟 Tunnel 路由禁用失败后删除已发布 WebApp，确认删除被阻止；恢复后确认先禁用路由，再删除程序与应用数据并发送 `removed`。
14. 分别从展开侧边栏、市场和插件资源卸载正在显示的 WebApp，确认三条入口均先卸载内嵌 `WebContentsView`、关闭独立窗口并阻止再次打开；runtime stop 或 PID 复验失败时不删除程序、数据、state、logs 和安装记录。
15. 确认 action 与 WebSocket catalog 包含 `install`、`checkRuntime`、`getPublishStatus`、`uninstall`，且不包含旧别名。Manifest v2 不声明 capability，直接从本地页面调用 `desktop.native.dialog.selectDirectory`，确认 macOS 与 Windows 都显示 Desktop 原生目录选择器，取消返回 `canceled=true`，选择目录只返回 `path`/`name`。缺少 Origin、伪造公网 Origin、`.m` 与 `.wa` 页面调用均为 403 且不弹框。
16. 在设置中将一个 WebApp 的打开方式设为“浮动窗口”，确认侧边栏点击后当前主页面和路由保持不变，
    WebApp 在独立 Electron 窗口内完成启动；窗口可拖动、缩放、最小化和最大化，操作主窗口导航与设置
    不受影响。再次点击同一 WebApp 应聚焦原窗口而不创建第二个窗口或后端；另一个浮动 WebApp 可并行
    打开。关闭原生窗口及侧边栏“关闭”都停止对应 runtime。再改回“主页面”并重启 Desktop，确认偏好
    持久化；未设置本机偏好的 WebApp 默认按主页面打开。分别验证 macOS 与 Windows 原生窗口控制行为。
17. 将一个 WebApp 以内置方式打开，从侧边栏该应用的操作菜单选择“在新窗口打开”，确认内置 surface
    退出、浮动窗口出现且内容区没有额外 Desktop 工具栏，PID、gateway URL 和后端端口均未变化，
    `openMode` 写为 `dialog`。再次打开侧边栏操作菜单，确认文案替换为“在内置窗口打开”；点击后

## 打包与卸载

1. macOS 执行 `BRAND=zenmind npm run dist:mac`，确认 DMG 输出。
2. Windows 主机执行 `BRAND=zenmind npm run dist:win`，非 Windows 主机执行 `npm run dist:win-docker`；检查 `win-unpacked/<ProductName>.exe` 的 PE 版本资源中 `InternalName`、`FileDescription` 和 `ProductName` 均为品牌名而不是 `electron.exe`/`Electron`，安装后任务管理器中的主进程、renderer、GPU 和 utility 子进程均显示品牌名。
3. 设置 `ENV_ZIP` 打包，确认首启导入只复制缺失文件。
4. macOS 运行应用包内 `uninstall.sh`，确认默认保留数据，选择清理时删除运行数据和程序数据。
5. 分别运行 ZenMind/CuteJ Windows 安装器，确认界面没有程序目录选择页，实际 `$INSTDIR` 始终为 `%LOCALAPPDATA%\Programs\<ProductName>`；即使静默安装传入 `/D=<其他路径>` 也不得改变程序安装目录。在唯一的数据目录页选择父目录，确认实际 `DataRoot` 为 `<父目录>\.<brand>`、`DataRootLayoutVersion=2`。数据根和安装根都有内容匹配的 `.desktop-owner`，程序目录标记位于同级 `%APPDATA%\<ProductName>.desktop-owner`；首次启动部署服务后该同级标记仍存在。
6. 保留一个合法且非空的已登记 `DataRoot` 后再次运行交互安装器，确认数据目录选择页仍然显示，并默认选中现有数据根的父目录；直接选择已有的 `.<brand>` 数据目录时不得生成 `.<brand>\.<brand>`。静默安装不得弹出该页面。
7. 在固定程序目录的父目录 `%LOCALAPPDATA%\Programs` 放置 sibling canary，依次测试首次安装、覆盖安装、卸载和重装；确认只创建或删除 `<ProductName>` 专属目录，父目录及 sibling canary 始终保留。已有空默认程序根可以安装，已有无标记非空默认程序根必须被拒绝。
