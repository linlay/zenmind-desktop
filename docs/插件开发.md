# 插件体系与生命周期

## 文档定位

本文描述 Desktop 插件的形态、包边界、生命周期和安全约束。Manifest 字段全集、类型定义、默认值和废弃字段以共享 contract、校验器及测试为准。

## 插件模型

插件用于扩展 Desktop 的服务、资源或两者组合：

- **运行时服务插件**：包含受管程序、生命周期入口、健康检查和可选 UI。
- **资源插件**：向 Agent Platform 或 Desktop 注册 Agent、Skill、Tool、Team 等声明式资源。
- **混合插件**：同时包含运行时服务与资源，但仍分别遵守两个领域的所有权规则。

插件可以没有 UI、提供嵌入页面或作为独立 surface。UI 形态不改变插件的进程、文件和权限边界。

## 包与 Manifest

插件通过单顶层 ZIP 导入，顶层目录、插件 id 和 manifest identity 必须一致。包内只包含可发布程序、manifest、生命周期脚本、配置模板和声明式资源，不包含用户数据或真实密钥。

Manifest 描述：

- 身份、版本、平台和程序入口。
- 服务生命周期、健康检查和运行文件。
- UI 形态与宿主入口。
- 设置 schema、资源声明、Desktop actions 和受限 hooks。
- Desktop 可以注入的布局和能力。

Manifest 是插件包 contract，不是任意 Electron 配置。未知字段、旧 schema、越界路径和未声明能力必须被拒绝。

## 生命周期

```text
选择 ZIP
  -> 校验归档、平台、identity 与 manifest
  -> 解压到同盘临时目录
  -> 安装程序版本
  -> deploy 插件配置和资源
  -> 注册服务、设置、动作和 UI
  -> 按需 start / stop / upgrade / uninstall
```

导入必须是事务性的：校验失败不写入安装目录，升级失败保留旧可用版本。插件进程复用 service manager 的程序/配置/数据/状态/日志分层，但插件配置内容仍由插件 deploy 负责。

卸载先停止受管进程并注销动作、快捷键、资源和 UI，再删除插件程序。是否删除用户配置与数据由明确卸载策略决定，不能根据包缺失推测。

## 设置与用户数据

Manifest 可以声明宿主渲染的设置字段或受限设置页面。实际用户值保存在包外的插件配置根，升级插件程序时保留。

renderer 不直接读取插件 `.env` 或任意文件。宿主只按 schema 暴露允许的字段，并在保存、启动和日志输出时保护敏感值。

## 资源与动作

声明式资源在安装或升级时通过对应领域安装器处理。插件不能直接修改 Agent Platform 数据库或其他插件目录，也不能用脚本绕过资源 contract。

Desktop Action 必须使用 canonical 名称、结构化参数和明确权限。插件只能注册 manifest 声明且通过宿主校验的动作；远端页面、Website 或普通 WebApp 不能借插件扩大原生权限。

全局快捷键、bridge 和 hooks 都由 Desktop 统一仲裁。冲突或不支持的平台能力可以保存为禁用状态，但不能覆盖现有系统或用户快捷键。

## 兼容与版本策略

- 当前插件 schema 是唯一写入格式，不为未发布或已废弃字段增加双读。
- 兼容代码只处理已经存在的用户安装数据，并应有明确删除条件和测试基线。
- 平台命令、可执行文件名和脚本解释器必须显式区分 macOS 与 Windows。
- 插件版本变化不自动改写用户配置；需要迁移时由插件 deploy 承担。
- Desktop 不维护空 denylist 式“退休插件”机制，也不因启动、市场列表或加载判断隐式删除插件数据。未来退休插件必须采用独立、可测试的迁移或卸载流程，明确程序、配置、用户数据、运行状态和日志分别保留或删除的规则，并由用户可见操作或版本化迁移触发。

## 安全约束

- 拒绝路径穿越、符号链接逃逸、超限归档和不安全可执行入口。
- 插件拿不到 Desktop 长期 token、其他插件密钥或任意 Electron API。
- Service WebView 使用受限 preload；设置页面与普通网页不能直接进入 main IPC。
- 日志和安装记录不保存真实密钥、授权 URL 和用户文件内容。
