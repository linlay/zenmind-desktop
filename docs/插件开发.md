# 插件开发

## 当前状态

Desktop 插件统一以 `.zip` 分发和导入。插件安装到品牌程序数据目录 `plugins/<plugin-id>/<version>/`，配置保存到 Desktop 数据根 `config/plugins/<plugin-id>/`，状态和日志分别保存到 `state/plugins/`、`logs/plugins/`。

插件导入只负责解包、校验 manifest、注册服务和保留已有配置；非 resource 插件导入后通常进入“待初始化”，用户在控制中心点击初始化后执行 `lifecycle.deploy`。

## 核心流程

```text
plugin .zip
  -> installPluginFromArchive()
  -> extract temp dir
  -> read manifest.json
  -> normalizeManifest(defaultKind: plugin)
  -> copy to plugins/<id>/<version>
  -> preserve config files and plugin resource ownership
  -> fix .sh permissions
  -> registerService()
  -> initializeService() when serviceMode === "resource"
```

插件包结构建议：

```text
my-plugin/
├── manifest.json
├── start.sh / start.ps1
├── stop.sh / stop.ps1
├── deploy.sh / deploy.ps1
├── .env.example
├── backend binary or scripts
└── frontend/dist/
```

## 配置与接口

manifest 关键字段：

- `id`、`name`、`version`、`description`。
- `pluginApiVersion`：插件 API 版本。
- `service.ui`：`none`、`embedded`、`standalone`。
- `service.web.healthPath`、`service.web.portEnvKey`、`service.web.defaultPort`。
- `lifecycle.start`、`lifecycle.stop`、`lifecycle.deploy`。
- `configFiles`：配置文件和模板路径。
- `runtime`：PID、日志、错误日志和 required paths。
- `desktop.actions`：插件暴露给 Desktop 的动作。
- `bridge.requests`、`hooks.subscribe`、`resources`、`settings`：插件桥接、资源声明和设置 UI。

插件相关动作：

- 导入 `.zip`。
- 初始化、启动、停止、重启。
- 打开前端。
- 调用 manifest 中声明的 desktop action。
- 卸载插件并移除插件资源。

## 约束与注意事项

- Desktop 所有平台只接受 `.zip` 插件包。
- 插件包解压后必须有单个顶层目录。
- `kind: "builtin"` 的包不能作为插件导入。
- 插件 manifest 不再支持旧字段 `kind`、`scripts`、`frontend`、`web`；旧字段会在导入时硬失败。
- `lifecycle.deploy` 必须幂等，能够安全重复执行。
- Windows 插件脚本使用 `.ps1`，macOS / Linux 使用 `.sh`。
- 插件如需设备标识，后端读取 `DESKTOP_DEVICE_ID`；需要认证的前端通过 token payload 读取 `device_id`。
