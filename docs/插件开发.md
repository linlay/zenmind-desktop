# 插件体系与生命周期

## 文档定位

本文描述 Desktop 插件的形态、包边界、生命周期和安全约束。Manifest 字段全集、类型定义、默认值和废弃字段以共享 contract、校验器及测试为准。

## 插件模型

插件是扩展能力的组合容器，可整合智能体、WebApp、系统功能、受管服务及其他声明式资源。插件级清单描述整个组合，WebApp 清单只描述其中单个 WebApp，不代表完整插件。当前插件级清单使用 `manifest.json`，WebApp 使用 `webapp.json`。现有生命周期形态包括：

- **运行时服务插件**：包含受管程序、生命周期入口、健康检查和可选 UI。
- **资源插件**：向 Agent Platform 或 Desktop 注册 Agent、Skill、Tool、Team 等声明式资源。
- **混合插件**：同时包含运行时服务与资源，但仍分别遵守两个领域的所有权规则。

插件可以没有 UI、提供嵌入页面或作为独立 surface。UI 形态不改变插件的进程、文件和权限边界。

插件运行程序通过[通用系统桥接](插件系统桥接.md)使用宿主能力。系统能力不依赖 WebApp，插件可以用本地界面资源或独立原生程序呈现；窗口样式、业务数据与恢复策略均归插件。Desktop 不维护具体插件的业务窗口管理器。

## 包与 Manifest

插件通过单顶层 ZIP 导入，顶层目录、插件 id 和 manifest identity 必须一致。包内只包含可发布程序、manifest、生命周期脚本、配置模板和声明式资源，不包含用户数据或真实密钥。

Manifest 描述：

- 身份、版本、平台和程序入口。
- 服务生命周期、健康检查和运行文件。
- UI 形态与宿主入口。
- 设置 schema、资源声明、Desktop actions 和受限 hooks。
- Desktop 可以注入的布局和能力。

Manifest 是插件包 contract，不是任意 Electron 配置。未知字段、旧 schema、越界路径和未声明能力必须被拒绝。

## 生命周期

```text
选择 ZIP
  -> 校验归档、平台、identity 与 manifest
  -> 解压到同盘临时目录
  -> 安装程序版本
  -> deploy 插件配置和资源
  -> 注册服务、设置、动作和 UI
  -> 按需 start / stop / upgrade / uninstall
```

导入必须是事务性的：校验失败不写入安装目录，升级失败保留旧可用版本。插件进程复用 service manager 的程序/配置/数据/状态/日志分层，但插件配置内容仍由插件 deploy 负责。

卸载先停止受管进程并注销动作、快捷键、资源和 UI，再删除插件程序。是否删除用户配置与数据由明确卸载策略决定，不能根据包缺失推测。

本地 ZIP 导入与市场安装、更新、卸载共用应用装配根创建的插件生命周期入口。该入口使用已注入集成端口的 Services facade 和同一 WebApp manager；插件加载器、市场模块和卸载确认流程不能直接调用未装配的服务生命周期函数或默认 WebApp 实例。停止失败时中止卸载，初始化失败时不写入新的市场已安装记录。

资源插件首次导入完成初始化后保持停止，由用户启动时加载声明式资源。重新导入保留资源的期望状态及包外用户数据；已有初始化失败的安装可以重试初始化恢复，无须先删除便签等应用数据。

## 设置与用户数据

Manifest 可以声明宿主渲染的设置字段或受限设置页面。实际用户值保存在包外的插件配置根，升级插件程序时保留。

renderer 不直接读取插件 `.env` 或任意文件。宿主只按 schema 暴露允许的字段，并在保存、启动和日志输出时保护敏感值。

## 资源与动作

声明式资源在安装或升级时通过对应领域安装器处理。插件不能直接修改 Agent Platform 数据库或其他插件目录，也不能用脚本绕过资源 contract。

插件声明的 Agent 由 Desktop 按文件协议交付到品牌运行根的 `agents/<key>/`，不调用 Platform Agent 创建、更新或删除接口。Desktop 只生成插件声明的定义和提示词，不补齐 Platform 业务默认值；Platform 负责校验、监听、加载与执行目录组装。Platform 停机不妨碍 Agent 来源目录的交付和移除，目录交付完成不代表运行期已加载。Desktop 不操作 `ru-agents`、连接器目录或运行租约。

来源目录先在隐藏暂存目录准备完整，再发布；更新和删除只接受本插件记录的安装身份与内容摘要，拒绝同名外部来源、符号链接、额外文件和用户修改。既有 API 安装记录没有摘要时，只允许接管与当前插件声明完全匹配的来源（忽略 YAML 格式差异），无法确认时保留现场并报错，不猜测或抹去服务补齐的配置。记录提交失败恢复原目录；不能恢复时保留隐藏备份并报告恢复路径。这是文件交付协议，不承诺与外部编辑器之间的快照隔离或跨进程崩溃原子性。

已加载插件升级或重新安装时，以新版声明逐项同步全部 Agent，并在原有资源记录中保存每个 Agent 成功同步的插件版本；发布完新版 Agent 后，再清理不再声明的旧 Agent。新版 Agent 清单为空也必须检查原有归属记录，不能跳过清理。每项成功后记录进度，冲突或失败保留剩余记录供重试；已停止的资源插件仍保持停止，下次启动时加载新版。

Windows 目录占用时停止本次变更，保留记录供重试，不原地强删；macOS 同样在目录操作失败时回滚。插件资源操作在 Desktop 内按插件串行，防止就绪重试与停止、卸载互相覆盖。自动任务仍通过现有 Platform API 管理，删除成功逐项更新清理进度；Platform 不可用或任一清理失败时卸载明确失败，保留插件及待清理记录，全部成功后才删除插件程序和记录。

自动任务更新只有收到 Platform 明确的任务不存在响应才转为新建；超时、鉴权失败、校验错误和服务故障保留原任务身份并报告失败。删除时明确不存在视为已清理，允许成功响应丢失后重试收尾；普通 HTTP 路由不存在不能据此删除归属记录。

Desktop Action 必须使用 canonical 名称、结构化参数和明确权限。插件只能注册 manifest 声明且通过宿主校验的动作；远端页面、Website 或普通 WebApp 不能借插件扩大原生权限。

全局快捷键、bridge 和 hooks 都由 Desktop 统一仲裁。冲突或不支持的平台能力可以保存为禁用状态，但不能覆盖现有系统或用户快捷键。

## 兼容与版本策略

ACP 引擎资源接入既有 Manifest/normalizeManifest 与 loader/lifecycle。精确声明见本仓库 `src/shared/contracts/agent-engine.ts`、`manifest.ts` 及安装校验测试；不依赖工作区计划书。普通插件使用 API v1，首版 API v2 为纯引擎资源声明；引擎包不混合其他资源、生命周期脚本或 Desktop 执行能力。类型仍归现有 contracts，不引入专属 Schema 或生成流程。

安装复用受管 Node 和 ZIP 安全检查，在私有暂存区核对来源、版本、包内依赖与全树摘要，准备独立 Desktop 交付副本；初始化成功后最后原子提交交付指针。异常恢复旧程序/状态/注册信息，重启只发现已提交的引擎交付；安装不执行 Adapter 或启动端口服务。市场与本地导入共用同一事务顺序。

Platform 仍拥有执行快照、会话和持久 profile；Desktop 卸载须获得真实撤销确认后再清理自身副本。ACP-004 已接通专用管理通道，只有匹配修订的确认才能标记已同步；未建立启动信任时保持待同步，不能绕过撤销确认删除。目录同步、执行及实际运行期升级不属于安装完成的证明。

引擎插件由 Desktop 交付可信包与启用意图，Platform 持有执行快照和进程；管理注册使用启动时建立的独立本机能力，不借用 app token 或 Plugin Bridge。该域不沿用“启动端口服务再自注册”的旧 ACP 方式，安装、同步与卸载已由下述链路承接，实际产品验收见 [ACP 手工标准](../qa/acp-acceptance.md)。

- 当前插件 schema 是唯一写入格式，不为未发布或已废弃字段增加双读。
- 兼容代码只处理已经存在的用户安装数据，并应有明确删除条件和测试基线。
- 平台命令、可执行文件名和脚本解释器必须显式区分 macOS 与 Windows。
- 插件版本变化不自动改写用户配置；需要迁移时由插件 deploy 承担。
- Desktop 不维护空 denylist 式“退休插件”机制，也不因启动、市场列表或加载判断隐式删除插件数据。未来退休插件必须采用独立、可测试的迁移或卸载流程，明确程序、配置、用户数据、运行状态和日志分别保留或删除的规则，并由用户可见操作或版本化迁移触发。

## 安全约束

- 拒绝路径穿越、符号链接逃逸、超限归档和不安全可执行入口。
- 插件拿不到 Desktop 长期 token、其他插件密钥或任意 Electron API。
- Service WebView 使用受限 preload；设置页面与普通网页不能直接进入 main IPC。
- 日志和安装记录不保存真实密钥、授权 URL 和用户文件内容。

## 引擎安装后的同步与恢复

引擎资源沿用原安装/市场入口与资源启停。安装完成、交付指针提交后发布完整期望清单；升级保留启用意图。安装、升级、禁用和卸载共用原插件事务队列，读交付失败时拒绝发送不完整快照。期望状态、修订和清单签名原子保存；响应丢失以同修订重试，不能将超时当成未生效。

组合根装配专用管理客户端。Platform 启动时读取 Desktop 私有一次性文件；秘密仅用于本机管理请求，不经过插件、普通应用 token 或 renderer。Platform 重连通过现有资源重试及 RealtimeBroker 完整对账，公共目录失效通知触发重读。服务列表分别显示同步、依赖、认证和运行状态；安装成功不等于登录或运行成功，过期页面/目录响应不覆盖新状态。

启用意图尚未获得 applied 确认时，不计为运行中；沿用停止状态保留启动重试入口，原提示区域显示同步状态与脱敏错误码。启用/停用命令只有确认同步后才返回成功并发出对应生命周期 hook；pending 期间仍允许撤销启用意图，不能因当前未运行而跳过撤销。无需新增 UI 或状态枚举。

离线卸载先持久化移除意图并保留安装文件，恢复后同步撤销；确认后用户重试卸载完成本机清理。Desktop 不清理 Platform 快照、profile 和 Chat。正常热插拔不重启 Platform；Desktop 重启失去内存管理凭据而旧 Platform 仍存活时，通过原生命周期重启该受管进程一次以重建信任，可能中断该旧进程的任务。

## ACP 接入边界

旧端口服务注册、Bridge 变更方法与配置变更 hook 已删除。普通 Plugin Bridge 的请求、事件与其他插件功能继续保留；引擎资源只能通过 Manifest 受信交付及专用目录管理通道接入，没有自动回退或修改 Platform 配置的路径。

认证由 Platform 持有操作和进程租约，嵌入的 WebClient 显示登录状态、会话配置和精确权限选项；终端登录复用现有 Terminal 通道。登录入口固定来自受信 Manifest，并与执行共用 profile/代理。历史 macOS 通过项不能替代新版本及 Windows 验收；当前组合按 [ACP 手工标准](../qa/acp-acceptance.md) 逐项记录。

## 活动引擎的更新与卸载（ACP-014）

Platform 在发布启用候选前进行有界协议预检；导入/启用写请求使用 30 秒期限，目录读取保留 5 秒。超时维持 pending 并按原修订对账，不推断提交失败。Desktop 已安装的交付版本与 Platform 当前可执行版本不同步时保持待同步，不能把下载/解压成功当作可运行。

卸载先持久化 removed 并同步撤销，再检查 ACK 中本插件的 drainingEngineIds。活动进程未排空返回 engine_busy，保留安装和交付文件；用户等待完成后重试，或使用现有聊天 Stop 明确取消后重试。不新增 UI 和隐式取消，不能将撤销准入视为进程已停止。Platform 独立回收快照并保留 Chat/profile。离线和 ACK 丢失仍遵循原有持久意图及幂等重连流程。

## Agent 引擎通用化边界

引擎 Manifest API v2 当前要求 Platform Agent Engine API 2（WebClient API 1）；沿用原解析器拒绝版本不匹配，不为旧包保留厂商环境或 relay 回退。认证声明随受信包进入 Platform；Desktop 只校验/交付，不按认证产品名分派。Platform 提供私有 profile 根，插件自行解释厂商变量和子目录，UI 仍消费目录与能力。

旧 local-cli-acp-relay 的 Node 启动特例和旧 Claude ACP/npx 解析器已移除；普通插件只通过原 Manifest/envBindings 与自己的部署脚本获得声明的配置。通用布局占位符和内置 Platform 受管 Node 准备保持原职责，不再依赖旧 relay 的测试或导出。


### 引擎程序的交付形式

Manifest `launch.runtime` 支持 `node` 和 `executable`。前者必须声明精确版本的 host-managed Node；后者直接运行包内入口，macOS 需要执行位，Windows 必须为 `.exe`。仅需要 Node 的插件触发运行时准备。adapter 来源描述可省略；Desktop 不以 node_modules、package.json 或某一 JS SDK 布局判定 ACP 程序。bundled 依赖以 path 声明文件/目录，entry 如存在须位于其内或为该文件本身；实际字节由受信整树摘要固定。

构建器负责依赖版本与目标平台内容；Desktop 保留 ZIP 路径/链接/权限/摘要校验和原安装事务，Platform 负责初始化预检、运行和版本排空。未知 runtime、任意系统命令和请求注入的 env 不接收。新增可执行交付需要新版 Desktop 与 Platform；WebClient、AGW 与现有 UI 不变。真实第三引擎及 Windows 原生运行仍须独立验收。
