# 插件系统桥接

## 定位与所有权

插件是可独立运行的扩展，可组合智能体、WebApp、系统功能及其他资源。Plugin Bridge 与 WebApp Gateway 无依赖关系；本地 HTML 是一种界面实现技术，不意味着插件必须注册 WebApp。

Desktop 只提供业务无关的系统能力。插件管理负责程序生命周期、身份与清单声明；系统桥接负责调用验证、窗口归属、事件投递和运行期资源回收；平台适配负责 macOS 与 Windows 的系统调用。界面样式、业务身份、内容、持久状态和恢复策略由插件拥有。

宿主不能枚举业务插件，不根据插件名称执行不同系统操作。接口不能包含便签、日历、文档库等业务概念。创建新插件应组合既有系统能力；新增系统能力以操作系统语义定义。

## 运行链路

插件运行程序通过已有的认证 Plugin Bridge 调用系统能力。macOS 使用本地 socket，Windows 使用命名管道。插件级清单声明允许请求的方法与订阅事件；身份从认证连接取得，不接受请求指定的其他插件身份。

通用窗口返回运行期不透明句柄，后续操作只允许所属插件。页面通过隔离 preload 与所属插件程序交换不透明消息，宿主不解释业务消息。窗口使用独立临时 session 加载插件包内的静态资源，无须 HTTP 服务；路径必须经过 realpath 校验，不能继承 Desktop 登录态或任意 Electron API。

页面不能自行调用通用系统方法。系统调用由插件运行程序通过认证连接发起，窗口页面仅有消息传递能力。

## 系统窗口与平台适配

普通窗口和桌面层窗口具有不同语义。桌面层窗口位于正常应用之下，能够在系统桌面交互；不能以全局置顶代替桌面附着。创建时实际执行系统适配，失败返回错误，不静默改变层级。

macOS 使用正常可交互 NSWindow，并设置桌面图标之上的窗口层级及桌面集合行为。Windows 将窗口附着到 Explorer 桌面图标所在的宿主，显式处理子窗口样式、屏幕坐标和 DPI 换算。Explorer 宿主探测依赖系统桌面实现，必须进行 Windows 实机回归；宿主丢失时报告错误并回收失效窗口，由插件决定重试策略。

原生 FFI 仅供宿主平台适配内部使用。插件不能提供库名、函数名、指针或原生窗口句柄。打包必须携带目标系统与架构的原生依赖，不能以开发机可运行替代目标平台验证。

## 生命周期与状态

模块装配阶段不注册系统监听或加载原生窗口依赖。系统窗口模块在插件首次调用时加载，并在 Electron ready 后才注册监听；未使用插件时不向启动就绪流程增加任务。提前退出只清理已初始化的资源，释放后不能因迟到的请求重新初始化。

Desktop 只保存运行期句柄与所属插件，不保存窗口布局或决定恢复哪些业务窗口。移动、缩放和关闭请求通过定向事件交付插件；插件保存布局、完成待保存操作后请求销毁窗口。

插件连接断开、停止或宿主退出时统一回收其系统窗口，不允许业务页面阻止宿主清理。窗口创建期间的停止会使在途创建失效。插件再次启动后按自己的数据重建窗口；启动恢复不添加任何业务插件的特殊分支。

JavaScript 生命周期脚本可使用宿主 Node 运行时执行；macOS 与 Windows 共用结构化命令参数。脚本负责插件的进程和数据，宿主不代写插件业务配置。
