# 数据目录与所有权边界

## 文档定位

本文描述 Desktop 数据分层、目录所有权和保留策略。具体文件名、路径函数、注册表字段、事务日志和 schema 以源码及测试为准，不在本文重复维护。

## 设计目标

Desktop 将用户运行数据与可替换的程序产物分开保存，并按品牌隔离。目录设计需要保证：

- macOS 与 Windows 的路径来源明确，平台差异显式处理。
- 覆盖安装、程序升级和普通启动不会误删用户数据。
- 服务、插件和 WebApp 获得相互隔离的运行目录。
- Desktop 只分配目录和编排生命周期，不解释服务拥有的配置内容。

## 三层根目录

| 根目录 | 主要内容 | 生命周期与所有者 |
| --- | --- | --- |
| 品牌运行根 | Agent、Skill、Registry、Team 等共享运行环境 | 用户长期数据，由对应平台能力管理 |
| Desktop 数据根 | 配置、业务数据、状态、日志、缓存、密钥和 Electron profile | Desktop 管理结构，各领域管理内容，升级默认保留 |
| 程序数据根 | 内置服务和插件的版本化程序文件 | Desktop 安装和替换，可以从发布包重建 |

Desktop 数据根位于品牌运行根的品牌配置子目录下。它只固定以下一级分区：

```text
<desktop-data-root>/
├── config/
├── data/
├── state/
├── logs/
├── cache/
├── secrets/
└── profiles/
```

二级目录及文件由相应领域模块定义。设计文档不维护完整叶子目录树，以免与源码产生两个事实源。

## 平台路径

### macOS

- 品牌运行根从 Electron 的用户主目录和品牌配置派生。
- 程序数据根从 Electron `appData` 路径和品牌程序目录名派生。
- Desktop 不依赖当前工作目录、安装包位置或开发者主目录推导用户数据。

### Windows

- 已登记且有效的数据根优先作为品牌运行根；没有登记值时从 Electron 用户主目录和品牌配置派生。
- 程序数据根从 Electron `appData` 路径和品牌程序目录名派生。
- 安装器选择的是数据父目录，实际管理和删除的只能是其下经过校验的品牌专属目录。
- 注册表读取、路径规范化、重解析点和所有权校验必须使用 Windows 专属实现，不能复用 macOS 路径假设。

## 所有权边界

Desktop 负责：

- 解析并创建顶层目录。
- 为服务、插件、WebApp 和 Desktop 自身分配隔离的配置、数据、状态与日志位置。
- 将目录作为生命周期参数传给受管程序。
- 在安装、升级、回滚和卸载时限制操作范围并保护用户数据。

内置服务负责：

- 解释和维护自己的 `.env`、YAML 或其他领域配置。
- 创建服务内部运行目录和默认内容。
- 清理旧配置键并执行配置迁移。
- 在服务自己的 `deploy.sh` 或发布流程中完成初始化。

Desktop 不合并、修复、标准化或生成内置服务配置，也不根据服务内部文件猜测兼容行为。

## 数据生命周期

- 服务和插件的程序版本可以安装、替换或清理；其配置、数据、状态和日志位于独立运行目录。
- WebApp 的程序包与持久业务数据分离；安装事务可以回滚程序，但不能因此覆盖应用数据。
- 临时安装、备份和恢复路径必须位于对应资源根内，不能接受或跟随越界路径。
- `env.zip` 的导入、还原和资源同步属于启动生命周期；目录文档只规定其不得破坏既有用户数据。
- 覆盖安装和版本变化不整体清空 Desktop 数据根。
- 卸载默认保留用户数据。只有用户明确选择清理且平台所有权校验通过时，才能删除品牌专属数据根。

## 安全约束

- 用户路径优先从 Electron `app.getPath()` 和品牌配置派生，不硬编码 home、AppData 或 Application Support。
- 程序文件不写入 Desktop 数据根；运行配置、数据和密钥不写入程序版本目录。
- renderer 不接触密钥目录、任意本地路径或服务配置文件。
- 日志、缓存和可重建状态不能成为业务数据的唯一事实源。
- 删除逻辑不得接收磁盘根、用户主目录、用户选择的裸父目录或未经规范化与所有权验证的路径。
- macOS 与 Windows 分别验证安装、升级、回滚和卸载路径，不能以单平台结果代替另一平台检查。

## 实现事实源

- `src/main/runtime-root.ts`：品牌运行根与 Windows 登记路径解析。
- `src/main/user-paths.ts`：Desktop 数据根、程序数据根及领域目录入口。
- `src/main/services/manager/layout.ts`：服务程序与运行目录映射。
- `src/main/webs/`：Website 和 WebApp 的持久化及安装事务。
- 路径、安装、升级和卸载相关测试。
