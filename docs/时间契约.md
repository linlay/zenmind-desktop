# 时间契约

## 目标

Desktop 在主进程、preload、renderer 和 shared contracts 间，使用 Unix epoch milliseconds 表示具体时间点。基础实现位于 `src/shared/time-contract.ts`，并由 `src/shared/contracts.ts` 导出；它不改变外部服务或既有业务 DTO。

## Epoch milliseconds

- `EpochMilliseconds` 是唯一的共享时间点类型。有效值为 `0..8_640_000_000_000_000` 内的安全整数，覆盖 `Date` 和 `Intl` 可表示范围。
- 边界必填字段使用 `requireEpochMillis(value, field)`；也可用 `assertEpochMillis(value, field)` 做类型断言。缺失的 `undefined` 或 `null` 会以 `TimeContractViolation` 报错。
- 可选字段使用 `parseOptionalEpochMillis(value, field)`：只有 `undefined` 和 `null` 表示缺失，返回 `undefined`；空字符串、ISO 文本、数字字符串、负数、浮点、`NaN`、`Infinity` 和越界值一律报错。
- `readEpochMillis(value)` 仅保留给确实需要丢弃无效值的兼容读取路径；新边界解析不得据此静默吞掉已提供的无效字段。
- renderer 仅在最终展示时调用 `formatEpochMillis(epochMs, locale?, options?)`。该函数只接收 epoch-ms，且会再次验证输入；不提供字符串兼容解析，也不以当前时间回填失败值。

后续 DTO 迁移应写为 `createdAt: EpochMilliseconds` 与 `expiresAt?: EpochMilliseconds | null`。历史 string 型 `*At` 字段由静态测试的显式基线冻结，本阶段不批量迁移；迁移某个 DTO 时同步缩减基线。

## 字段命名与例外

- 新增 shared contract 的 `*At` 或 `*timestamp` 字段不得是 `string`，静态测试会拒绝。
- 外部协议必须保留 RFC3339 文本时，字段名使用 `iso*` 或 `*Time`，并在该协议旁注明 RFC3339 语义；不要伪装成 `createdAt`、`expiresAt` 等 epoch-ms 字段。
- 可选时间绝不用 `""` 表示缺失。TypeScript 内省略字段使用 `undefined`，需要显式 JSON 空值时使用 `null`。
- JWT 原始 `iat`、`exp` 只在 JWT 解码/校验内部按 Unix 秒处理。离开该内部边界的具体时间点须转换并验证为 `EpochMilliseconds`，不能把秒级 JWT 字段直接当作 shared epoch-ms。
- 通用时间契约的验证器不根据数值大小猜测或转换“秒级数”，以保证 `0` 和早期合法时间可用。`agent-platform` 是显式例外：它的运行态 `*At` / `timestamp` 除 `0` 外必须不小于 `1_000_000_000_000`，Desktop 因而拒绝如 `1_710_000_000` 的 Unix 秒级值；这只是在 Desktop 的 agent-platform 边界拒绝响应，不会改写服务数据，也不适用于 JWT 秒级字段。

## 禁止行为

- 不使用 `Date.parse` 或 `new Date(string)` 把文本兼容为 epoch-ms。
- 不用 `Date.now()`、`0` 或任意猜测值补偿无效或缺失的必填上游时间。
- 不在 Desktop 侧修复、改写或迁移 agent-platform 的时间字段；边界只验证并报告问题。
