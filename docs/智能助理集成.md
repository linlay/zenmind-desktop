# 智能助理集成

## 当前状态

Desktop 的智能助理能力主要通过 `agent-platform` 服务提供。主进程的 assistant bridge 负责把 Desktop UI、Quick/Copilot、桌宠、附件和 agent-platform HTTP/SSE API 连接起来。

设置保存到 Desktop profile，不再保存外部 LLM baseURL/model/apiKey；运行时模型和 agent 配置以 agent-platform 环境为准。

## 核心流程

```text
renderer assistant UI / quick / copilot
  -> main IPC
  -> AgentPlatformAssistantBridge
  -> agent-platform HTTP API / SSE
  -> AssistantEvent
  -> renderer state / pet state / kanban sync
```

主要能力：

- 读取 agent 列表和导航状态。
- 创建 chatId / runId 并启动 run。
- 解析 SSE，识别 `[DONE]`。
- 提交 awaiting question / approval / form / planning。
- 上传附件并映射到 platform resource ticket。
- 读取 chats、chat detail、memory、export。
- 语音转写和语音纠错请求代理。
- 导航 WebSocket 的运行事件用于更新主进程导航快照，并通过只读 preload 事件同步给 renderer。bootstrap agent 的释放只由 nav agent 列表是否仍包含其 key 判定，不根据 run 终态推断。

## 配置与接口

Desktop profile 中的 assistant 字段：

- `voiceCorrectionEnabled`
- `copilot.agentKey`（settings IPC 中投影为 `desktopHelperAgentKey`）
- `chat.agentKey`（settings IPC 中投影为 `chatDefaultAgentKey`）
- `quick.enabled`
- `quick.agentKey`
- `navigation.desktopCopilotPages`

`assistant.chat.agentKey` 只能指向 agent-platform `scope=nav` 返回的导航智能体。未配置 bootstrap contract 的旧 profile 可迁移为首个可用 nav 智能体；一旦配置 `bootstrapAgentKey`，Desktop 不再用候选 fallback 覆盖正式默认值。

侧栏 Projects 仅展示 `mode=CODER` 或 `mode=KBASE` 的项目智能体；Chats 仅面向其他 mode 的普通导航智能体。bootstrap 本身属于 Chat agent：它存在时运行时接管 Chats，但不会写入 `assistant.chat.agentKey`；消失后恢复配置中的正式默认智能体。Chats 最多展示当前智能体最近 8 条会话，超过时打开该智能体的历史页面。

展开 Desktop 侧栏后，只有鼠标 hover Chats 标题行时，才在折叠箭头后显示当前智能体，文案随语言显示为 `Chat with {name}` 或 `与 {name} 对话`；鼠标移出、整个侧栏收起、智能体尚在加载或没有可用 Chat agent 时隐藏该文案。hover/focus 不再打开智能体切换浮层；标题点击仍只控制 Chats 分组折叠，默认 Chat agent 统一在「助理设置」中切换。

侧栏 Chats 和 Projects 分组在没有内容时统一显示居中弱化的空状态引导文案：Chats 为「将鼠标移到「对话」上，点击 + 开始新对话。」（无可用默认 Chat 智能体时保留「请先在助理设置中选择可用的 Chat 默认智能体。」），Projects 为「将鼠标移到「项目」上，点击 + 添加项目。」。bootstrap 引导会话存在时 Chat 空状态替换为降级入口，不显示引导文案；Projects 空状态仅在导航智能体数据已加载后显示。

bootstrap 初始化只复用现有 agent-webclient 对话页和其 Chat 主区域。全新 runtime 通过 env 中的 seed `chats.db` 和 `<bootstrapChatId>.jsonl` 回放一条仅包含 assistant 自我介绍的已完成 run；自我介绍使用 WebClient 已有 Markdown，介绍 Chats、Projects、Sites，并以 `<bootstrapChatId>/bootstrap-overview.png` 作为同一 Chat 的本地资源，由已有 `/api/resource` 图片链路显示。Desktop 不创建初始化内容页面或消息组件。导航数据就绪且 bootstrap 仍存在时，Desktop 每次启动只自动选择一次该 Chat，用户下一条消息沿用同一 chatId，正常经过 WebClient、Run、SSE 与 awaiting。若 seed 未进入已有数据库索引，Desktop 自动打开 bootstrap 新会话并显示同名黄色降级入口，不合并或修复 agent-platform 的数据库。预置 Chat、Help 黄框、浮动气泡和新手引导卡全部以 bootstrap 是否仍在 nav 为生命周期依据。

默认 agent key 来自 shared assistant settings：

- Desktop helper agent。
- Quick assistant agent。

与 agent-platform 交互的服务 id 固定为 `agent-platform`。

## 时间契约

agent-platform 派生的 IPC / preload 数据中的 `createdAt`、`updatedAt`、`startedAt`、`completedAt`、`timestamp` 和 `expiresAt` 统一传递 Unix epoch milliseconds `number`。主进程边界只接受安全整数毫秒（拒绝数字字符串、ISO 文本、十位 Unix 秒、浮点和 `0`）；必填 stream / navigation 时间无效时不更新本地快照，记录诊断并刷新平台快照，绝不补当前时间。

`readAt`、JWT refresh 的 `expiresAt` 等可选时间在上游缺失时保持字段缺失，不编码为 `0` 或 `null`。渲染层只在最终展示时将 epoch milliseconds 格式化为本地可读文本。`full_access` 是权限枚举，不存在 lease expiry，因此 shared contract 不再包含 `fullAccessExpiresAt`；未来若引入 lease，必须使用可选 epoch-ms number 的新字段。

## 约束与注意事项

- Desktop 只保存助理 UI 偏好，不保存真实模型 API key。
- 附件路径必须通过 attachment store 解析，避免直接暴露任意本地路径。
- bridge 需要处理 awaiting 的 pending / answered / cancelled 状态，不能只看单一事件字段。
- `agent-webclient` 的前端鉴权走 Token Bridge，不绕过 identity-center。
