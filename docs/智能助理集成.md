# 智能助理集成

## 文档定位

本文描述 Desktop 与 Agent Platform、Agent WebClient 之间的职责分工，以及 Main Assistant、Copilot 和附件链路的主要设计。接口字段、事件清单和 UI 细节以源码与测试为准。

## 系统边界

- Agent Platform 负责 Agent、Chat、Run、流式事件与工具执行的业务事实。
- Agent WebClient 负责完整聊天页面及其交互体验。
- Desktop 负责服务发现、身份交付、窗口与 surface 编排、页面上下文，以及把平台事件映射为桌面状态。

Desktop 不复制 Agent Platform 的运行状态机，也不把 renderer 变成平台 API 客户端。主进程 bridge 是唯一的平台访问边界。

## 两类助理 Surface

完整 Agent 页面嵌入 `agent-webclient`。guest 通过固定的可信 Platform Frame Port 收发普通平台数据帧与 Run 实时帧，但不获得 App access token；显式 HTTP-only 能力由 Desktop host 注入凭据，Agent Platform 业务 WS 与 Run HTTP/SSE 入口不向 guest 开放，参见[鉴权、SSO 与 Token Bridge](鉴权SSO与TokenBridge.md)。

Main Assistant 是 Desktop 自有的轻量对话 surface：renderer 发送意图，主进程通过专用 bridge 查询 Platform，并把规范化的流式状态推送给 UI。它不复用 WebClient 页面动作面，也不依赖页面 DOM 才能完成基本对话。

## Main Assistant 主流程

```text
renderer 发起对话
  -> main 校验 agent、chat 与附件上下文
  -> 必要时上传附件
  -> Assistant adapter 进入共享 Realtime Broker
  -> Broker 建立或复用唯一 Platform 物理连接
  -> 提交 query 并等待身份匹配的 run.start
  -> 转发业务事件与终态
  -> 更新 Desktop surface 状态
```

连接按 endpoint 与不含 token/过期字段的身份 session key 管理，并支持多个 Run 交错。一次调用成功表示 Platform 已确认对应 Run，而不只是本地排队。已接受 Run 断线后只用最后服务端序列 attach；绝不重提 query。认证临期在同一连接内刷新，endpoint、登出或身份变化会先关闭旧 generation。

Assistant、导航 Push、桌宠状态、桌宠 Run attach、可信 WebClient bridge 与 Desktop WS `ap` namespace 都是 Broker consumer。Run 最多一个上游 query/attach stream，本地 subscriber 共享有界 replay；未知 id/type、旧 generation、seq 回退和重复终态只进入脱敏诊断。

这条唯一物理连接同时承载 Platform 发回的 Desktop Action/CDP request。Platform 为每个 run 保存独立逻辑 target；普通可见 run 沿用 query/attach 建立的绑定，`run_query`、automation 等无绑定独立 run 在 Desktop 模式下补绑当前 `desktop-main`。父 run 结束不影响子 run，设备重连只让后续尚未发送的动作改绑新 generation，不重放已发送动作。该路由不替代 WorkPanel 的 Run/Chat grant，也不改变 Agent WebClient surface 的页面归属。

WebClient 普通新聊天没有预造 `chatId/runId`，关联 query stream 的首个合法 `chat.start` 先给出 canonical `chatId`。附件暂存则可能在 query 前预建 Chat，使 outbound query 已携带 canonical `chatId` 且该 stream 不再重复 `chat.start`；Desktop 只在服务端 `request.query` 回显同时匹配提交时记录的 `requestId + chatId + owner` 后接受该身份。两条路径都会校验 active Main Chat、surface generation、`agentKey` 与 `newChat` nonce，并立即同步外层路由和 Main Chat surface owner。Broker 仍在 `run.start` 前校验 bootstrap 事件，只有随后匹配的 canonical `run.start` 才注册 Run、解析 owner并绑定可见 surface。缺失合法 Chat 身份证据、两阶段身份冲突或宿主同步失败时均 fail closed，不从 `run.start`、`chat.created` 或当前页面反推 Chat。acceptance 前断线失败，acceptance 后重连只携带 canonical identity 和 `lastSeq` attach，绝不重发 query。

## Chat 与 Run 身份

Desktop 必须保留 Platform 返回的 `agentKey`、`chatId`、`runId` 与外部业务身份，不自行合成可冲突的 run 关系。历史对话、运行终态和消息正文以 Platform 为权威；Desktop 只保存恢复 surface 所需的最小导航信息。

市场等 Desktop 原生页面需要引导用户进入一类对话时，应打开显式新对话路由并传递受控的一次性 Composer 意图，由 Agent WebClient 生成可编辑草稿。Desktop 不代替用户发送消息，也不为这类入口调用 `assistant.startRun`；只有用户在 WebClient 中发送后才产生 Chat/Run。

`chat.start` 建立普通新 query 的 Chat 身份；附件预建 Chat 使用匹配的服务端 `request.query` 回显建立同一身份。`run.start` 是 Run acceptance 的唯一边界，不能替代前述 Chat 身份证据。来源 Run 的 WorkPanel 动作只有在 Chat 路由/surface owner 同步确认且 `run.start` 身份匹配后才能执行；授权建立后与页面 observer 生命周期分离，切换 Chat 不撤销该 Run 对自己 workspace 的动作权限，后续 canonical attach 可以恢复尚未成功的授权。已有 canonical `ownerChatId` 的 Main Chat surface 不要求重复 `chat.start`，并优先于更新可能滞后的 guest `currentUrl` 判定后续 query 为续聊。

Kanban 等业务发起的运行还需遵守各自的 server-prepared identity，不能把普通 Assistant query 冒充为业务原子操作。

## 首装引导 Chat

Bootstrap Agent 是系统介绍和可选用户初始化助手，不是 Desktop 可用性的门禁。首次 Desktop 安装只消费一次主进程内存信号：优先打开仍存在的固定 seed Chat；seed 已被用户删除时打开 Bootstrap Agent 新 Chat；Bootstrap Agent 不可用时回退默认 Chat Agent。普通启动、升级和保留数据后的重装都不触发该导航。

`OWNER.md` 只保存用户明确要求创建的名字与协作偏好。它可以不存在，也可以由用户删除；Desktop 不监听它、不据此迁移 Chat，也不把资料完成状态复制成导航状态。所有常规新 Chat 入口始终解析为默认 Chat Agent。

## Copilot 与页面上下文

Copilot 把指定 Agent 与当前 Website、WebApp 或内置 surface 关联。页面上下文由 Desktop 根据活动 surface 构造，至少隔离：

- 页面身份与允许暴露的 URL 信息；
- 可用的页面控制 capability；
- 当前聊天的相对路由和恢复信息；
- 用户显式选择或上传的内容。

页面切换、关闭或来源变化时必须失效旧上下文。页面控制继续经过统一动作桥和确认策略，Copilot 身份本身不授予额外权限。

全页面 Copilot 与右侧 Copilot Dock 是两个独立 surface。Dock 的实际 guest 使用固定实例身份，会话恢复则按独立的页面 `contextKey` 分区；`contextKey` 不是 surfaceId。当前上下文本身已登记为 Chat、Website、WebApp、Browser 或 Service 时，Dock 可以声明该父级，否则保持无父级，不能用 Desktop route 伪造一个 surface。

## 附件与内容

附件先由主进程校验类型、大小和来源，再上传 Platform；renderer 不持有服务密钥。上传结果与 query 使用稳定引用关联，失败时不能发送一个看似完整但缺少附件的请求。

截图、页面选区和本地文件属于不同授权来源，应在 UI 和审计信息中可区分。临时文件在运行结束、取消或超时后按所有权清理。

## 对话导出与分享

Markdown 与静态 HTML 都由 Agent Platform 对持久化 Chat 做一次一致读取后生成。Desktop main 通过 Platform export endpoint 下载完整 Buffer，再使用统一跨平台下载路径写入；renderer 不读取快照或模板。

创建和撤销公开分享也只调用 Platform share endpoint。Desktop main 从当前 SSO 与 Tunnel 设置解析站点 token 和 API origin，将它们放入独立私有 header；Platform 自身访问 token 仍使用标准 `Authorization`。Platform 负责生成 HTML、调用 Tunnel 和校验响应，Desktop 不直接向 Tunnel 上传或删除内容，也不回退旧事件流协议。完整边界见[对话快照分享与导出](对话快照分享与导出.md)。

## 状态、时间与故障

- renderer 先读取快照再订阅增量事件，重连后重新对账。
- Platform 的无效必填时间会使该事件被拒绝并触发刷新，Desktop 不用当前时间补写。
- shared contract 中的时间统一为 `EpochMilliseconds`，参见[时间契约](时间契约.md)。
- Platform 未就绪时 surface 显示可恢复状态，不回退到未认证的直连请求。
- 未知反向请求显式返回 unsupported/unknown，不能静默执行页面或系统能力。
- 日志保留 run 关联和故障阶段，但移除 token、正文与附件内容。

Debug 设置只负责打开独立的 Realtime Inspector 窗口；观察器可以在主窗口切换页面时保持打开，并以紧凑帧列表和单帧 Payload/Surface 上下文面板只读观察共享物理连接与 Agent WebClient Frame Port 的逐帧投递。诊断数据使用进程内有界缓冲区，按可信 Surface Registry 派生的 `surfaceId` 关联，不改变 Broker 路由或页面 capability；token、Cookie、secret 等敏感字段在跨 IPC 前递归脱敏，关闭进程后不保留。

## 扩展原则

新增助理能力应优先扩展 Platform contract 与主进程 bridge。只有涉及 Desktop 独有窗口、页面或系统能力时，才增加桌面动作；动作权限仍按[桌面协议与动作桥](桌面协议与动作桥.md)处理。

macOS 与 Windows 的文件选择、权限提示、窗口激活和系统集成必须显式分支验证。
