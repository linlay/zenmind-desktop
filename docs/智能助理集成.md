# 智能助理集成

## 当前状态

Desktop 的智能助理能力主要通过 `agent-platform` 服务提供。主进程的 assistant bridge 负责把 Desktop UI、Copilot、桌宠、附件和 agent-platform HTTP/SSE API 连接起来。

设置保存到 Desktop profile，不再保存外部 LLM baseURL/model/apiKey；运行时模型和 agent 配置以 agent-platform 环境为准。

## 核心流程

```text
renderer assistant UI / copilot
  -> main IPC
  -> AgentPlatformAssistantBridge
  -> agent-platform HTTP API / SSE
  -> AssistantEvent
  -> renderer state / pet state / kanban sync
```

主要能力：

- 读取 agent 列表和导航状态。
- 创建 chatId / runId 并启动 run。
- 解析 SSE，识别 `[DONE]`。
- 提交 awaiting question / approval / form / planning。
- 上传附件并映射到 platform resource ticket。
- 读取 chats、chat detail、memory、export。
- 语音转写和语音纠错请求代理。
- schema v5 本地 WebApp 通过同源 ES Module `/__desktop/bridge.js` 使用 `desktop.assistant.chat({ message })`，由 Desktop Helper Agent 处理最多 12,000 字符的通用消息并返回 `{ text, chatId, runId }`；SDK 不暴露 `complete()`，也不内置翻译等业务提示词。纯前端页面必须声明 `assistant.chat`，托管后端也只有声明后才获得仅限该动作的一次性 token；两者均不接触模型凭证。schema v4 页面和托管后端继续兼容 `desktop.assistant.chat` 与 `desktop.assistant.complete`，供存量应用迁移。页面路径只接受匹配 loopback WebApp origin 的请求，Website、`.m`、`.wa` 和普通 Desktop Action 调用不能借用 WebApp scope。
- 导航 WebSocket 始终由 Electron 主进程以 `source=desktop-nav` 连接，运行事件用于更新主进程导航快照，并通过只读 preload 事件同步给 renderer。因此 renderer DevTools 的 Network 只会看到 renderer 自己的连接（例如 Vite HMR），不会显示该 WS；调试时可在 Console 调用 `window.electronAPI.assistant.getNavigationLiveStatus()` 查看脱敏连接状态。返回的 `recentFrames` 按时间从旧到新保留最近 20 条连接、请求、响应、push、错误或无效帧记录；每条仅含时间、方向、事件类别和 WS type，绝不保存 payload、token 或 deviceId。连接建立、导航刷新和 chat/run/awaiting push 后，Desktop 通过同一连接请求 `/api/chats`，payload 固定为 `{ "mode": "REACT", "limit": 9 }`：前 8 条是侧栏列表，第 9 条只生成 `chatItemsHasMore` 溢出标记；其中顶层 `mode` 表示 Agent Mode，等待交互使用 `awaitingMode` 或 `awaiting.mode`。HTTP 与 WebSocket `/api/chats` 和 `/api/agents?includeChats=N` 使用相同的 `activeRun` 摘要契约：存在对象型 `activeRun` 时导航 chat 显示 loading，字段省略时视为没有运行中的 run；因此启动、重连及 push 后的快照刷新都能恢复同一运行状态。`chat.created` 不等待常规防抖，而是立即请求一次快照；Desktop 不乐观插入会话，仍以 `response.data` 的服务端排序和前 8 条截断为准。Chats 中已经展示的会话收到 chat/run/awaiting push 时立即更新 loading / awaiting 状态，不依据 agent mode 再过滤；未展示会话仍等待快照决定是否进入前 8 条。Chats 运行时先选择可用的正式默认 agent，默认 agent 未出现时才由 bootstrap 接管；不根据 run 终态推断交接。
- 对已存在的会话，Desktop 仅根据合法 `frame=push` 的 `chatId` 投影运行状态：`run.started` 进入 loading，`awaiting.asking` 进入 question / approval / form / planning 对应的 Await，`awaiting.answered` 在 run 未结束时回到 loading，`run.finished` 清除两种状态。同一 patch 同步应用到 Projects、activity 和 Chats，不使用 push 的 `agentKey` 选择 Project，也不修改会话标题或预览；刷新期间到达的运行状态 push 会在新快照发布前按 `chatId` 重放。未知 `chatId` 不乐观创建行，只触发快照刷新。
- Projects 标题右侧的刷新按钮会显式绕过主进程导航快照，并立即重新请求 `/api/agents?includeChats=N&scope=nav`；启动、push 和其他自动刷新仍优先复用已有快照，避免无意义的重复请求。

## 配置与接口

Desktop profile 中的 assistant 字段：

- `voiceCorrectionEnabled`
- `copilot.agentKey`（settings IPC 中投影为 `desktopHelperAgentKey`）
- `chat.agentKey`（settings IPC 中投影为 `chatDefaultAgentKey`）
- `navigation.desktopCopilotPages`

`assistant.chat.agentKey` 只能指向 agent-platform `scope=nav` 返回的导航智能体。未配置 bootstrap contract 的旧 profile 可迁移为首个可用 nav 智能体；一旦配置 `bootstrapAgentKey`，Desktop 不再用候选 fallback 覆盖正式默认值。

侧栏 Projects 仅展示 `mode=CODER` 或 `mode=KBASE` 的项目智能体；Chats 使用独立的全局 REACT 会话列表，不从 `/api/agents` 的 `recentChats` 聚合。列表只接受带有效 `agentKey`、`createdAt` 和 `updatedAt` 的摘要，固定显示 agent-platform 已排序的前 8 条；不显示 TEAM 会话。第 9 条有效摘要存在时，侧栏显示「查看更多历史」入口；该入口打开当前默认 Chat agent 的 WebClient 历史列表，不代表或筛选全局 Chats 集合。Chats 标题和新建对话仍严格按 `assistant.chat.agentKey`（或 desktop-init 的 `defaultChatAgentKey`）再到 `bootstrapAgentKey` 解析：正式默认 agent 在 nav 中可用时始终优先，bootstrap 只在默认 agent 未出现时接管，且不会写入 `assistant.chat.agentKey`。

Projects 中的项目标题只控制自身展开/折叠，不触发 WebClient 路由；进入会话、新建对话和打开历史必须使用各自的显式入口。项目标题保留 running/awaiting spinner，并以数字显示当前可枚举的 awaiting 会话数；Projects 分组收起时同样以数字显示处于 awaiting 状态的项目数。项目标题不再提供“全部已读”，打开单条未读会话时仍沿用现有的自动已读流程。

展开 Desktop 侧栏后，Chats 标题默认不显示默认智能体控件；鼠标 hover 标题行或键盘焦点进入标题行时，在折叠箭头后显示当前默认 Chat agent 名称的紧凑选择器。点击后菜单顶部显示「设置对话的默认智能体」说明，选项显示 `agentName · role`；收起侧栏的 Chats hover Popover 提供相同选择器。选择可用 `scope=nav` Chat agent 后，Desktop 复用 `assistant.saveSettings({ chatDefaultAgentKey })` 持久化设置；保存期间禁用控件，保存失败保留原值。切换只影响标题、新建对话与历史入口，不会过滤全局前 8 条 Chats 或打断当前会话；标题点击仍只控制 Chats 分组折叠。

侧栏 Chats 和 Projects 分组在没有内容时统一显示居中弱化的空状态引导文案：Chats 为「将鼠标移到「对话」上，点击 + 开始新对话。」（无可用默认 Chat 智能体时保留「请先在助理设置中选择可用的 Chat 默认智能体。」），Projects 为「将鼠标移到「项目」上，点击 + 添加项目。」。bootstrap 引导会话存在时 Chat 空状态替换为降级入口，不显示引导文案；Projects 空状态仅在导航智能体数据已加载后显示。

bootstrap 初始化只复用现有 agent-webclient 对话页和其 Chat 主区域。全新 runtime 通过 env 中的 seed `chats.db` 和 `<bootstrapChatId>.jsonl` 回放一条仅包含 assistant 自我介绍的已完成 run；自我介绍使用 WebClient 已有 Markdown，先以 `<bootstrapChatId>/desktop-overview.png` 标注导航、内容和副驾/概览区域，再以 `<bootstrapChatId>/desktop-sidebar-actions.png` 说明如何新建 Chat、Project、Site。两张图片均作为同一 Chat 的本地资源，由已有 `/api/resource` 图片链路显示。Desktop 不创建初始化内容页面或消息组件。仅当正式默认 agent 尚未出现在 nav 时，Desktop 才在每个启动会话自动选择一次 bootstrap 预置 Chat；该 REACT 会话只要位于全局前 8 条即可在 Chats 中显示。正式默认 agent 出现后，标题和新建对话目标立即切换为正式默认 agent；全局 REACT Chats 列表不按默认 agent 切换。若用户仍停在 bootstrap Chat，则本次启动仅一次性进入默认 agent 的新会话，用户在 Help 或其他页面时不跳转。若 seed 未进入已有数据库索引，Chats 自动打开 bootstrap 新会话并显示同名黄色降级入口，不合并或修复 agent-platform 的数据库。预置 Chat、Help 黄框、浮动气泡和新手引导卡全部以 bootstrap 正在接管 Chats（正式默认 agent 尚未在 nav 中可用）为生命周期依据。

默认 agent key 来自 shared assistant settings：

- Desktop helper agent。

与 agent-platform 交互的服务 id 固定为 `agent-platform`。

## 时间契约

agent-platform 派生的 IPC / preload 数据中的 `createdAt`、`updatedAt`、`startedAt`、`finishedAt`、`completedAt`、`answeredAt`、`resolvedAt`、`pushedAt`、`timestamp` 和 `expiresAt` 统一传递 `EpochMilliseconds`。主进程边界只接受安全整数毫秒：`0` 或 `1_000_000_000_000..8_640_000_000_000_000`（拒绝秒级数、数字字符串、ISO 文本、负数和浮点）；必填 stream 时间或导航事件实际使用的时间字段无效时不更新本地快照，记录诊断并刷新平台快照，绝不补当前时间。这个 agent-platform 专用下限不适用于 JWT 秒级字段；通用规则见[时间契约](时间契约.md)。

导航 WebSocket 的 `frame: "push"` 按事件语义取时刻，不再使用通用 `data.timestamp`。除 `heartbeat` 外，只要 push 顶层 data 出现 `timestamp`，Desktop 就拒绝该 live patch、记录诊断并刷新快照；绝不兼容回退。契约如下：

| `push.type` | 时间属性 |
| --- | --- |
| `connected` | 无 |
| `heartbeat` | `timestamp` |
| `auth.expiring` | `expiresAt` |
| `run.started` | `startedAt` |
| `run.finished` | `finishedAt` |
| `chat.created` | `createdAt` |
| `chat.updated` | `updatedAt` |
| `chat.unread` | `createdAt` |
| `chat.read` | `readAt` |
| `chat.read_all`、`chat.deleted`、`chat.renamed`、`chat.archived` | 无 |
| `archive.restored` | 顶层无；`summary.createdAt`、`updatedAt`、`lastRunAt`、`archivedAt` 必填，`summary.readAt` 可选 |
| `archive.deleted` | 无 |
| `catalog.updated` | `updatedAt` |
| `awaiting.asking` | `createdAt`；`timeout` 是时长 |
| `awaiting.answered` | `answeredAt`；`durationMs` 是时长 |
| `resource.pushed` | `pushedAt` |

无时间的 chat 操作只更新已有快照可安全确定的状态。未被 Desktop 直接渲染的有效 push（例如 catalog、resource、archive）只触发快照收敛。SSE 与 WebSocket `frame: "stream"` 不属于此表，继续使用各自事件的 `timestamp`。

`readAt`、JWT refresh 的 `expiresAt` 等可选时间在上游缺失时使用字段缺失或显式 `null`，绝不编码为 `""` 或 `0`。Assistant IPC 保留 `undefined` 与显式 `null` 的区别；渲染层只在最终展示时将 epoch milliseconds 格式化为本地可读文本。`full_access` 是权限枚举，不存在 lease expiry，因此 shared contract 不再包含 `fullAccessExpiresAt`；未来若引入 lease，必须使用可选 `EpochMilliseconds` 的新字段。

## 约束与注意事项

- Desktop 只保存助理 UI 偏好，不保存真实模型 API key。
- WebApp Bridge v1 只提供 `assistant.chat`；不要为 WebApp 重新增加 `complete`、`translate` 或其他带业务语义的助理入口。
- 附件路径必须通过 attachment store 解析，避免直接暴露任意本地路径。
- bridge 需要处理 awaiting 的 pending / answered / cancelled 状态，不能只看单一事件字段。
- `npm run dev` 只在启动时构建主进程；修改主进程导航 WS 逻辑后必须重启 dev 进程，Vite HMR 只更新 renderer。
- `agent-webclient` 的前端鉴权走 Token Bridge，不绕过 identity-center。
