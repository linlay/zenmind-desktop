# 智能助理集成

## 当前状态

Desktop 的智能助理能力主要通过 `agent-platform` 服务提供。主进程的 assistant bridge 负责把 Desktop UI、Quick/Copilot、桌宠、附件和 agent-platform HTTP/SSE API 连接起来。

设置保存到 Desktop profile，不再保存外部 LLM baseURL/model/apiKey；运行时模型和 agent 配置以 agent-platform 环境为准。

## 核心流程

```text
renderer assistant UI / quick / copilot
  -> main IPC
  -> AgentPlatformAssistantBridge
  -> agent-platform HTTP API / SSE
  -> AssistantEvent
  -> renderer state / pet state / kanban sync
```

主要能力：

- 读取 agent 列表和导航状态。
- 创建 chatId / runId 并启动 run。
- 解析 SSE，识别 `[DONE]`。
- 提交 awaiting question / approval / form / plan。
- 上传附件并映射到 platform resource ticket。
- 读取 chats、chat detail、memory、export。
- 语音转写和语音纠错请求代理。
- 导航 WebSocket 的 `run.start` / `run.complete` 通过只读 preload 事件同步给 renderer；`run.complete` 无论是否带 preview 都触发 nav 刷新，用于可靠识别 bootstrap agent 的释放。

## 配置与接口

Desktop profile 中的 assistant 字段：

- `voiceCorrectionEnabled`
- `copilot.agentKey`（settings IPC 中投影为 `desktopHelperAgentKey`）
- `chat.agentKey`（settings IPC 中投影为 `chatDefaultAgentKey`）
- `quick.enabled`
- `quick.agentKey`
- `navigation.desktopCopilotPages`

`assistant.chat.agentKey` 只能指向 agent-platform `scope=nav` 返回的导航智能体。未配置 bootstrap contract 的旧 profile 可迁移为首个可用 nav 智能体；一旦配置 `bootstrapAgentKey`，Desktop 不再用候选 fallback 覆盖正式默认值。

侧栏 Projects 仅展示 `mode=CODER` 或 `mode=KBASE` 的项目智能体；Chats 仅面向其他 mode 的普通导航智能体。bootstrap 本身属于 Chat agent：它存在时运行时接管 Chats，但不会写入 `assistant.chat.agentKey`；消失后恢复配置中的正式默认智能体。Chats 最多展示当前智能体最近 8 条会话，超过时打开该智能体的历史页面。

bootstrap 初始化复用现有 agent-webclient 对话页。全新 runtime 通过 env 中的 seed `chats.db` 和 `<bootstrapChatId>.jsonl` 回放一条仅包含 assistant 自我介绍的已完成 run；用户下一条消息沿用同一 chatId，正常经过 WebClient、Run、SSE 与 awaiting。若 seed 未进入已有数据库索引，Desktop 显示同名降级入口并打开新会话，不合并或修复 agent-platform 的数据库。

默认 agent key 来自 shared assistant settings：

- Desktop helper agent。
- Quick assistant agent。

与 agent-platform 交互的服务 id 固定为 `agent-platform`。

## 约束与注意事项

- Desktop 只保存助理 UI 偏好，不保存真实模型 API key。
- 附件路径必须通过 attachment store 解析，避免直接暴露任意本地路径。
- bridge 需要处理 awaiting 的 pending / answered / cancelled 状态，不能只看单一事件字段。
- `agent-webclient` 的前端鉴权走 Token Bridge，不绕过 identity-center。
