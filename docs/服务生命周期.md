# 服务生命周期

## 文档定位

本文定义 Desktop 对内置服务和运行时插件的生命周期职责。具体状态字段、命令参数、PID 文件和健康探针以 manifest、源码及测试为准。

## 生命周期模型

```text
发现资源
  -> 校验 bundle 与 manifest
  -> 安装程序版本
  -> deploy 服务配置
  -> start 受管进程或 host runtime
  -> verify 运行状态
  -> stop / restart / upgrade / uninstall
```

安装、部署、启动和停止是不同阶段：

- **install**：把已验证程序包放入版本化程序目录。
- **deploy**：由服务脚本创建或重建服务拥有的配置与运行条件。
- **start**：消费已经部署好的配置，启动进程或 Desktop host。
- **verify**：结合进程身份、端口、健康接口和运行文件确认真实状态。
- **stop**：只终止属于当前服务实例的进程树并等待资源释放。

阶段参数不能混用。Desktop 只传递 manifest 与生命周期 contract 已声明的上下文，不追加服务未知的兼容参数。

唯一的运行形态启动契约是：Desktop 启动内置 `agent-platform` 时固定注入 `--runtime-mode=desktop`（并覆盖 service definition 中的其他 runtime-mode 值），并继续追加 `--daemon`；macOS/Linux 与 Windows lifecycle script 透传该形态。插件服务和其他内置服务不接收该参数。独立启动的 Platform 不带该参数，使用其默认 `standalone`。

## 目录与所有权

每个服务获得独立的程序、配置、数据、状态和日志目录。程序目录可以按版本替换，运行目录默认保留。目录分层见[数据目录](数据目录.md)。

Desktop 可以创建顶层目录、备份不透明配置目录并把路径传给服务，但不能解释服务配置字段。服务自己的 `deploy` 负责默认值、清理、迁移、密钥放置和 runtime 初始化。

## 服务形态

- **内置服务**：从平台资源包发现并由 Desktop 编排。
- **运行时插件**：复用相同布局和生命周期，但程序、能力和卸载边界归插件系统管理。
- **host-managed 前端**：由 Desktop 托管静态内容与代理，不执行 bundle 内普通 start/stop。
- **install-only 服务**：只参与资源准备，不作为持续运行依赖。
- **外部服务**：企业聊天 Server 等不进入 service manager，Desktop 只作为客户端连接。

不同形态必须由 manifest 或宿主设计显式声明，不能根据文件名、端口或历史安装痕迹猜测。

install-only 或可选服务的外部运行时探测必须异步、限时、共享进行中的结果，并在超时后终止完整进程树；不得在 Electron 主线程同步等待 CLI。macOS 还必须拒绝从 `/Volumes` 或 `AppTranslocation` 运行容器引擎，避免挂载镜像或隔离路径阻塞 Desktop。

## 状态与健康

进程存在不等于服务健康。Desktop 需要区分未安装、已停止、启动中、运行、失败和不可确认等状态，并结合该服务声明的探针判断。

PID、端口和日志只是诊断信息；停止或重启前还要验证进程身份和受管根，避免终止无关进程。平台实现必须分别处理 macOS 与 Windows 的进程树、脚本和文件锁。

macOS 与 Windows 的启动验证在所有检查通过后立即成功，仅失败时等待重试。同一轮验证的认证能力检查与依赖 HTTP 检查共享一次 access token 获取结果（包括失败），本轮结束即丢弃；不跨重试、服务或启动保存。此复用不减少健康检查项，也不改变服务自身的公钥与签发职责。失败诊断记录检查项和 HTTP 状态码，不记录凭据。

Agent WebClient Frame Port 的消息热路径使用专用只读状态观察，不执行同步进程探测、端口扫描或 PID 文件修复。首次及过期的进程身份通过异步、限时的 Windows/macOS 查询验证，并合并同一身份的进行中请求；近期成功的观察可短时复用，同时在后续访问中触发异步复验。每次读取仍检查 PID 文件指纹与进程存活，身份变化、退出、无法确认或复验失败使观察失效；旧查询完成不能覆盖新实例。该观察不缓存 token，不替代 Frame Port 的 sender、surface 或 Run 授权，异步等待结束后必须重新校验 live surface。停止、重启、升级及卸载继续使用完整进程归属验证，不能使用热路径观察授权进程终止。

状态轮询不得重复写入内容未变化的 PID 文件，避免无意义磁盘写入及进程身份观察失效。热路径状态读取的缓存界限、字段和测试以 service manager 源码为准。

## 升级与失败

- 新 bundle 在停止旧服务前完成完整性和平台校验。
- 程序安装采用临时目录和原子切换，失败不覆盖可用版本。
- 配置 reset 由服务 deploy 执行，Desktop 只提供版本与备份上下文。
- 健康检查失败时保留日志、配置现场和事务状态，不自动改写服务配置。
- 卸载插件或服务程序前先停止受管进程；是否删除运行数据由对应产品流程决定。

## Desktop 退出协调

正常退出按依赖和所有权关闭 WebApp、插件、核心服务、桥接服务器、企业聊天、Kanban、桌宠和其他非核心 runtime。更新器或卸载器必须先请求主实例清理，再独立复验受管进程已退出；仅收到内部 ACK 不能替代外部进程检查。

## Desktop 提供的 Node 运行时

Desktop 在三个核心服务并发启动前完成自己的 Node/npm 准备；启动 Agent Platform 时只读取准备结果，将命令入口置于该子进程 PATH 的最前面。手动启动 Platform 使用同一准备入口。入口固定在 Desktop 数据根的 `bin` 目录；应用可执行文件、Node 版本、平台、架构和 npm 版本用于判断是否需要更新。不写内置服务 `.env`，也不修改用户的 nvm、Homebrew 或全局 PATH。连接器的版本要求仍由 Platform 校验，安装程序和账号登录材料仍由连接器领域按协议隔离。

macOS/Linux 的 node 入口通过当前 Electron 可执行文件运行脚本；Windows 使用随 Desktop 构建的原生 node.exe 转发程序。只有 Node 子进程设置 ELECTRON_RUN_AS_NODE，Platform 本身不携带该模式，避免把后续启动的 Desktop 应用误当脚本解释器。两端均保留参数、工作目录、标准输入输出和退出码。升级时先在 Desktop 状态目录准备并验证新入口，再将旧目录移至保留区，发布到固定的 bin；发布失败恢复旧目录。Windows 若文件占用阻止旧目录移动则明确失败，不原地覆盖正在运行的 node.exe。旧目录和历史哈希目录不在启动过程中删除。

Node/npm 准备通过异步文件操作执行，避免复制文件和探测进程阻塞 Electron 主线程。这一阶段先于核心服务启动，不以 Platform watcher 冲突作为准备依据。同一 Desktop 实例复用成功的准备结果，并发请求共享进行中的任务，失败后下一次启动可重新尝试；启动命令组装不执行文件复制或 Node 探测。Windows 对复制、目录发布及暂存清理的瞬时占用执行有上限的异步退避；长期占用仍明确失败，不通过原地覆盖绕过。暂存清理失败不得覆盖原始准备错误，也不得把已经发布并验证的运行时误报为不可用。发布和回滚同时失败时保留旧运行时的保留目录并报告恢复路径；不在启动时删除旧运行时或未知残留目录。

npm 随 Desktop 使用固定版本及摘要校验的资源交付，运行时不依赖用户安装的 npm，也不在首次启动时联网下载 npm。Desktop 只提供执行能力，不改写 npm prefix；安装命令和凭据仍归连接器及 Platform 管理。Platform 补充 npm 全局命令目录时必须保留已有 PATH 优先级，不能把系统 Node 移到 Desktop 入口之前。

## 按需浏览器版 WebClient

本机服务设置可按需启动独立的浏览器 HTTP Host。它复用已安装 WebClient 静态资源、消费当前内嵌 Host 的可信 Platform 目标，不启动第二个 Platform，不修改服务配置，也不改变内嵌 Host 的 Frame Port 模式。独立指监听器、运行配置和浏览器会话；其运行时仍由 Desktop 主进程托管。

启动和停止进入既有服务变更队列，依赖 Platform 与内嵌 WebClient 已运行。重复打开复用监听器并签发新的短期打开票据；首选端口冲突时仅请求系统空闲端口，不终止占用进程。实际地址由宿主状态返回。Windows 与 macOS 均显式绑定 IPv4 loopback，由 Electron 委托操作系统默认浏览器打开。

停止 WebClient 或 Platform、WebClient 资源替换、Desktop 正常退出和 SSO 失效时关闭浏览器监听器、连接和全部会话；不自动恢复旧授权。用户单独停止浏览器版不影响内嵌 WebClient 和 Platform。并发启动结果必须受 generation 校验，停止后迟到的启动不能重新发布监听器。
