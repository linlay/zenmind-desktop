# 服务生命周期

## 当前状态

Desktop 用统一 service manager 管理内置服务和插件服务。生命周期覆盖安装、初始化、启动、停止、重启、状态读取、日志读取、健康检查和启动恢复。

服务定义来自 manifest，服务程序安装到品牌程序数据目录，配置、数据、状态和日志分别写入 Desktop 数据根。

## 核心流程

```text
manifest definition
  -> installBuiltinService() / installPluginFromArchive()
  -> initializeService()
  -> startService()
  -> getServiceState()
  -> stopService() / restartService()
```

安装和初始化：

- 内置服务从 bundled asset 解压或复制到 `services/<service-id>/<version>/`。
- 插件从用户选择的 `.zip` 解压到 `plugins/<plugin-id>/<version>/`。
- 非核心插件服务的缺失配置可从 manifest `configFiles.templateRelativePath` 回填。
- 内置核心服务 `agent-container-hub`、`agent-platform`、`agent-webclient`、`identity-center` 的 `.env` 和服务配置由各自 `deploy.sh` 负责创建、迁移和清理；Desktop 不做兼容修复。
- `.sh` 脚本在 macOS / Linux 上修复可执行权限。
- `scripts.deploy` 是初始化钩子，需要幂等。

启动和状态：

- service manager 根据 manifest 脚本启动进程，并只追加约定的 lifecycle/layout 参数。
- `start.sh` 消费已部署配置和启动时参数；服务内部配置默认值、旧 env 清理和 runtime 目录写入必须在服务自己的 `deploy.sh` 中完成。
- PID、日志和错误日志路径由 manifest runtime 字段和 Desktop layout 解析。
- HTTP 服务通过端口和 web URL probe 判断 running。
- 停止时优先按 managed PID / 进程树清理，平台差异显式处理。

## 配置与接口

控制中心和动作桥可触达：

- list / detail / status。
- install / initialize / start / stop / restart。
- log metadata / read log / open log viewer。

服务状态核心字段包括：

- `status`
- `healthMeta.port`
- `healthMeta.webUrl`
- `healthMeta.pid`
- `logPath`
- `errorLogPath`

## 约束与注意事项

- `agent-webclient` 可走 host-managed 模式，由 Desktop 托管静态前端和代理；本地监听端口来自 Desktop defaultPort，普通 `/api` 与 `/ws` 上游来自 host-managed start 参数 `--base-url`，不写入服务 `.env`。
- `identity-center` 认证脚本在 Windows 使用 PowerShell，在 macOS / Linux 使用 `.sh` 或后端二进制子命令。
- `agent-platform` runtime 根通过 deploy lifecycle 参数交给服务包处理；Desktop 不读取或修复 `.env` runtime 覆盖项。
- 启动失败优先检查控制中心状态、PID 文件和日志文件。
