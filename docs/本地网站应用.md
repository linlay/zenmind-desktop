# 本地网站应用：Manifest v2

## 文档定位

本文描述 WebApp 的宿主模型、生命周期和安全边界。Manifest v2 的精确字段和校验由 `src/shared/webapp-manifest.ts` 维护，并生成机器可读的 [JSON Schema](../contracts/webapp/webapp.schema.json) 与 validator；本文不重复字段手册。

## WebApp 模型

WebApp 是安装在 Desktop 本地、通过 loopback gateway 访问的应用包。它可以是：

- 仅静态前端。
- Desktop 托管的本地后端进程加前端。
- Desktop 附着到用户管理的外部容器或服务，再由 gateway 统一代理。

这三种形态对 renderer 暴露相同的 `webUrl`。WebView、Desktop surface、移动访问和发布能力都只消费 gateway，不根据后端语言或启动器分支。

## 包与配置

WebApp 包使用稳定 id、版本化 Manifest、前端资源和可选后端程序。安装包不能包含用户实际配置、真实密钥或持久业务数据。

配置分为：

- `appConfig`：随包发布的非敏感业务配置。
- `userConfig`：设置字段定义和非敏感默认值。
- 用户实际值：由 Desktop 保存到包外数据根，升级程序时保留。
- runtime binding：用户选择的 Java、Python、容器等本机运行时位置，属于 Desktop 本机设置。

配置不能借环境变量或任意 JSON 键绕过 secret policy。需要密钥的应用应使用明确的外部凭据方案，而不是把 token 打进 WebApp 包。

## 宿主架构

```text
WebApp package
  -> manifest 与包结构校验
  -> 安装事务
  -> launcher 启动或附着后端
  -> loopback gateway
  -> workspace WebView 或独立窗口
```

Gateway 统一承担静态文件、受限后端代理、健康访问和 Desktop Bridge。它先处理保留的宿主路径，再按 Manifest route policy 代理后端或返回静态内容；路径穿越、任意反向代理和跨 origin 调用必须被拒绝。

workspace 与独立窗口只改变渲染容器，不改变 runtime、gateway、权限或持久化边界。外部容器是 attach-only：Desktop 可以停止自己的 gateway，不能停止或删除用户管理的容器。

独立窗口的原生右键菜单由 WebApp 宿主提供，支持保持置顶和小窗模式，并保留编辑区的剪切、复制、粘贴等系统操作。窗口偏好只在该窗口的生命周期内有效；macOS 使用原生浮动窗口层级，Windows 使用 topmost 层级。页面不能通过 Manifest、脚本或 Bridge 自行控制窗口，也不能因此创建第二个 WebApp guest。便签等工具的内容与恢复仍归各自 WebApp 的持久数据根所有。

主窗口中的 WebApp 默认允许透明区域透出同一张 Desktop 皮肤背景，主工作区、WorkPanel 与 WorkPanel 全屏遵循同一合成规则。WebApp 自己声明的背景正常覆盖宿主壁纸；Desktop 只处理外层容器，不注入页面 CSS、不复制背景图片，也不增加 Manifest 配置或 bridge 权限。无皮肤图片和独立窗口继续使用既有宿主底色；完整视觉边界见[主窗口外观与皮肤](主窗口外观与皮肤.md)。

## 生命周期与事务

```text
校验归档和 identity
  -> 解压到同盘 staging
  -> 校验程序、前端和 route policy
  -> 原子替换当前程序包
  -> 启动并检查健康
  -> 成功提交或失败回滚
```

WebApp 只维护当前程序版本，不把长期版本历史当作用户数据。升级失败回滚程序目录，持久业务数据不参与替换。Desktop 重启时根据可信 journal 恢复未完成事务，不能跟随 journal 中的越界路径。

WebApp runtime 与 WebView 展示所有权是两层状态。主工作区和 WorkPanel 共享按 `webappId` 唯一的 canonical WebView，AppShell 只移动 presentation owner 和布局，不重建 guest；隐藏 WorkPanel 不停止 runtime，关闭 WorkPanel tab 销毁 guest 但不停止 runtime。独立窗口维持原有 WebContentsView：若窗口已存在，WorkPanel 只聚焦它；停止、卸载、启动失败清理或应用退出必须同时回收 presentation 引用和 guest。WorkPanel 转移不写入持久 `openMode`。

WebApp 始终保持单页，不增加 popup、新 tab 或内层标签栏，移入 WorkPanel 也不能借用普通 Web item 的 popup 路由。已获授权的 Copilot Run 可继续控制后台 canonical guest；主区与 WorkPanel 转移保持该授权，隐藏时保留最后一个有效视口。切换独立窗口造成 guest 替换、关闭页面或停止 runtime 均使旧授权失效，不自动重开。

停止、重启和卸载先回收窗口、guest、gateway 和 Desktop 托管进程树。卸载是否删除持久数据必须由明确用户操作决定。

资源插件停止时可移除 WebApp 程序并保留用户数据；后续卸载复用同一清理入口。仅在程序已移除且持久发布状态明确为未发布时，允许跳过重复取消发布，继续清理剩余数据；发布状态缺失或仍为活跃时不能据此绕过发布检查。


## Desktop Action 响应边界

WebApp 领域实现可以为设置页和内部 IPC 维护完整 item、runtime state、publish state 与 WebApp 列表，但公共变更 Action 的成功结果只描述当前实例：生命周期返回 id/status，打开额外返回 route，偏好返回提交后的 label/openMode，安装返回 id/operation，发布返回 id/status/public URL。成功响应不返回完整 Manifest、领域 message、内层 ok 或其他 WebApps；需要完整读取时使用对应 list/status Action。

生命周期、偏好、安装、卸载与发布的领域业务失败统一转换为稳定的外层 `webapp_*_failed`。错误必须保留当前实例足以定位问题的详细信息：精简 identity、完整 runtime state 与 prerequisite issues、当前 publish info/state，或安装 executable、stage、diagnostic、suggestion 和直接相关路径。诊断清理必须删除全局 WebApp 集合并递归脱敏 Token、Cookie、授权头、密码及凭据；领域声称成功却缺少契约所需字段时返回 `invalid_action_result`，不能伪造成功。

## Desktop Bridge

WebApp 页面从 gateway 同源加载 ES Module bridge。Main 结合运行中实例、页面 origin、page scope 和 Manifest 能力校验请求；page token 不进入 HTML、URL、日志或页面存储。

公开能力只覆盖明确的宿主交互，例如系统浏览器打开、用户发起的文件/目录选择、通知、文本剪贴板或受限媒体授权。Desktop 只返回用户选择结果，不替 WebApp 任意读写文件。

图片类 WebApp 可以使用受限的 Assistant Image 能力：页面把单张原图和可选 PNG 蒙版先提交到同源专用上传入口，Main 在有界字节、MIME 与文件签名校验后生成短期、绑定 WebApp 身份的一次性句柄；随后图片 Action 只消费该句柄、结构化生成参数和宿主固定的 Agent 身份。页面不能指定其他 Agent、读取 Platform token、取得宿主路径或把句柄交给另一 WebApp。图片请求宽高必须同时是 16 的倍数，不满足时 Main 会在启动 Run 前拒绝；WebApp 应同步补齐原图和蒙版并在生成后裁回用户尺寸。生成结果由 Main 从对应 Chat 的受控资源面读取并移除内部路径后返回；取消请求只作用于同一 WebApp 发起的 Run。普通 Action 的 64 KiB JSON 边界不因图片能力而放宽。

WebApp 页面、托管后端 token 和普通 Desktop Action 使用不同 scope。Website、Tunnel 页面、伪造 origin 或后端进程不能借用 page-only 原生能力。

## 持久化与运行时

程序、用户数据、runtime state 和日志分别保存。WebApp 可以在自己的数据根使用 SQLite 或其他本地格式，但数据库 schema 和迁移属于 WebApp，不由 Desktop 解释。

Desktop 托管进程必须使用显式平台启动器并清理进程树；Python、Java、本地可执行文件和容器在 macOS 与 Windows 分别校验路径、命令和退出行为。

## Tooling 与发布

WebApp tooling 负责初始化 manifest、校验目录、构建 ZIP 和验证发布包。Desktop 安装器与 tooling 必须共享同一 Manifest parser 和包安全策略，避免开发期通过而运行期拒绝。

生成 contract 由源码构建并通过漂移检查维护，不能直接编辑 `contracts/webapp/` 中的产物。

WebApp 初始化、包校验和 ZIP 构建归 Desktop Main 所有；包校验包含 Manifest 校验，并通过仅限可信 Agent Platform Run 的 Desktop Actions 暴露。Agent Platform 只在反向 WebSocket 帧顶层注入当前 Execution Session 的可信 Workspace 根并转发调用，不保存 WebApp 配置、不读取 Tooling 环境变量，也不提供 Standalone 磁盘扫描降级。Action 参数只能使用 Workspace 相对路径；Main 对现有目标执行 realpath 校验，对新建目标校验最近的已存在父目录，并拒绝绝对路径、URI、`..`、控制字符和符号链接或 Junction 越界。

扫描、ZIP 解压与压缩在 `app.asar` 内的一次性 Worker 中执行，最长十分钟；成功、失败或超时都终止 Worker 并清理临时文件。`package.init` 幂等且不覆盖已有 Manifest/入口，`package.build` 以唯一临时文件校验后做原子无覆盖提交。生产包不得包含可独立调用的 `Resources/scripts/webapp-tooling.mjs` 或 `Resources/tooling/webapp-tooling.mjs`。

WebApp Builder `0.2.0` 与提供这些 Action 的 Desktop、Agent Platform 及同版本 `env.zip` 必须原子发布；不保留旧环境变量和脚本路径兼容层。正式 macOS/Windows 分发缺少版本匹配的 `env.zip` 时构建失败，开发模式仍可不带 `env.zip`。

## 实现事实源

- `src/shared/webapp-manifest.ts`
- `src/shared/webapp-package-validation.*`
- `src/main/modules/webs/webapps/`
- `src/main/modules/webs/webapps/tooling/` 是 WebApp Tooling 的 TypeScript 权威实现；Worker 随 Main 编译进 `app.asar`，不发布独立 Resource 脚本。
- `src/shared/desktop-actions.ts` 定义三个 Tooling Action 和 Workspace 相对输入契约；Agent Platform 只提供通用可信来源与传输。
- `scripts/generate-webapp-contract.mjs`
- WebApp manifest、package、gateway、runtime、安装和发布测试

### Worker 入口与 Workspace 一致性

开发 Main 的逐模块编译布局与生产 Main bundle 布局不同。Tooling Worker 入口由宿主从应用根定位，构建同时交付版本一致的独立 Worker bundle；不能根据调用模块的目录猜测入口，也不能搜索其他品牌或旧 staging 目录降级。Agent 只调用正式 Desktop Action，不需要知道 Worker 路径。

初始化、校验、构建与安装使用同一 Run 的可信 Workspace。构建返回的相对归档路径可以原样交给安装；Chat 资源目录不是隐含 Workspace，宿主不搜索其他目录补找缺失文件。参数预检先于 Worker 启动，文件系统错误保留直接原因和未执行状态；Worker 启动后异常或超时不能声称工程未改动。Worker 失败、文件解析失败与安装事务失败必须分别诊断。

初始化失败必须区分 Workspace 不可用、目标文件操作失败与已有 Manifest 非法。可信 Workspace 为文件系统根目录时仍允许其内部可写子目录，不能因根目录本身只读而拒绝全部项目。调用方根据已知目标与 Workspace 的实际包含关系计算相对路径；Shell cwd 与 Chat 目录都不隐式改变根。文件操作失败保留真实目标、原始 errno 与恢复条件；已有非法 Manifest 不由 init 补造身份或覆盖，应保留原工程，在新的空目录初始化后迁入业务产物。

Platform 的 WebApp Action 入口支持当前 Session 的 `@chat`、`@workspace` 路径别名，并在发送前转成现有 Workspace 相对路径；Desktop 不重复解析别名，也不改变可信 Workspace。未经转换的保留别名必须在 Desktop 参数预检拒绝，避免旧 Platform 把别名当作普通目录名创建。文件工具和 Action 使用同一语义路径，具体字段范围由 Platform 工具契约约束。

## WebApp 数据能力与宿主认证

统一 SDK 的公开命名空间为 `assistant`、`connector`、`skill`、`automation`、`kanban`、`artifact`、`desktop`。宿主原生能力只使用 `desktop`；既有内部 Action 名由显式白名单映射，不通过通用前缀转换开放新的 Desktop Actions。浏览器加载 gateway 同源 SDK；受管 Node 后端使用同一源码生成的模块和注入的 backend token，不能获得 page-only UI 权限。接入示例见 [SDK 契约说明](../contracts/webapp/README.md)。

WebApp 采用安装即信任模型：安装后即可使用宿主对 WebApp 开放的能力，不按 Manifest 声明过滤连接器或看板，也不要求应用级二次授权。旧 Manifest 的能力声明只为兼容既有包而接受，不参与权限决策；旧 SDK 的权限申请直接返回已允许。账号登录、操作系统权限、页面与后端接口职责及实例身份校验仍各自生效。退出账号撤销已有 page/backend token，重新登录后应重启 WebApp。进行中的请求在返回前重新校验身份和实例，不能将旧账号的结果投递给新账号。应用标识来自宿主 token，不接受调用方自行指定账号、应用主体、凭据或任意 Platform 路由。

连接器直接执行由 WebApp 选择已安装连接器的 CLI 或 MCP adapter，WebApp 使用同一接口且不消耗 Agent 模型调用。Main 根据当前请求自动用宿主身份向 Platform 换取短期、限定应用、连接器和 adapter 的调用凭据，调用后撤销；凭据不进入页面和业务返回。连接器登录是独立宿主流程：WebApp 用户点击触发请求，Desktop 确认后打开 Platform 提供并校验的认证入口，Platform 持有 session 和刷新凭据。同一账号、连接器的并发登录合并；应用退出只移除自身等待，不取消其他调用方共享的 Platform 登录会话。应用安装时已获得能力访问，认证只建立连接器账号身份；认证成功不自动重试业务操作。

Agent 使用宿主选定的智能体；固定 Copilot 配置优先，技能选择受该应用声明约束。后台运行返回运行标识，宿主代理订阅并仅投递文本与精简状态，工具参数、工具结果和原始协议帧不透传。订阅是有界、带游标的当前实例缓存；断开订阅不自动中断 Agent，停止运行需要本应用的运行归属校验。停止 WebApp 或身份失效会释放订阅。

产物授权沿本应用发起的 Chat 建立，读取必须带 Chat 上下文，可进一步限定 Run；没有全局产物列表，也不能仅凭产物 id 或外部 Chat id 获取文件。Main 使用限定 Chat 的 Platform grant；预览从当前 Chat manifest 解析受控资源，另存为只能写入系统文件选择器确认的位置，不接受页面提供的宿主路径。当前归属记录不持久化，重启 WebApp 后旧 Chat 不自动恢复访问。字节读取有体积上限，SDK 返回的流是有界读取后的流，非贯穿 Platform 的网络流。

看板提供无需额外授权的只读投影，不返回本机目录、Chat 权限和完整运行缓存；云连接断开不展示云端问题缓存。WebApp 不新增任何 issue 状态变更、分配或运行派发接口，继续遵守 Server 权威的看板协议。自动化等待 Platform 提供按应用归属与授权的管理接口，目前明确保留，不复用全局自动化管理入口。截图、剪贴板读取、窗口控制、摄像头、系统分享等原生能力亦保持预留。

连接器认证复用 Platform 当前部署的一套凭据和 config 目录，不按 WebApp 或用户 subject 创建独立账号目录。宿主身份及应用 grant 仍用于授权和结果隔离，不代表连接器账号隔离；连接器退出对 Agent、管理界面和 WebApp 共同生效。登录和执行均不依赖 Manifest 能力声明。Desktop 不补造业务操作清单；Platform 从已安装连接器解析命令入口或 MCP 组件，直接传递 argv 或原生工具参数。业务 SQL、字段解析和文案属于 WebApp。


### 连接器写操作

安装信任包含连接器读取、发送消息和修改数据，不再区分应用级读写授权，也不弹出执行权限确认。连接器执行仍是页面接口，后端 token 与 handler 均拒绝该调用；这是接口作用域约束，不是应用能力白名单。Platform 负责现有凭据、包锁、账号版本、进程期限、输出上限和可选持久幂等回执；不解释业务字段，不拼接 shell 字符串，也不承诺操作系统沙箱或外部 exactly-once。

Desktop 透传幂等键和非凭据的连接器授权版本，不解释具体业务、拼接 Shell 或自动重发。Platform 持有持久发送收据和结果未知状态，应用负责稳定的业务幂等键、按钮状态及向用户展示核对提示。文档查询、人员识别、会议聚合和群提醒模板属于工作台；连接器原包和服务配置仍由各自所有者管理。
