# 本地网站应用

## 当前状态

本地网站应用是 Desktop `webs` 域中的可运行本地应用。它包含 `webapp.json` 和静态前端目录；Node 后端是可选项。纯前端应用由 Desktop 直接启动本地 HTTP server；全栈应用额外启动 Node 后端，并把 API 前缀代理到后端。

小君完成 WebApp 后通过公开动作 `desktop.web.webapp.installAndOpen` 安装、刷新侧栏并打开真实页面。WebApp 启动后，Desktop 使用 Tunnel 设备的 `.m` 主机和当前前端端口生成手机专用地址；该链路不要求用户点击发布，也不会创建公网分享路由。设置中的“一键发布”是另一条独立链路，只在用户主动操作后创建 `.wa` 公网分享地址。Bootstrap 只负责首次初始化与交接，不持有 WebApp 构建或桌面动作权限。

每个网站应用存储在 `data/webs/webapps/<webapp-id>/`。

## 核心流程

```text
webapp.json
  -> readWebappItemFromDir()
  -> webappRuntime.start()
  -> optional: reserve backend port / spawn node backend / wait healthPath
  -> start frontend static server on 127.0.0.1
  -> write state/webs/webapps/<id>/runtime.json

package.zip
  -> desktop.web.webapp.installAndOpen
  -> validate / install or replace
  -> emit webs.changed
  -> start and open /webs/webapp:<id>
  -> derive https://<device>.m.../webapps/<frontend-port>/ for paired mobile access
  -> push webapp.changed

Settings 一键发布 or desktop.web.webapp.publish
  -> ensure local runtime is running
  -> register stable Tunnel route by webapp id
  -> write state/webs/webapps/<id>/publish.json
  -> show .wa public share URL and QR code

React App through Desktop Tunnel WS
  -> event.subscribe(webapp.changed)
  -> web.webapp.list
  -> receive sanitized ordered WebApp catalog
  -> receive .m publicUrl for the running WebApp
  -> open publicUrl with the current paired app token on first navigation
```

运行期环境变量：

- `HOST=127.0.0.1`
- `PORT=<backend-port>`
- `WEBAPP_ID`
- `WEBAPP_ROOT`
- `WEBAPP_STATE_DIR`
- `WEBAPP_LOG_DIR`
- `DESKTOP_ACTION_BRIDGE_URL`：当前 Desktop 本地动作桥地址，供 WebApp Node 后端调用明确开放的 Desktop 能力。

## 配置与接口

`webapp.json` 新包使用 schema v3，继续兼容读取现有 schema v2。关键字段：

- `id`、`kind`、`label`、可选 `copilotAgentKey`。缺少或为空时动态跟随 Desktop 当前默认 Copilot，不保存当时的默认 key。
- `frontend.root`：静态前端根目录，默认 `frontend`。
- `frontend.index`：入口 HTML，默认 `index.html`。
- `frontend.spa`：是否启用 SPA fallback，默认 true。
- `frontend.apiPrefix`：需要代理到后端的 API 前缀，默认 `/api`。
- 可选 `backend`：省略时是纯前端应用；提供时 `runtime` 只支持 `node`，并配置 `entry`、`args`、`env`、`port`、`healthPath`。

动作接口：

- `desktop.web.webapp.getStatus`
- `desktop.web.webapp.start`
- `desktop.web.webapp.stop`
- `desktop.web.webapp.restart`
- `desktop.web.webapp.open`
- `desktop.web.webapp.installAndOpen`
- `desktop.web.webapp.getPublishInfo`
- `desktop.web.webapp.publish`
- `desktop.web.webapp.unpublish`

## 约束与注意事项

- `frontend` 和可选 `backend` 路径必须是 webapp 根内的安全相对路径，禁止绝对路径、`..` 和隐藏段。
- 旧 `agentKey` 仅作为读取和输入兼容 alias；非空 `copilotAgentKey` 优先。正常编辑会写回 schema v3 canonical 字段并移除 legacy 字段，启动读取不会批量重写现有 manifest。
- bootstrap WebApp 由 `desktop-init.json` 的 `webs.items` 只引用 id，固定从 `desktop-init/sites/<id>/` 安装，且 `webapp.json` 的 id 必须与目录和声明一致。Copilot 只在 `webapp.json` 配置，避免两个配置源。安装后是普通本地资源，可编辑、删除和排序。
- 静态 server 只监听 `127.0.0.1`。
- 非 API 请求走静态文件；匹配 `frontend.apiPrefix` 的请求代理到后端。
- 日志写入 `logs/webs/webapps/<id>/main.log` 和 `error.log`。
- WebApp 不读取 Desktop token 或模型密钥；纯前端与全栈页面都可通过同源 `POST /__desktop/actions/call` 使用明确开放的助理动作。该路径只接受匹配当前 loopback WebApp 的 Origin，Tunnel 公网页面不能借此消费本机模型。
- Tunnel 发布前必须先通过本地安装与运行验收；发布状态保存在安装目录之外，因此覆盖安装同 id 的新版 WebApp 不会丢失既有公开路由。运行时再次启动后会把稳定路由同步到新的本地端口。
- 移动端目录只返回 id、显示名、顺序、时间、运行状态、可用性和 `.m` Tunnel `publicUrl`；不返回独立端口字段、`targetUrl`、安装路径、后端配置、日志、route id 或任何 token。
- `.m` 是已配对手机的自动访问链路：WebApp 安装并启动后即可生成地址，不依赖移动端是否正在线订阅，也不会调用 `.wa` 公网发布接口。
- React App 首次打开 `.m` 地址时使用当前配对 `app` token 建立 HttpOnly Tunnel 会话；Tunnel 重定向到不含 token 的干净地址，认证信息不会进入本地 WebApp 请求。
- `.wa` 是用户主动开启的公网分享链路：只有设置页“一键发布”或 `desktop.web.webapp.publish` 才会创建；停止分享只禁用 `.wa` 路由，不改变 `.m` 手机访问规则。
- 删除已发布 WebApp 前必须先禁用 Tunnel 路由；禁用失败时保留本地安装，避免留下仍激活但失去管理入口的公网路由。
- Tunnel 未登录或缺少设备配置时，一键发布必须给出明确前置条件，并提供跳转 Tunnel Hub 设置的入口；已完成 Desktop 登录时，Tunnel 可使用站点 token，或在品牌没有配置可选站点桥时使用仍有效的 Desktop SSO access token；点击“一键发布”会自动启用已经配置完整的 Tunnel Hub，不要求用户先去隧道设置重复开启，也不得通过扩充 Bootstrap 权限绕过。
- 两条链路都依赖 Desktop 和本地 WebApp 运行：手机目录的 `.m` 地址使用设备主机下的 `/webapps/<前端端口>/` 路由，公网分享的 `.wa` 地址必须直接使用 Tunnel Hub 返回的稳定 HTTPS `publicUrl`。
- WebApp starter 与 demo 源码由 `webapp-builder` skill 的 `assets/` 维护，不放入 Desktop Renderer 的 `public/` 目录。
- 打包 demo 由 `DEMO=true` 控制，并要求 `WEBAPP_BUILDER_SKILL_DIR` 指向 `webapp-builder` skill；Desktop 只把 `assets/demo-node-html` 复制为可选打包资源并负责安装运行。
