# 本地网站应用

## 定位

本文件是 ZenMind Desktop WebApp schema v4 的规范来源。WebApp 是 `webs` 域中的本地可运行应用，页面始终通过 Electron Main 创建的 loopback gateway 暴露；WebView、Mobile Tunnel 和公网 Tunnel 只依赖 gateway 的 `webUrl`，不感知后端使用 Node、Go、Rust、Java 还是外部容器。

Desktop 的职责是安装校验、运行编排、gateway、同源代理、健康检查、日志、状态、Tunnel 和 Desktop 托管进程树清理。Desktop 不在用户机器上构建应用、不执行 `npm install`，也不下载 JRE 或管理容器生命周期。

## 运行模型

```text
webapp.json v2/v3/v4
  -> 校验并归一化为 v4 内部模型
  -> WebappRuntime 状态机
  -> 内置 Launcher Registry
       none      纯静态，无子进程
       node      Electron 自带 Node 子进程
       native    Go/Rust 等当前平台预编译程序
       java      系统 Java 独立 JVM
       container 外部 Docker/Podman 容器，只读挂接
  -> 每个 WebApp 一个 127.0.0.1 gateway 和独立 origin
  -> WebView / .m Mobile Tunnel / .wa Public Tunnel
```

`WebappRuntime` 只负责状态机和资源编排，语言相关命令由内置 `BackendLauncher` 实现。Manifest 不得携带任意 shell 命令，插件暂不能注册 launcher。

### Gateway

- `frontend.mode=static`：gateway 托管 `root/index`，可启用 SPA fallback；只有匹配 `apiPrefix` 的 HTTP、SSE 和 WebSocket 请求代理给后端。
- `frontend.mode=proxy`：gateway 将整站 HTTP、streaming、SSE 和 WebSocket 请求代理给后端，适合 SSR 或由后端输出页面。
- `/__desktop/*` 永远由 Desktop 保留，不转发给后端。
- 所有 listener 只监听 `127.0.0.1`。不同应用使用独立端口和 origin，以保留根路径资源、localStorage、Service Worker 和现有 Tunnel 按端口寻址语义。
- 所有 gateway 运行在同一个 Electron Main Node 事件循环；纯 HTML 应用只有一个轻量 listener，`pid=null`。

## schema v4

最小静态应用：

```json
{
  "schemaVersion": 4,
  "id": "example-static",
  "kind": "webapp",
  "version": "1.0.0",
  "target": "universal",
  "label": "Example Static",
  "openMode": "workspace",
  "frontend": {
    "mode": "static",
    "root": "frontend",
    "index": "index.html",
    "spa": true,
    "apiPrefix": "/api"
  }
}
```

带托管后端的应用：

```json
{
  "schemaVersion": 4,
  "id": "example-app",
  "kind": "webapp",
  "version": "1.0.0",
  "target": "darwin-arm64",
  "label": "Example App",
  "frontend": {
    "mode": "static",
    "root": "frontend",
    "index": "index.html",
    "spa": true,
    "apiPrefix": "/api"
  },
  "backend": {
    "launcher": "native",
    "entry": "backend/server",
    "args": [],
    "env": {},
    "port": 0,
    "health": {
      "type": "http",
      "path": "/health",
      "timeoutMs": 10000
    }
  }
}
```

公共规则：

- `version` 必填，使用语义版本，进入安装记录、日志和 runtime state；程序目录仍只保留当前版本。
- `target` 必须是 `universal`、`darwin-arm64`、`darwin-x64`、`windows-arm64` 或 `windows-x64`，本地导入和市场安装都校验当前平台。
- `frontend.mode=proxy` 必须提供 `backend`；`static` 可以省略后端。
- `openMode` 是 Desktop 展示偏好，可选值为 `workspace` 或 `dialog`。缺省及未知值按
  `workspace` 处理；`dialog` 是兼容字段名，表示由 Desktop 打开独立、可拖动的非模态
  Electron 窗口，只改变宿主窗口，不改变 gateway、运行时、鉴权或 Tunnel。
- 托管后端 `port` 默认 `0`，由 Desktop 分配。
- v4 后端必须显式提供 HTTP 或 TCP `health`；HTTP 还必须提供 `path`。
- 所有包内路径必须是安全相对路径，禁止绝对路径、`..`、隐藏段、符号链接逃逸和 shell。

### Node

```json
{
  "launcher": "node",
  "entry": "backend/server.mjs",
  "args": [],
  "env": {},
  "port": 0,
  "health": { "type": "http", "path": "/health", "timeoutMs": 10000 }
}
```

Desktop 固定用 Electron 的 `process.execPath` 并注入 `ELECTRON_RUN_AS_NODE=1` 启动独立子进程，不依赖系统 Node。包必须包含完整可运行产物，安装时不执行依赖安装。异常退出会关闭 gateway、撤销动作令牌并清理进程树。

### Go / Rust 与其他原生程序

```json
{
  "launcher": "native",
  "entry": "backend/server",
  "args": [],
  "env": {},
  "port": 0,
  "health": { "type": "tcp", "timeoutMs": 10000 }
}
```

Desktop 直接 spawn 包内入口，不经过 shell。市场包应按 OS/架构提供预编译资产，目标机器不需要 Go、Rust 或构建工具。macOS 会校验入口并修复执行位；Windows 入口必须是 `.exe`。原生二进制应使用平台专用 `target`。

### Java

```json
{
  "launcher": "java",
  "entry": "backend/app.jar",
  "jvmArgs": ["-Xmx512m"],
  "args": [],
  "env": {},
  "port": 0,
  "health": { "type": "http", "path": "/health", "timeoutMs": 15000 }
}
```

- Desktop 不携带、不下载、不安装 JRE/JDK。
- Java WebApp 使用 `javac --release 21` 构建；运行时最低 Java 21，不设最高版本，推荐 Java 25 LTS。
- JRE、JDK 和不同 OpenJDK 发行版均可，不绑定厂商。JavaFX 不属于基础运行时；JNI 应用必须发布平台专用资产。
- 查找顺序为设置中的 `javaExecutable`、`JAVA_HOME/bin/java`、系统 `PATH`。
- Desktop 以有界超时运行 `java -XshowSettings:properties -version`，检测规范版本与 `java.home` 并缓存结果。
- 启动命令固定为 `java [jvmArgs] -jar <entry> [args]`，每个应用一个独立 JVM。
- 找不到 Java、探测失败或版本低于 21 时状态为 `blocked`。用户在系统外安装/升级 Java 或配置路径后可重新检查并启动。

### 外部 Docker / Podman 容器

```json
{
  "launcher": "container",
  "management": "external",
  "engine": "auto",
  "containerName": "example-app",
  "image": "example-app:1.0.0",
  "containerPort": 8080,
  "health": { "type": "http", "path": "/health", "timeoutMs": 10000 }
}
```

容器和镜像必须提前在 ZenMind 外部准备好。Desktop 不执行 pull、load、build、create、start、stop、restart 或 delete，也不允许 Manifest 声明容器启动命令、环境变量或构建配置。

start/restart 只执行：

1. 发现声明或设置指定的 Docker/Podman。
2. 确认期望 image 已安装。
3. inspect 指定容器并确认 `running`。
4. 比较运行容器的 image ID 与期望 image ID。
5. 查找 `containerPort/tcp` 的 host 端口。
6. 只接受 `127.0.0.1` 或 `::1` 绑定。
7. 后端健康检查通过后创建 gateway。

任何前置条件不满足都进入 `blocked`，由用户在 ZenMind 外部修复。stop/restart/退出 Desktop 只关闭或重建 gateway，绝不改变容器状态。共享监控器会检查已挂接容器；失联后清除 `webUrl` 并关闭 gateway。

## 托管进程环境与动作安全

Node、native 和 Java 固定收到：

- `HOST=127.0.0.1`
- `PORT=<backend-port>`
- `WEBAPP_ID`
- `WEBAPP_ROOT`
- `WEBAPP_DATA_DIR`
- `WEBAPP_STATE_DIR`
- `WEBAPP_LOG_DIR`

v4 托管后端每次启动还会获得 `DESKTOP_ACTION_BRIDGE_URL` 和一次性 `DESKTOP_ACTION_BRIDGE_TOKEN`。令牌只授权 WebApp 后端所需的安全助理动作，停止或进程退出立即撤销，且不写入 manifest、runtime state、日志或移动端响应。v2/v3 保留原动作桥地址行为以避免兼容性破坏。

页面可通过同源 `POST /__desktop/actions/call` 使用明确开放的本地动作；该路径校验当前 loopback WebApp Origin，Tunnel 公网页面不能借此消费本机模型或打开宿主机目录选择器。外部容器不会收到启动环境或动作令牌，但其页面仍可使用 gateway 的同源安全动作。

本地 WebApp 页面可调用 `desktop.web.webapp.selectDirectory` 打开一次 Desktop 原生目录选择器。
结果只包含 `canceled` 与用户明确选择的单个目录 `path`/`name`。该动作不授予 Desktop
文件读写能力，也不把路径加入公共移动端目录；WebApp 后端若使用该目录，必须自行限制
workspace root、拒绝路径逃逸，并确保其文件 API 不对 `.m`/`.wa` 暴露。

## 兼容、状态与接口

- v2/v3 `backend.runtime=node` 在内存中归一化为 `launcher=node`，启动时不改写文件。
- 编辑 v2 会写成 v3；编辑 v3 保持 v3；编辑 v4 保持 v4 和 launcher 专用字段。
- v2/v3/v4 均可保存顶层 `openMode`；历史 manifest 未声明时保持原有主页面打开行为。
- `openMode=dialog` 时每个 WebApp 只保留一个原生窗口；重复打开聚焦已有窗口，关闭窗口
  停止 runtime，主窗口始终保持可交互。
- 侧边栏 WebApp 操作菜单按当前宿主显示“在新窗口打开”或“在内置窗口打开”。两种动作都
  写回 `openMode` 并复用已运行的 gateway；宿主切换本身不停止或重启 WebApp runtime。
- `WebappRuntimeStatus` 为 `stopped | starting | running | blocked | error`。
- runtime state 包含 `version`、`target`、`launcher`、`ownership`、`runtimeVersion`、`externalId` 和脱敏的 `prerequisiteIssues`，并保留 URL、端口和 PID 字段。
- 移动端 catalog 不返回 launcher 路径、Java 路径、容器名、内部端口、前置条件详情或 token。

公开动作保持 start/stop/restart/open/publish 名称不变，并新增：

- `desktop.web.webapp.checkPrerequisites`
- `desktop.web.webapp.selectDirectory`

Preload IPC 还提供 `checkPrerequisites`、`getRuntimeSettings` 和 `saveRuntimeSettings`，供安装预检及设置页使用。

## 安装、升级、恢复和卸载

程序目录继续使用 `data/webs/webapps/<id>/` 的平铺结构，不创建 `versions/`、`current.json`、历史清理任务或手动回滚 UI。持久数据独立位于 `data/webs/webapp-data/<id>/`。

升级采用同盘事务替换：

1. 解压到 `.staging/<id>-<nonce>/`。
2. 完整校验 manifest、平台、路径和运行前置条件。
3. 停止旧应用。
4. 将旧目录原子 rename 到 `.backup/<id>-<nonce>/`。
5. 将 staging 原子 rename 为正式目录。
6. 启动新版并完成健康验收。
7. 成功删除 backup；失败立即恢复旧目录并重启旧版。

`state/webs/webapps/<id>/install-transaction.json` 只在事务进行中存在。Desktop 启动时处理意外中断：正式目录缺失但 backup 存在时恢复；正式目录完整时清理遗留 staging/backup。Windows 在进程树停止后进行有界 rename 重试，macOS 另行处理入口执行位。

新安装缺少 Java 或外部容器时允许以 `blocked` 保留。升级已有应用若预检失败，不替换旧版本。升级保留 `webapp-data/<id>`；卸载删除当前程序、该持久数据、state 和 logs，不保留历史版本。

卸载由侧边栏、市场和插件资源统一进入 disposal 流程：

```text
阻止新打开
  -> 关闭独立窗口并卸载内嵌 WebContentsView
  -> 停止发布路由
  -> 关闭 gateway / socket 并撤销 token
  -> 停止并复验 Desktop-owned 进程树
  -> 删除程序、数据、state、logs 和安装记录
  -> 广播 removed
```

任一步停止或复验失败都保留安装记录与文件，并向调用方返回可操作错误。Desktop 退出时除内存中的 runtime 记录外，还读取持久化 state 中的 Desktop-owned PID，清理重启后失去子进程句柄的孤儿。外部 container 仍只关闭 gateway，不停止或删除容器。

## Tunnel 与移动端

- `.m` 是已配对手机的自动访问链路，使用 `https://<设备>-<gateway-port>.m.../`，不要求用户发布。
- `.wa` 是用户主动的一键发布链路，停止分享只禁用 `.wa` 路由。
- gateway 端口改变后，已发布稳定路由会自动同步。
- 删除已发布 WebApp 前必须先禁用 Tunnel 路由；失败则保留本地安装。
- 移动端只取得脱敏目录字段，首次用配对 token 建立 HttpOnly Tunnel 会话后跳转到无 token 地址。
