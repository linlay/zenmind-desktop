# 本地网站应用：Manifest v1

ZenMind WebApp 的唯一宿主契约是 `src/shared/webapp-manifest.ts`。它导出 Zod schema、`WebappManifestV1`、解析函数和 JSON Schema 生成入口；公开生成物是 `docs/contracts/webapp.schema.json` 与无依赖校验器 `docs/contracts/webapp-manifest-validator.mjs`。CI 使用 `npm run webapp-contract:check` 检查生成物漂移。

ZIP 只负责传输目录。Desktop 与 WebApp 的关系只建立在包根目录的 `webapp.json` 上，不从 ZIP 名、目录名、会话文本或安装参数推导身份和运行策略。

## 契约边界

| 区域 | 解释者 | 内容 |
| --- | --- | --- |
| 宿主契约 | Desktop | 身份、版本、target、打开方式、前端托管、后端启动、健康检查、权限和智能体路由 |
| `appConfig` | WebApp | 任意 JSON 业务配置、展示规则、输出格式、提示词片段和功能开关 |

业务需求默认只扩展 `appConfig` 与 WebApp 代码。只有新增 Desktop 系统能力时才增加对应 typed capability；不提供插件系统、动态脚本、模板 DSL、通用 workflow 或万能 extensions。

## 完整示例

```json
{
  "schemaVersion": 1,
  "id": "meeting-notes-6f39d82a541c793e",
  "label": "会议纪要",
  "version": "1.0.0",
  "target": "universal",
  "openMode": "workspace",
  "appConfig": {
    "outputLanguage": "zh-CN",
    "defaultStyle": "concise",
    "sections": ["摘要", "关键结论", "行动项"],
    "allowMarkdown": true,
    "features": {
      "summarize": { "prompt": "输出摘要、关键结论和行动项。" },
      "polish": { "prompt": "保持原意，只返回正式、自然的改写结果。" }
    }
  },
  "frontend": {
    "root": "frontend",
    "index": "index.html",
    "spa": true,
    "apiPrefix": "/api"
  },
  "backend": {
    "command": {
      "type": "electron-node",
      "script": "backend/server.mjs"
    },
    "args": [],
    "env": {},
    "health": {
      "type": "http",
      "path": "/health",
      "timeoutMs": 10000
    },
    "shutdownTimeoutMs": 3000
  },
  "desktopBridge": {
    "version": 1,
    "capabilities": {
      "assistant.chat": {
        "agentKey": "summary-agent",
        "instruction": "你是中文文档处理助手，严格按照本次任务要求输出。"
      },
      "native.dialog.directories": {}
    }
  }
}
```

未知宿主字段、未知 capability、旧 schema、capability 数组和顶层 `assistantAgentKey` 直接拒绝。没有兼容读取或迁移。

## appConfig

`appConfig` 必须是 JSON object，可任意嵌套字符串、有限数字、布尔值、null、数组和对象。Desktop 不解释业务字段，但拒绝危险对象键与 secret-like 字段名。manifest 上限 256 KiB，`appConfig` 上限 128 KiB；包默认可读，严禁密码、访问令牌、模型密钥和私钥。

前端只通过 SDK 读取，不需要理解 Gateway 的内部配置路径：

```js
const appConfig = await desktop.app.getConfig();
```

后端通过 `WEBAPP_MANIFEST_PATH` 读取同一 manifest。manifest 是打包配置；用户运行后可修改的数据写 `WEBAPP_DATA_DIR`，升级不覆盖。

## 前端与后端

Desktop 永远静态托管 `frontend.root`，入口是 `frontend.index`，`spa=true` 时无扩展名的缺失路径 fallback 到入口。只有 `apiPrefix` 本身及其子路径代理到当前 WebApp 的动态后端端口；`/__desktop/*` 是保留路径。

backend command 只有三种：

- `electron-node + script`：用 Electron bundled Node 执行包内 JS module。
- `bundled + executable`：执行包内目标平台可执行文件，因此 target 不能是 `universal`。
- `system + executable`：从 Desktop 本机绑定或 PATH 解析已有可执行文件；不写回 manifest，不自动下载。

声明 `backend` 但省略 `command` 时，Manifest v1 明确默认 `{ "type": "electron-node", "script": "backend/server.mjs" }`。

Desktop 使用安装根目录作为 cwd，以参数数组直接 spawn，绝不经过 shell。Desktop 注入 `HOST`、`PORT`、`WEBAPP_ID`、`WEBAPP_ROOT`、`WEBAPP_MANIFEST_PATH`、`WEBAPP_DATA_DIR`、`WEBAPP_STATE_DIR`、`WEBAPP_LOG_DIR`，以及获准时的 Action Bridge URL/token；manifest env 不能覆盖保留变量。

后端必须声明 HTTP 或 TCP health。停止时终止进程组，等待 `shutdownTimeoutMs` 后强杀；没有 stopCommand、shell、任意 cwd 或 restartPolicy。

## 智能体

一个 WebApp 最多绑定一个智能体。`assistant.chat.agentKey` 可省略，缺省使用 Desktop Helper Agent；显式 Agent 不可用返回 `assistant_agent_unavailable`，不静默替换。`instruction` 可省略，最大 8,000 字符，是整个 WebApp 每次调用都追加的固定要求。

摘要、润色、翻译等具体功能提示词属于业务配置，放入 `appConfig`。WebApp 根据用户选择组合 prompt 和本次内容，不为每种功能扩展 Desktop schema。

页面调用：

```js
const appConfig = await desktop.app.getConfig();
const prompt = appConfig.features.summarize.prompt;
const result = await desktop.assistant.chat(
  `${prompt}\n\n待处理内容：\n${meetingContent}`
);
```

后端向 `${DESKTOP_ACTION_BRIDGE_URL}/actions/call` POST `desktop.assistant.chat` 与 `{ "message": "..." }`，并携带注入 token。Desktop 从 token 得到可信 WebApp ID，读取已安装 manifest，校验 capability，解析固定 Agent 与 instruction，再结构化组合本次 message 调用现有 Agent Platform `/api/query`。总输入最大 12,000 字符。

调用方传入的 agentKey、instruction、permission、chatId、runId 或 full_access 全部拒绝。v1 只支持一次性文本，不支持流式、会话复用、附件、approval 或 awaiting；出现真实需求时新增独立 typed capability。

## ID、安装与升级

`desktop-webapp init` 首次生成 `<label-slug>-<16位随机hex>`；中文或空 slug 使用 `webapp-<suffix>`。会话内容不参与 ID。继续修改同一项目复用 manifest；创建第二个项目重新 init。显式 ID 只校验，不规范化；目录名与 expectedId 只做精确断言。

- 未安装 ID：安装。
- 同 ID、更高版本：确认后事务升级。
- 同 ID、同版本、相同目录摘要：幂等成功。
- 同 ID、同版本、不同摘要：`version_content_conflict`。
- 同 ID、低版本：`downgrade_not_allowed`。
- 不同 ID：并行安装。

v1 没有 force、覆盖和降级。每次安装/升级都真实启动静态 gateway 和可选后端并执行 health；失败回滚旧包并恢复升级前运行状态。

## 模块职责

对外只有 WebApp Manager 语义：Manifest Contract 解析 manifest，Installer 管版本/摘要/事务/回滚，Runtime Supervisor 管托管/启动/健康/停止，Bridge Policy 管 capability/token/Agent 路由。Renderer 只展示摘要、本机 system executable 绑定和结构化错误，不解析 manifest、不决定版本、不路由 Agent。
