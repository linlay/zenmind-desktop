# 架构与模块边界

## 当前状态

`zenmind-desktop` 是 Electron 桌面壳。主进程负责本地资源、服务生命周期、插件、市场、网站应用、看板、桌宠和桌面协议；渲染层负责 React UI；preload 负责安全暴露 webview / renderer bridge；`src/shared` 保存跨进程契约。

当前服务注册已经迁移到 `manifest.json` 驱动。`service-registry.ts` 只维护运行时 registry，不再硬编码内置服务结构。

## 核心流程

启动装配主链路：

```text
src/main/index.ts
  -> lifecycle/startup
  -> ensure data roots / env bootstrap / desktop state
  -> loadBuiltinServices() + loadInstalledPlugins()
  -> runStartupPreparation()
  -> start non-core runtime: webs, pet, desktop ws, assistant bridges
  -> renderer AppShell
```

核心模块边界：

- `src/main/services/manager`：内置服务与插件的安装、初始化、启停、健康检查、日志、PID 和恢复。
- `src/main/manifest-utils.ts`：manifest 读取、兼容归一化和服务定义默认值。
- `src/main/plugin-*`：插件导入、桥接、设置、资源声明、卸载和桌面动作。
- `src/main/marketplace*`：市场 catalog、下载、安装记录和各资源分区安装器。
- `src/main/webs`：外部网站、本地网站应用、排序和可被桌面动作激活的 web surface。WebApp 子域内由 `store` 负责 Manifest v2 校验与本地配置，`runtime` 只编排状态机，`launchers` 封装 Electron Node、独立可执行文件、Python 和 Java 的启动差异，`gateway` 统一暴露 loopback origin 与 WebApp Bridge ES Module，`capability-policy` 统一维护 Desktop 公开 Bridge 能力、canonical action 和 invocation scope；它们不注册为 service。
- `src/main/assistant`：agent-platform bridge、Copilot、附件和桌宠状态同步。
- `src/main/enterprise-chat-runtime.ts`：企业聊天的 SSO 换票、HTTP/WS 协议、重连和内存投影；不属于 built-in service lifecycle。
- `src/main/kanban*`：本地 Kanban、云只读缓存、远端控制和 automation 同步。
- `src/main/desktop-action-bridge.ts` 与 `src/main/desktop-ws-server.ts`：桌面自动化协议入口。
- `src/renderer`：AppShell、Control Center、Market、Service WebView surfaces、Kanban、settings 和插件管理页面。
- `src/preload`：renderer preload 与 service webview preload。
- `src/shared`：contracts、desktop actions、desktop ws、brand、auth bridge 等共享定义。

对话分享的创建、复制与撤销交互属于 Desktop；安全快照由 Agent Platform 提供并上传到 Tunnel。Tunnel 只保存并公开返回版本化 JSON，最终 `/share/{shareId}` 页面由独立部署的 `agent-webclient` 轻量入口渲染，不属于 Desktop WebView 或 Tunnel Public SPA。

## 配置与接口

- Node / Electron 入口由 `package.json -> main` 指向 `dist-electron/main/index.js`。
- 主进程 TypeScript 通过 `npm run build:main` 编译和 bundle；渲染层通过 `npm run build:renderer` 由 Vite 输出。
- 主进程、preload、renderer 之间的 DTO 优先定义在 `src/shared/contracts` 及邻近共享模块。

## 约束与注意事项

- 新增跨进程字段先补 shared contract，再接 IPC / bridge / renderer。
- 新增服务能力优先进入 service manager 或对应领域模块，不在 `src/main/index.ts` 堆业务逻辑。
- 企业聊天长期 JWT、短期 IM session token 和 WebSocket ticket 只停留在主进程；preload/renderer 只消费 shared DTO。
- WebApp Desktop 边界以 Manifest v2 为唯一契约，包含程序包事务安装、`electron-node`/`executable`/`runtime` 三种 typed command、typed routeConfig gateway、健康检查、日志、生命周期、用户配置和 Desktop Bridge 版本。所有本地 WebApp 页面共享 Desktop 集中维护的公开 Bridge 白名单，不在 Manifest 中逐项声明 capability。`appConfig` 与 `userConfig` 的业务语义由 WebApp 解释；WebApp 不能借插件扩展运行时。
- Manifest v2 原生交互只包含 HTTP(S) 系统浏览器打开、用户发起的文件/目录/保存路径选择、audio-only 麦克风授权与页面采集、文本剪贴板写入和通知。Desktop 只返回用户明确选择的 path/name，不读取、创建、保存或管理文件；工作目录校验、文件读写、监听和业务配置仍属于 WebApp。Desktop 不录制、传输或上传麦克风音频。
- page gateway、托管后端和普通 Desktop Action 使用独立 scope。公开原生能力只能由本地 `webappPage` 调用；Website、Tunnel、后端 token、缺少/伪造 Origin 和普通 `/actions/call` 都不能调用。reserved SDK 函数不能注册成 Action 或使用内部 IPC fallback。
- 外部容器是 attach-only 资源，Desktop 的 stop/restart/退出只能处理自身 gateway，不能改变容器或镜像。Node/native/Java 才是 Desktop 托管进程，必须使用进程树清理。
- WebView 和 Tunnel 只消费 WebApp gateway `webUrl`，不得按后端语言分支，也不得绕过 gateway 直接访问后端端口。
- 平台差异靠显式分支处理，尤其是脚本、路径、可执行文件名、打包资源和 Windows PowerShell。
- `dist-electron/` 是构建产物镜像；长期维护事实以 `src/` 为准。

## Chat Work Panel 边界

- `agent-webclient-chat` 仍是唯一常驻主聊天 WebView；切换 `chatId` 只导航这一实例，不为每个 Chat 创建主聊天 WebView。
- `ChatWorkPanelHost` 是独立的 renderer 运行期宿主，维护 `chatId -> workspace`。一个 workspace 可包含多个真实 WebView Tab，切换 Chat 或 Desktop 页面只改变可见性，不卸载已开启 workspace。
- 每个 Chat workspace 使用独立的非持久 Electron partition；同一 workspace 的 Tab 共享 partition。关闭最后 Tab、用户或 Agent 关闭、归档或永久删除 Chat 时卸载全部 guest，并清理该 partition 的 storage、cache 和 auth cache。
- Work Panel 不进入 Website/WebApp/Builtin Browser 的公开 surface registry。它只以 `chat-work-panel` 类型进入内部 embedded CDP registry，并携带可信 `ownerChatId`。
- workspace、Tab、URL 与 generation 只存在于本次 Desktop renderer 进程；重启不恢复，也不做后台淘汰。
