# 桌宠系统

## 当前状态

Desktop 桌宠是独立小窗能力，支持内置品牌桌宠、用户导入桌宠、agent 绑定、未读/运行任务状态、预览面板和手动 signature 动作。

配置保存到 `config/desktop/pet.json`，运行状态保存到 `state/desktop/pet-state.json`，用户资产保存到 `data/pets/<pet-id>/`。

## 核心流程

```text
pet settings
  -> desktop-pet runtime
  -> pet window
  -> agent-platform status / stream
  -> unread, awaiting, running task count
  -> state file + renderer updates
```

窗口模式：

- `base`
- `bubble`
- `preview-collapsed`
- `preview-expanded`
- `task-list-compact`
- `task-list`

标准状态包括 idle、jumping、moving-left、dragging、done、failed、running、awaiting、review。

## 配置与接口

桌宠设置核心字段：

- `desktop.pet.state`

- `desktop.pet.hide`
- `desktop.pet.list`
- `desktop.pet.set`

## 时间契约

桌宠的任务、消息、预览项和状态快照沿用助理 IPC 的 `EpochMilliseconds` 契约：平台派生的 `createdAt`、`updatedAt` 和事件 `timestamp` 不在主进程转换为 ISO 字符串。桌宠流只接受 `0..8_640_000_000_000_000` 内的安全整数；缺失、字符串、负数或浮点时间的事件会被忽略并触发状态刷新，不会以本机当前时间替代。桌宠 UI 如需显示时间，仅在渲染时格式化该值。完整规则见[时间契约](时间契约.md)。

## 约束与注意事项

- `boundAgentKey` 是运行绑定，长期用户偏好和运行状态需要分清。
- 用户桌宠资产通过 `desktop-pet` 专用 asset protocol 读取，不直接拼未校验文件 URL。
- 桌宠窗口位置需要按当前 display workArea clamp，拖拽和 edge dock 行为要显式处理。
- 新增桌宠外观必须包含 required state keys，并满足标准动作帧数约束。
