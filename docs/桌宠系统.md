# 桌宠系统

## 文档定位

本文描述桌宠的资产、窗口、状态和 Agent 绑定边界。设置字段、动作参数、像素、动画帧和 UI 样式以源码、资产 contract 及测试为准。

## 系统模型

桌宠由四部分组成：

- **资产包**：角色外观、状态动画和元数据。
- **用户设置**：启用状态、当前外观和宿主偏好。
- **窗口 runtime**：透明置顶窗口、拖动、显示器定位和平台交互。
- **导航状态投影**：把 Main WS Primary Push 形成的共享导航快照映射为桌宠表现。

资产、设置、窗口和导航状态分别管理，不能把窗口是否可见当作持久设置或 Agent 运行事实。配置只保存当前选择和宿主偏好，外观由当前选择派生供运行期 UI 使用；未读状态单独读写，状态文件缺失时使用正常初始值，不从配置补取。

## 生命周期

```text
加载设置与资产
  -> 校验当前外观
  -> 按启用状态创建窗口
  -> 读取共享导航快照
  -> 映射动画与未读状态
  -> 隐藏、切换、销毁或退出恢复
```

显示失败必须回滚到未启用的真实状态，不能留下“设置已启用但窗口不存在”。隐藏、关闭或异常销毁时同步清理预览和临时交互状态；正常应用退出可以保留下次恢复偏好。

## 资产与安装

桌宠资产通过内置品牌资源、本地导入或市场安装进入品牌隔离的数据根。安装前校验 identity、包结构、资源类型、大小和必需状态；升级不能覆盖用户选择和运行设置。

设置中的宠物助理外观沿用皮肤交互，仅提供“导入”按钮和单个 ZIP 包拖拽入口。Main 持有路径与安装权限，在异步操作及提交前复验主窗口顶层 frame；预加载只把浏览器 File 转换为宿主文件路径。导入器校验单角色清单、必需动作、图片解码、归档路径和有界资源量，拒绝目录、符号链接与大小写冲突，暂存完成后原子提交。同名本地或市场宠物不覆盖；失败清理暂存，保留原有资源与设置。导入只刷新外观列表，不自动切换角色、绑定 Agent 或启用桌宠。macOS 与 Windows 均只选择 ZIP 文件，拖入失败不得回退弹出选择器。

受授权的 Desktop Action 可按本机绝对 ZIP 路径导入单个桌宠，复用同一安装器和 runtime 拥有的串行队列；文件选择、拖入、工具导入及删除共享该队列。IPC 保留主窗口所有权复验，工具入口独立校验受信任调用方与平台路径。导入成功只返回外观标识和名称，不回传完整状态或资产路径。Platform 调用使用外观审阅及自动批准策略，并豁免重复 Desktop 确认；普通 Desktop 调用仍保留确认。

用户安装的宠物可在设置列表中确认删除，内置品牌宠物不提供删除入口，Main 同时拒绝其删除请求。删除仅按已安装目录中的用户宠物 ID 定位，拒绝任意路径、符号链接与越界目录，并与导入串行执行。macOS 移入废纸篓，Windows 移入回收站，不回退为永久删除。删除当前选中宠物后持久切回内置默认形象，其他设置不变；删除失败不切换选择。

renderer 通过受限资源协议加载本地资产，不接触任意文件路径。损坏或缺失外观回退到当前品牌可用默认项，并报告可诊断错误。

## Agent 绑定

导航为最近活动和 attention 分别保留投影：最近活动继续使用每个 Agent 的有界最近会话并合并全局置顶，供动画、插件活动快照和托盘使用；attention 对项目与无目录 Agent 读取完整 Chat 摘要，持有待确认身份与版本游标。桌宠只提供一个对话概览，不再按活动任务或运行预览切换面板。概览由导航的未读与待确认会话集合合并而成，不把仅运行中的会话当作待处理消息。

桌宠不直接连接 Agent Platform，也不注册 Realtime Broker consumer。Navigation 是桌宠通知状态的唯一事实源：冷启动和重连时统一建立 HTTP 基线，运行期只由 `desktop-main` Primary lane 校验通过的全局 Push 更新，再把同一快照同时发布给 Nav Bar 和桌宠。桌宠不读取 Chat 数据库、不单独请求 Agent/Chat、不消费 Assistant Run 逐事件流，也不订阅、创建、恢复或清理 RunChannel，不发送 run attach/detach。绑定 Agent 不授予桌宠额外执行权限，也不改变 Copilot、Chat 或 Kanban 的运行所有权。

Chats、Projects 与桌宠使用同一个 attention 计算契约。unread 保持当前导航会话范围：普通 `chatItems`、可导航项目的完整未读会话和额外普通置顶；pending 统一按完整摘要中仍待确认的会话数量统计，不再按项目数量计数，也不受普通 Chats 显示窗口、项目最近活动或手动顺序截断。分组按归属展示，置顶可以同时归属于项目，桌宠全局按 Chat 身份去重。概览标题分别标明未读和待确认数量，同一会话可同时贡献两个数字、只显示一张卡片；pending-only 会话不增加蓝色未读数。预览缓存和持久化状态都不能参与角标计算。unread 使用 Nav Bar 相同的蓝色，pending 使用橙色。

人物只显示未读和待确认数量角标，两种角标打开同一个完整概览，待确认卡片始终排在前面；没有待处理会话时收起概览，不展示独立任务面板、运行数量角标或运行预览。人物动画仍由当前运行状态驱动。展开面板不隐藏人物角标。

时间点使用 shared epoch-milliseconds contract。临时连接失败保持最近可解释状态或进入 idle，不以当前时间伪造事件。

## 对话概览

桌宠“对话概览”逐条呈现 unread 与 awaiting 的并集，按 Chat 身份去重，标题分别标明两种数量，与人物对应角标一致。不因已读、会话时间、摘要缺失、侧栏窗口或显示数量上限丢弃仍待确认的会话；阅读只改变 unread，不解除 awaiting。awaiting 会话优先，同类按更新时间倒序排列；视窗完整显示三条，其余全部通过滚动访问，不再有前两条任务与不可操作的“更多”摘要。普通 unread 使用蓝点，awaiting 使用内联橙色时钟，不为状态单独保留一列。

普通 unread 可以在桌宠内继续回复或显式标为已读并关闭；awaiting 只提供打开原对话的入口，不承载回答表单，不显示回复与关闭按钮，Main 同时拒绝过期待确认条目的回复或标读关闭请求。普通阅读仍由 WebClient 在目标内容显示后同步 read。关闭普通 unread 时 Main 校验 Chat/Run 与版本，通过 Platform 单 Chat `/api/read` 提交已读，失败保留卡片并允许重试。卡片、标题数量和未读角标一起等待 Navigation 应用权威 Push，不在 Main 或 renderer 本地提前隐藏或减数；awaiting 在 read 后继续存在，只在上游等待状态解除且不再 unread 时移除。桌宠打开、成功回复、悬停、滚动和展开列表都不直接修改已读状态。

## 平台边界

macOS 与 Windows 分别处理透明窗口、置顶、任务栏可见性、拖动范围、显示器切换和退出行为。窗口位置必须约束在当前可用显示区域；休眠、分辨率变化和显示器移除后重新收敛。

macOS 的人物窗口使用不激活应用的浮动 panel，其边界由 Desktop 按显示区域约束，禁止 AppKit 再按 Dock 工作区移动或缩小宿主，避免松手后覆盖人物逻辑位置；承载回复输入的交互面板使用可成为 key window 的普通透明窗口，并维持置顶。Windows 显式保留无边框、可聚焦的交互面板。展示面板时不主动抢焦点，用户点击回复后允许正常键盘及输入法输入。

窗口 runtime 拥有人物的屏幕位置，并向 renderer 投影人物在透明宿主内的偏移。宿主因屏幕边界或 macOS 侧边 Dock 改变位置、尺寸时，人物仍连续跟随拖动；贴边标记只参与朝向与附属面板布局，不能在人物尚未到边缘时重新定位人物。拖动期间的几何投影只更新宠物窗口，不触发导航状态刷新。同一显示器上的基础宿主宽度保持稳定，不按人物横坐标在窄窗口和全宽窗口之间切换；只有显示器存在左侧工作区内缩时使用持续的全宽透明宿主，其余情况左右边缘均使用窄宿主。原生窗口边界与 renderer 偏移异步更新时，不得让过渡位置跳出本次移动区间。

透明宿主的空白区域必须允许鼠标点击落到下方窗口。macOS 与 Windows 均转发鼠标移动以恢复人物和角标的交互；renderer 按当前图像帧的可见像素判定人物命中范围，拖动持有期间保持鼠标捕获，角标按各自按钮的可见范围响应。

## 安全约束

- 桌宠页面不获得 Node、文件系统或任意 Desktop Action 权限。
- 资产内容不能注入脚本或逃逸资源根。
- 状态日志不包含消息正文、token 或用户身份明文。
- 预览窗口与正式窗口使用独立临时状态，不能覆盖持久设置。
- renderer/IPC 可以使用完整 `DesktopPetState` 编排窗口和动画，但公共 Desktop Action 只能返回启用状态、支持状态、当前外观 ID，以及外观的 `id/displayName/description` 摘要。任务、消息、Agent 状态、窗口状态、动画状态、资产路径、states 和 signature 不得进入公共 action 成功或错误响应。
