# 桌面协议与动作桥

## 文档定位

本文定义 Desktop 自动化能力的入口边界、动作模型、授权原则和页面控制归属。动作清单、请求字段、端口默认值与错误码以 `src/shared`、主进程实现和测试为准。

## 协议边界

Desktop 存在四类调用入口：

| 入口 | 主要消费者 | 边界 |
| --- | --- | --- |
| Desktop WebSocket | 已认证的本地或隧道客户端 | 会话、订阅、动作与状态事件 |
| Platform 反向 WebSocket Bridge | 内置 Agent Platform | 当前 run 逻辑绑定的 Desktop Action/CDP request |
| HTTP Action Bridge | 本机 WebApp 与调试工具 | 单次动作调用；不再是 Platform 调用链 |
| WebApp Bridge | 已安装的同源本地 WebApp | manifest 授权的有限能力 |
| renderer IPC | Desktop 自有 UI | 内部窗口与交互编排 |

这些入口可以复用同一动作注册表和执行器，但认证方式、调用上下文与授权范围不能互相替代。Agent Platform 助理使用的出站 WebSocket 不属于供外部客户端接入的 Desktop WebSocket。Desktop WS 的 `ap` namespace 只是全局 Realtime Broker 的本地 adapter，不拥有额外 Platform 连接，并会重写每个上游 request id。Broker 最多拥有 `desktop-main` Primary 与 `desktop-btw` BTW 两条物理 lane；反向 Action/CDP 只允许从 Primary 进入。内置 Platform 发来的反向 Action 直接以具体 `desktop.*` 名作为 request `type`，`id` 同时是动作请求标识，可信 Run/Chat owner 和当前 Execution Session 的 `workspaceRoot` 位于帧顶层 `source`，`payload` 只含动作参数；调用参数不能覆盖可信来源。`workspaceRoot` 只供 Main 做边界解析，不得出现在响应、调试记录或业务日志中。`desktop.cdp.call` 继续使用独立契约。Main Broker 将两者分发到现有核心 handler，不绕行 loopback HTTP。旧的统一 Action envelope 不提供兼容入口。

## 统一动作模型

动作定义集中在 shared contract，至少表达：

- 稳定名称与所属 namespace；
- 输入、输出及时间字段的类型边界；
- 只读或变更语义；
- 所需 capability 与调用面限制；
- 是否需要用户确认、页面上下文或活动窗口。

入口层只负责把可信上下文交给统一执行器，不能各自维护一份动作清单或自行改变语义。新增动作时，应先确定所属资源、最小权限、幂等性和失败模型，再补充实现与契约测试。

公共响应固定使用 `{ ok, action, result | error }`。普通资源写动作成功时只返回本次提交后的目标资源或其稳定标识符，不附带同领域的列表快照、成功提示或内层 `ok`；完整集合只由显式列表读取动作返回。动作后的直接容器状态如果是调用方正确理解结果所必需，可以作为有界例外返回：Web tab 动作返回当前 surface 的公开 tabs 与 activeTab，WorkPanel 动作返回可信 source Chat 的单个 workspace，但都不能扩展为其他 surface、其他 Chat 或全局资源快照。领域层即使为 renderer/IPC 生成更完整的 UI 状态，统一执行器也必须先把它投影为 action contract 声明的 DTO。

领域业务失败必须转换为外层 `ok=false`。一般错误 details 只保留定位请求或输入问题所需的信息，不能借错误响应回传资源全集；WebApp 生命周期错误是可诊断性例外，可以返回当前目标 WebApp 的精简 identity、完整 runtime/publish state、前置条件问题或安装阶段诊断，但仍禁止其他 WebApps、全局列表、Token、Cookie 和未脱敏凭据。领域声称成功却缺少契约要求的目标资源、状态或标识符时按 `invalid_action_result` 失败。

## 调用主流程

```text
请求进入协议适配层
  -> 校验身份、来源与大小限制
  -> 解析统一动作定义
  -> 校验 capability 和输入
  -> 必要时准备预览并请求用户确认
  -> 在所属模块执行
  -> 投影最小公共结果
  -> 规范化时间与错误
```

动作执行必须保留请求身份和运行上下文，便于审计与关联响应；敏感参数在确认界面和日志中必须脱敏。

## 会话与认证

Desktop WebSocket 在握手后建立有期限的设备会话，并负责 hello、心跳、token 临期提示和订阅清理。客户端 token 必须绑定允许的 scope 与当前安装的 device identity。

Main 对 device identity 采用进程级稳定快照：首次读取完成后，本进程内的 Realtime、Desktop WebSocket、Kanban、Tunnel 与其他消费者必须复用同一个 deviceId，不能因后续系统机器标识探测超时而切换。有效但不同的机器标识只在下一次进程启动的首次读取中触发重新绑定；账号、session、endpoint 或确认后的设备身份真实变化仍必须失效旧 Realtime generation，且不得自动重放请求。

HTTP Action Bridge 只监听 loopback，但“仅本机”不等于“已授权”。它仍需校验调用来源、请求形态和动作权限，并限制请求体、超时及并发。若未来允许非本机绑定，必须另行设计网络认证，不得复用当前信任假设。

Platform 反向请求只在其当前物理连接上处理。小结果返回标准 `response/error`；大 JSON 与 `Page.captureScreenshot` 分别使用 `desktop.bridge.response.delta`、`desktop.cdp.screenshot.delta`，chunk payload 不超过 256 KiB，最终 response 携带 streamId、chunkCount 与 totalBytes。收到 `desktop.bridge.cancel` 后停止后续 chunk 和终态发送；Desktop 不自行重放动作。

`desktop.webapp.package.init`、`desktop.webapp.package.validate` 与 `desktop.webapp.package.build` 只允许可信 Agent Platform Run 调用，所有工程、归档和输出路径都相对该 Run 的 `workspaceRoot`。其中初始化和构建虽写入 Workspace，但因目标被可信 Run 与 realpath 边界共同限制而不增加确认框。Agent Platform 调用 `desktop.webapp.install` 时只能提交 `workspaceArchivePath`；Desktop UI 和既有本机文件选择入口继续使用绝对 `archivePath`。Standalone 对三个 Tooling Action 返回 `desktop_action_unsupported_runtime`，不执行本地磁盘扫描。

`desktop.display` 是无需确认、无数据访问的 Main Window 显示动作，只接受 `kind=effect`、`effect=fireworks|snowfall|nationalDay` 与可选整数 `durationMs`。缺省时长为 8000 ms，有效范围是 1000–30000 ms；请求被接受后立即返回，不等待效果结束。主窗口隐藏、最小化或不可用时返回 `display_target_unavailable`。同一时刻只保留一个效果，新请求替换旧效果；覆盖层不接管鼠标和焦点，并在减少动态效果偏好下改用静态装饰与淡入淡出。

Desktop 托管模式下，Agent Platform 把 `scope=app` 且 JWT `device_id` 与握手 `deviceId` 一致的已认证 `source=desktop-main` 连接作为唯一 Desktop Main 默认 target；握手里的 `source` 本身不构成授权。`source=desktop-btw` 只登记 BTW lane，不替换 Primary、不成为默认 target，也不接收 Desktop Action/CDP 或全局 Push。每个 run 仍维护独立的运行期逻辑绑定；直接 query/attach 已有的有效绑定优先，`run_query`、automation 或其他独立根 run 缺少绑定时才指向当前 Desktop Main 并写回该 run。同一设备的同 lane 新连接只替换本 lane 旧 generation；旧 generation 在请求发送前已不可达时可以安全改绑，发送后断线不得重放。Standalone 不使用该默认 target，也不存在 HTTP、其他窗口或浏览器 tab fallback。

隧道只转发经过验证的协议帧，不扩大 Desktop 动作权限，也不绕过本机确认策略。

## 授权与用户确认

普通只读动作在满足 capability 后可直接执行；动作定义可以把会读取本机身份、路径、凭据摘要或内部服务拓扑的只读动作标记为敏感读取。敏感读取在全局动作确认开启且 `permissionMode` 不是 `full_access` 时每次确认，确认前不得开始聚合数据，确认界面只列出将读取的数据类别，不展示已读取的值。会修改页面、应用状态、文件或外部系统的动作默认需要确认，除非用户已显式授予覆盖该动作的权限模式。

`desktop.runtime.info` 只返回启动时缓存的产品名、版本和构建时间，并与 Desktop WebSocket `runtime.info` 共享同一信息源。`desktop.runtime.diagnostics` 由 Main 的单一聚合器读取设备信息、宿主路径、Electron/Node 版本、服务状态与 canonical Desktop SSO access token 摘要；它不返回 token 原文或 token 文件路径，不签发、不刷新也不改变认证状态，并禁止 WebApp page/backend 调用。凭据摘要只对应 Desktop 数据根目录下唯一的 canonical SSO access token，不扩大到 Tunnel runtime 凭据、Cookie partition 或临时 Agent token；其中过期时间只按 JWT payload 做未验证的诊断解析，不代表完成签名验证。

确认由主进程决定并构造安全摘要，renderer 只展示请求和返回选择。确认结果可以是拒绝、仅本次执行，或在明确范围和期限内授权连续的低风险页面操作。

以下情况必须拒绝或重新确认：

- 调用上下文、活动页面或目标资源在等待期间发生变化；
- 参数包含未经允许的跨域目标、路径或协议；
- 请求试图提升 permission mode 或绕过 capability；
- 主窗口和安全确认 fallback 都不可用。

## 页面控制与活动 Surface

页面动作由 Desktop 管理的活动 surface 执行。控制链路必须先确认当前可控对象，再取得其 DevTools/CDP 目标；不能凭历史 tab、URL 或 renderer 提交的任意 target 直接操作页面。Registry live active 不等于公开 CDP current：公开 current 还必须是与 Desktop 当前页面快照一致的非 child surface，且候选必须唯一；缺失或歧义均 fail closed。Copilot Dock 等 child surface 不进入公开查询，也不能凭已知 targetId 绕过当前页面边界；Chat WorkPanel 继续只接受匹配 source Chat 的私有授权。

公开 `Page.reload` 只接受可选布尔值 `ignoreCache`。Desktop 在完成精确 target 授权后直接刷新对应 guest WebContents；普通刷新和忽略缓存刷新都不通过临时 debugger attach/detach，不等待页面加载终态，也不得重建相邻 guest。未知参数或非布尔 `ignoreCache` 返回 `invalid_args`。

动作输出使用 canonical 短 surfaceId，并把角色、层级、父级和交互等级作为独立元数据返回。旧 surfaceId 只允许在限期兼容的输入解析层映射到 canonical ID，结果不得继续输出旧名；这类兼容映射不适用于 Agent WebClient capability 授权。

`desktop.web.navigate/reload/goBack/openTab/closeTab/switchTab` 返回提交后的单个公开 surface、该 surface 的完整公开 tabs 和明确的 activeTab。这个全景是 tab 动作的直接结果，不属于跨资源快照；`guestId`、`webContentsId` 等 Electron 内部身份不得进入公共 Action。操作目标或结果使用 `targetTabId`、`openedTabId`、`closedTabId` 表达，不能再复制一份 tab 对象。关闭最后一个 tab 时必须明确返回 `surface=null`、空 tabs 和 `activeTab=null`。`activateSurface` 继续返回激活后的详细目标 surface，批量 `refreshSurface` 继续返回刷新成功/失败的 tab 标识。

`agent-webclient`、Website、WebApp 与 Copilot surface 的页面权限彼此隔离。公开调用的控制上下文随当前页面变化；已授权 Website/WebApp Run 使用以下独立边界。

Broker 的 Run 页面授权绑定提交时的实例、注册 generation 和 canonical Run/Chat/owner。只有可信 Platform 反向 CDP 可由 Broker 附加内部 capability；HTTP、公共 CDP 网关及普通调用方自填 source/surfaceId 均不能获得后台权限。WorkPanel 的既有私有授权保持独立。

已授权的目标查询返回绑定应用当前全部已注册 tab，以及应用内部选中的 tab，公开响应结构不变。Website 后续新 tab 自动可见；命令每次按最新 Registry 检查实例、generation 和 guest，拒绝其他应用及关闭的 target。后台 bring-to-front 只改变该 Website 内部选择，close 精确关闭目标，两者经宿主内部通道投递，不导航主窗口，也不将 WebApp guest 当作 WorkPanel item。

切页、隐藏 Dock、observer detach 与同身份重连不撤销绑定；终态、页面关闭、WebApp 停止或身份失效释放授权，失效后不回退前台。授权 guest 按引用计数关闭后台节流，最后一个 Run 释放时恢复原设置；后台宿主保留有效视口与可渲染 guest，输入期间使用 CDP 焦点模拟而不激活窗口。

Electron webview 的宿主元素、内部 iframe 和原生 child widget 具有不同的焦点状态。后台命令按宿主串行执行焦点事务：先捕获前台焦点，输入阶段临时借用已授权 guest 的内部焦点，命令结束（包括失败）后恢复前台元素与 child widget；后台新 tab 的 DOM ready 也恢复前台 iframe。该通道不调用 BrowserWindow 的显示或激活动作，不改变前台路由。它保证命令结束后前台输入继续落在原页面；同一窗口内用户与 Agent 完全同时输入的零竞争不属于当前 Electron webview 实现已验证的保证。

页面内容提取与输入属于高敏感能力：限制数据量、屏蔽凭据字段，对上传文件、剪贴板与下载行为采用独立授权。

## Work Panel 与调试工作台

正式 WorkPanel Action 只使用 `desktop.workpanel.*`：`openTab` 承载通用 descriptor，`openWeb` 和 `refreshWeb` 接受规范化 HTTP(S) URL，`openLocalFile` 接受来源 Agent 权威 workspace 下的相对路径，`activateTab`、`closeTab` 使用 tabId，`closeWorkpanel` 销毁整个面板。按 URL 刷新只能命中可信 source Chat 已有的 Web item，并在刷新后激活该 item，不能跨 workspace 定位 guest。Main 绑定可信 source Chat 后才转交 AppShell command service；调用方不能提交 workspace、stable key、绝对路径、preload 或任意 webPreferences。未在当前注册表声明的调用一律按未知动作处理。

`webapp-ref`、`local-file` 与原生 document descriptor、文件选择与 Terminal 不属于公共 WorkPanel Action。固定 Agent WebClient `openItem` 与 `desktop.workpanel.openTab` 必须在进入 reducer 前拒绝这些 host-only kind；HTTP Action Bridge、Desktop WebSocket、WebApp page 和调试工作台也不能调用对应 claim 或句柄 IPC。`desktop.workpanel.openLocalFile` 仍是 Platform-only 例外。原生 HTML/图片只能由可信 Agent WebClient 的 `openDocument` 进入：Main 以真实 sender 取得 owner Chat，重新校验来源身份、realpath、MIME/签名与文本编码，再向 AppShell 发送不在公共动作表中的一次性 claim 消费请求。

WorkPanel reducer 与内部 IPC 可以继续返回 command item 和完整领域状态，公共 Action 边界只返回可信 source Chat 的提交后 workspace；不返回内层 `ok`、重复 item、其他 Chat workspace 或全局 WorkPanelState。关闭 item 时额外返回 `closedItemId`，最后一个 item 导致 workspace 销毁时 workspace 为 null；关闭整个面板只返回 workspaceId 与 closed 标记。

Agent WebClient 新 Chat 的反向 WorkPanel 请求还必须通过 Run 级 grant 门禁：普通新 query 的合法 `chat.start`，或附件预建 Chat 的匹配服务端 `request.query` 回显，已经完成 Desktop 路由与 Main Chat surface owner 同步，且匹配的 `run.start` 已注册。动作在同步进行中等待，成功后 grant 按 `runId + chatId + owner` 保留；切换 Chat 或关闭旧 logical surface 只释放 live observer，不撤销 grant。同步完成前用户切走、surface generation 失效或登记失败时仍 fail closed，但同一 canonical Run 的后续 attach 可以更新失败或未完成的 grant；旧同步结果不能覆盖新 generation。Run 完成、失败、取消、身份轮换或 Broker 销毁时才撤销 grant。确定性失败必须标记为不可立即重试并给出恢复条件，不通过 `run.start` 推断 Chat，也不重新导航到来源页面。

Desktop Main 默认 target 只解决反向请求送达，不授予 Chat workspace。`desktop.workpanel.*` 即使由补绑后的独立 run 发来，也必须继续通过上述 grant；没有 canonical Chat surface/grant 时返回 `source_chat_not_ready`，不能借用当前可见 Chat。Website、Pet、Theme 等不依赖 Chat workspace 的动作仍执行各自 capability 与确认策略。

Broker 完成上述 Run grant 校验后，必须用不可由协议 payload 构造的内部 Platform invocation context 调用统一执行器。只有这个上下文中的 `desktop.workpanel.openWeb`、`desktop.workpanel.openLocalFile` 与 `desktop.workpanel.refreshWeb` 免除远程动作确认；grant 缺失、身份冲突、失效或同步失败仍在进入执行器前 fail closed。`openLocalFile` 还必须匹配来源 Agent 的权威 workspace，Run 结束只撤销后续动作资格，不破坏用户仍在查看的本地文件 tab。HTTP Action Bridge、Desktop WebSocket、企业聊天、调试工作台与普通 Action handler 不获得该豁免，其他 WorkPanel 动作也不随之放宽。

`desktop:agent-webclient:new-chat:prepare` 是 Main Chat 用户重问动作的 query 前置握手，不属于 Platform Frame Port。renderer 必须用真实 service、surface、guest、active 状态、当前 canonical route 和 `ownerChatId` 校验 `agentKey + sourceChatId`，导航到一次性 `newChat` 后等待无 owner Surface 注册成功，再返回 `desktop:agent-webclient:new-chat:prepared`。任一身份变化、重复准备、登记失败或超时均返回失败并在仍停留目标 route 时回滚；Main 的 query/canonical owner 校验不读取也不信任该 ACK。

可信 Agent WebClient 页面的固定 WorkPanel bridge 是宿主内部用户交互入口：v6 增加语义来源联合 `openDocument`，Desktop 只对权威分类为 HTML/图片的文档返回 `native-html` 或 `native-image` 及 WorkPanel item 身份；不返回 handle、路径、revision 或内部 descriptor。仅 `unsupported_native_type` 允许 WebClient 回退 Document Surface；所有授权、缺失、越界和身份错误直接终止。兼容矩阵固定为 v4 仅旧 item 操作，v5 在此基础上增加 `openResource`，v6 支持当前完整能力，其他版本拒绝。v4/v5 每个 `version + method` 每进程只记录一次命中，日志同时包含 Desktop 版本，不包含请求参数。

最低可启动的 Agent WebClient Program bundle 是已验证发出 bridge v6 请求的 `agent-webclient v0.3.60`。安装、恢复和升级发现低于该版本的已安装 bundle 时不得启动；可用的当前内置 bundle 应完成替换，否则保持服务不可用。R0 已建立版本门槛、兼容矩阵测试和命中记录，正式发布命中数待采集；最低版本约束生效后，只有后续连续两个 Desktop 正式版本 R1、R2 的 v4/v5 事件都为零，才允许在 R3 或更晚删除 v4/v5 分支。任一 `version + method` 命中都记录发生版本并重置整个 v4/v5 观察窗，v6 不进入退出流程。

Office/未知文档的 Finder/默认应用动作不进入 Agent WebClient v5 WorkPanel bridge，而使用 Service WebView 内部消息 `desktop:agent-webclient:current-resource:action`。Guest 只提交动作、owner Chat 身份、Artifact/Reference profile 与受限相对路径；Main Chat Surface 必须匹配当前 owner Chat，WorkPanel Surface 还必须匹配当前可信 descriptor。Renderer 随后调用既有类型化 `chatWorkPanelTabContextMenu` preload/IPC，Main 完成 runtime root、realpath、普通文件与 shell 校验；响应不得包含绝对路径。

WorkPanel Resource Viewer tab 的“下载当前文件”属于 host-to-guest 用户动作，不扩展远程 `desktop.workpanel.*` Action。它只适用于仍由 WebClient Viewer 承载的资源；原生图片不创建该 guest。WebClient 仅在当前 `/resource-viewer` surface 注册处理器，并复用既有资源下载与 Platform 鉴权链路。协议不得携带 route、资源 URL、绝对路径、Token 或调用方自定义命令。

WorkPanel document review 与 Composer draft 同样属于内部用户交互，不属于远程 `desktop.workpanel.*` Action。原生 HTML 使用无 Node/Desktop bridge 的隔离预览，原生图片批注、选区和扁平化导出由 Desktop Canvas 完成；Markdown/文本/代码批注由 WebClient 以 revision 与文本范围锚定。Composer draft 只能投递给 owner Chat 对应的 canonical Main Chat surface：输入为空时填入，非空时追加分隔符，绝不覆盖或自动发送。Desktop 必须以当前可信 item 校验 guest 提交的 dirty、busy、annotation count 与交接请求；ack 失败时保留批注。

本地文件评审不经过 Service WebView action。Main 只有在 canonical Run grant、workspace realpath 边界和预览类型都通过后，才在 opaque local-file descriptor 上附加 review capability、workspace 相对路径和无敏感信息的 revision，并为 `zenmind-local-file://` 签发专用 sandbox preload。绝对路径、完整 DOM、表单值、密码、Token、带查询密钥的 URL 与未受限 PNG 都不能进入 renderer、guest 或 Composer。

Main 到 renderer 的 WebView 新标签通知必须携带固定 `target` 判别字段。`desktop-browser` 只由内置 Browser 消费；`work-panel` 只由 WorkPanelHost 消费，并以真实 `sourceGuestId` 反查 owner Chat 后创建外层 Web item。WorkPanel popup 与内容右键不得复用 `desktop-browser` target，也不得通过 Desktop 根路由间接打开；来源 guest 已回收、不是 WorkPanel guest 或 URL 不是 HTTP(S) 时无操作。

WebApp 在 WorkPanel 展示时仍保持 canonical WebApp surface identity 和 gateway bridge，但登记额外的 `presentationScope=workpanel`。该 scope 用于 Cmd/Ctrl+W 与上下文菜单归属，WebApp popup 仍遵守单页策略；公开 CDP active 必须为 false，不能让 WorkPanel 中的 WebApp 成为公开 `Target.getCurrentTarget`。移回主区后清除该 scope 并恢复主区的公开 surface 行为；原有 Run 页面授权在两种 presentation 间保持，独立窗口替换 guest 后失效。

WorkPanel 是运行期可视化工作区，不是新的凭据入口。Overview、Debug、Source、Planning、Artifact、Reference 先通过 owner Chat replay 定位，File 直接读取 Workspace。Overview 与 Debug 没有独立的上游 live Run capability；它们必须同时匹配 active Main Chat observer token、surface generation、owner Chat、runId 和 Run owner，随后只读订阅 Broker RunChannel。BTW 子 Surface 例外地允许在激活且归属于 Main Chat 时发送 `/api/btw` 和该 BTW 的 attach，但它复用 Main Chat Root Observer，并通过唯一 BTW lane 连接承载；普通 Web item 没有 Realtime capability。

Planning WorkPanel item 由可信 owner Chat、`chatId` 与 `planningId` 联合定位，不依赖 agent 归属。guest 提供的 `chatId` 必须与 owner Chat 一致，同一 Chat 内重复打开同一 `planningId` 只激活已有 item。

Main Chat 右上入口及 workspace presentation visibility 由 Desktop 独占管理。首次点击为稳定 Chat 创建 Overview item，再次点击只隐藏；已有隐藏 workspace 恢复原 active item。该可见状态不持久化、不进入 IPC 或 Agent WebClient bridge contract；`openItem`、`activateItem` 会自动显示，`closeWorkspace` 与最后一个 item 关闭仍销毁 workspace。Desktop 只向可信 WorkPanel 子 surface 延伸既有 active 布尔生命周期通知，不扩大 realtime capability。

Agent WebClient 使用 `__AGENT_WEBCLIENT_PLATFORM_FRAME_PORT__` 提供的结构化 Frame Port v2。帧内容只允许 Platform `request/response/stream/push/error`；preload、CustomEvent 与 IPC 不做二次 JSON 字符串化，Main 校验帧类型和序列化后大小。本地校验失败返回相同请求 id 的标准 error frame，不返回本地成功 ACK。通过真实 sender、origin、partition 和 Surface Registry 校验后，普通平台请求作为一次性 request/response 转发，不要求 surface active；query/attach/BTW 仍按 live capability 与 active 状态额外授权。Main 为逻辑 Session 只维护 local id 与 Broker operation/subscription id 映射。Broker 在发送 query 前建立 pending transaction，收到匹配的 canonical `run.start` 后原子登记 RunChannel、绑定 Root Observer、写入有界 replay 并扇出给本地订阅；不存在“WebView 先拥有 stream、Broker 再复制”的双写交接。Platform `connected/heartbeat` 只更新所属物理 lane 状态，不进入业务 Push 或 Frame Port。canonical `chatId/runId/owner` 只从关联 stream bootstrap event 取得；`chat.created` push 只更新 Chat 列表。

Primary、BTW 物理 WebSocket 与逻辑 Frame Port 分别维护 generation。任一 lane 断线只向相关 consumer 投影自己的状态；已接受 Run 不重放 query。有 Root Observer 的 Channel 在该 lane 握手恢复后按 `runId + lastSeq` attach，dormant Channel 不自动 attach。接受前断线与普通一次性请求分别返回稳定、可诊断的连接错误。Surface inactive、identity 变化或销毁会同步撤销其 clone、解除所有 Channel observer 并对最后一个 observer 发送一次 detach；detach 不中断后台 Run。身份失效、协议不兼容与应用退出才永久关闭逻辑 Session。

高流量 Root Observer 只可能是 `main-chat`、`copilot-dock` 或 `kanban-chat`；激活的 `btw` child 通过 Main Chat observer 使用 BTW lane RunChannel。Overview/Debug 的 attach 必须同时匹配真实登记的只读 role、父级 `main-chat`、owner Chat、active Main generation、runId 和 Run owner，Main 在本地回放并订阅后拦截其 detach，二者都不写入物理 WS。clone 比 `run.start` 更早到达时，只能等待同一 observer generation 下明确匹配的 pending query；父 observer、Chat/Run identity、generation 或 WebContents 变化立即以 `parent_observer_closed`、`visible_run_changed`、`run_not_registered` 或 `surface_generation_superseded` 取消，不使用 polling 和 readiness timeout。请求游标早于本地有界 replay 窗口时必须返回可重试的 `seq_expired`，并附带请求游标、首个可用游标、最新游标、保留事件数和字节数；不得扩大窗口、伪造被淘汰前缀或从窗口中间继续投影。observer 交接由每个 RunChannel 的 generation 队列串行化：detach 未写出可取消，已经写出则新 attach 等待完成；不存在跨所有 Session 的全局 detach 门禁。

桌面动作工作台是开发调试窗口。它可列出和调用动作，但仍经过正式执行器、权限与确认流程，不能成为生产安全策略的旁路。窗口形态和视觉细节属于 renderer 实现，不在本文固化。

## 事件、可靠性与时间

- 状态事件采用 snapshot + 增量通知；订阅建立后应能重新获取权威快照。
- 连接中断不自动重放可能产生副作用的动作。是否重试由动作幂等性和调用者的 request identity 决定。
- 慢动作必须有超时、取消或终态，不能让会话永久占用资源。
- 外部服务错误转换为稳定的协议错误类别，同时保留不含敏感数据的诊断信息。
- shared contract 中的语义时间统一为 `EpochMilliseconds`，不得用本机当前时间修补上游无效事件，参见[时间契约](时间契约.md)。

## 扩展原则

新增 namespace、入口或动作前应回答：

1. 能否复用现有动作注册表，而不是新增平行协议？
2. 谁认证调用者，权限最小范围是什么？
3. 是否会修改状态，怎样确认、取消和去重？
4. 目标 surface、服务或文件的所有权属于哪个模块？
5. macOS 与 Windows 是否需要不同的系统能力或降级路径？
