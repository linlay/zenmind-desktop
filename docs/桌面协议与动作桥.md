# 桌面协议与动作桥

## 文档定位

本文定义 Desktop 自动化能力的入口边界、动作模型、授权原则和页面控制归属。动作清单、请求字段、端口默认值与错误码以 `src/shared`、主进程实现和测试为准。

## 协议边界

Desktop 存在四类调用入口：

| 入口 | 主要消费者 | 边界 |
| --- | --- | --- |
| Desktop WebSocket | 已认证的本地或隧道客户端 | 会话、订阅、动作与状态事件 |
| Platform 反向 WebSocket Bridge | 内置 Agent Platform | 当前 run 逻辑绑定的 Desktop Action/CDP request |
| HTTP Action Bridge | 本机 WebApp 与调试工具 | 单次动作调用；不再是 Platform 调用链 |
| WebApp Bridge | 已安装的同源本地 WebApp | manifest 授权的有限能力 |
| renderer IPC | Desktop 自有 UI | 内部窗口与交互编排 |

这些入口可以复用同一动作注册表和执行器，但认证方式、调用上下文与授权范围不能互相替代。Agent Platform 助理使用的出站 WebSocket 不属于供外部客户端接入的 Desktop WebSocket。Desktop WS 的 `ap` namespace 只是共享 Realtime Broker 的本地 adapter，不拥有第二条 Platform 连接，并会重写每个上游 request id。内置 Platform 发来的 `desktop.action.call` 与 `desktop.cdp.call` 由 Main Broker 直接分发到现有核心 handler，不绕行 loopback HTTP。

## 统一动作模型

动作定义集中在 shared contract，至少表达：

- 稳定名称与所属 namespace；
- 输入、输出及时间字段的类型边界；
- 只读或变更语义；
- 所需 capability 与调用面限制；
- 是否需要用户确认、页面上下文或活动窗口。

入口层只负责把可信上下文交给统一执行器，不能各自维护一份动作清单或自行改变语义。新增动作时，应先确定所属资源、最小权限、幂等性和失败模型，再补充实现与契约测试。

## 调用主流程

```text
请求进入协议适配层
  -> 校验身份、来源与大小限制
  -> 解析统一动作定义
  -> 校验 capability 和输入
  -> 必要时准备预览并请求用户确认
  -> 在所属模块执行
  -> 规范化结果、时间与错误
```

动作执行必须保留请求身份和运行上下文，便于审计与关联响应；敏感参数在确认界面和日志中必须脱敏。

## 会话与认证

Desktop WebSocket 在握手后建立有期限的设备会话，并负责 hello、心跳、token 临期提示和订阅清理。客户端 token 必须绑定允许的 scope 与当前安装的 device identity。

HTTP Action Bridge 只监听 loopback，但“仅本机”不等于“已授权”。它仍需校验调用来源、请求形态和动作权限，并限制请求体、超时及并发。若未来允许非本机绑定，必须另行设计网络认证，不得复用当前信任假设。

Platform 反向请求只在其当前物理连接上处理。小结果返回标准 `response/error`；大 JSON 与 `Page.captureScreenshot` 分别使用 `desktop.bridge.response.delta`、`desktop.cdp.screenshot.delta`，chunk payload 不超过 256 KiB，最终 response 携带 streamId、chunkCount 与 totalBytes。收到 `desktop.bridge.cancel` 后停止后续 chunk 和终态发送；Desktop 不自行重放动作。

Desktop 托管模式下，Agent Platform 把 `scope=app` 且 JWT `device_id` 与握手 `deviceId` 一致的已认证 `source=desktop-main` 连接作为唯一 Desktop Main 默认 target；握手里的 `source` 本身不构成授权。每个 run 仍维护独立的运行期逻辑绑定；直接 query/attach 已有的有效绑定优先，`run_query`、automation 或其他独立根 run 缺少绑定时才指向当前 Desktop Main 并写回该 run。同一设备重连以新 WebSocket session 作为新 generation；旧 generation 在请求发送前已不可达时可以安全改绑，发送后断线不得重放。Standalone 不使用该默认 target，也不存在 HTTP、其他窗口或浏览器 tab fallback。

隧道只转发经过验证的协议帧，不扩大 Desktop 动作权限，也不绕过本机确认策略。

## 授权与用户确认

普通只读动作在满足 capability 后可直接执行；动作定义可以把会读取本机身份、路径、凭据摘要或内部服务拓扑的只读动作标记为敏感读取。敏感读取在全局动作确认开启且 `permissionMode` 不是 `full_access` 时每次确认，确认前不得开始聚合数据，确认界面只列出将读取的数据类别，不展示已读取的值。会修改页面、应用状态、文件或外部系统的动作默认需要确认，除非用户已显式授予覆盖该动作的权限模式。

`desktop.runtime.info` 只返回启动时缓存的产品名、版本和构建时间，并与 Desktop WebSocket `runtime.info` 共享同一信息源。`desktop.runtime.diagnostics` 由 Main 的单一聚合器读取设备信息、宿主路径、Electron/Node 版本、服务状态与 canonical Desktop SSO access token 摘要；它不返回 token 原文或 token 文件路径，不签发、不刷新也不改变认证状态，并禁止 WebApp page/backend 调用。凭据摘要只对应 Desktop 数据根目录下唯一的 canonical SSO access token，不扩大到 Tunnel runtime 凭据、Cookie partition 或临时 Agent token；其中过期时间只按 JWT payload 做未验证的诊断解析，不代表完成签名验证。

确认由主进程决定并构造安全摘要，renderer 只展示请求和返回选择。确认结果可以是拒绝、仅本次执行，或在明确范围和期限内授权连续的低风险页面操作。

以下情况必须拒绝或重新确认：

- 调用上下文、活动页面或目标资源在等待期间发生变化；
- 参数包含未经允许的跨域目标、路径或协议；
- 请求试图提升 permission mode 或绕过 capability；
- 主窗口和安全确认 fallback 都不可用。

## 页面控制与活动 Surface

页面动作由 Desktop 管理的活动 surface 执行。控制链路必须先确认当前可控对象，再取得其 DevTools/CDP 目标；不能凭历史 tab、URL 或 renderer 提交的任意 target 直接操作页面。

动作输出使用 canonical 短 surfaceId，并把角色、层级、父级和交互等级作为独立元数据返回。旧 surfaceId 只允许在限期兼容的输入解析层映射到 canonical ID，结果不得继续输出旧名；这类兼容映射不适用于 Agent WebClient capability 授权。

`agent-webclient`、Website、WebApp 与 Copilot surface 的页面权限彼此隔离。页面切换、关闭、崩溃或导航到不受信任来源时，应立即失效旧控制上下文。

页面内容提取与输入属于高敏感能力：限制数据量、屏蔽凭据字段，对上传文件、剪贴板与下载行为采用独立授权。

## Work Panel 与调试工作台

正式 WorkPanel Action 只使用 `desktop.workpanel.*`：`openTab` 承载通用 descriptor，`openWeb` 和 `refreshWeb` 接受规范化 HTTP(S) URL，`activateTab`、`closeTab` 使用 tabId，`closeWorkpanel` 销毁整个面板。按 URL 刷新只能命中可信 source Chat 已有的 Web item，并在刷新后激活该 item，不能跨 workspace 定位 guest。Main 绑定可信 source Chat 后才转交 AppShell command service；调用方不能提交 workspace、stable key、绝对路径、preload 或任意 webPreferences。未在当前注册表声明的调用一律按未知动作处理。

Agent WebClient 新 Chat 的反向 WorkPanel 请求还必须通过 Run 级 grant 门禁：普通新 query 的合法 `chat.start`，或附件预建 Chat 的匹配服务端 `request.query` 回显，已经完成 Desktop 路由与 Main Chat surface owner 同步，且匹配的 `run.start` 已注册。动作在同步进行中等待，成功后 grant 按 `runId + chatId + owner` 保留；切换 Chat 或关闭旧 logical surface 只释放 live observer，不撤销 grant。同步完成前用户切走、surface generation 失效或登记失败时仍 fail closed，但同一 canonical Run 的后续 attach 可以更新失败或未完成的 grant；旧同步结果不能覆盖新 generation。Run 完成、失败、取消、身份轮换或 Broker 销毁时才撤销 grant。确定性失败必须标记为不可立即重试并给出恢复条件，不通过 `run.start` 推断 Chat，也不重新导航到来源页面。

Desktop Main 默认 target 只解决反向请求送达，不授予 Chat workspace。`desktop.workpanel.*` 即使由补绑后的独立 run 发来，也必须继续通过上述 grant；没有 canonical Chat surface/grant 时返回 `source_chat_not_ready`，不能借用当前可见 Chat。Website、Pet、Theme 等不依赖 Chat workspace 的动作仍执行各自 capability 与确认策略。

Broker 完成上述 Run grant 校验后，必须用不可由协议 payload 构造的内部 Platform invocation context 调用统一执行器。只有这个上下文中的 `desktop.workpanel.openWeb` 与 `desktop.workpanel.refreshWeb` 免除远程动作确认；grant 缺失、身份冲突、失效或同步失败仍在进入执行器前 fail closed。HTTP Action Bridge、Desktop WebSocket、企业聊天、调试工作台与普通 Action handler 不获得该豁免，其他 WorkPanel 动作也不随之放宽。

`desktop:agent-webclient:new-chat:prepare` 是 Main Chat 用户重问动作的 query 前置握手，不属于 Platform Frame Port。renderer 必须用真实 service、surface、guest、active 状态、当前 canonical route 和 `ownerChatId` 校验 `agentKey + sourceChatId`，导航到一次性 `newChat` 后等待无 owner Surface 注册成功，再返回 `desktop:agent-webclient:new-chat:prepared`。任一身份变化、重复准备、登记失败或超时均返回失败并在仍停留目标 route 时回滚；Main 的 query/canonical owner 校验不读取也不信任该 ACK。

可信 Agent WebClient 页面的固定 WorkPanel bridge 是宿主内部用户交互入口：Main 必须先依据真实 IPC sender、已登记 surface、capability 和 owner Chat 完成授权，再把受限的 open/activate/close item command 映射到当前正式 WorkPanel Action，不进入 HTTP Action Bridge、Desktop WebSocket 或调试工作台的远程动作确认流程。通过这些外部入口调用 `desktop.workpanel.*` 动作时，仍遵守通用确认策略。

WorkPanel Resource Viewer tab 的“下载当前文件”属于 host-to-guest 用户动作，不扩展远程 `desktop.workpanel.*` Action。Desktop 只能向 Artifact/Reference descriptor 对应的 guest 发送共享契约声明的版本化动作；WebClient 仅在当前 `/resource-viewer` surface 注册处理器，并复用既有资源下载与 Platform 鉴权链路。协议不得携带 route、资源 URL、绝对路径、Token 或调用方自定义命令。

Main 到 renderer 的 WebView 新标签通知必须携带固定 `target` 判别字段。`desktop-browser` 只由内置 Browser 消费；`work-panel` 只由 WorkPanelHost 消费，并以真实 `sourceGuestId` 反查 owner Chat 后创建外层 Web item。WorkPanel popup 与内容右键不得复用 `desktop-browser` target，也不得通过 Desktop 根路由间接打开；来源 guest 已回收、不是 WorkPanel guest 或 URL 不是 HTTP(S) 时无操作。

WorkPanel 是运行期可视化工作区，不是新的凭据入口。Overview、Debug、Source、Planning、Artifact、Reference 先通过 owner Chat replay 定位，File 直接读取 Workspace。Overview 与 Debug 没有独立的上游 live Run capability，但可在激活且归属于 Main Chat 时只读订阅 Main Chat 当前 visible Run 的 Desktop 本地镜像。BTW 子 Surface 例外地允许在激活且归属于 Main Chat 时发送 `/api/btw` 和该 BTW 的 attach，但明确禁止 `/api/query`。普通 Web item 没有 Realtime capability。

Planning WorkPanel item 由可信 owner Chat、`chatId` 与 `planningId` 联合定位，不依赖 agent 归属。guest 提供的 `chatId` 必须与 owner Chat 一致，同一 Chat 内重复打开同一 `planningId` 只激活已有 item。

Main Chat 右上入口及 workspace presentation visibility 由 Desktop 独占管理。首次点击为稳定 Chat 创建 Overview item，再次点击只隐藏；已有隐藏 workspace 恢复原 active item。该可见状态不持久化、不进入 IPC 或 Agent WebClient bridge contract；`openItem`、`activateItem` 会自动显示，`closeWorkspace` 与最后一个 item 关闭仍销毁 workspace。Desktop 只向可信 WorkPanel 子 surface 延伸既有 active 布尔生命周期通知，不扩大 realtime capability。

Agent WebClient 使用 `__AGENT_WEBCLIENT_PLATFORM_FRAME_PORT__` 提供的结构化 Frame Port v2。帧内容只允许 Platform `request/response/stream/push/error`；preload、CustomEvent 与 IPC 不做二次 JSON 字符串化，Main 校验帧类型和序列化后大小。本地校验失败返回相同请求 id 的标准 error frame，不返回本地成功 ACK。通过真实 sender、origin、partition 和 Surface Registry 校验后，普通平台请求作为一次性 request/response 转发，不要求 surface active；query/attach/BTW 仍按 live capability 与 active 状态额外授权。Main 为逻辑 Session 维护 local id 与 upstream id 映射，Platform 每到一条 stream frame 就立即向主目标 guest 原样投递，同时把 Main Chat visible Run 的 canonical event 写入 Broker 有界 replay buffer 并扇出给本地只读 consumer，不使用 timer、batch size 或 bytes queue。Platform `connected/heartbeat` 只更新物理 Broker 状态，不进入业务 Push 或 Frame Port。canonical `chatId/runId/owner` 只从关联 stream bootstrap event 取得；`chat.created` push 只更新 Chat 列表。

物理 WebSocket 与逻辑 Frame Port 分别维护 generation。物理断线只向现存 Session 发布 `reconnecting`；已接受 Run 标记 suspended，重连握手完成后按 `runId + lastSeq` 恢复一次，禁止重放 query。接受前断线与普通一次性请求分别返回稳定、可诊断的连接错误。Surface inactive/销毁只解除观察者和订阅，不中断后台 Run；身份失效、协议不兼容与应用退出才永久关闭逻辑 Session。

高流量主 Run observer 只可能是 `main-chat`、`copilot-chat` 或 `kanban-chat`；激活的 `btw` child 可拥有独立 BTW stream。Overview/Debug 的 attach 必须同时匹配真实登记的只读 role、父级 `main-chat`、owner Chat、active 状态和当前 visible Run，Main 在本地回放并订阅后拦截其 detach，二者都不写入共享物理 WS。请求游标早于本地有界 replay 窗口时必须返回可重试的 `seq_expired`，并附带请求游标、首个可用游标、最新游标、保留事件数和字节数；不得扩大窗口、伪造被淘汰前缀或从窗口中间继续投影。Main 根据真实登记身份授权，不接受 guest 自报角色。切换 live surface 时旧上游 detach 先写入共享物理 WS，再放行新 query/attach/BTW；detach 只释放 observer，不 interrupt 后台 Run，也不撤销已认证 Run 的 WorkPanel grant。其他 push 与内部 consumer 规则不变。

桌面动作工作台是开发调试窗口。它可列出和调用动作，但仍经过正式执行器、权限与确认流程，不能成为生产安全策略的旁路。窗口形态和视觉细节属于 renderer 实现，不在本文固化。

## 事件、可靠性与时间

- 状态事件采用 snapshot + 增量通知；订阅建立后应能重新获取权威快照。
- 连接中断不自动重放可能产生副作用的动作。是否重试由动作幂等性和调用者的 request identity 决定。
- 慢动作必须有超时、取消或终态，不能让会话永久占用资源。
- 外部服务错误转换为稳定的协议错误类别，同时保留不含敏感数据的诊断信息。
- shared contract 中的语义时间统一为 `EpochMilliseconds`，不得用本机当前时间修补上游无效事件，参见[时间契约](时间契约.md)。

## 扩展原则

新增 namespace、入口或动作前应回答：

1. 能否复用现有动作注册表，而不是新增平行协议？
2. 谁认证调用者，权限最小范围是什么？
3. 是否会修改状态，怎样确认、取消和去重？
4. 目标 surface、服务或文件的所有权属于哪个模块？
5. macOS 与 Windows 是否需要不同的系统能力或降级路径？
