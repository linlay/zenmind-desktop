# 桌面协议与动作桥

## 当前状态

Desktop 暴露两类本地自动化协议：

- HTTP action bridge：本地 `127.0.0.1:11788`，端口可由 Desktop 配置覆盖。
- Desktop WebSocket：默认 `ws://127.0.0.1:7082/ws`。

动作定义集中在 `src/shared/desktop-actions.ts`，WebSocket frame 和 namespace 定义集中在 `src/shared/desktop-ws.ts`。

## 核心流程

HTTP action bridge：

```text
POST / action call
  -> handleDesktopActionRequest()
  -> validate action definition
  -> read / validate / preview / apply / execute
  -> optional confirmation for mutating page control
  -> response
```

确认交互：

- `desktopActionConfirmationEnabled` 开启时，除 `permissionMode=full_access` 外的变更类动作需要用户确认。
- 主进程负责判断是否需要确认、构造确认内容、脱敏参数与 URL；渲染层只展示主进程准备好的确认请求并回传用户选择。
- renderer 默认确认框沿用 Cmd+K 的居中弹层、圆角、边框、明暗主题和紧凑行式视觉；暗色弹层与 Cmd+K 使用相同的 `#2D2D2D` 底色。默认只展示小号非粗体的确认标题与业务摘要，操作区左侧提示可在「设置 / 常规」关闭确认。动作说明、动作、目标、权限、参数摘要、`requestId`、`runId`、`chatId`、`agentKey` 与完整脱敏参数统一收在可展开详情中。
- 普通变更动作默认聚焦「执行」，按 Enter 可直接执行；按 Esc 始终取消。低风险 page control 仍默认「仅执行这一步」。
- 低风险 page control 动作继续支持「允许本次页面操作」「仅执行这一步」「取消」三种选择；10 分钟授权缓存逻辑保持在主进程。
- 如果主窗口不可用，主进程使用简化的原生确认框 fallback，只展示紧凑摘要，不展示调试详情。

Debug 设置中的「桌面动作工作台」使用独立顶级、非模态且不设置 `parent` 的 `BrowserWindow` 和专用 renderer 路由，不再使用设置页内的 Modal。它与 Desktop 主窗口没有父子层级或前后顺序锁定，两者均可独立置前、切到后方并参与系统窗口切换。macOS 与 Windows 均保留原生标题栏，窗口可脱离 Desktop 主窗口范围移动、缩放、最小化和最大化；它不设置 always-on-top。工作台为单实例，重复打开只恢复并聚焦已有窗口，保留当前请求和响应；点击「关闭调试」时同时关闭工作台。

Desktop WebSocket：

```text
client token
  -> verify Desktop access token
  -> session.hello
  -> action.list / action.call / service.* / assistant.startRun / webapp.list
  -> event.subscribe(webapp.changed)
  -> push heartbeat / auth.expiring / service.changed / web.changed / webapp.changed
```

Namespace：

- `d`：Desktop。
- `ap`：agent-platform bridge。
- `wa`：webapp。

## Agent Platform IPC 时间契约

这一节约束 Desktop 与 agent-platform 之间的助理、导航、桌宠和 memory IPC，也约束 HTTP action bridge 面向 agent-platform 的响应边界。平台派生的结构化时间字段（`createdAt`、`updatedAt`、`startedAt`、`completedAt`、`timestamp`、`expiresAt`、`readAt`）统一是 `EpochMilliseconds`。

- Desktop 自身 typed IPC 只接受 `0..8_640_000_000_000_000` 内的安全整数；agent-platform 公共时间点进一步只接受 `0` 或 `1_000_000_000_000..8_640_000_000_000_000`。秒级数字、数字字符串、RFC3339 字符串、负数、浮点和空字符串都是 `time_contract_violation`；必填 `null` 也是错误，可选字段才可使用缺失或 `null`，并在 IPC 中保留两者差别。
- 导航和桌宠遇到必填时间无效时忽略 push、记录诊断并刷新快照，绝不以本机当前时间补写平台事件。
- 可读文本仅在 renderer 最终展示时格式化。`full_access` 是权限枚举，没有 `fullAccessExpiresAt` IPC 字段；将来若有 lease，必须另加可选 epoch-ms number。

HTTP `POST /actions/call` 的 `result`、`preview` 与 `error.details` 是 agent-platform 上游协议的一部分。bridge 在写出响应前递归规范化其中的语义时间字段：`*At`（`triggeredAt` 除外）、`*UnixMs`、`timestamp`、`ts` 与 `mtimeMs`。

- bridge 不解析或转换 ISO / RFC3339、数字字符串或秒级数字；合格 epoch-ms number 保持原样，其他值只会导致对应响应或事件被拒绝。
- 规范化只发生在 action 的响应边界，不改变业务持久化。例如 `data/webs/websites/<id>/website.json` 的 `createdAt` / `updatedAt` 继续按 manifest 约定存为 ISO 字符串，`desktop.website.list/add/update` 的响应则是 epoch-ms number。
- Site Copilot 字段在 Desktop action、typed IPC、preload 和 Web surface DTO 中统一为 `copilotAgentKey`。Website/WebApp 输入暂时接受旧 `agentKey` alias，并在进入业务层前规范化；若两个字段同时非空，以 `copilotAgentKey` 为准。所有响应只返回 canonical 字段。

完整字段命名、RFC3339 和 JWT 规则见[时间契约](时间契约.md)。

## 配置与接口

HTTP action bridge 默认：

- host：`127.0.0.1`
- port：`11788`
- 配置文件：`config/desktop/desktop-action-bridge.json`
- 初始化入口：`desktop-init.json` 顶层 `desktopActionBridge.port`

Desktop WebSocket 默认：

- host：`127.0.0.1`
- LAN bind host：`0.0.0.0`
- port：`7082`
- path：`/ws`

移动端 WebApp 协议：

- `webapp.list` 返回按 Desktop 侧边栏排序的脱敏 WebApp 目录。
- `webapp.changed` 事件原因包括安装、更新、发布、停止发布、删除、稳定路由同步和发布失败。
- 只有完成 `event.subscribe` 的连接收到对应 push；只有 Tunnel 会话中的有效 `app` 连接会被计为移动端在线订阅者。
- Desktop 返回由设备 `.m` 主机派生的 HTTPS `publicUrl`，形如 `https://<device>-<frontendPort>.m.0-o.cc/`；端口只进入派生 Host，不单独返回端口字段、`targetUrl`、安装路径或凭据。
- React App 打开 `.m` 地址时，首次导航附加当前配对 `app` token。Tunnel 将其换成 HttpOnly 会话 Cookie、重定向到无 token 地址，并在转发到本地 WebApp 前剥离认证信息；后续 HTTP、静态资源和 WebSocket 共用该会话。

WebApp 生命周期 action 与 WebSocket 短名一一对应：

- `desktop.webapp.install` / `webapp.install` 只安装本地 archive；市场条目使用 `desktop.market.installItem`。
- `desktop.webapp.checkRuntime` / `webapp.checkRuntime` 只做运行环境检查，环境未就绪由 `ready=false` 表达。
- `desktop.webapp.getStatus` / `webapp.getStatus` 只查询本地 runtime；`desktop.webapp.getPublishStatus` / `webapp.getPublishStatus` 独立查询 Tunnel 公网发布状态，Tunnel 未就绪同样返回 `ready=false`。
- `desktop.webapp.publish` / `webapp.publish` 只发布正在运行且已有 `webUrl` 的 gateway；`unpublish` 幂等关闭 `.wa` 路由，不停止 runtime。
- `desktop.webapp.uninstall` / `webapp.uninstall` 完整清理公网路由、runtime、窗口、程序与持久数据。

旧 canonical action `installAndOpen`、`checkPrerequisites`、`getPublishInfo`、`selectDirectory` 及其旧短名均为未知请求，不提供 alias。`.m` 是配对移动端的自动访问地址，`.wa` 是用户主动发布的公网地址，两者不等价。

动作类别：

- navigation
- assistant（仅保留 `desktop.assistant.chat` 通用对话；旧 `desktop.assistant.complete` 已删除且不提供兼容层）
- general（只读设备名）
- theme
- locale
- copilot
- web
- controlCenter
- market
- help
- kanban
- pet
- web page interaction（`desktop.web.interactElement`、`desktop.web.executeScript`）

网页内容、DOM 和结构化数据读取统一使用 Desktop CDP；`desktop.web.getPageContext`、
`desktop.web.readPageData` 和 `desktop.web.extractStructured` 不在公共 action 清单中，也不提供兼容层。

旧的 `desktop.page.*` 动作及 `page.*` WebSocket 别名不在公共 action 清单中，也不提供兼容层。

### WebApp Desktop Bridge v1

Manifest v2 WebApp 从同源 `/__desktop/bridge.js` 导入 `{ desktop, DesktopBridgeError }`。SDK 调用同源
`POST /__desktop/actions/call`；gateway 校验准确的 loopback Origin 后，用不暴露给页面的一次性 page token
转发到内部 `/webapps/pages/actions/call`。页面 token、托管后端 token 和普通 Desktop 请求是三个独立
invocation scope，gateway 停止时 token 立即撤销。

Manifest 只声明 `desktopBridge.version=1`。所有本地 loopback WebApp 页面默认获得以下公开能力：

- `assistant.chat` -> `desktop.assistant.chat`
- `native.browser.external` -> `desktop.native.browser.openExternal`
- `native.dialog.files` -> `desktop.native.dialog.selectFiles`
- `native.dialog.directories` -> `desktop.native.dialog.selectDirectory`
- `native.dialog.savePath` -> `desktop.native.dialog.selectSavePath`
- `native.microphone` -> `desktop.native.microphone.getPermission/requestAccess`；`open()` 由 SDK 在授权后调用页面 `getUserMedia()`
- `native.clipboard.write` -> `desktop.native.clipboard.writeText`
- `native.notification` -> `desktop.native.notification.show`

`desktop.capabilities.list` 对本地 WebApp 页面始终可用，返回 available/reserved/unavailable 和独立
permission 状态；为兼容现有 SDK，公开能力的 `declared` 固定为 true，reserved 固定为 false，`has()` 对 available 能力返回 true。原生 actions 必须来自
`webappPage`：普通 `/actions/call`、后端 token、Website、`.m`、`.wa` 均返回 `forbidden`。托管后端
存在时自动获得 token，且只能调用 `assistant.chat`。

页面调用 `desktop.assistant.chat(message)`，后端 action args 只传 `{ message }`。可选 Agent 由 `userConfig.fields` 中 `source: "desktop.agents"` 的字段选择；未声明该字段或用户尚未选择时，使用 Desktop 当前配置的默认助手智能体。需要安装后直接选择特定 Agent 时，生成包可以声明目标 Desktop 环境中有效的 `default`，用户仍可在设置页切换；通用包不得硬编码品牌 Agent Key。业务提示词由 WebApp 使用 `appConfig`、`userConfig` 与本次输入组合；Desktop 不读取或追加 instruction。调用方传入 Agent、instruction、permission、chatId 或 runId 均拒绝；显式配置的 Agent 不可用返回 `assistant_agent_unavailable`。

第二阶段的 screen capture、clipboard read、file reveal、window control、camera 和 system share 仅存在于
SDK，调用固定 reject `DesktopBridgeError(code="not_implemented")`；它们没有 Action 定义，也不能声明在
manifest。旧 schema 和旧 action 不提供兼容层。

浏览器只接受 HTTP(S)；文件对话框和保存路径只返回用户选择的 path/name，不读写文件；剪贴板只写文本且
上限为 1 MiB；通知只接收 title/body，点击最多聚焦所属 WebApp。系统浏览器与通知按 WebApp 限流。
原生对话框优先以所属浮动窗口为 owner，否则使用主窗口。

### Desktop 设置专用动作

Desktop 不提供跨领域的 Setting 聚合、Patch 校验、预览或应用动作。以下旧动作及其 `setting.*` 公共别名不存在，也不提供兼容层：

- `desktop.setting.getState`
- `desktop.setting.validatePatch`
- `desktop.setting.previewPatch`
- `desktop.setting.applyPatch`

设置能力按领域公开：

- `desktop.general.deviceName`：只读，无参数，只返回 `{ deviceName, configuredDeviceName }`。`configuredDeviceName` 为空表示采用系统名称；智能体没有设备名写入动作，设置页人工编辑继续使用内部 IPC。
- `desktop.theme.get`：只读，无参数，返回 `{ themeMode, resolvedTheme }`。
- `desktop.theme.set`：变更动作，参数 `{ themeMode: "light" | "dark" | "system" }`；持久化并立即更新界面，返回更新后的主题状态。
- `desktop.locale.get`：只读，无参数，返回当前 `LocaleSettings`。
- `desktop.locale.set`：变更动作，参数 `{ locale: "zh-CN" | "en-US" }`；持久化并广播语言变化，返回更新后的 `LocaleSettings`。
- `desktop.copilot.getPagePreferences`：只读，无参数，返回完整 `desktopCopilotPages` 和 `agentOptions`。
- `desktop.copilot.setPagePreference`：变更动作，参数 `{ pageKey, enabled?, agentKey? }`，其中 `enabled` 与 `agentKey` 至少一个存在。`pageKey` 仅允许 `controlCenter`、`market`、`help`、`agents`、`schedules`、`skills`；一次只合并一个页面，启用后的 `agentKey` 必须存在。

主题、语言和 Copilot setter 均沿用 Desktop Action 的变更确认机制；getter 和设备名读取不触发确认。网站继续使用 `desktop.website.list/add/update/remove`，市场、服务和看板继续使用各自领域动作。

### Embedded CDP 目标查询

HTTP action bridge 的 `POST /cdp/call` 与 embedded CDP gateway 只能看见 Desktop 当前激活
surface。当前 surface 由 Desktop 当前页面快照确定，调用方不能用 `surfaceId`、URL 或 scope
扩大边界。

- `Target.getTargets` 无参数，返回当前 surface 的全部存活 tabs；活动和非活动 tab 都有各自稳定的
  `targetId`，并通过 `tabId`、`current` 与 `activeTabId` 标记当前活动 tab。不会返回其他后台
  surface 的 target。
- `Target.getCurrentTarget` 无参数，只返回当前 surface 的活动 tab。当前页面没有 CDP surface 或
  surface 没有存活 tab 时，返回 `targetInfo: null`、`currentTargetId: null` 和
  `currentSurfaceId: null`，不以其他 surface 或首项兜底。

- `Target.closeTarget` 关闭当前 surface 内的指定 target。`POST /cdp/call` 以顶层 `targetId` 为
  canonical 输入，并兼容标准 `params.targetId`；两处同时存在且不一致时返回 `invalid_args`。
  WebSocket target 连接可关闭自身并返回 `{ success: true }`。关闭操作不直接销毁 guest，而是解析为
  稳定的 `surfaceId + tabId` 后进入 renderer 的统一标签关闭事务；后台 surface、失效 target 继续
  分别返回 `target_not_in_current_surface`、`target_not_found`。
- 除上述两个查询方法外，每个方法都必须显式传入 `targetId`；缺失时返回 `target_required`。
  同一当前 surface 内的非活动 tab 可直接操作。其他 surface 的 target 返回
  `target_not_in_current_surface`；tab 已关闭或重建导致 target 失效时返回 `target_not_found`。
- `Page.bringToFront` 只允许在当前 surface 内切换活动 tab，不负责激活其他 surface，也不会隐式
  创建或导航到新 surface。
- targetId 由 surface registration generation、`surfaceId` 和 `tabId` 生成。同一标签 reload 或
  guest WebContents 被替换时 targetId 保持稳定；整个 surface 重建并产生新 registration generation
  后 targetId 才更新。已连接的 debugger session 发现同一 target 的 WebContents id 变化时必须自动
  从旧 guest 解绑并绑定新 guest。
- `/json` 与 `/json/list` 只发现当前 surface 的 tabs；`/json/activate/<targetId>` 只接受当前
  surface 的 target；`/json/new` 固定禁用。

### Chat Work Panel 动作与 CDP 所有权

公开动作包括 `desktop.chatWorkPanel.getState/open/close/openTab/activateTab/closeTab`。调用方不得在 args 中传 `chatId`、`surfaceId` 或 `agentKey`；agent-platform 从执行上下文生成 `source`，Desktop renderer 只使用 `request.source.chatId`。

`open` 幂等并保证至少一个 `about:blank` Tab；`openTab` 只接受 `http:`、`https:` 和 `about:blank`，面板不存在时直接用目标 URL 创建首 Tab。`getState` 返回逻辑 `surfaceId`、活动 Tab 与每个 live Tab 的 `targetId/title/url/isLoading`。关闭最后 Tab 等同关闭 workspace。

Work Panel registry surface 永远不标为当前 active surface，因此普通 `desktop.web.listSurfaces`、`Target.getTargets` 和 `Target.getCurrentTarget` 维持原行为。除当前 active surface target 外，`POST /cdp/call` 只允许 `target.ownerChatId === request.source.chatId` 的 Work Panel target。跨 Chat 返回 `target_not_owned_by_chat`；关闭或重新创建后的旧 generation target 返回 `target_not_found`。`Page.bringToFront` 仅激活面板内部 Tab，不导航 Chat、不聚焦主窗口。

公开的 CDP 方法固定为以下 19 个：

- Target：`Target.getCurrentTarget`、`Target.getTargets`、`Target.closeTarget`
- Page：`Page.bringToFront`、`Page.enable`、`Page.navigate`、`Page.reload`、
  `Page.captureScreenshot`
- Runtime：`Runtime.evaluate`
- DOM：`DOM.getDocument`、`DOM.querySelector`、`DOM.querySelectorAll`、`DOM.getOuterHTML`、
  `DOM.getBoxModel`
- Input：`Input.dispatchMouseEvent`、`Input.dispatchKeyEvent`、`Input.insertText`
- Network：`Network.enable`、`Network.disable`

HTTP、WebSocket 和 action bridge 使用同一 target 约束。连接建立后如果用户切换到其他 surface，
旧 target 的后续命令立即失效，不能借已有连接继续跨 surface 操作。macOS 与 Windows 采用相同
判定逻辑。

单标签刷新只使用标准 `Page.reload(targetId)`，不另设 `Target.refreshTarget`。整 surface 原位刷新由
`desktop.web.refreshSurface({ surfaceId })` 提供，WebSocket alias 为 `web.refreshSurface`；它只接受
当前激活 surface，并发刷新调用开始时的全部存活 tabs，以统一 15 秒期限等待 `dom-ready`，保留
surface、tabId、顺序、活动标签和地址栏状态。全部成功返回 `{ surfaceId, refreshedTabIds,
failedTabs: [], activeTabId }`；部分失败返回 `surface_refresh_partial`，逐标签结果位于错误 details。
`desktop.web.closeTab({ surfaceId, tabId })` 使用同一关闭事务，并返回 `{ surfaceId, closedTabId,
closedSurface, remainingTabIds, activeTabId }`。

## 约束与注意事项

公开分享页唤起 Desktop 使用当前品牌 `brand.json -> protocols.open.scheme` 显式声明的 scheme，并固定为单一 `://open` 动作（例如 ZenMind 配置生成 `zenmind://open`）。协议不得从品牌 ID、产品名或其他字段隐式派生。该入口不是 Desktop Action，也不接受 route、query 或 fragment；macOS `open-url` 与 Windows 首实例/`second-instance` 只在精确匹配时显示、聚焦主窗口并导航到 `/`。正式安装包注册同一品牌配置值，Windows Electron 开发态使用显式 executable 与 app entry 参数。该能力不导入分享内容，也不扩展为通用 deep-link router。

- WebSocket token 必须通过 identity-center JWK 校验，scope 为 `app`，device id 匹配本机。
- `<device>-<frontendPort>.m...` 同样必须由 Desktop 校验 `app` token、device id 和运行中的 WebApp 端口；`.wa` 公网分享保持匿名访问，不套用移动端配对鉴权。
- 移动端重连必须重新订阅并调用 `webapp.list`；订阅状态只属于当前连接，快照读取本身不触发发布。
- Desktop WebSocket 与 agent-webclient 的业务 `/ws` 相互独立。Desktop 不读取或处理 agent-webclient 的 `chat.created`、`run.*` 或内容流；主聊天只通过 URL 和 Token Bridge 与 Desktop 集成。
- public action aliases 只用于仍明确支持的简短命名；新增能力必须先补 `DESKTOP_ACTION_DEFINITIONS`，不得用通用 Setting 动作重复暴露其他领域。
- 高风险 page interaction 需要确认或 page control grant。
- 旧的 Kanban public issue CRUD 名称不要重新接入；遵守只读云缓存协议。

## WebView 上下文菜单内部动作

`desktop:service-webview:action` 额外承载 Desktop 内部的 `contextMenu.resolve` 与 `contextMenu.execute`。它们不是公共 Desktop Action，也不经过 agent-platform HTTP、SSE 或 WebSocket。guest 只能通过专用 IPC 响应通道返回版本化语义目标，不能提供菜单标题、脚本或任意命令；Main 对响应大小、字段、目标类型和 capability 做严格白名单校验。

首版固定动作只覆盖编辑、复制、链接、Workspace 文件、Chat 资源、媒体与页面导航。需要 WebClient 状态的复制、侧栏预览和鉴权资源下载仍由 WebClient 既有处理器执行。未来业务动作必须在 Main 注册新的固定 Action Provider，不能由页面动态注入。

## 侧边栏原生上下文菜单 IPC

主侧边栏的 Chats、Projects、Sites 条目与分组标题在鼠标右键、`ContextMenu` 或 `Shift+F10` 时，通过 `sidebarContextMenu.popup` 请求 Main 弹出系统原生菜单。行尾“…”、WebApp/Sites 分组动作和 Projects 排序按钮也复用同一原生菜单链路，不再保留对应的 renderer 自绘 Action Menu。该 IPC 是 Desktop renderer 的内部宿主能力，不属于公共 Desktop Action，也不进入 agent-platform 协议；默认智能体等动态选择器与 Settings 菜单继续由 renderer 管理。

Renderer 只提交固定目标类型、当前能力布尔值和主窗口内容区坐标，不提交标题、路径、聊天正文或菜单文案。Main 严格校验字段，以固定 Action ID 和中英文词典组装菜单，并验证调用方属于当前主窗口；菜单始终以主窗口为 owner，坐标限制在其内容区。Main 只回传用户选中的白名单 Action ID，Renderer 再按 agent key、chatId 或 Web entryKey 查找当前目标并调用既有处理器；目标已刷新、移除或动作已禁用时取消执行。
