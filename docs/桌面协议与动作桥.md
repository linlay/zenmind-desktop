# 桌面协议与动作桥

## 当前状态

Desktop 暴露两类本地自动化协议：

- HTTP action bridge：本地 `127.0.0.1:11788`，端口可由 Desktop 配置覆盖。
- Desktop WebSocket：默认 `ws://127.0.0.1:7082/ws`。

动作定义集中在 `src/shared/desktop-actions.ts`，WebSocket frame 和 namespace 定义集中在 `src/shared/desktop-ws.ts`。

## 核心流程

HTTP action bridge：

```text
POST / action call
  -> handleDesktopActionRequest()
  -> validate action definition
  -> read / validate / preview / apply / execute
  -> optional confirmation for mutating page control
  -> response
```

确认交互：

- `desktopActionConfirmationEnabled` 开启时，除 `permissionMode=full_access` 外的变更类动作需要用户确认。
- 主进程负责判断是否需要确认、构造确认内容、脱敏参数与 URL；渲染层只展示主进程准备好的确认请求并回传用户选择。
- renderer 默认确认框沿用 Cmd+K 的居中弹层、圆角、边框、明暗主题和紧凑行式视觉；默认只展示小号非粗体的确认标题与业务摘要。动作说明、动作、目标、权限、参数摘要、`requestId`、`runId`、`chatId`、`agentKey` 与完整脱敏参数统一收在可展开详情中。
- 低风险 page control 动作继续支持「允许本次页面操作」「仅执行这一步」「取消」三种选择；10 分钟授权缓存逻辑保持在主进程。
- 如果主窗口不可用，主进程使用简化的原生确认框 fallback，只展示紧凑摘要，不展示调试详情。

Debug 设置中的「桌面动作工作台」使用独立顶级、非模态且不设置 `parent` 的 `BrowserWindow` 和专用 renderer 路由，不再使用设置页内的 Modal。它与 Desktop 主窗口没有父子层级或前后顺序锁定，两者均可独立置前、切到后方并参与系统窗口切换。macOS 与 Windows 均保留原生标题栏，窗口可脱离 Desktop 主窗口范围移动、缩放、最小化和最大化；它不设置 always-on-top。工作台为单实例，重复打开只恢复并聚焦已有窗口，保留当前请求和响应；点击「关闭调试」时同时关闭工作台。

Desktop WebSocket：

```text
client token
  -> verify Desktop access token
  -> session.hello
  -> action.list / action.call / service.* / assistant.startRun / web.webapp.list
  -> event.subscribe(webapp.changed)
  -> push heartbeat / auth.expiring / service.changed / web.changed / webapp.changed
```

Namespace：

- `d`：Desktop。
- `ap`：agent-platform bridge。
- `wa`：webapp。

## Agent Platform IPC 时间契约

这一节约束 Desktop 与 agent-platform 之间的助理、导航、桌宠和 memory IPC，也约束 HTTP action bridge 面向 agent-platform 的响应边界。平台派生的结构化时间字段（`createdAt`、`updatedAt`、`startedAt`、`completedAt`、`timestamp`、`expiresAt`、`readAt`）统一是 `EpochMilliseconds`。

- Desktop 自身 typed IPC 只接受 `0..8_640_000_000_000_000` 内的安全整数；agent-platform 公共时间点进一步只接受 `0` 或 `1_000_000_000_000..8_640_000_000_000_000`。秒级数字、数字字符串、RFC3339 字符串、负数、浮点和空字符串都是 `time_contract_violation`；必填 `null` 也是错误，可选字段才可使用缺失或 `null`，并在 IPC 中保留两者差别。
- 导航和桌宠遇到必填时间无效时忽略 push、记录诊断并刷新快照，绝不以本机当前时间补写平台事件。
- 可读文本仅在 renderer 最终展示时格式化。`full_access` 是权限枚举，没有 `fullAccessExpiresAt` IPC 字段；将来若有 lease，必须另加可选 epoch-ms number。

HTTP `POST /actions/call` 的 `result`、`preview` 与 `error.details` 是 agent-platform 上游协议的一部分。bridge 在写出响应前递归规范化其中的语义时间字段：`*At`（`triggeredAt` 除外）、`*UnixMs`、`timestamp`、`ts` 与 `mtimeMs`。

- bridge 不解析或转换 ISO / RFC3339、数字字符串或秒级数字；合格 epoch-ms number 保持原样，其他值只会导致对应响应或事件被拒绝。
- 规范化只发生在 action 的响应边界，不改变业务持久化。例如 `data/webs/websites/<id>/website.json` 的 `createdAt` / `updatedAt` 继续按 manifest 约定存为 ISO 字符串，`desktop.web.website.list/add/update` 的响应则是 epoch-ms number。
- Site Copilot 字段在 Desktop action、typed IPC、preload 和 Web surface DTO 中统一为 `copilotAgentKey`。Website/WebApp 输入暂时接受旧 `agentKey` alias，并在进入业务层前规范化；若两个字段同时非空，以 `copilotAgentKey` 为准。所有响应只返回 canonical 字段。

完整字段命名、RFC3339 和 JWT 规则见[时间契约](时间契约.md)。

## 配置与接口

HTTP action bridge 默认：

- host：`127.0.0.1`
- port：`11788`
- 配置文件：`config/desktop/desktop-action-bridge.json`
- 初始化入口：`desktop-init.json` 顶层 `desktopActionBridge.port`

Desktop WebSocket 默认：

- host：`127.0.0.1`
- LAN bind host：`0.0.0.0`
- port：`7082`
- path：`/ws`

移动端 WebApp 协议：

- `web.webapp.list` 返回按 Desktop 侧边栏排序的脱敏 WebApp 目录。
- `webapp.changed` 事件原因包括安装、更新、发布、停止发布、删除、稳定路由同步和发布失败。
- 只有完成 `event.subscribe` 的连接收到对应 push；只有 Tunnel 会话中的有效 `app` 连接会被计为移动端在线订阅者。
- Desktop 返回由设备 `.m` 主机派生的 HTTPS `publicUrl`，形如 `https://<device>-<frontendPort>.m.0-o.cc/`；端口只进入派生 Host，不单独返回端口字段、`targetUrl`、安装路径或凭据。
- React App 打开 `.m` 地址时，首次导航附加当前配对 `app` token。Tunnel 将其换成 HttpOnly 会话 Cookie、重定向到无 token 地址，并在转发到本地 WebApp 前剥离认证信息；后续 HTTP、静态资源和 WebSocket 共用该会话。

动作类别：

- navigation
- assistant（开放受限的 `desktop.assistant.complete` 通用文本生成和 `desktop.assistant.translate` 翻译动作）
- general（只读设备名）
- theme
- locale
- copilot
- web
- controlCenter
- market
- help
- kanban
- pet
- page context / CDP interaction

本地 WebApp 页面还可通过自身 gateway 的 `POST /__desktop/actions/call` 调用
`desktop.web.webapp.selectDirectory`。该动作打开原生目录选择器并返回用户选择的单个目录；
它要求当前 loopback WebApp Origin，缺少 Origin、Website、`.m` 和 `.wa` 请求均不能调用。
目录内容不经过 Desktop Action Bridge，后续文件访问由 WebApp 自身负责。

### 翻译动作

`desktop.assistant.translate` 接受：

```ts
{
  text: string;
  targetLanguage: "en" | "ja" | "zh";
  domain?: "general" | "futures";
  terminology?: Array<{ source: string; target: string }>;
}
```

- 缺少 `domain` 时保持原有通用翻译提示词，并在结果中返回 `domain: "general"`。
- `domain: "futures"` 时加入期货、期权和衍生品语境，保留合约/交易所代码、数字、价格、单位和多空方向。
- `terminology` 最多 40 条；主进程校验数组、字段类型、长度和控制字符。术语以 JSON 数据嵌入提示词，不能作为额外指令解释。
- 术语匹配、内置词库和用户词库的持久化由调用方负责；Desktop Action 不机械替换用户原文。

### Desktop 设置专用动作

Desktop 不提供跨领域的 Setting 聚合、Patch 校验、预览或应用动作。以下旧动作及其 `setting.*` 公共别名不存在，也不提供兼容层：

- `desktop.setting.getState`
- `desktop.setting.validatePatch`
- `desktop.setting.previewPatch`
- `desktop.setting.applyPatch`

设置能力按领域公开：

- `desktop.general.deviceName`：只读，无参数，只返回 `{ deviceName, configuredDeviceName }`。`configuredDeviceName` 为空表示采用系统名称；智能体没有设备名写入动作，设置页人工编辑继续使用内部 IPC。
- `desktop.theme.get`：只读，无参数，返回 `{ themeMode, resolvedTheme }`。
- `desktop.theme.set`：变更动作，参数 `{ themeMode: "light" | "dark" | "system" }`；持久化并立即更新界面，返回更新后的主题状态。
- `desktop.locale.get`：只读，无参数，返回当前 `LocaleSettings`。
- `desktop.locale.set`：变更动作，参数 `{ locale: "zh-CN" | "en-US" }`；持久化并广播语言变化，返回更新后的 `LocaleSettings`。
- `desktop.copilot.getPagePreferences`：只读，无参数，返回完整 `desktopCopilotPages` 和 `agentOptions`。
- `desktop.copilot.setPagePreference`：变更动作，参数 `{ pageKey, enabled?, agentKey? }`，其中 `enabled` 与 `agentKey` 至少一个存在。`pageKey` 仅允许 `controlCenter`、`market`、`help`、`agents`、`schedules`、`skills`；一次只合并一个页面，启用后的 `agentKey` 必须存在。

主题、语言和 Copilot setter 均沿用 Desktop Action 的变更确认机制；getter 和设备名读取不触发确认。网站继续使用 `desktop.web.website.list/add/update/remove`，市场、服务和看板继续使用各自领域动作。

### Embedded CDP 目标查询

HTTP action bridge 的 `POST /cdp/call` 对以下两个 Target 方法提供 Desktop surface 语义：

- `Target.getTargets` 和 `Target.getCurrentTarget` 接受可选
  `params.scope: "sites" | "all"`，默认 `"sites"`。
- `scope="sites"` 只返回已挂载且 guest WebContents 存活的 Website/WebApp；内置 Browser、
  服务前端和仅配置但未打开的 Site 不返回。
- `scope="all"` 保留全量调试视图，并通过
  `surfaceKind: "website" | "webapp" | "browser" | "service"` 与 `open` 区分类别和打开状态。
- `Target.getTargets` 直接返回 `currentTargetInfo`；当前页面不在查询范围时，
  `currentTargetInfo`、`currentTargetId`、`currentSurfaceId` 均为 `null`，不以列表第一项兜底。
  `Target.getCurrentTarget` 对应返回 `targetInfo: null`。此时 `/cdp/call` 外层不返回
  `targetId` / `surfaceId`。
- 非法 `scope` 返回 `invalid_args`。embedded CDP gateway 的 `/json` 与 `/json/list`
  继续保留全量 DevTools discovery 行为。

## 约束与注意事项

- WebSocket token 必须通过 identity-center JWK 校验，scope 为 `app`，device id 匹配本机。
- `<device>-<frontendPort>.m...` 同样必须由 Desktop 校验 `app` token、device id 和运行中的 WebApp 端口；`.wa` 公网分享保持匿名访问，不套用移动端配对鉴权。
- 移动端重连必须重新订阅并调用 `web.webapp.list`；订阅状态只属于当前连接，快照读取本身不触发发布。
- Desktop WebSocket 与 agent-webclient 的业务 `/ws` 相互独立。Desktop 不读取或处理 agent-webclient 的 `chat.created`、`run.*` 或内容流；主聊天只通过 URL 和 Token Bridge 与 Desktop 集成。
- public action aliases 只用于仍明确支持的简短命名；新增能力必须先补 `DESKTOP_ACTION_DEFINITIONS`，不得用通用 Setting 动作重复暴露其他领域。
- 高风险 page interaction 需要确认或 page control grant。
- 旧的 Kanban public issue CRUD 名称不要重新接入；遵守只读云缓存协议。
