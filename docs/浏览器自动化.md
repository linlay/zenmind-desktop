# 浏览器自动化

## 定位与边界

小君通过 Platform 内嵌 web-control 工具操作当前 Chat 的 WorkPanel 网页，或用户显式连接的 Chrome 标签。小君自身的模型与 Run 负责规划；Desktop 只拥有页面授权、连接、动作执行和结果转换。

WorkPanel 沿用已有网页宿主、Cookie 会话和精确 Surface 身份。Chrome 使用微软 Playwright 扩展的受控连接与授权标签组，登录态留在原 Chrome profile。两者不复制 Cookie，不根据 URL 或当前前台窗口重建授权。

## 调用与所有权

对话顶部的浏览器入口只向可信 Main renderer 暴露状态、选择、连接、断开、激活与接管。Main 复验 canonical 当前 Chat；网页和服务 guest 不获得这组 IPC。

浏览器选择属于 Chat，执行环境在 canonical Run grant 建立时冻结，授权就绪后才允许动作。Chrome 连接与已授权页面注册表由 Main 的浏览器工作区拥有，Run 只持有临时操作租约。用户开启记住 Chrome 连接后，新建对话、新对话重问和派生对话可沿用仍存活的共享工作区及其页面身份；未记住授权的手动连接继续属于当前 Chat 的私有工作区。沿用工作区不能使 WorkPanel Run 改为 Chrome，也不允许列出授权标签组之外的页面。

工作区同一时刻只交给一个实际调用浏览器工具的 Run 控制，其他对话不能抢占。纯文本任务不占用浏览器。Run 终态、取消或身份失效撤销其操作租约；已有请求仍在执行时先保持收尾占用，丢弃迟到结果，待请求排空后再交给下一个 Run。普通任务取消不关闭共享连接，也不重放可能已派发的写操作。删除或归档某个 Chat 只释放该 Chat 的 Run；不能断开其他 Chat 沿用的共享工作区。显式断开、接管并停止、忘记授权或应用退出才释放相关工作区的连接。

每次调用仍严格校验 canonical Chat、Run、根 agent 身份和工作区连接代际。元素引用、模态引用、AWCP 手册绑定与当前 Chat 的附件权限不能随页面沿用，后续 Run 必须重新观察或读取手册。已有 Run 的环境不能随界面选择变化。

Platform 继续使用既有网页工具、反向 Desktop bridge、执行结果与截图 Chat 引用。Chrome 的基础动作由受控 Node Worker 执行；Main 只交付当前 Run 获授权页面的操作。公共 HTTP/CDP 入口不能获得 Chrome 会话。

## 设置与首次连接

浏览器设置由 Desktop 的浏览器模块统一拥有。新对话默认浏览器与是否记住 Chrome 连接属于应用级偏好。记住连接同时允许后续 Chrome 对话沿用当前进程中已授权的共享工作区；具体 Run 的身份、操作租约、观察引用与手册绑定仍独立。新默认值用于后续会话；已有 Run 的环境不能因设置变更而重绑定。

记住连接是用户明确开启的本机授权选项。配对凭据只在 Main 中经操作系统加密后保存到当前品牌的 secrets 分区，公共设置接口只返回是否已配置，不能回读凭据。macOS 使用系统 Keychain 保护，Windows 使用 DPAPI；系统安全存储不可用时保留手动连接，不降级为明文。元数据与凭据均由 Desktop 自有 store 维护，不写服务配置或进程的全局环境。

会话创建、Run 授权与后台状态通知只读取偏好元数据和最近一次安全存储状态，不探测或初始化系统密钥；设置页的明确查询刷新真实可用性，实际保存或使用授权时重新验证，避免 Keychain 的同步交互阻塞 canonical 会话同步。

已配置记住连接时，Chrome Run 首次需要网页工具时优先沿用存活的共享工作区，不为每个新 Chat 再创建一个空授权标签组。没有可用连接时才由 Main 显式交付授权并按需握手。握手由工作区拥有，一个等待 Run 的取消不能关闭其他合法等待者的连接。Worker 忽略继承的扩展授权环境变量，仅在私有握手期间使用受控值并及时清理；握手有界且受工作区释放与连接代际校验保护。失效、资料不匹配或连接失败时显示当前 Chat 的连接引导，不自动扩大授权或切换环境。输入明确网址的任务可以直接建立本任务页面；工作区授权组以外的既有 Chrome 标签仍需用户显式选页。

Worker 进程存活不代表 Chrome 传输仍然连接。每个新 Run 在首次派发 Chrome 操作前复验已有连接；已关闭的传输先撤销旧页面身份，再按当前保存授权重新建立连接。工作区仅在当前 Main 进程与同一实际连接期间延续；应用重启或真正断连后，不能按相同 URL、标题或旧 Surface ID 自动找回原标签。恢复仅发生在该 Run 尚未派发业务动作时，不重放上一轮操作，也不能将旧 Surface 或观察引用带入新连接。网页拒绝连接、DNS 或导航失败属于目标站点诊断，不能仅凭这类失败撤销有效授权或要求用户重新配对。

未配置授权的新会话第一次请求 Chrome 时，由已验证的 Run 发出受限连接提示，可信 Main renderer 只为匹配的当前 Chat 展开一次。用户连接后在同一 Chat 发送新消息继续；界面区分“尚未连接”与“已连接但旧 Run 环境不匹配”，不能要求用户反复新建 Chat 或自动重放原任务。关闭记住连接只影响后续自动连接；显式忘记授权在无活动 Run 时清除保存授权并释放空闲连接，也可恢复损坏的本机配置。

## 页面与元素身份

Chrome Worker 基于固定上游 Playwright runtime，补丁为真实 Page 分配连接期间不复用的私有身份。Main 对外只交付工作区页面注册表中的 Surface 身份。新 Chat 沿用同一存活工作区时可以发现相同 Surface；页面关闭、脱离授权标签组或重新连接后旧身份失效，不能回退相邻标签、标题相同的页面或同 URL 页面。页面不在当前工作区时应指导重新读取页面清单或明确打开任务网址，不能仅凭找不到旧 ID 就要求重新配置 Chrome 授权。

每次 Chrome 操作、后续快照和结果序列化固定同一 Page。模型不获得原始 MCP 代码执行、浏览器连接地址或 profile 路径。原始脚本与 CDP 不属于 Chrome provider 的公开能力。

Chrome 只把获授权的 HTTP(S) 业务页登记为 Surface。扩展连接页、欢迎页、浏览器内部页和临时空白页不进入页面列表或 UI；业务页改为内部协议后，原页面 ID 的操作与迟到结果均拒绝，不能落到其他标签。

Chrome 的观察保留混合文本及控件的语义状态，正文、元素、选项与模态信息共同受响应预算约束。敏感字段先遮蔽再截断；截断不能把提交值改成另一个值。操作完成后，在同一串行执行通道、同一 Page 上取得新观察，并由 Main 将其登记到发起操作的 Run 与 Surface。模型可直接使用返回的新引用，旧引用不因优化而继续有效。操作结果与随后观察的结果分别表达；观察失败不能把已派发动作改为未执行，也不能触发自动重放。

浏览器连接具有 Main 生成的短显示别名，帮助用户辨认共享或私有的扩展授权组；别名不参与授权。Chrome 多个原生窗口可能同时各有可见标签，“当前页”采用当前工作区显式选择或操作的 Surface。存在多个网页而尚未选择时返回歧义状态，不把列表首项或系统前台窗口当作目标。运行和收尾期间，其他对话的界面不能改变工作区选页或重连；界面显示实际占用并保留明确的工作区接管入口。

WorkPanel 语义观察在隔离 world 保存真实节点引用，覆盖当前文档、同源 iframe 和开放 Shadow DOM。正文与元素数量有界，密码和文件输入值不进入结构化观察。新观察、导航、元素替换或意外 debugger 断连使旧引用失效；正常的单次命令 debugger 释放不撤销仍有效的文档引用。

## Chrome AWCP 与标准操作

同一 Chrome 工作区页面同时提供 AWCP 业务动作与类型化页面操作。模型继续使用既有 `awcp_manual`、`awcp_invoke`，以及观察、点击、填写、导航和截图工具，不切换浏览器连接或复制登录态。新 Chat 沿用页面时也必须为新 Run 重新读取目录和章节。协议缺失或手册没有目标动作时，可以在任务许可范围内使用标准操作；AWCP 已提交、失败或结果未知时先核实业务状态，不能转为点击重放写入。

网站桥沿用设置中的现有安装、启用和精确 origin/path 规则。Main 从已安装且启用的包生成固定脚本，只交付当前 Run 所属 Chrome Page；Worker 在真实页面再次核对 URL 后，在主 world 幂等安装。首次 AWCP 请求负责按需安装，因此不要求用户再装一个 Chrome 扩展或给模型开放通用脚本。网页已有原生 AWCP 时优先使用，不由桥包覆盖。脚本、包路径与安装操作均不是模型参数。

Electron guest 与 Chrome Worker 共用 AWCP 协议信封和返回校验，业务 Schema 校验仍由页面运行时负责。Chrome 手册绑定归属于精确 Run、Page、主文档代际和 revision，只有已读章节可被调用；导航、断连、Run 结束和桥包变更会失效绑定。用户更新、禁用或卸载桥时，Worker 取消相关在途 AWCP、回收注入运行时与手册绑定，Chrome 页面和标准操作保持可用。原生 AWCP 不参与自定义桥回收。标准 DOM 操作与 AWCP 变更交叉使用后都须读取相应新状态，不共享旧元素引用或假定业务已经完成。

## Chrome 交互与文件

Chrome 使用类型化操作完成按键、悬停、勾选、原生单选与多选、滚动及表单填写。观察引用是首选定位方式；兼容的 CSS 与坐标定位仍须来自当前页面证据，截图坐标必须匹配截图所示的坐标系。原始脚本与通用 CDP 不因这些能力开放。后置等待绑定真实目标所在的 Frame，不能用主文档同名元素代替 iframe 内的结果。

原生网页对话框与文件选择器使用当前 Page、当前观察内的临时身份。对话框文本是网页数据，不构成执行授权；接受、取消及 prompt 输入均使用固定动作。网页弹窗阻塞期间不再等待页面脚本来读取状态。登录、验证码、OTP 和浏览器站点权限仍由用户在 Chrome 完成，已有接管与新 Run 续问流程负责恢复。

文件上传由 Platform 在当前 Chat 的附件与产物范围内解析引用、检查路径与权限，再向 Desktop 传递有界文件字节；Worker 不接收或寻找任意本机文件路径。文件选择器与观察引用沿用同一 Run/Page 校验。上传文件名、大小与格式异常必须在实际派发前拒绝。

官方 Chrome 扩展模式的下载只截获已授权 Page 原始 HTTP(S) 附件导航响应：扩展不提供 Playwright 所依赖的 Browser 下载事件，因此固定上游适配器通过该 Page 既有传输上的受限 Fetch/IO 响应端口，有界读取正文后恢复同一次 HTTP 响应，并把同份字节交给本连接的受控缓存。它不再次请求 URL、不重放表单，也不搜索用户 Downloads；Blob/data URL、内联 PDF 和页面脚本二次生成的文件不属于已交付的导入能力。普通响应直接继续；超限附件明确失败并取消本次导入，不能宣称文件已交付。纯隔离浏览器 fixture 保留原生 Playwright 下载路径，不能据此扩大官方扩展能力承诺。上游通用临时文件保存不能成为额外的无界副本。Platform 完成校验与原子持久化后，才把当前 Chat 的稳定文件引用交付给模型；重复保存保持幂等，已有不同内容不能被覆盖。断连先清理该响应端口及未决流，再释放尚未保存的临时数据，已持久化的 Chat 文件继续存在。上传、下载与分块传输的文件字节不进入诊断预览。

## 接管与失败

接管先撤销实际占用工作区的 Run 租约，再释放该工作区的 Chrome 自动化连接并请求 Platform 中断；界面必须说明共享工作区会影响所有关联对话。用户的 Chrome 与标签保留；WorkPanel guest 也保留。只有真正重新建立并授权的页面可继续使用，不能恢复旧 Surface 身份。普通停止或 Run 终态只撤销该 Run 并等待在途请求排空，不等同于工作区断连。

内嵌 WebClient 的 Run 属于 Main WebSocket 控制来源，接管必须沿用同一 Main broker 通道，并使用授权 Run 冻结的根智能体身份。HTTP 中断不能作为回退；Platform 的 transport、lane 与 owner 校验保持有效。只有平台明确接受取消，界面才能报告任务已停止，不能把浏览器租约撤销等同于平台取消完成。

已发送的页面请求不能通过取消回滚。超时、断连和迟到结果不能推断为未执行；写动作不自动重放。Chrome 连接失败不切换至 WorkPanel。截图进入现有 Chat 文件链路，视觉识别仍需 Platform 的有效 VL 配置。

## 构建与验证

Chrome Worker 随 Desktop 打包，通过 Electron Utility Process 运行，使用消息端口与 Main 通信。运行时无需用户安装 Node、Python 或下载 Chromium。官方扩展由用户在 Chrome 安装并批准连接。

上游版本、完整性和补丁基线由构建清单固定，构建期重放补丁并携带许可。macOS 与 Windows 的实际安装包和 Chrome 扩展连接分别验收；测试浏览器或某个平台的 fixture 成功不能替代另一平台的产品验收。

源码事实源为 `src/main/modules/browser-use/`、`src/main/modules/web-surfaces/cdp/observation*.ts`、`src/shared/browser-use.ts` 与 Platform 的 web-control 工具。手工验收见 `qa/manual-regression.md`。

Platform 内置的 web-control 技能随对应服务包发布，Chrome 工作流按需读取其配套参考，不能转而安装另一个浏览器 CLI 或借用其他会话。工作流组织参考了 [agent-browser core](https://github.com/vercel-labs/agent-browser/blob/5ee8691339a5a002e4d7454eec95250253bc7419/skill-data/core/SKILL.md) 的简短示例、状态验证和按需文档方式；实际参数、引用失效、等待、文件与授权规则仍以本项目已实现契约为准。尤其不能沿用该工具跨快照复用引用、通用脚本、批量命令或独立会话创建的规则。
