# 看板与云同步

详细 JSON 对接协议见 [Kanban 云端与 Desktop 同步协议 v3.2](Kanban云端与Desktop同步协议-v3.2.md)。v3.1 的快照、事件流和 Website 远程派发基线仍见 [v3.1 协议](Kanban云端与Desktop同步协议-v3.1.md)。

## 当前状态

Desktop Kanban 同时支持本地看板和云端权威缓存。Desktop 不把 cloud issue 当作可直接 CRUD 的公有 issue API；contract 3.2 仅开放 `issue.claim` 原子认领，运行通过正常 Chat `/api/query` 启动，再由 `run.event.append` 报告。云同步引擎保留为 no-op 兼容壳，远端控制和云快照通过 Desktop Kanban WebSocket 客户端处理。

运行状态、`chatId`、`runId` 和 automation 仍通过 agent-platform runtime 协议同步。

## 核心流程

```text
Kanban UI / desktop action
  -> KanbanRuntime
  -> local SQLite store
  -> cloud issue.claim / persistent run-event outbox
  -> normal assistant /api/query or automation create/update/delete
  -> assistant events -> run.event.append -> authoritative issue.updated
```

本地存储：

- legacy local store：`~/<brand>/.desktop/kanban.db`。
- v3 Desktop Kanban store：`data/desktop-kanban/kanban.db`。
- 新建 private Issue 的本地主键使用 `local-<UPPER_BASE36_TICK>`：时间 tick 与 Server 一致取 `floor(epochMillis / 100)`，转大写 Base36；如 SQLite 中已存在则递增 tick 直到唯一。已有 `local_...` 长 ID 保持不变，不做主键迁移。
- 表结构包含 board、project、workflow、issue、review、event_log、desktop_issue_sync、project_desktop_binding 等。
- `kanban_cloud_mutation_outbox` 保存稳定 `issue.claim` mutation，`kanban_run_event_outbox` 保存稳定运行事件，`kanban_manual_run_receipt` 保存 Query 前生成的 `chatId/runId` 以支持重启恢复。
- 云端 Issue 的非核心详情字段保存在 `issue.DETAIL_JSON_`；用户、Issue 类型、动态字段定义/上下文/选项、工作流目录、标签关系、依赖、评审、评论和近期事件保存在按当前用户隔离的 `kanban_cloud_detail_cache`。完整 `project_set` 快照会替换这份详情缓存，增量 Issue 事件只更新对应 Issue，不清空目录数据。
- `dueDate` 是严格的 `YYYY-MM-DD` 日历日期，按原字符串缓存到 `issue.DETAIL_JSON_`，不得转换成 epoch 或附加时区。旧 `dueTime` 只取日期前缀，旧 `dueAt` 只在迁移读取时按原 Desktop 本地日历语义转换；新写入不再产生旧键。Server 计算的 `dueRisk` 只读缓存，本地 private Issue 不复制风险算法。
- Project 通过 `versions` 和 `components` 维护版本、组件目录，分别缓存到 `project.VERSIONS_JSON_` 与 `project.COMPONENTS_JSON_`。Issue 使用 `projectVersion` 与 `componentKeys`；旧 `version` 只作为 Desktop Action/存量详情兼容输入。Website 和 Desktop 原生表单均从所属 Project 目录选择，云端 Issue 继续保持只读。
- Issue 的 `resolution`、`securityLevelKey`、`reporterId`、`originalEstimate`、`remainingEstimate`、`timeSpent` 与上述日期/目录字段都随完整快照和单 Issue 增量实体写入详情缓存；工时统一使用非负整数秒。`securityLevelKey` 在原生 UI 只读，Desktop Action 可为 private Issue 设置；`dueRisk` 不可写。
- 云端 `priority` 的 `urgent/high/medium/low` 在 Desktop 缓存边界映射为 `P0/P1/P2/P3`，Desktop Action 同时接受两种输入、输出仍使用 P0–P3。`priority` 与 `severity` 都允许为空，不再补 `P2` 或 `medium`。
- Issue Card 顶边使用 3px 工作流进度轨，优先采用当前 Stage 的目录 `color`，缺失时使用稳定语义色板。Issue Type 在左上角显示低饱和度竖线与实心图标；Project 和 `projectVersion` 分开显示，Todo 排序号位于顶部状态区。标题前的优先级/重要程度使用一个合并标识：优先显示优先级文字，未设置优先级时才显示重要程度文字，标识颜色始终由重要程度决定；两者都缺失时不渲染，完整信息保留在 tooltip。Footer 固定为人员在左、时间或截止信号在右；Todo 始终显示未设置/今天/未来/逾期四类日期信号，其他未完成状态显示更新时间，Completed 显示完成更新时间。时间区域只显示紧凑时间值，不显示 `Updated`、`Completed`、`更新`、`完成` 等前缀，具体时间语义保留在 tooltip。Server 提供 `dueRisk` 时显示可减少动态效果的红色闹钟；第二行只显示失败、取消、等待审批等异常状态，不重复运行中。卡片不提供聊天或删除悬浮按钮；点击进入详情，聊天保留在详情头部，本地删除保留在详情和右键菜单。

远端控制：

- WS URL 由 `serverUrl` 派生 `/ws`。
- role 固定为 `desktop`，协议版本当前为 `v=3`。
- token 来自环境变量或 SSO site token。
- 支持 snapshot、delivery、issue events、受限 `issue.claim`、`run.event.append`、dispatch issue、list agents、start run、automation sync、local project binding。
- 云连接状态区分前置条件：未填写 Server URL、未启用 Kanban 或未开启远程控制时显示“未配置”；配置完整但 Desktop SSO 凭证尚未就绪、site token 缺失或已过期时显示“请重新登录”，不再将凭证问题误报为未配置。重新登录生成有效 site token 后自动刷新连接状态。

## 配置与接口

配置文件：`config/desktop/kanban.json`。

可覆盖环境变量：

- `DESKTOP_KANBAN_SERVER_URL`
- `DESKTOP_KANBAN_TOKEN`
- `DESKTOP_KANBAN_REMOTE_CONTROL_ENABLED`
- `DESKTOP_KANBAN_PROJECT_ID`
- `DESKTOP_KANBAN_REMOTE_START_ACK_TIMEOUT_MS`

## 日志与排障

Kanban Server WebSocket 由 Desktop 主进程建立，因此不会显示在 renderer DevTools 的 Network 面板。连接、关闭、错误，以及每一条收发帧都会独立写入 JSONL 日志：`~/<brand-runtime-root>/.desktop/logs/desktop/kanban-ws.log`（Windows 为 `%USERPROFILE%\\<brand-runtime-root>\\.desktop\\logs\\desktop\\kanban-ws.log`）。Settings → Debug → Desktop Logs 的 **Kanban WS Log** 会在独立浮层中实时查看该文件，不与 Desktop `main.log` 混合。

每一行包含时间、连接诊断或收发方向、字节数与完整协议帧。token、authorization/cookie/secret/password/API key、敏感 URL 查询参数、本机绝对路径与 private issue 内容会递归替换为脱敏标记。文件固定为一个路径，超过 10 MiB 时只保留最近的完整日志行。

桌面动作：

- `desktop.kanban.listIssues`
- `desktop.kanban.getIssue`
- `desktop.kanban.createIssue`
- `desktop.kanban.updateIssue`
- `desktop.kanban.deleteIssue`
- `desktop.kanban.moveIssue`

Renderer IPC 另提供 `kanban.claimIssue(issueId)` 与 `kanban.runIssue({ issueId, agentKey })`；它们不是 Desktop Action 公共 CRUD。

## 约束与注意事项

- cloud Kanban issue 的正文和工作流状态在 Desktop UI/runtime 中保持只读；3.2 的“认领”只写 assignee，“开始处理”只通过正常 Chat 与运行事件推进。
- 卡片默认 `width: 100%` 撑满所在列，最小宽度为 `200px`；列内容区顶部 padding 与卡片间 gap 均为 `4px`，左右和底部 padding 为 `8px`，横向滚动时单列最窄为 `216px`。五列外层不保留 padding，Kanban 最小内容宽度为 `1080px`。亮色 Column 使用 `#F3F4F6`、白色 Issue Card；暗色 Column 使用 `#212121`，Issue Card 及拖拽镜像统一使用 `#181818`。卡片按真实内容自然增高，顶边 Stage 工作流进度轨固定为 `3px`。项目、独立版本标签与顶部细分 Status 使用紧凑整数像素字号；长标题、版本和人员在 200px 卡片中截断。键盘焦点作用于整张卡片。Issue 不包含 `reviewerId` 或 Issue 级 `reviewRequired`；审核由工作流 Status 表达。所有构建只展示实体与目录中实际存在的数据，不生成演示人员、不补默认等级或 Project/Issue Type。
- Project 筛选在选择 2 个及以上项目时，hover 或键盘聚焦仅显示已选项目清单；项目每行显示一个，可附带父级路径，不重复 Issue 数量或“已选 N 个”摘要。展开 Project 菜单时隐藏该提示，并在每个项目行右侧显示 Issue 数；父项目按筛选语义汇总自身及全部后代项目的 Issue，叶子项目显示自身 Issue 数。
- Search issues 增加 Issue Type 多选；优先级和重要程度筛选都提供“未设置”，并可与 Project、负责人和自动化筛选组合。全文索引包含类型、组件、Reporter、负责人/执行者 ID、Project ID/名称/路径、版本及附件名。负责人筛选使用“他人 / 自己 / 未分配”三项多选，按云端 `assigneeId` 与当前用户 ID 判定；筛选组合保存在 renderer 本地偏好中，首次使用时系统默认仅选择“自己”。
- `/kanban` 的 Issue Detail 使用固定的内容/属性双栏：桌面端最大尺寸为 `1062px × 738px`，右栏固定为 `280px`，左栏使用剩余宽度；头部只在云端 Issue 显示 Cloud 来源；左侧紧凑展示 Title、Markdown Description、附件列表和逐条评论。Description 在只读态直接渲染安全的 GFM Markdown 预览，进入本地编辑态后才显示 Markdown 原文 textarea；编辑器根据实际文字内容及可用宽度自动增高，自身不显示纵向滚动条。Description 与 Comments 的 Markdown 图片允许受限的 base64 raster 与 `image/svg+xml` Data URL，SVG 仍通过 `<img>` 隔离显示，不以内联 HTML 执行；`mermaid` 围栏代码块按需加载 Mermaid 并渲染图表，使用严格安全级别禁用图表内点击脚本和原始 HTML；非法语法降级显示原始代码，不影响其余 Markdown；Website 使用相同 Mermaid 配置。右栏顶部提供吸顶锚点导航，并只保留基本属性、负责人、关联、时间线四组。云端 Issue 全部只读，但未认领 Todo 可执行“认领”，本人已认领 Todo 可执行“开始处理”；本地 Issue 默认只读打开，可编辑 Title、Description、日期型截止日期、项目版本、Resolution、Components、Reporter、三类工时、可空优先级/重要程度、状态、执行 Agent、自动化和附件。Basic 同时只读展示 `dueRisk` 与 `securityLevelKey`，Project/Issue Type/Workflow/Stage 和云端动态字段不在 Desktop 管理。聊天入口位于详情头部并导航唯一主 Chat WebView，不创建 Kanban 专用 WebView；本地删除位于 Basic 底部。Settings 中 Debug、双击复制、安全 Markdown、关联、时间线与窄屏响应式规则保持不变。
- Issue Detail 的 Markdown 图片允许 HTTPS URL，包含远程 `image/svg+xml`；HTTP URL 继续由 CSP 禁止，远程 SVG 仅作为 `<img>` 图片加载，不获得脚本或内联 HTML 执行能力。
- 不调用已移除的 public issue CRUD / review / label / dependency 端点。
- `run.event.append` 是 Desktop runtime 同步 run state、`chatId`、`runId` 的协议，不是 public issue CRUD。
- Cloud 终态只按 active `runId` 关联；不得仅凭相同 `chatId` 修改 Issue。`clientEventId` 固定由 device、issue、run 和 event type 生成。
- 非拖拽完成任务有保护逻辑，避免普通更新直接把 issue 标记为 completed。
- automation 同步走 agent-platform `/api/automation/create`、`/api/automation/update`、`/api/automation/delete`。
