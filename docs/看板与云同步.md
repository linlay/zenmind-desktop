# 看板与云同步

详细 JSON 对接协议见 [Kanban 云端、Website 与 Desktop 同步协议 v3.1](Kanban云端与Desktop同步协议-v3.1.md)。该文档同时标注旧版 Current v3 兼容行为、当前 v3.1 规范和兼容规则。

## 当前状态

Desktop Kanban 同时支持本地看板和云端只读缓存。Desktop v3 不再把 cloud issue 当作可直接 CRUD 的公有 issue API；云同步引擎保留为 no-op 兼容壳，远端控制和云快照通过 Desktop Kanban WebSocket 客户端处理。

运行状态、`chatId`、`runId` 和 automation 仍通过 agent-platform runtime 协议同步。

## 核心流程

```text
Kanban UI / desktop action
  -> KanbanRuntime
  -> local SQLite store
  -> optional cloud WS snapshot / delivery
  -> assistant startRun / automation create/update/delete
  -> assistant events update run state
```

本地存储：

- legacy local store：`~/<brand>/.desktop/kanban.db`。
- v3 Desktop Kanban store：`data/desktop-kanban/kanban.db`。
- 表结构包含 board、project、workflow、issue、review、event_log、desktop_issue_sync、project_desktop_binding 等。
- 云端 Issue 的非核心详情字段保存在 `issue.DETAIL_JSON_`；用户、Issue 类型、动态字段定义/上下文/选项、工作流目录、标签关系、依赖、评审、评论和近期事件保存在按当前用户隔离的 `kanban_cloud_detail_cache`。完整 `project_set` 快照会替换这份详情缓存，增量 Issue 事件只更新对应 Issue，不清空目录数据。
- 云端 `dueTime` 使用 RFC3339 文本传输；Desktop 主进程严格转换为 epoch-ms `dueAt`，并随其他非核心详情写入 `issue.DETAIL_JSON_`。该字段在 Desktop 卡片中只读展示，不增加本地编辑或云端 mutation。
- Project 通过 `versions` 维护可选版本号目录，Issue 的 `version` 为可空字符串；Website 新建和编辑 Issue 只能从所属 Project 的版本目录下拉选择，Desktop 将 Project 目录写入 `project.VERSIONS_JSON_`、将 Issue 版本写入详情缓存。本地 Issue 编辑同样使用 Project 版本目录下拉选择，云端 Issue 继续保持只读。
- Issue Card 顶边的工作流进度由 renderer 根据只读的 `workflowStages`、`workflowStatuses` 与 Issue 当前 Stage/Status 推导，不新增协议百分比字段。填充区始终只使用当前 Stage 的单一颜色；五个大状态仅在列头用灰、黄、蓝、橙、绿小圆点区分，Kanban 页面不重复展示 Stage 颜色图例。卡片右上角在细分 Status 右侧显示 Issue Type 的纯色实心 SVG 图标，不绘制方形背景底；图标与颜色优先读取 `issueTypes` 目录，目录缺失时按需求、故事、任务、子任务、问题提供稳定回退，完整类型名称保留在 tooltip。卡片主体按 Backlog、Todo、In Progress、In Review、Completed 分别选择决策、排队、执行、审核和归档信息，分隔线下方最多两行。优先级统一使用 `P0`、`P1`、`P2`、`P3`；卡片重要程度使用 i18n 短文案，中文为“关键/重要/普通/低”，英文为“Crit./Imp./Norm./Low”，完整英文文案仍保留在 tooltip 和表单等非紧凑界面中。

远端控制：

- WS URL 由 `serverUrl` 派生 `/ws`。
- role 固定为 `desktop`，协议版本当前为 `v=3`。
- token 来自环境变量或 SSO site token。
- 支持 snapshot、delivery、issue events、dispatch issue、list agents、start run、automation sync、local project binding。
- 云连接状态区分前置条件：未填写 Server URL、未启用 Kanban 或未开启远程控制时显示“未配置”；配置完整但 Desktop SSO 凭证尚未就绪、site token 缺失或已过期时显示“请重新登录”，不再将凭证问题误报为未配置。重新登录生成有效 site token 后自动刷新连接状态。

## 配置与接口

配置文件：`config/desktop/kanban.json`。

可覆盖环境变量：

- `DESKTOP_KANBAN_SERVER_URL`
- `DESKTOP_KANBAN_TOKEN`
- `DESKTOP_KANBAN_REMOTE_CONTROL_ENABLED`
- `DESKTOP_KANBAN_PROJECT_ID`
- `DESKTOP_KANBAN_REMOTE_START_ACK_TIMEOUT_MS`

## 日志与排障

Kanban Server WebSocket 由 Desktop 主进程建立，因此不会显示在 renderer DevTools 的 Network 面板。连接、关闭、错误，以及每一条收发帧都会独立写入 JSONL 日志：`~/<brand-runtime-root>/.desktop/logs/desktop/kanban-ws.log`（Windows 为 `%USERPROFILE%\\<brand-runtime-root>\\.desktop\\logs\\desktop\\kanban-ws.log`）。Settings → Debug → Desktop Logs 的 **Kanban WS Log** 会在独立浮层中实时查看该文件，不与 Desktop `main.log` 混合。

每一行包含时间、连接诊断或收发方向、字节数与完整协议帧。token、authorization/cookie/secret/password/API key、敏感 URL 查询参数、本机绝对路径与 private issue 内容会递归替换为脱敏标记。文件固定为一个路径，超过 10 MiB 时只保留最近的完整日志行。

桌面动作：

- `desktop.kanban.listIssues`
- `desktop.kanban.getIssue`
- `desktop.kanban.createIssue`
- `desktop.kanban.updateIssue`
- `desktop.kanban.deleteIssue`
- `desktop.kanban.moveIssue`

## 约束与注意事项

- cloud Kanban issue 在 Desktop UI/runtime 中是只读缓存。
- 卡片默认 `width: 100%` 撑满所在列，最小宽度为 `200px`；列内容区顶部 padding 与卡片间 gap 均为 `4px`，左右和底部 padding 为 `8px`，因此横向滚动时单列最窄为 `216px`。五列外层不保留 padding，Kanban 最小内容宽度为 `1080px`，再窄时显示整体横向滚动；留白位于 Column Body 内部，列边界仍从工具栏下沿连续铺到内容区底部。亮色 Column 使用 `#F3F4F6`、白色 Issue Card；暗色 Column 使用 `#212121`，Issue Card 及拖拽镜像统一使用 `#181818`。不设置统一最小高度或等高约束，按标题、仅 Backlog 可见的描述和实际 Footer 行数自然增高；顶边 Stage 工作流进度轨固定为 `2px`。Column 容器不使用圆角，五个列头保持直角并形成连续横向结构；列头使用透明背景、`40px` 高度和更轻的 `12px` 标题，标题前以灰、黄、蓝、橙、绿圆点区分大状态，数量改为无胶囊的弱化数字，加号使用现有图标库且只在 hover 时出现轻底色。项目名与顶部细分 Status 使用 `10px`，项目名后仅在 Issue 版本非空时追加 ` (版本号)`；标题使用 `12px` 常规字重，描述使用弱化的 `10px`，卡片内字号只使用整数像素。细分 Status 为直接使用当前 Stage 颜色的无边框文字，缺失时回退到列状态，文字前不再显示独立色标。键盘焦点作用于整张卡片，不对可点击的上半块单独绘制选择框；hover/focus 只显示可用的聊天和本地删除操作，不显示独立详情按钮；没有操作按钮时智能信号保持可见，优先级、重要程度、人员、时长和截止信息不随之隐藏或位移。Issue 不包含 `reviewerId` 或 Issue 级 `reviewRequired`；审核由工作流 Status 表达，具体 Review 记录只在关联事项中展示。开发模式可为缺少人员字段的云端演示数据确定性补齐负责人、真人或智能体执行者；生产构建始终保留云端真实缺失状态，不伪造人员。
- Project 筛选在选择 2 个及以上项目时，hover 或键盘聚焦仅显示已选项目清单；项目每行显示一个，可附带父级路径，不重复 Issue 数量或“已选 N 个”摘要。展开 Project 菜单时隐藏该提示，并在每个项目行右侧显示 Issue 数；父项目按筛选语义汇总自身及全部后代项目的 Issue，叶子项目显示自身 Issue 数。
- Search issues 的负责人筛选使用“他人 / 自己 / 未分配”三项多选，按云端 `assigneeId` 与当前用户 ID 判定；筛选组合保存在 renderer 本地偏好中，首次使用时系统默认仅选择“自己”。
- `/kanban` 的 Issue Detail 使用固定的内容/属性双栏：桌面端最大尺寸为 `1062px × 738px`，右栏固定为 `280px`，左栏使用剩余宽度；头部只在云端 Issue 显示 Cloud 来源；左侧紧凑展示 Title、Markdown Description、附件列表和逐条评论。Description 在只读态直接渲染安全的 GFM Markdown 预览，进入本地编辑态后才显示 Markdown 原文 textarea；编辑器根据实际文字内容及可用宽度自动增高，自身不显示纵向滚动条。Description 与 Comments 的 Markdown 图片允许受限的 base64 raster 与 `image/svg+xml` Data URL，SVG 仍通过 `<img>` 隔离显示，不以内联 HTML 执行；`mermaid` 围栏代码块按需加载 Mermaid 并渲染图表，使用严格安全级别禁用图表内点击脚本和原始 HTML；非法语法降级显示原始代码，不影响其余 Markdown；Website 使用相同 Mermaid 配置，确保相同围栏代码不会在一端显示图形、另一端退化为普通代码块。Comments 正文也使用同一 Markdown 预览，原始 HTML 不执行，链接交给系统浏览器打开。右栏顶部提供吸顶锚点导航，并只保留基本属性（英文标题为 `Basic`）、负责人、关联、时间线（英文标题为 `Timeline`）四组：基本属性吸收项目、版本号、类型、工作流、阶段、标签和动态字段，同时包含 ID、细分状态、优先级、重要程度、创建/更新时间及创建/更新人，本地云同步开关也放在该组；负责人、执行者和自动化配置合并到标题更短的“负责人”；关联统一包含所属需求/父任务、子任务、依赖、审查与运行记录，运行记录由 Issue 当前 run 字段和事件快照合并去重；时间线作为独立区块保留，每个状态变更节点显示操作者、操作时间和明确的 `from → to` 状态，优先使用 Server 事件中的 `statusTransition`，历史事件按相邻快照补全。来源权限由头部 Cloud 标识和右栏底部的弱化只读提示表达，不再在基础属性顶部展示大块“云端只读缓存”，也不展示独立“来源与同步”区块。Settings 中的 Debug 未解锁时不显示 revision 和事件原始 payload；解锁 Debug 后，revision 出现在基础属性中，事件 payload 可从对应时间线节点展开查看。Basic 区全部可复制属性均支持双击复制，复制能力不改变鼠标指针或 hover 样式，Issue ID 不显示额外复制按钮。整体使用紧凑留白与细分隔线组织内容，不为每个区块重复绘制完整卡片边框。详情层使用不模糊的轻量遮罩，使原看板卡片仍可辨认；右栏字段统一使用横向 label/value，窄于 `760px` 时改为上下单列；字段行在只读态显示 value，本地编辑态在同一 value 槽替换为现有协议支持的输入组件。详情不使用分组页签、解释性副标题或底部状态栏。云端 Issue 的 Title 保持禁用输入框，Description 和 Comments 以只读 Markdown 预览展示；本地 Issue 默认以只读态打开，可显式进入编辑态修改现有基础字段；Desktop 不创建或维护动态字段定义。
- Issue Detail 的 Markdown 图片允许 HTTPS URL，包含远程 `image/svg+xml`；HTTP URL 继续由 CSP 禁止，远程 SVG 仅作为 `<img>` 图片加载，不获得脚本或内联 HTML 执行能力。
- 不调用已移除的 public issue CRUD / review / label / dependency 端点。
- `run.event.append` 是 Desktop runtime 同步 run state、`chatId`、`runId` 的协议，不是 public issue CRUD。
- 非拖拽完成任务有保护逻辑，避免普通更新直接把 issue 标记为 completed。
- automation 同步走 agent-platform `/api/automation/create`、`/api/automation/update`、`/api/automation/delete`。
