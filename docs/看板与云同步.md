# 看板与云同步

详细 JSON 对接协议见 [Kanban 云端、Website 与 Desktop 同步协议 v3.1](Kanban云端与Desktop同步协议-v3.1.md)。该文档同时标注旧版 Current v3 兼容行为、当前 v3.1 规范和兼容规则。

## 当前状态

Desktop Kanban 同时支持本地看板和云端只读缓存。Desktop v3 不再把 cloud issue 当作可直接 CRUD 的公有 issue API；云同步引擎保留为 no-op 兼容壳，远端控制和云快照通过 Desktop Kanban WebSocket 客户端处理。

运行状态、`chatId`、`runId` 和 automation 仍通过 agent-platform runtime 协议同步。

## 核心流程

```text
Kanban UI / desktop action
  -> KanbanRuntime
  -> local SQLite store
  -> optional cloud WS snapshot / delivery
  -> assistant startRun / automation create/update/delete
  -> assistant events update run state
```

本地存储：

- legacy local store：`~/<brand>/.desktop/kanban.db`。
- v3 Desktop Kanban store：`data/desktop-kanban/kanban.db`。
- 表结构包含 board、project、workflow、issue、review、event_log、desktop_issue_sync、project_desktop_binding 等。

远端控制：

- WS URL 由 `serverUrl` 派生 `/ws`。
- role 固定为 `desktop`，协议版本当前为 `v=3`。
- token 来自环境变量或 SSO site token。
- 支持 snapshot、delivery、issue events、dispatch issue、list agents、start run、automation sync、local project binding。

## 配置与接口

配置文件：`config/desktop/kanban.json`。

可覆盖环境变量：

- `DESKTOP_KANBAN_SERVER_URL`
- `DESKTOP_KANBAN_TOKEN`
- `DESKTOP_KANBAN_REMOTE_CONTROL_ENABLED`
- `DESKTOP_KANBAN_PROJECT_ID`
- `DESKTOP_KANBAN_REMOTE_START_ACK_TIMEOUT_MS`

## 日志与排障

Kanban Server WebSocket 由 Desktop 主进程建立，因此不会显示在 renderer DevTools 的 Network 面板。连接、关闭、错误，以及每一条收发帧都会独立写入 JSONL 日志：`~/<brand-runtime-root>/.desktop/logs/desktop/kanban-ws.log`（Windows 为 `%USERPROFILE%\\<brand-runtime-root>\\.desktop\\logs\\desktop\\kanban-ws.log`）。Settings → Debug → Desktop Logs 的 **Kanban WS Log** 会在独立浮层中实时查看该文件，不与 Desktop `main.log` 混合。

每一行包含时间、连接诊断或收发方向、字节数与完整协议帧。token、authorization/cookie/secret/password/API key、敏感 URL 查询参数、本机绝对路径与 private issue 内容会递归替换为脱敏标记。文件固定为一个路径，超过 10 MiB 时只保留最近的完整日志行。

桌面动作：

- `desktop.kanban.listIssues`
- `desktop.kanban.getIssue`
- `desktop.kanban.createIssue`
- `desktop.kanban.updateIssue`
- `desktop.kanban.deleteIssue`
- `desktop.kanban.moveIssue`

## 约束与注意事项

- cloud Kanban issue 在 Desktop UI/runtime 中是只读缓存。
- 不调用已移除的 public issue CRUD / review / label / dependency 端点。
- `run.event.append` 是 Desktop runtime 同步 run state、`chatId`、`runId` 的协议，不是 public issue CRUD。
- 非拖拽完成任务有保护逻辑，避免普通更新直接把 issue 标记为 completed。
- automation 同步走 agent-platform `/api/automation/create`、`/api/automation/update`、`/api/automation/delete`。
