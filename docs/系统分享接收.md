# 系统分享接收

## 定位与边界

Mac 版 Desktop 通过随应用安装的原生共享扩展接收用户在微信等应用中主动分享的文件。入口沿用系统共享菜单，显示当前品牌名称与图标。扩展只接收这一次分享的内容；Desktop 的聊天界面继续负责草稿、附件和用户发送行为。

微信是首个落地来源。架构必须支持后续接入飞书、企业微信、QQ 等聊天来源；来源接入和格式解析可以增量实现，但不能要求改名、分叉公共传输协议或替换 WebClient 附件草稿链路。

共享扩展是 Desktop 应用包的一部分，不属于市场插件或内置服务。Windows 不注册 macOS 扩展，也不根据分享协议打开文件。Windows 分享入口需要独立的平台契约。

## 主流程与数据所有权

原生扩展通过系统附件提供器取得文件，在自己的沙盒容器暂存全部内容。整批成功后原子发布，建立一次性本机传输，并唤起包含它的 Desktop 应用。传输只监听 loopback，通过短时随机能力票据授权；唤起请求不能提供任意网络地址或本地路径。开发版与正式版分别使用各自的应用及扩展身份。

所有品牌共用同一业务协议与能力模型。共享扩展通过显式包含 App 目标交付统一唤起协议；品牌身份只决定展示、签名、目标 App 与存储隔离，不参与协议名、header、IPC、消息类型或 DTO 字段。Main、原生扩展及打包注册从同一协议事实源取得命名，并同批发布。

Desktop Main 在自己拥有的数据目录中有界接收批次，校验清单、文件大小与路径边界，整批成功后原子发布并确认收到，再打开默认 Chat Agent 的新对话入口。原始 ZIP 保持为附件，不在导入时解压，也不根据其中的文本执行动作。Main 持有原始路径，renderer 和 WebClient 只得到受限文件描述与有界数据块。

WebClient 将文件添加到可编辑附件草稿，保留既有输入、技能与附件。用户发送前不调用模型。草稿仅在 guest 内存时不能确认批次完成；用户点击发送、附件通过原有上传流程持久保存后，才确认批次收到并继续正常 query。确认完成不删除原始分享文件。确认回执已写入但 guest 尚未提交 query 时，同一活动批次与新对话身份仍可重新读取原件，避免响应丢失或刷新把草稿锁死；来源变更、query 提升到真实 Chat 或原身份失效后，既有来源校验立即拒绝读取。

## 多来源接入边界

- 来源适配负责从系统分享、应用导出或后续经授权的连接器取得本次导入的原始内容；平台差异在各平台入口处理，不进入公共批次协议。
- Desktop 的共同职责是有界暂存、完整性校验、批次授权和附件交付。该层不限制来源为微信，也不解释聊天记录的消息、人员、时间或媒体格式。
- 来源格式的解释属于独立的解析能力或 Agent 技能/连接器，保留原文件与来源语义；专用格式、加密内容或需要登录的来源必须由对应适配实现，不得伪装成已支持，也不在原生传输层加入聊天应用分支。
- WebClient 始终消费统一文件描述与数据块，进入已有可编辑附件草稿和用户发送流程；未来来源不能新增独立 Composer、自动发送入口或按应用复制 bridge。
- 每个实际来源上线必须验证该应用的真实入口与原始内容。通用格式夹具只证明公共传输可复用，不替代飞书、企业微信或 QQ 的实机验收。

## 安全与失败策略

- 扩展启用 App Sandbox，不继承 Electron 的 JIT 权限；网络权限仅用于本机监听和已接受连接，代码固定 loopback，不建立外部网络连接，不申请辅助功能或录屏权限。
- Main 不直接读取扩展的沙盒容器。macOS 的应用数据保护也约束非沙盒宿主；本机开发签名没有 Apple Developer Team，不能依赖 App Group 自动授权或完整磁盘权限来交接文件。
- 本机传输只接受固定批次路径、临时端口与一次性能力票据，不跟随重定向，不解析任意 URL。票据不进入日志、renderer、WebClient 或模型请求；成功、取消与超时后关闭监听。
- 清单和附件必须是接收目录中的普通文件；拒绝符号链接、目录越界、清单身份不符、大小不符与超限批次。部分暂存批次不能进入聊天。
- 接收 IPC 只允许主窗口顶层 frame；每次读取还必须对应实际活动的 Main Chat、同一 Agent、新对话 nonce 与分享批次。异步读取完成后再次校验，失效来源不能取得迟到文件。
- 失败和取消保留已发布的原包，不把不完整附件当成成功。扩展在 Main 原子接收后才结束分享；发送前刷新当前分享入口可从 Main 保存的原包重新读取，重复唤起同一待处理批次复用其对话身份。
- 原生扩展独立签名后再签包含应用，签名流程保留内置服务已有完整性边界。源码测试、扩展注册与真实微信菜单验收分别记录证据，不能互相替代。

## 实现事实源

- `native/macos-share/`：原生扩展与系统附件读取。
- `src/main/modules/native-share/`：批次验证、读取和完成状态。
- `src/main/app/assembly/native-share.ts`、`src/main/app/app-events.ts`：真实来源校验与冷启动、热启动入口。
- `src/shared/native-share.ts` 与生成的 WebClient bridge contract：受限 DTO。
- `src/shared/native-share-protocol.json`：原生传输与系统唤起的品牌无关协议命名。
- WebClient 的共享导入、附件 staging 和发送流程；Desktop 服务 WebView 桥。
- 原生扩展构建、开发壳与签名脚本及相应测试。
