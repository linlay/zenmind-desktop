# 网站密码与登录协助

## 文档定位

本文描述 Desktop 本地网站密码保险库的设计：在用户同意后记录 WebView 中的网站登录账号密码、加密保存在本机、在设置中管理和查看，以及让 Agent Platform 的 web-control 请求 Desktop 代为填写。

**状态：设计已于 2026-10-13 确认，尚未实现。** 本文是实现的依据；实现落地后，精确的接口、字段、状态枚举和默认值以 `src/`、`src/shared/`、`contracts/` 与测试为准，并按[配套改动](#配套改动)一节同步其他专题文档。

非目标：

- 不读写系统 Chrome 或其他浏览器的密码库，不使用 Chromium 内置密码库。
- 不保存短信/邮件验证码、TOTP 种子、恢复码或 Passkey 私钥，不绕过 CAPTCHA 与多因素验证。
- 不做云同步，保险库不随官网 SSO 账号迁移。
- 不承诺抵御恶意智能体、同一系统用户下的其他程序或被攻破的主进程，见[安全目标与保证范围](#安全目标与保证范围)。

## 安全目标与保证范围

本设计的安全目标是：**密码明文不进入模型上下文、工具结果、日志和云端对话记录，也不以明文落盘。** 智能体只能请求 Desktop 填写并得到状态，不能取得密码。

这个目标是有意收窄的。智能体登录后控制页面，通常就能代表用户操作该账号；拥有 Host Bash 的智能体与用户同权。因此"恶意智能体也拿不到密码"需要先限制智能体的宿主运行身份，属于另一项工程，不在本设计内。

| 威胁 | 本设计提供的保证 |
| --- | --- |
| 只取得保险库文件 | 无法读出明文，前提是未同时取得系统密钥保护能力 |
| 普通网页或 WebApp 请求密码 | 没有查询接口，Main 校验真实来源 |
| 钓鱼页面索要其他域名的密码 | 按精确来源匹配，确认界面显示 Main 判定的真实域名 |
| 智能体正常调用登录动作 | 只得到状态与脱敏用户名 |
| 智能体的文件工具读取保险库 | Platform 受保护路径拒绝；且文件本身是密文 |
| 智能体事先在页面植入脚本，或拥有 Host Bash | 不保证。属于已接受的残余风险 |
| 目标网站自身恶意或存在 XSS | 不保证。密码填入页面后网站脚本可读 |
| 同一系统用户下的其他程序 | macOS 受应用签名约束；Windows 不保证 |

产品文案不得超出上表承诺，尤其不能把"查看前的系统认证"表述成"需系统密码才能解密"。

## 模块职责与数据所有权

凭据是 Main 进程内的独立领域，与 Identity 的 canonical access token、Chromium 的 Cookie 互不替代，也不复用 Token Bridge 分发。

| 组成 | 职责 |
| --- | --- |
| 保险库 | 加密持久化、密钥管理、记录版本、导入导出、删除 |
| 凭据编排 | 一次保存、填充或登录协助的流程与状态；来源匹配与默认账号选择 |
| WebSurfaces | 提供可信的页面身份、frame、session 和生命周期；填充期间暂停该页面的自动化 |
| guest 采集与填充逻辑 | 只做登录候选表单识别、受控读取和固定逻辑填充，不暴露任何取密码的函数 |
| 设置界面 | 开关、账号列表、查看、修改、删除、导入导出 |
| Agent Platform / web-control | 调用凭据动作并接收状态，不持有也不转发密码 |

密码只在 Main 与目标 frame 之间传递。它不经过 renderer 的普通状态、事件广播、页面 `postMessage`、AWCP 参数或通用 Desktop Action 结果。设置界面只在用户请求查看某一条时取得该条明文。

## 存储与加密

保险库位于 Desktop 数据根的 `secrets/` 分区下的独立子目录，不放在 `state/chromium`，也不放进 Agent Platform 的 `.state`：

- 浏览器状态会被清理浏览器数据的操作波及，密码不应随之删除。
- `.state` 的结构和生命周期归 Platform 所有，Platform 进程本身可读；网站密码应只有 Desktop Main 能解密。

加密分两层：随机生成保险库密钥，用操作系统能力保护这把密钥，再用它对保险库整体做认证加密。域名、用户名、备注和"永不保存"名单都会暴露隐私，一并加密；普通配置只保存功能开关等非敏感项。密钥不写入配置文件。

平台分支必须显式实现并分别验证：

- **macOS**：保险库密钥由系统 Keychain 保护，依赖稳定的应用签名。未签名的开发构建保护较弱。
- **Windows**：保险库密钥由当前用户范围的 DPAPI 保护。DPAPI 不隔离同一用户下的其他进程，这一点要在启用说明中如实告知，不能与 macOS 等同宣传。
- 其他平台没有可用的系统密钥保护时，功能不可用，不降级为弱保护或明文。

目录与文件访问控制：

- `secrets/` 目录仅当前用户可访问。macOS 使用目录和文件权限；Windows 使用专门的 ACL 与路径所有权检查，不能复用 macOS 的权限假设。
- Agent Platform 的受保护路径需要包含 Desktop 的 `secrets/`，使智能体文件工具拒绝读取、搜索工具自动跳过。路径由 Desktop 在启动 Platform 时通过已有的生命周期参数传入，Platform 侧负责执行。这同时覆盖 `secrets/` 中已有的其他内容。

失败策略：

- 系统密钥保护不可用、被拒绝或密钥缺失时，保险库显示为不可用并保留原文件，禁止保存，不能把解密失败当作空保险库覆盖。
- 写入使用暂存与原子替换；临时文件和备份同样只包含密文。
- 遇到比当前程序更新的保险库格式时拒绝写入，不覆盖成旧格式。

## 记录流程

功能默认关闭。用户在设置中显式启用后，Desktop 才识别登录表单；每次保存或更新仍在登录后单独询问。

```text
用户启用密码管理
  -> 识别候选登录表单
  -> 用户输入并发起登录
  -> 候选只在内存中短暂保留
  -> Desktop 可信界面询问保存或更新
  -> 用户确认后 Main 加密写入保险库
```

采集范围严格限定在登录候选表单内：不记录键盘历史，不扫描所有输入框，不从网络请求正文中提取密码。页面提供的字段属性、标签和结构都只是不可信线索。未保存的候选有期限、数量和长度上限，在用户取消、页面关闭、锁屏或超时后清除，不进入日志、崩溃材料或模型上下文。

"提交了表单"不等于"登录成功"。保存状态与登录验证状态分开记录；无法判断是否成功时标明未验证，由用户决定是否保存。登录失败不覆盖已有密码。

| 场景 | 处理 |
| --- | --- |
| 标准用户名密码表单、SPA 或 AJAX 登录 | 支持，不依赖传统表单提交事件 |
| 用户名与密码分两页 | 在同一次短期登录流程内关联；超时或跨到不明来源后丢弃 |
| 注册、重置密码 | 区分旧密码、新密码与确认密码，只保存新密码 |
| 同一账号更换密码 | 询问更新 |
| 隐藏表单、脚本伪造的提交 | 不触发保存 |
| 无法识别的特殊控件 | 由用户在设置中手动添加，不扩大为全页面采集 |
| 已有有效登录态 | 直接使用，不为记录密码要求重新登录 |
| 扫码、Passkey、第三方身份登录 | 没有密码可记录，不生成虚假记录；身份提供方页面上的密码归属于该身份提供方的来源 |
| HTTP Basic、代理认证、跨源 iframe | 第一阶段不支持 |

用户还可以通过导入文件批量加入已有密码，见[设置与数据生命周期](#设置与数据生命周期)。

## 来源匹配与填充

凭据按精确来源关联：协议、主机和端口全部一致才算匹配。同一组织的不同子域不默认共享，本地 WebApp 不因同为 `localhost` 而共享。

- 匹配依据是 Main 从真实 WebContents 与 frame 解析出的当前来源，不接受调用方或页面声明的网址。
- 只向证书有效的 HTTPS 顶层页面填充；HTTP、证书错误页、本地文件和内嵌数据页面一律拒绝。
- 只填入可见、可交互且无歧义的字段。
- 填充前复验页面实例、文档代次和来源；确认期间发生导航、刷新或页面替换则本次填充作废。

同一来源有多个账号时由 Desktop 选择：用户可为网站指定默认账号，未指定时取用户最近一次在该网站使用的账号。每个账号有"禁止智能体使用"开关，优先级高于其他一切策略。

密码填入页面后，目标网站的脚本可以读取它；部分页面在输入事件后就会发送表单数据。因此填充本身已是向目标网站披露密码，最后一步是否点击登录不是唯一的安全边界。

## 智能体登录协助

web-control 通过独立的 `desktop.credentials.*` 动作命名空间请求 Desktop 填写，这是本设计的必备能力。

| 动作 | 作用 | 结果 |
| --- | --- | --- |
| 列出账号 | 查询指定 Surface 当前页面来源下的可用账号 | 账号的不透明标识与脱敏用户名 |
| 填充 | 让 Desktop 向指定 Surface 填入账号密码，可选择是否提交 | 仅状态 |

规则：

- **范围**：列出账号只覆盖指定 Surface 的当前来源，不能查询其他网站或整个保险库。智能体不能传入域名。已禁止智能体使用的账号不返回。
- **账号标识**：只在对应来源下有效，用于其他来源的 Surface 时拒绝。
- **未指定账号的填充**：来源下只有一个可用账号时使用它；有多个时使用该网站的默认账号。
- **状态语义**：已填充不代表已提交，已提交不代表登录成功。需要验证码、短信等二次验证时返回需要用户处理。超时不代表没有执行，不自动重放。
- **Surface 授权**：沿用现有 Run 页面授权链路，按精确 Surface 校验归属、guest 与 generation；凭据动作不授予访问其他 Chat 或前台页面的权限。

确认策略分两层，互不替代：

- **Platform 人工审阅**：凭据动作自动批准，不弹审阅。
- **Desktop 确认**：由 Desktop 决定。凭据动作**不属于** `desktop.web.*`，不继承该命名空间对可信 Platform Run 的统一确认豁免，也不加入可信 Platform 的动作确认豁免名单。填充按普通会修改页面的动作处理，跟随 Desktop 的动作确认开关与权限档位；列出账号只返回脱敏信息，不确认。

确认开启时，确认界面显示 Main 判定的真实域名和脱敏用户名，同一来源有多个账号时用户可以改选。确认关闭时直接执行，多账号使用默认账号。不为凭据另建一套"网站 + 账号"的授权记录；后续各类确认支持单独开关时，凭据填充作为其中一项。

由此带来的行为：确认开启时，无人值守任务遇到登录过期会停在确认界面，超时后以未开始执行失败。

填充期间的自动化隔离：

- 从填充开始到提交完成或用户接手，该页面的 CDP 与 AWCP 读取挂起，截图、DOM 导出等不返回密码字段的值。
- 这只保证密码不经正常工具通道进入模型上下文。智能体事先植入页面的脚本、同 session 的其他页面或 Service Worker 仍可能观察到密码，属于已接受的残余风险。

曾评估并放弃的方案：为每次登录创建临时隔离 session，登录后把登录态交接回默认 session。真实网站会把全新 session 视为新设备而反复触发验证，登录态也往往无法只靠 Cookie 交接，覆盖面与成本不成比例。

## 设置与数据生命周期

设置中提供密码与登录的管理入口，包含功能开关、站点与脱敏账号列表、默认账号、是否允许智能体使用、最近使用时间。

查看明文、复制、修改、删除、导入和导出都从这一可信界面发起，并先通过操作系统认证：

- 列表不加载任何明文。认证通过后 Main 只解密被请求的那一条，短时间后自动隐藏。
- 认证有效期很短，锁屏或睡眠后立即失效。
- macOS 与 Windows 的系统认证需要分别实现。系统账号没有设置密码时拒绝显示明文。
- 第一阶段这是界面门禁，保险库密钥本身无需认证即可解开。把密钥绑定到系统认证属于后续增强。

| 事件 | 处理 |
| --- | --- |
| 关闭保存功能 | 停止采集，保留已有密码；删除另有明确入口 |
| Desktop 升级 | 保留保险库，格式迁移必须可恢复 |
| 清理浏览器数据、删除 Website 入口 | 不删除密码 |
| 官网 SSO 退出或切换账号 | 不删除本地密码 |
| 环境导出、诊断包、项目同步 | 默认排除保险库与密钥 |
| 数据目录复制到另一台机器 | 不保证可解密，不静默重建覆盖 |
| 卸载 | 延续默认保留用户数据；用户明确选择清理时才删除 |

导入支持常见浏览器导出的密码文件，导入后提示用户删除原始明文文件。跨机器备份使用单独的加密导出，密钥来自用户设置的导出密码；不提供默认的明文导出，也不上传云端。

所有 Chat 共用默认浏览 session：一次登录后，其他已获页面授权的任务也能使用该登录态。锁定或删除密码不会让网站退出，清除网站会话是独立操作。

## 长期不变量

- 密码明文不落盘，不进入日志、诊断、崩溃材料、动作结果和模型上下文。
- 没有任何接口向 renderer 之外的调用方返回密码；renderer 也只在用户通过系统认证后取得单条明文。
- 来源匹配只信任 Main 解析的真实页面来源。
- 账号上的"禁止智能体使用"优先于确认开关和权限档位。
- 凭据动作保持独立命名空间，不并入 `desktop.web.*`。
- 系统密钥保护不可用时失败关闭，不降级。
- macOS 与 Windows 的密钥保护、访问控制和系统认证分别实现、分别验证。

| 阶段 | 内容 |
| --- | --- |
| 第一阶段：本地保管 | 显式启用、保存与更新、加密保险库、目录访问控制、设置中管理与认证后查看、用户手动填充、导入与加密导出 |
| 第二阶段：智能体协助 | 两个凭据动作、Desktop 确认接入、填充期间的自动化挂起、Platform 侧动作白名单与受保护路径 |
| 后续演进 | 复杂表单与更多登录形态、密钥绑定系统认证、按 Profile 隔离浏览 session |

## 配套改动

实现时需要同批完成：

- **Agent Platform**：凭据动作加入 Desktop Action 白名单并设为自动批准；受保护路径加入 Desktop `secrets/`；web-control 手册加入两个动作及其状态语义。Desktop 与 Platform 需同批发布，旧端对未知动作明确拒绝。
- **设计文档**：[数据目录](数据目录.md)补充 `secrets/` 的访问控制与智能体保护；[桌面协议与动作桥](桌面协议与动作桥.md)补充凭据命名空间与确认策略；[鉴权、SSO 与 Token Bridge](鉴权SSO与TokenBridge.md)补充网站密码与身份凭据的分界；[外部网站](外部网站.md)与[前端嵌入与导航](前端嵌入与导航.md)补充 guest 采集、填充与自动化挂起。
- **手工回归**：`qa/manual-regression.md` 增加保存与更新、多账号、认证后查看、导入导出、智能体填充的确认开与关、填充期间导航、密钥不可用，以及 macOS 与 Windows 各自的验证项。
