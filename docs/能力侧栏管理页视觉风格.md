# 能力侧栏管理页视觉风格

## 页面类别

Desktop 的二级侧栏有两类页面，不能使用同一套布局：

| 类别 | 代表入口 | 内容组织 |
| --- | --- | --- |
| 设置侧栏 | 外观、隧道等设置详情 | 居中的窄栏表单、分组卡片和字段控件 |
| 能力侧栏 | 智能体、技能中心、连接器中心、归档、市场、产物管理、分享管理 | 铺满工作区的管理页面，按内容使用列表／详情工作台或网格浏览 |

`/artifact-management`、`/share-management` 与 `/agents`、`/skills`、`/connectors` 同属能力侧栏，不能沿用设置详情的 `--settings-content-max` 窄栏。智能体、技能和连接器的内容由内嵌 Agent WebClient 绘制；分享管理由 Desktop renderer 原生绘制。它们共享页面类别和视觉层级，各自仍消费所属文档的主题变量。

依据见 `src/renderer/app-shell/navigation/capabilityNavigation.ts`、`src/shared/agent-webclient-routes.ts`，以及 Agent WebClient 的 `src/app/layout/ManagementPages.module.css`、智能体／技能／连接器 Console 样式。设置窄栏的依据是 `src/renderer/pages/settings/SettingsPage.css`。

## 背景底板

- 背景是能力管理页的第一层视觉约定。没有图片背景时，市场、分享管理和帮助保持各自的实色回退；启用图片时，Desktop 的唯一背景层透过市场与分享管理根容器，由主工作区提供连续阅读衬底。页面边距、列表和详情不各自铺第二层底板。
- 智能体、技能和连接器由 WebClient 绘制，使用它自己的 `--management-page-surface`。只有宿主图片背景能力完成协商时，这些 guest 页面才在 Desktop 壁纸上使用约 94% 不透明的连续阅读层。Help 使用匿名独立 WebView，不消费这条外观桥；Desktop 只能清除宿主层，帮助站点负责 guest 文档的透明背景与正文阅读衬底。
- 选中项、专用卡片、可编辑控件和弹窗可以使用各自的阅读表面；不能让整张分享管理页多一层图片叠加。视觉验收应在相同皮肤下对照实际页面，而不是只比对变量名。

## 能力页布局

- 页面占用主工作区的完整可用宽高，只留约 10–12px 的内侧边距。页首或列表工具栏放页面名称、简短说明、刷新和创建等全局操作。
- 有明确“对象列表 → 当前对象内容”关系时，采用约 240–280px 的左侧列表和自适应的右侧详情。两栏各自滚动；窄窗口可以上下排列。市场网格、单纯的历史列表等业务使用相应的全宽内容组织。
- 列表条目平时透明，悬停显示轻微底色，当前条目使用主题选中色。详情标题、只读内容和操作直接排列在页面底板上，以间距和少量细分隔线形成层级。
- 不用设置页的外框卡片包住每个管理对象，也不在只读链接和每个行内按钮外重复描边。只有真实可编辑字段、选中状态或需要明确边界的专用面板使用方框。

## 文本、控件与状态

- 标题和当前对象名称比计数、ID、URL、时间更醒目。列表业务名约 13px，正文和操作约 12px，辅助信息约 11–12px；长 ID 与 URL 截断展示，原始值由复制操作保留。
- 已有复制按钮的分享 URL 显示为普通文本，不使用只读输入框。普通操作采用无边框按钮，悬停和键盘聚焦显示反馈；危险操作保留显式文字、颜色及确认步骤。
- Desktop 原生页面使用 `src/renderer/styles/theme.css` 的 `--desktop-ui-bg`、`--shell-content-bg`、`--ink`、`--line`、`--accent`、`--control-*` 等语义变量。WebClient 使用自己的管理页主题变量；不能通过注入样式改变 guest 页面。主窗口背景边界遵循[主窗口外观与皮肤](主窗口外观与皮肤.md)。
- 加载、空状态和错误状态沿用同一宽度及文本层级，不突然切换成设置表单式的大卡片布局。

## 应用检查

新增能力侧栏页先核对侧栏模式及管理页背景底板，再对照智能体、技能或连接器的全宽容器、选择状态和列表／详情滚动。分别检查默认浅深色、图片皮肤、自定义照片、长文本、窄窗口、禁用与键盘聚焦。数据契约、导航权限和业务交互仍以各页面源码及测试为准。
