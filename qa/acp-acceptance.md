# ACP 插件产品与发行手工验收

整理日期：2026-11-06。本表为当前预期与待填写标准，不是通过记录。范围：Desktop 跨 Node 升级、Windows、认证与特殊生命周期、第三真实引擎、最终发行五类验收；具体支持组合须按本次候选版本重新记录。按当前架构和 UI 操作，不增加网关配置入口，不保留旧 ACP 兼容。

共享 Node 的升级前协调已通过 macOS 双插件实测；**真实签名 Desktop 跨 Node 覆盖升级尚未完成**。五类均须有对应执行人的手工验收报告；文档不执行安装、升级或发布，也不把交接记为完成。跨 Node 升级需先准备两份内嵌 Node 不同的真实签名 Desktop 包、对应兼容插件及测试更新包地址；已有正式包可直接验证，不要求在当前机器签名。其余手工测试可独立开展。原始标准来自工作区历史计划，本仓库版本按当前代码维护，独立检出即可使用；QA 命令见 [索引](README.md)，共享 Node 策略见 [服务生命周期](../docs/服务生命周期.md)。

平台校验遵循当前产品策略：macOS 保留宿主签名及原生更新器验证；Windows 使用更新清单验签和文件校验，Authenticode 额外签署可选，不要求安装包与当前 EXE 匹配证书。表中的签名负向测试按各平台实际门禁执行。

## 1. 执行准备与判定规则

- 固定并记录 Desktop、Platform、WebClient、插件、Adapter、CLI/SDK、内嵌 Node 的版本，系统版本/架构、包摘要、测试时间及网络/代理方式。每个支持的平台/架构都要有记录，不能用 macOS 或交叉编译结果代替 Windows 原生结果。
- 使用测试工作区和可恢复的测试数据。两个插件各建独立 Chat；强杀只针对本次测试确认归属的 PID，不按通用 `node`/`claude`/`codex` 名称批量杀进程。
- 每个 Chat 首轮发送不同随机标记，例如 `请记住本次标记 <现场随机值>，后面会问你`。恢复后仅问“第一条消息中的标记是什么”，不要在问题中重新给出答案；同时确认此前创建文件的内容和所选配置。
- 准备一个工作区内测试文件，以及一个明确不允许写入的测试路径。审批前记录文件内容/摘要，拒绝后复核没有改动；禁止用个人重要文件做越界测试。
- 结果只填：**通过 / 失败 / 阻塞 / 不适用**。未执行一律保持未勾选；“能启动”“prepare 成功”“下载完成”均不等于对应完整用例通过。
- 必需能力必须通过。可选能力仅在本版支持范围明确排除、UI/协议均不宣称可用时可记“不适用”，写明理由；已声明支持却失败不能改记“不适用”。缺入口、缺依赖或没有可用环境记“阻塞”，并登记实现/环境缺口。
- 证据至少包含版本、步骤、预期与实际结果、截图、脱敏日志和 Chat/Run 标识。进程测试补 PID/父子关系和退出记录，升级补前后版本/包摘要。不得记录 Token、密码、OAuth code 或完整认证回调 URL。

下面每行是一项验收条件，最后一列勾选表示该行所有要求通过；多引擎/平台组合须在结果表中分别记录。

## 2. 真实 Desktop 跨 Node 升级（ACP-014）

本项优先在 macOS 原生执行，不能用开发 Electron 壳、单独替换 Node 文件或仅重启 Platform 代替。准备旧版 A 和新版 B：同一品牌/架构、符合原生验签要求，B 的应用版本高于 A，且内嵌 Node 确实不同。A 也必须包含本次 ACP 排空门禁；不含新 ACP 逻辑的历史旧应用不能证明该门禁生效。两版各有精确匹配 Node 的 Codex/Claude 插件包。

使用独立系统测试账号或已有受支持的隔离数据根。通过应用现有测试更新入口加载合法清单，或使用测试 HTTPS 更新源；安装仍走正式验证与原生更新器。记录包摘要、签名发布者、实际安装位置和数据位置，不绕过签名、品牌或版本校验。两插件各留下随机记忆、一个工具创建的文件、所选配置和未发送草稿。

| ID | 手工操作 | 通过标准 | 通过 |
| --- | --- | --- | --- |
| N01 基线与下载 | 在 A 中确认两个插件能正常提问；下载 B 但不点击安装；普通退出并重开 A | 实际仍运行 A/旧 Node，后台下载不会提前安装；原 Chat、配置和草稿保持，缓存经复验可继续使用 | [ ] |
| N02 两端活动时升级 | 两插件各进入真实待审批或工具执行状态，点击现有升级入口并确认 | 返回忙碌状态（诊断为 updateBusy）；Platform 和两插件活动进程不被强停，原审批仍可提交，旧 Node 文件不被替换；不是仅凭 UI 显示“升级失败”判通过 | [ ] |
| N03 仅一端活动 | 先完成 Codex，保留 Claude 活动，再尝试升级；重新准备场景，交换两端重复 | 两个方向都拒绝升级；仍活动的另一插件保持原 Run/审批/凭据。可继续完成或取消，之后允许显式重试 | [ ] |
| N04 全部排空后实际安装 | 结束全部任务，重试升级；观察退出、原生替换和自动重启；尝试安装开始后的新请求 | 先关闭新准入并确认旧树退出，再交给原生安装器；无夹入的新执行。B 从实际安装位置启动，服务恢复健康；About 应用版本和实际插件进程所用 Node 都是预期新版，不能用终端全局 `node -v` 作证据 | [ ] |
| N05 插件兼容与同步 | 在 B 中先保留旧 Node 精确依赖的插件尝试准备，再通过现有入口安装匹配新 Node 的兼容插件 | 不兼容时明确 dependency_missing，不借系统 Node、不改写 Manifest、不创建空会话。兼容包安装/启用后动态发现并可运行，无 YAML 或手工重启 Platform 要求 | [ ] |
| N06 双插件原会话恢复 | 分别打开升级前原 Chat，显式询问首轮随机标记及旧文件事实，核对模型等配置、凭据/profile 和草稿；再完成一次审批 | 两端上下文、配置和原数据保持，恢复原外部会话；审批正常。没有自动重发旧 Query、重复工具执行、悄悄新建空 Chat；升级后没有仍运行的旧 Adapter/CLI 后代 | [ ] |
| N07 下载与校验失败 | 中断测试下载后重试；通过测试源提供错误摘要、损坏包或签名不合法的候选 | 中断可重试；不合法包不能进入替换安装，A 和原数据保持可用，有明确错误。不要修改真实发布包或生产更新源进行负向测试 | [ ] |
| N08 清理或原生安装失败 | 在隔离副本中用可复现的占用/不可写条件触发清理或原生替换失败，恢复条件后按 UI 指引重启/重试 | 清理失败不调用安装器；原生阶段失败不谎报升级成功，诊断可取得，聊天和凭据保留。重新启动实际仍有效的安装版本后服务可恢复，并可显式重试；不要求当前产品未承诺的自动应用降级或数据回滚 | [ ] |

证据必须串起「A/旧 Node → 忙碌拒绝 → 全部排空 → 原生替换 → B/新 Node → 两插件原 Chat 恢复」。两种排空顺序的拒绝都要实测；成功替换至少有一条完整记录。没有旧包/新包、可信测试源或兼容插件时记“阻塞”，不能复用已有组件测试勾选本项。

至少分别执行 Codex、Claude；两插件隔离用例交换操作对象再执行一次。

| W08 安装器与卸载边界 | 按发行支持范围测试安装覆盖、取消提权、不可写目录及插件卸载/重装 | 取消/失败有明确状态，不报安装成功；插件卸载后不能新执行，Chat/认证 profile 保留，重装能恢复；Desktop 本体卸载的数据删除选择遵循原产品语义，不扩大为一律保留 | [ ] |

## 4. 认证与特殊生命周期（ACP-012/013/014/016）

认证按本版实际支持方式执行：Codex 浏览器登录；Claude 本轮已确认范围是复用既有网关配置。Claude 新用户配置入口未实现且不在本轮范围，不能用测试脚本写配置来替代其产品验收；其他认证方式须先确定发行范围。

| ID | 手工操作 | 通过标准 | 通过 |
| --- | --- | --- | --- |
| A01 登录取消与超时 | 新隔离 profile 发起浏览器/已支持终端登录；分别取消、关闭授权页、等待现有认证期限到期，再显式重试 | UI 结束等待并明确结果；回调监听和所属辅助进程退出；不误报已认证、不创建成功绑定；重试后能真实提问 | [ ] |

| A08 长会话 | 建议每个插件至少连续 20 轮、30 分钟，含文件工具、审批、取消及一次重启；首尾核对随机记忆和文件事实 | 无重复历史、串话、卡死或不可恢复等待；正常轮有唯一 complete，取消/失败轮有唯一对应终态；上下文压缩后仍满足声明的恢复能力。此轮数/时长是本次建议测试规模，不是新增产品上限 | [ ] |

| A10 可选交互 | 逐项核对本版能力清单中的多选提问、规划、持续授权、steer、附件和沙箱范围 | 声明支持的能力有真实操作证据、选项/结果准确且越界被拒绝；未验证能力保持关闭，不以 Native 的表现推断外部引擎支持 | [ ] |

## 5. 第三真实引擎（通用化-07 / ACP-016）

先选择一个符合当前 Manifest API 2、ACP stdio 和已声明 Node/executable 交付形式的真实引擎，固定版本、目标 OS、认证方式及能力。原生 executable 已有交付分支；未知运行时或超出现有协议能力的候选须登记通用能力缺口，不能以此临时修改宿主产品分支。

| --- | --- | --- | --- |
| T01 冻结宿主 | 接入前记录 Platform/Desktop/WebClient 和公共构建工具修订或文件摘要，只新增第三插件、依赖锁和工作区声明 | 接入后宿主和共享工具不需要新增厂商名判断、认证特例或构建分支；对照 diff/摘要有证据。若需要修改，门禁未通过，先登记通用能力缺口 | [ ] |
| T02 安装与发现 | 用正式支持的安装入口导入第三插件，启用/禁用并查看项目创建选项 | 无需重启 Platform、编辑 YAML 或暴露固定 ACP 服务端口；目录及两端项目创建选项及时更新，禁用后不可新执行 | [ ] |
| T03 真实产品链路 | 通过现有 UI 完成允许的认证、配置选择、多轮 Query、真实文件/工具审批、取消和显式恢复 | 认证/profile 无 Codex/Claude 特例；配置按协议能力投影；支持的 HITL 正常且无虚构选项；重启后原会话随机记忆恢复，历史不重复 | [ ] |
